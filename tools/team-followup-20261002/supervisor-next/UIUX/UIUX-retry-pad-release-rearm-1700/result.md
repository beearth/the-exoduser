# UIUX-RETRY-PAD-RELEASE-REARM-1700

생산 적용0/native 인수0. source5 양판 기준 새 독립 caller 후보다. SUPERVISOR-UIUX-1700이 기존 UIUX2 예약을 실제 해제해 candidate.patch/result.md 두 신규 파일만 허용했다. 생산·정본docs·Git·index·앱·GUI·세이브·타팀 원자료 수정0. 원래 source4 앱3386과 GUI lease는 건드리지 않았다.

## 문제와 후보
기존 재도전 입력해제 후보(_clearHeldInput)를 적용한 baseline에서도 죽음 UI에서 LT+A로 재도전을 선택하고 계속 유지하면 첫 게임 poll이 Digit1을 새로 주입한다. 전체 registered keyboard callback과 slot dispatcher가 boneWall aim을 다시 켠다. 기본 A만 유지하는 경로는 기존 _gpSynced 스냅샷이 이미 보호한다.
후보는 재도전 시 당시 pressed 또는 value>0.5인 버튼 index를 _pollGamepad._retryHeld에 저장한다. 다음 poll에서 저장된 버튼 중 하나라도 계속 눌려 있으면 _gpClearAll 후 return한다. 저장 버튼이 모두 풀리면 latch를 지우고 기존 LT held/mod 및 kLT0~3 상태를 초기화한다. 새로운 LT+A는 다시 정상 디스패치한다. transient 함수 속성이며 저장 스키마에 추가하지 않는다.
candidate.patch에는 이전 1652 helper 호출을 재사용한 부분1 + 이번 held capture1 + poll guard1을 포함한다. 이전 마우스 검사 및 GC focus/root 재진입12/옛16수정 묶음은 재실행0.

## 검수 Gate와 한계
- 새 source-composition assertions: 양판 2상황 × baseline/candidate = 4쌍/8실행. 최종 검사 프로세스 exit0. 실제 전체 poll→전체 generic death nav→등록 retry onclick→full async retry→다음 poll→실제 전체 keyboard callback→full slot dispatcher.
- baseline은 생산 source5 전체가 아니라 source5 retry에 이전 메모리 _clearHeldInput 1회 호출을 접합한 것이다. 후보는 그 기준에서 pad latch 두 접점을 추가한다.
- LT+A 유지: baseline 첫 poll Digit1/aim=true, 후보 false. 후보 release→fresh LT+A는 aim=true.
- 기본 A 확인 후 새 LT+A: 첫 held 프레임과 fresh 상태가 baseline/candidate 동일.
- DOM selector/query/click/event transport/scroll은 대역이다. source death markup의 첫 retry 버튼을 선택하도록 구성했다. 최초 실패3건은 document.querySelector 누락, retry가 death 자식으로 배치되지 않음, click 메서드 누락이었다. fixture를 보완했고 생산 후보를 그 때문에 바꾸지 않았다.
- 최종 출력이 19,854tokens여서 tool output 한도에 잘렸다. exit0와 전체 assertions 완료는 확인되며 마지막 easy case 배열은 raw에서 정확히 복구했다. main per-case raw 일부는 복구되지 않았다. stdout 확장을 위해 완료 검사를 재실행하지 않았다. main/easy 정상 동등은 실행 script assertions와 exit0 수준의 근거이며, 모든 raw가 보존됐다고 주장하지 않는다.
- full initStage/applyStats는 endpoint이며 actual resource refill·fallenResolve failure·input/dispatcher 함수만 실행했다. 실제 맵·보스복원·full game update·실물패드·native default action·visual/audio/save는 미인수.
- 의도된 후보 범위: 저장된 이전 버튼이 하나라도 눌린 동안 다른 새 패드 버튼과 스틱도 polling return에 의해 잠시 억제된다. 모든 이전 버튼 release 후 재무장한다. 이것을 독립 새 입력의 무조건 즉시 허용이라고 주장하지 않는다. 다른 버튼·다른 컨트롤러 교체/재연결·새 오버레이·cutscene·aim release family 전체와 shared _pollGamepad pending 변경 병합은 root 검수 Gate다.

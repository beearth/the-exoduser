# BUILD-CONDITIONAL-RANGE

기존 BUILD 세션의 다음 한 건. 기준 HEAD/원격8e4ed4e446329c863ed4d2d556d386c37f3ae310, server SHA6a7c1083ac10b105cca3624c8fd0e919d14a59b32774612ff0a00cb881be8538. 이전 suffix 후보는 root가 생산에 통합하고 합본40검사를 마쳤다. 동일 과제 진행/대기·초안을 먼저 확인하고 중복이면 추가 실행하지 않는다.

이전 media-range 결과에 남은 If-Range 및 조건부 GET/Range 순서를 한 건으로 조사한다. 현재 실제 분기/handler를 추출해 RFC9110의 조건부 요청 우선순위와 If-Range 불일치 시 전체응답 계약을 대조한다. 실제 반례가 있으면 기존 RED를 보존하고 최소 미적용 패치·회귀를 BUILD/conditional-range-*에 작성한다. 가능한 것만 좁게 고치고 HTTP 전반을 재작성하지 않는다. 기존 suffix/fixed/large/invalid 범위, GET 캐시·gzip·HEAD와 저장 helper/route를 보존한다. 실제 source SHA·함수 SHA·원자료 및 남은 한계를 적는다.

다른 담당과 같은 checkout을 공유한다. 소유는 새 prefix와 BUILD MD 본인 추가구역만, server/HTML/공유docs는 읽기 전용. 타팀 변경·stage·초안·기존 자료를 되돌리지 않는다. 서버 전체 실행/listen/HTTP/포트/앱/브라우저/빌드/에셋/권한변경/Git쓰기/새세션·팀·에이전트0. 기존 EPERM 우회0. QA 실제UI 슬롯과 사용자게임1573846373·세이브 보존. 한국어 receipt/result에 실제 수신/Read/Edit/명령 시각과 gate를 구분한다.

# BUILD-MEDIA-RANGE

기존 BUILD 세션의 다음 독립 작업. AGENTS/BUILD 팀 문서/기존 media 진단을 읽고 동일 과제의 진행·대기 중복을 먼저 확인한다. 이전 초안과 후보를 보존한다.

현재 server.cjs 정적 파일 Range 분기는 bytes=-500을 start=0,end=500으로 계산한다. 영상 탐색 관련 기존 미검수 백로그에서 이 실제 코드 결함을 분리하여 재현하고 최소 수정 후보를 만든다. 이 결함이 이전 영상 오류 원인이라고 단정하지 않는다.

소유 파일은 tools/team-followup-20261001/BUILD/media-range-* 및 팀 MD 본인 추가 구역. server.cjs는 읽기만 하고 패치는 새 소유 파일로 제출한다. 실제 원 분기를 추출한 req/res/fs 대역 fixture로 기존 suffix 실패와 후보 정상 결과를 증명한다. 고정 범위, 열린 끝, suffix, 끝 초과, 빈 파일, 잘못된 단위·숫자·다중 범위 정책을 공식 HTTP 표준에 대조한다. HEAD는 별도 의미이므로 조사가 필요하면 증거와 범위를 분리하고 불필요하게 패치를 키우지 않는다. 기존 GET/캐시/압축 경로 보존을 검수한다. 실제소스 SHA와 후보 적용가능성을 기록한다.

네트워크 listen/서버 실행/포트 탐색/API 요청/브라우저·앱 실행/대형 빌드/에셋 처리는 하지 않는다. BALANCE의 EPERM을 우회하는 통합 검수가 아니라 독립적인 소스 단위 결함 재현이다. QA만 실제 UI/런타임 슬롯을 소유한다. 사용자 게임탭·세이브 접촉0. 공용 HTML/server/총괄docs/Git/index 수정0, 새 세션/팀/에이전트/권한변경0. 한국어 receipt/result에 수신·Read·수정·실행·제한을 구분한다.

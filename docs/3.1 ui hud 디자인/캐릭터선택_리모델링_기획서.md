# HELL: EXODUSER 캐릭터 선택/생성 화면 리모델링 기획서

## 1. 현재 진단

스크린샷 기준 문제점

- 캐릭터 썸네일이 빈 사각형으로 노출 (시각화 0%)
- 좌우 화면 60% 이상이 검은 빈 공간, 패널만 중앙에 떠있음
- 게임 톤(다크 판타지/베르세르크/소울본)과 UI 톤(일반 웹폼)의 괴리
- 정보 부족: 이름/Lv/위치만, 플레이타임/통계 없음
- 삭제 버튼 상시 노출 - 오클릭 위험
- 캐릭터 생성: 이름만 입력하고 끝, 의식감 0
- LOCAL MODE 표기가 컨텍스트 없이 외롭게 떠있음
- 한국어 드롭다운 셀렉트가 OS 기본 스타일 그대로

## 2. 컨셉 방향

- 레퍼런스: Diablo IV 캐릭터 선택창, Elden Ring 캐릭터 메뉴, Hollow Knight 분위기
- 무드: ritual, 묵직함, 화면 안에 누군가 서있다는 존재감
- 핵심 변화: "리스트에서 데이터 고르기" -> "지옥에 보낼 캐릭터 고르기"
- HELL 로고 톤(주황/적색)을 액센트 컬러로 일관 사용

## 3. 레이아웃 (3분할)

화면을 좌 50% / 중 28% / 우 22% 비율로 분할.

### 좌측 50% - 캐릭터 디스플레이

- 선택된 캐릭터 풀바디 또는 흉상 (게임 내 idle 스프라이트 재활용)
- idle 애니메이션 루프 노출
- 캐릭터 뒤에 그라데이션 배경 + 미세한 안개/먼지 파티클
- 무기/장착 이펙트 그대로 노출
- 좌측 하단에 미세한 viginette

### 중앙 28% - 정보 패널

- 캐릭터 이름 (대형 타이틀, 로고 폰트와 통일)
- Lv. + (있다면) 클래스 태그
- 진행도: 예) 1장 썩은 숲 4층
- 플레이타임: hh:mm
- 누적 처치수
- 누적 사망 횟수
- 보유 골드/주요 재료 요약 (3개까지)
- 마지막 플레이: yyyy-mm-dd hh:mm

### 우측 22% - 슬롯 리스트

- 슬롯 카드 세로 정렬 (스크롤 가능)
- 활성 슬롯: 보더 글로우 + opacity 1.0
- 비활성 슬롯: opacity 0.6
- 호버시 scale 1.02, 200ms ease
- 삭제는 호버시에만 우측 끝 X 아이콘 노출

### 상하단

- 좌상단: HELL 로고 작게
- 우상단: LOCAL/ONLINE 모드 토글 + 언어 선택 (커스텀 셀렉트로 교체)
- 우하단: 빌드 버전 (v0.x.x)
- 좌하단: 종료 버튼
- 중앙 하단: 입장 버튼 (대형, 글로우)

## 4. 슬롯 카드 스펙

- 사이즈: 280 x 72
- 구성: 좌 56x56 흉상 썸네일 + 우측 텍스트 영역
- 텍스트 상단: 이름 (16px bold)
- 텍스트 하단: Lv.000 ㆍ 1장 썩은 숲 4층 (12px, 디밍)
- 보더: 1px solid rgba(255,255,255,0.08)
- 활성시 보더: 1px solid #c44 + box-shadow 0 0 12px rgba(196,68,68,0.4)
- 호버시 transform: scale(1.02)
- 삭제 X 아이콘은 hover시에만 fade-in (opacity 0 -> 0.7)

빈 슬롯

- + 아이콘 + "새 캐릭터" 텍스트
- 클릭시 생성 모달 진입
- 최대 슬롯 수는 정책에 맞게 (8개 추천)

## 5. 캐릭터 생성 플로우 개편

현재: 이름 입력 -> 생성 (단일 단계)

신규: 풀스크린 또는 큰 모달로 전환

1단계 - 이름 입력 (2~5자 제약 유지)
2단계 - (선택) 시작 외형/색조 프리셋 3~4개 중 선택
3단계 - 확인 -> ritual sfx + 페이드 트랜지션 -> 캐릭터 디스플레이로 자연스럽게 전환

외형 프리셋 추가가 부담이면 1, 3단계만 유지하되 트랜지션 강화.

## 6. 삭제 처리 강화

현재: 삭제 버튼 클릭시 즉시 삭제 (위험)

신규:

- 호버시에만 X 버튼 노출
- 클릭시 확인 모달 표시
- 모달 내용: "캐릭터 [이름] 을(를) 영구 삭제합니다. 확인을 위해 이름을 입력하세요."
- 이름 직접 타이핑 입력 일치시에만 삭제 활성
- 또는 대안: 길게 누르기 2초 + 진행 게이지

## 7. 모션/사운드

- 슬롯 전환: 좌측 디스플레이 fade 200ms + 정보 패널 슬라이드인 (translateX 8px -> 0)
- 호버: ui_hover sfx (기존 자산 재활용)
- 클릭: ui_select sfx
- 입장 (게임 시작): 화면 페이드 아웃 + 묵직한 transition sfx
- 생성 완료: ritual sfx + 짧은 글리치 또는 ember 파티클
- 삭제 확인: 낮은 톤 confirm sfx

## 8. 데이터 추가/마이그레이션

캐릭터 데이터에 추가 필드 필요

- totalKills: number
- totalDeaths: number
- playTimeMs: number
- lastPlayedAt: timestamp
- thumbnailFrame: 캐릭터 썸네일용 idle 프레임 캡쳐 (또는 동적 렌더)

기존 캐릭터: 없는 필드는 0 또는 null로 초기화.

## 11. 구현 동기화 — 슈퍼와이드 외형 선택 영상 (2026-08-08)

`index.html`의 풀스크린 외형 선택 팝업(`charVisualPop`)은 캐릭터가 포함된 16:9 아이들 영상 두 종을 기본 `object-fit: cover`로 표시한다. 3440×1440(약 21:9)에서는 중앙 정렬 시 영상 상단이 약 247px 잘려 머리가 화면 밖으로 나가고 전신도 과도하게 확대된다. 슈퍼와이드에서는 원본 프레임을 기준으로 상단 기준 15% 확대와 가로 10% 확장을 적용하며, 남는 좌우 영역에는 금속 프레임 질감을 제한적으로 겹친다.

| 대상 | 기본 동작 | 21:9 이상 동작 | 적용 위치 | 의도 |
|---|---|---|---|---|
| `idle_warrior.mp4` | `object-fit: cover`, 기본 중앙 크롭 | `object-fit: contain; object-position: center top; transform: scale(1.15) scaleX(1.1)` | `#charVisualPop .cs-idle-vid` | 전사 머리 보존, 발끝만 허용 크롭·가로 10% 확장 |
| `idle_silvertail.mp4` | `object-fit: cover`, 기본 중앙 크롭 | `object-fit: contain; object-position: center top; transform: scale(1.15) scaleX(1.1)` | `#charVisualPop .cs-idle-vid` | 실버테일 머리 보존, 발끝만 허용 크롭·가로 10% 확장 |
| `fdg_reference_1280x720.png` | 미사용 | 좌·우 가장자리 크롭 텍스처 (밝기 62%, 불투명도 94%) | `#charVisualPop .cs-side-texture::before/::after` | 뒤 영상이 비치지 않게 금속·석재 질감을 선명히 표시, 중앙 로고·인물은 제외 |

- 브레이크포인트: `@media (min-aspect-ratio: 21/9)`.
- 16:9·16:10·일반 창 크기의 중앙 구도는 변경하지 않는다.
- 확대 기준점은 `center top`이다. 상단(머리)은 고정하고 하단(발끝)만 최대 216px 범위에서 크롭한다.
- 질감 레이어는 `output/fdg_reference_1280x720.png`를 사용하며, `@media (min-aspect-ratio: 21/9)`에서만 표시한다. 일반 비율에서는 `display:none`으로 레이아웃에 영향을 주지 않는다.
- 양쪽은 각각 화면 폭의 30%까지만 사용하고, 원본의 좌·우 가장자리만 `background-position:left/right center`로 잘라 쓴다. 원본 중앙의 FDC 로고는 노출하지 않으며, 바깥 65%만 불투명하게 표시한 뒤 중앙으로 페이드한다.

## 12. 구현 동기화 — 로비 선택 캐릭터 타이틀 (2026-08-08)

로비 좌측 하단의 안내 문구는 캐릭터 초상화 슬롯을 선택했을 때 선택 캐릭터의 이름과 직업을 표시한다. 캐릭터 이미지를 새로 띄우지 않고 기존 로비 배경 위의 텍스트 정보만 갱신한다.

| 상태 | 주 타이틀 | 보조 타이틀 | 데이터 원본 | 적용 위치 |
|---|---|---|---|---|
| 미선택 | `당신은 누구인가` | 없음 | 고정 안내 문구 | `#charDispTitle` |
| 선택됨 | 캐릭터 이름 | 캐릭터 직업 | `CHAR_VISUALS[charIdx].job` (대체: `cls`) | `#charDispTitle`, `#charDispSub` |

- 텍스트 스타일은 게임 메인 화면의 맵 정보 타이틀과 같은 구성을 사용한다: 중앙 정렬, 좌우 장식선, 빛바랜 상아색 이름, 절제된 황동색 직업 보조선.
- 온라인 슬롯은 `ch.charIdx` 또는 `ch.data.charIdx`, 로컬 슬롯은 `s.charIdx`로 직업을 조회한다.
- 온라인과 로컬 선택 경로 모두 `_updateCharDisplay(s)`로 수렴한다. 목록을 다시 불러오면 미선택 상태로 복귀한다.
- 텍스트 갱신은 `#charDispTitle`, `#charDispSub` 리프 노드에만 수행해 로비 DOM 구조를 보존한다.
- 언어를 바꿀 때도 `_selectedCharDisplay`를 다시 적용한다. 선택 중인 캐릭터 이름은 유지하고 직업 표기만 선택 언어에 맞춰 갱신한다.
- 초기 언어 적용은 DOM 도우미 `$`가 선언되기 전에 실행될 수 있으므로, 기본 안내 문구 갱신에는 `document.getElementById`를 사용한다. 초기화 예외가 발생하면 기존 타이틀 화면의 진행 이벤트까지 중단되므로 이 순서를 유지한다.
- 선택 시 `#lobbyCharPreview`에 캐릭터 선택 창과 동일한 전신 아이들 영상 `CHAR_VISUALS[charIdx].idleVid`를 좌측 전체 크기로 재생한다. 기존 고정 거대 전사 로비 배경은 영상 레이어가 완전히 덮어 선택 캐릭터와 무관한 인물이 남지 않는다. 미선택 상태에서는 영상 소스를 비우고 기본 배경만 표시한다.

## 13. 구현 동기화 — 로비 슬롯 진행도 (2026-08-30)

온라인·로컬 캐릭터 슬롯의 진행도는 저장값 `game.stage`/`stage`를 10구역 고정 공식으로 해석하지 않는다. `lobby-stage-info.js`의 장별 가변 구역 테이블을 공통으로 사용하며, 최초 스테이지도 `시작점`으로 숨기지 않고 `1장 썩은 숲 1층`으로 표시한다.

| 장 | 한글명 | 저장 stage 범위 | 표시 층 | 적용 위치 |
|---:|---|---:|---:|---|
| 1 | 썩은 숲 | 0~3 | 1~4층 | 온라인·로컬 슬롯 |
| 2 | 벌레굴 | 4~9 | 1~6층 | 온라인·로컬 슬롯 |
| 3 | 지옥의 겨울 | 10~13 | 1~4층 | 온라인·로컬 슬롯 |
| 4 | 고통의 화염지대 | 14~20 | 1~7층 | 온라인·로컬 슬롯 |
| 5 | 지옥의 군단 | 21~25 | 1~5층 | 온라인·로컬 슬롯 |
| 6 | 사도의 마굴 | 26~31 | 1~6층 | 온라인·로컬 슬롯 |
| 7 | 지옥성 | 32~34 | 1~3층 | 온라인·로컬 슬롯 |

- 표기 공식: `{chapter}장 {canonical chapter name} {stage - startStage + 1}층`.
- `stage 12`는 `3장 지옥의 겨울 3층`, `stage 13`은 `3장 지옥의 겨울 4층`이다.
- 범위를 벗어나거나 유효하지 않은 저장값은 안전하게 전체 stage 범위 `0~34`로 정규화한다.
- 온라인 `_renderOnlineSlots()`와 로컬 `_renderSlotList()`는 반드시 `_formatLobbyStageProgress(stage,_TL)` 하나로 수렴한다.

# EXODUSER UI/UX 개선 프로젝트

> 상태: 진행 중 · 시작: 2026-09-30 · 관리 책임: Codex UI/UX 리드
>
> 이 문서는 UI 개선의 작업대장이다. 실제 규격과 수치는 각 시스템의 기존 SSOT 문서와 코드가 우선한다. 구현·검수 결과가 바뀔 때마다 이 문서의 상태와 근거를 갱신한다.

## 목표

전투 중 필요한 정보를 빠르게 읽고, 메뉴에서는 원하는 항목을 적은 조작으로 찾고 변경하게 한다. 프레임·재질·타이포그래피를 게임의 어두운 금속 미술 방향과 일치시키며 키보드·마우스·게임패드·작은 화면에서 정보와 조작이 잘리지 않게 한다. AAA급 완성도를 목표로 하되 실화면 검수와 동작 증거가 없는 화면을 완료로 표시하지 않는다.

## 관리 원칙

1. 각 패스 시작에 Git 상태와 화면의 현재 모습을 확인한다. 다른 작업의 변경은 보존한다.
2. 사용자 지시, `AGENTS.md`, 각 시스템 SSOT를 먼저 읽고 UI 문제를 **보이는 현상 → 원인 → 수정 → 실제 화면 재검수** 순서로 기록한다.
3. 한 번에 한 흐름을 완성한다. 정보 위계·입력 피드백·스크롤·반응형·접근성·성능 영향을 함께 검토한다.
4. 코드 변경 뒤 `docs/` 전체 관련 키워드를 검색해 동기화하고 코드와 문서를 함께 커밋한다. 본편 `game.html`과 쉬운판 `game-easy-test.html`의 공통 UI는 둘 다 확인한다.
5. 검수 단계는 소스 검사, 자동 테스트, 로컬 실화면, 패키지, 배포를 분리해 기록한다. FPS 또는 입력 지연은 직접 측정하지 않았다면 판정하지 않는다.

## 공통 완료 기준

| 게이트 | 확인 내용 |
|---|---|
| 정보 위계 | 탭·제목·섹션·값·위험 동작의 우선순위가 한눈에 구분된다. 중복 제목과 과도한 빈 공간을 줄인다. |
| 동작 | 마우스 클릭, 키보드 Tab/Enter/Space/화살표, 가능한 경우 패드 입력으로 같은 목표에 도달한다. 설정값·저장·기존 단축키는 의도 없이 바뀌지 않는다. |
| 화면 | 기본 데스크톱, 1324×982, 1280×800, 390×844에서 가로 넘침·가림·잘린 버튼이 없다. 긴 내용은 스크롤되며 닫기 동작이 남는다. |
| 접근성 | 버튼에 이름과 초점 표시가 있고, 탭/섹션 관계와 상태를 읽을 수 있다. 언어 전환 뒤 이름이 갱신된다. |
| 안정성 | `node --check`, 관련 회귀 테스트, 본편·쉬운판 새로고침 후 동작이 통과한다. 콘솔 오류와 저장 데이터 부작용을 확인한다. |
| 기록 | 해당 화면의 수치·ID·검수 범위·미검증 항목을 SSOT와 이 작업대장에 갱신한다. |

## 현재 패스: UI-01

| 항목 | 기준선 / 설계 결정 |
|---|---|
| 기준선 | 게임 탭 내부 순서는 시스템 → 게임 설정. 기존 4개 설정 탭과 옵션 ID·리스너 유지. 1324×982에서 첫 화면은 시스템 액션까지만 보이며 본문 스크롤이 약 400px 남는다. |
| 수정 방향 | 설정 재진입 때 현재 탭 내용의 시작으로 돌아간다. 게임 탭 상단에 시스템·게임 설정 구역 이동을 제공하고 섹션 제목에 초점을 연결한다. |
| 보호 항목 | 프리셋 저장/불러오기, 캐릭터 선택, 리셋·종료, 옵션값과 저장 포맷을 바꾸지 않는다. 사용자 세이브를 쓰는 버튼은 검수 중 실행하지 않는다. |
| 판정 | 구현 후 본편·쉬운판에서 재진입, 섹션 이동, 언어 전환, 1324×982/390×844 스크롤·가로 넘침을 확인해 기록한다. |

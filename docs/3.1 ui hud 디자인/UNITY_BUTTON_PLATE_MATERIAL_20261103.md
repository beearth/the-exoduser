# Unity 버튼 판 재질 정리 (2026-11-03)

브랜치 `codex/unity-death-screen-20261103` (사망 화면 다음 커밋). Unity 전용. 웹 미수정.
사용자 지적(Unity 일시정지 캡처): "질감이 너무 구린 거 아니냐", "박스들". 프레임 장식은 괜찮고 버튼 판이 밝은 회색 그라데이션 플라스틱 상자처럼 보이며, 선택 버튼은 탁한 빨간 판.

## 새 판 (공통 `NativeSilverHellUi.ActionPlate`)
기준: UI_FOUNDATION·UI_COMPOSITION(흑철·뼈색 문자·금빛 헤어라인·붉은 지옥불 포인트) + BG3 메뉴 공통점(어두운 판, 절제된 가는 테두리, 가는 명조).

| 층 | 값 |
|---|---|
| 바탕 | 화면 sRGB 기준 불투명 흑철 세로 그라데이션 (22,20,19) → (14,13,13) → (9,8,8). 눌림 0.78배. `RGBAHalf`·linear 텍스처에 Linear 프로젝트에서는 입력 `.linear`, Gamma 프로젝트에서는 입력 그대로 저장 |
| 음각 가장자리 | 바깥 절단선 1px (2,2,2), 위 모서리 빛 받이 1px (64,57,48) α.55, 아래 안쪽 그림자 1px 검정 α.5 |
| 음각 홈 | 3px 안쪽 1px 검정 α.72 (높이 30 미만은 생략) |
| 금빛 헤어라인 | 홈 바로 안쪽 1px. 일반 (104,92,70), 주요 (140,123,90) + 안쪽 옅은 두 번째 헤어라인 α.35 |
| 선택·호버 | 판은 그대로 어둡다. 헤어라인 안쪽 가장자리에서 붉은 불빛 (150,26,12) α.24가 스며들고, 글자 뒤 폭 50%·높이 42% 타원 숨 (120,22,10) α.20. 헤어라인은 불빛을 머금은 금색으로 50% 이동 |
| 주요 버튼 | 아래 가장자리에 늘 아주 약한 불씨(선택 불빛의 40%) |
| 바깥 번짐 | `ButtonFocus`는 원화 알파 35%, 범위 축소 |

- 선은 물리 픽셀에 스냅해 1px(정수 배율에서는 배율만큼)로 그린다. 1.33배(5120x1440)에서도 두께가 흔들리지 않는다.
- 절차 텍스처는 매끈한 그라데이션뿐(노이즈·디더 없음). `iron_480` 질감은 알파 .14에서 대비가 1/255 미만이라 쓰지 않았다.
- 글자: 일시정지·종료 확인 = Hahmlet(명조) 뼈색 (223,214,194), 선택 (240,227,206). 로비 종료 확인도 같은 색. 캐릭터 삭제 확인 = Hahmlet 400 + 지역 명조 대체, 삭제 버튼 글자 (222,150,128), 패널은 공통 `Panel`.
- 적용 화면: 일시정지 메인·종료 확인·키 설정, 설정(A15) 버튼·키 목록, 로비 종료 확인, 첫 안내 버튼, 캐릭터 생성·이름·선택 화면 버튼, 스킬·대장간 하단 버튼, 필드 HUD 상태 판, 캐릭터 삭제 확인.

## 18:40 Mac FAIL 후속 — 색 공간·선택 슬롯·직접 촬영

- 기존 절차 텍스처의 sRGB 수치를 IMGUI blit에 그대로 보내면 Linear 최종 출력 변환에서 바탕 9~22가 약 53~82로 밝아진다. Mac 측정 61~78과 같은 범위다. 원화/글꼴을 바꾸지 않고 `Effect(..., displayColor:true)`의 명시적 linear 저장과 `PlateTint`의 `.linear` 변환으로 수정했다. 낮은 명도의 8bit 선형 양자화를 피하려고 바탕만 `RGBAHalf`를 사용한다. 마스크·다른 Effect 호출은 기존 경로를 유지한다.
- 흑철 바탕은 외부 RGB 틴트를 받지 않고 기존 알파만 받는다. 프레임·헤어라인·불씨 틴트는 `PlateTint`, 글자는 기존 전용 `TextColor`를 따른다.
- 로비 캐릭터 슬롯 390×84도 `ActionPlate`를 사용한다. 기존 (194,26,16) α.1 빨간 채움·2px 빨간 세로 띠를 제거했다. 선택/호버 이름은 (240,227,206), 일반 이름은 (223,214,194).
- Mac 직접 촬영: `--unity-death-ui-smoke -ui-screen pause|settings|quit|character-delete|lobby|lobby-quit -output <절대경로>` (값 하나씩 실행). `settings`는 실제 설정 4탭을 각각 촬영한다. 해상도는 Player의 `-screen-width/-screen-height`를 그대로 쓴다.
- 삭제 확인은 인메모리 검수 캐릭터로 창만 연다. 해당 플래그에서는 `ConfirmCharacterDelete`가 즉시 false를 반환하므로 우발 입력도 삭제/세이브 삭제를 실행하지 않는다. 영수증에 실제 활성 페이지·대화창·로스터 전후 수·선택 이름 불변·파일 저장 비활성 상태를 남긴다.
- 세이브 로그가 없었던 이유: 기존 smoke는 설정·로스터 저장소를 생성하지 않아 일반 바인딩 경로를 통과하지 않는다. 이제 두 촬영 플래그 모두 `DEATH_UI_SAVE_BINDING qaRoot=... settings=disabled roster=disabled combat=disabled`를 실제 상태에서 출력하고 JSON에도 넣는다. 개인 세이브 경로로 연결해 로그를 만드는 방식은 쓰지 않는다.
- PC 회귀: `unity/Tools/death-ui-tests/run.cjs <I: 절대 출력경로>`에서 실제 생성 함수·틴트 함수를 추출 컴파일해 Linear/Gamma 화면 색 범위 및 알파 보존을 검사하고, 두 촬영 인자의 로비 우회 등록도 확인한다. GPU/시각 PASS를 뜻하지 않는다. 최종 판정은 Mac 1x에서 위 모든 화면을 1920×1080·3840×1080으로 비교한다.

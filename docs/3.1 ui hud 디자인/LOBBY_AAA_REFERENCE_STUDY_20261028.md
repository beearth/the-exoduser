## 0. 조사 방법과 한계

- 대상: Diablo IV, Path of Exile 2, Lost Ark, Elden Ring, Last Epoch, No Rest for the Wicked, Dragon's Dogma 2의 로비·캐릭터 선택·생성 화면.
- 원칙: 화면 구성만 배운다. 에셋 반입·베끼기 금지(메모리 `poe2-reference-study` 원칙과 같음).
- **한계(정직하게 표기):** 이번 회차에는 앱 내장 브라우저의 정책 확인이 일시적으로 응답하지 않아 공식 스크린샷을 화면으로 직접 대조하지 못했다. 웹 검색은 글 위주 결과만 줬고, 일부 기사는 접근이 막혔다(403). 아래 §1 표는 디자인총괄이 알고 있는 각 게임 화면 구성을 정리한 것이며, 표의 "직접 대조" 칸이 미완인 항목은 승인 단계 전에 공식 스크린샷으로 다시 확인한다.
- 참고한 글: Diablo IV 2.0 PTR에서 모닥불 캐릭터 선택이 직업 아이콘을 고르는 애니메이션 화면으로 바뀌었다는 보도(icy-veins), Diablo IV 2020-02 분기 업데이트의 UI 방향(화면 가운데 배치·시스템 전달 역할), Last Epoch 0.8.1 캐릭터 선택 화면 장비 표시 개발 공지.

## 2. 공통 원칙 (P1~P8)

| # | 원칙 | 설명 |
|---|---|---|
| P1 | 캐릭터가 주인공 | 화면의 50~70%를 캐릭터와 장면에 쓴다. UI는 가장자리에만 둔다 |
| P2 | 상자 대신 그라데이션 | 정보 영역은 단단한 판이 아니라, 화면 가장자리에서 어둡게 번지는 그라데이션 위의 글자다 |

| P4 | 엠블럼은 기능이 있을 때만 | 로고 외의 문장을 배경 워터마크로 깔지 않는다. 문장은 직업 아이콘·진영 표시처럼 뜻이 있는 곳에만 쓴다 |

| P7 | 홍보는 구석 작게 | 마케팅 문구·외부 브랜드 버튼을 메인 영역에 크게 두지 않는다 |

## 5. 개선 시안 (승인 대기)

비교: `compare_current_A_B.jpg`(현재·A·B 세로 나열), 개별 `mockA_1920.png`·`mockB_1920.png`, 1x 확대 `mockA_crop1x.png`(오른쪽 열)·`mockB_crop1x.png`(아래 띠). 예시 캐릭터 2명은 목업용 가짜 자료다.

| 시안 | 구성 | 근거 레퍼런스 | 해결하는 문제 |
|---|---|---|---|
| **A 무대 + 오른쪽 그라데이션 목록 [추천]** | 무대 그림 전체를 살리고, 오른쪽만 그라데이션으로 어둡게 한다(상자·가시 틀 없음). 위에 로고, 그 아래 "캐릭터" 라벨 + 헤어라인, 캐릭터 행(이름 명조 22px / 직업·레벨·지역 Cinzel 11px), 선택 행만 진홍 2px 막대 + 옅은 진홍 빛. "+ 새 캐릭터" 한 줄, 아래 ENTER(은빛), 맨 아래 작은 줄에 시네마틱·STEAM 찜하기·버전 | Diablo IV·PoE2·Last Epoch | L1·L2·L3·L4·L5·L6 |
| B 위 로고 + 아래 띠 | 무대 전체, 로고는 오른쪽 위에 크게. 아래 띠(그라데이션)에 왼쪽 글자 메뉴(캐릭터 선택·시네마틱·STEAM 찜하기·종료), 가운데 캐릭터 카드 가로 줄(세로 헤어라인 구분, 선택 = 위 진홍 막대), 오른쪽 ENTER | Elden Ring·Lost Ark | L1~L6. 캐릭터가 많아지면 가로 줄 공간이 부족하다는 약점 |

공통: 장식된 요소는 ENTER 하나, 빨강은 선택 표시에만, 글꼴은 명조 + Cinzel 2종, 개발 정보는 숨김. ENTER 에셋은 은빛·진홍으로 다시 칠해야 한다(L7).

## 7. 사용자 레퍼런스 (1순위, 2026-10-28) — "저정도 깔끔한 시작화면 폰트 페키지", "깔끔한 케릭터 화면"

사용자가 직접 준 상용 AAA 판타지 게임 화면 4장(`tmp/design-review/20261028_aaa_reference/user_ref_*.webp`: 시작 화면·메인 메뉴·난이도 카드·캐릭터 생성). **배우기만 한다 — 로고·그림·프레임·글꼴 파일은 가져오지 않는다.** 이 4장이 §1 표보다 우선하는 기준이다.

| 화면 | 레퍼런스에서 본 구성 | 배울 점 |
|---|---|---|
| 시작 화면 | 키아트 한 장이 화면 전체(전경 가지 → 중경 성벽 → 원경 도시). UI는 아래 가운데 작은 안내 판 하나 | 그림이 화면을 끈다. 안내 판 = 양끝 뾰족한 얇은 이중선 판, 작고 가는 명조, 자간 넓게 |
| 메인 메뉴 | 어두운 3D 장면 전체. 왼쪽 위 로고, 그 아래 작은 버튼 세로 목록(같은 모양 8개, 현재 항목만 강조색). 판권·계정은 구석에 아주 작게 | 버튼은 작고 모두 같은 부품. 강조는 한 개만 |
| 난이도 카드 | 세로 카드 4장, 고른 카드만 컬러·나머지 흑백. 얇은 이중선 테 + 모서리 작은 장식. 위 가운데 가는 제목 띠, 아래 버튼 2개(메뉴 버튼과 같은 모양) | 선택 = 색, 비선택 = 흑백. 부품 재사용 |
| 캐릭터 생성 | 캐릭터가 실제 장면 가운데 크게. 좌우 판은 화면 가장자리에 붙은 반투명 어두운 판 + 얇은 테. 진행 단계는 왼쪽 끝 체크 아이콘 세로 목록. 하단 가운데 버튼 2개 | 판은 가장자리에만, 무대를 가리지 않는다 |

공통(= "패키지"): 버튼·판·카드 테·제목 띠가 화면마다 같은 부품. 글꼴은 작고 가는 명조 한 계열. 장식은 테 모서리 마디뿐. 색은 어두운 판 + 금속 테 + 강조 한 색.

## 10. 캐릭터 무대 — 웹(2D)에서 어디까지 가능한가

| 항목 | 웹(2D) | Unity(3D) |
|---|---|---|
| 캐릭터가 장면 가운데 크게 서는 구도 | **가능(이미 하고 있음)** — 직업별 키아트 전면 + 대기 영상(`ch.idleVid`) | 가능 |
| 대기 움직임 | 영상 루프·파티클·안개 층으로 가능 | 애니메이터로 가능 |
| 장비·외형이 바뀐 모습 | **불가** — 정지 원화라 장비 반영 불가(장비별 원화를 다 그릴 수 없음) | 가능(장착 장비 메시) |
| 회전·카메라 이동 | 불가(약한 시차 효과 정도만) | 가능 |
| 조명 반응 | 그림에 구워짐 | 실시간 |

판단: 웹은 "키아트 무대 + 가장자리 판" 구도까지가 한계이고 그 범위에서는 레퍼런스와 같은 인상을 낼 수 있다. 장비 반영·회전이 필요한 "진짜 무대"는 Unity 몫이다. UI 부품(이 패키지)은 웹·Unity가 같이 쓰므로 Unity는 같은 판·버튼 위에 3D 무대만 바꿔 끼우면 된다.

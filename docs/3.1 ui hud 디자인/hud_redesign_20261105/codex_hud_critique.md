- 단위: 1920×1080 논리 px, 화면 y는 아래 방향. k=min(W/1920,H/1080), 원점=((W−1920k)/2,(H−1080k)/2). 3840×1080은 같은 크기에 x+960, 1280×720은2/3배다. 기존 아트 배율0.9를 다시 곱하지 않는다(current_measure.md:19–31, H1_unity_prototype.md:10).
- **확정(코드)**는 상수·식·분기, **계산**은 그 수치의 산술, **추론**은 미실행 CSS box model 등이다. **Mac 보고**는 타 검수자의 기록이고 **직접 이미지**는 이번에 연 축소 비교판에서 보이는 형태·색 관계다. 후자의 “기계적/유리구슬 같다·더 눈에 띈다”는 미적 해석이며 정량 실측과 구분한다. 원본 픽셀, 실제1x 판독·동작·조작 등은 계속 **미확인**이다. 원화 Rect/코드 알파 모델/액체 원/실제 고리 잉크를 같은 측정량으로 합치지 않는다(current_measure.md:45–65,201,216–217).
- **부분**은 원리 일부 충족과 수치/기능 미충족이 함께 있다는 뜻이다. **미충족**은 적힌 제안 계약과 다르다는 뜻이지 곧 나쁜 디자인이라는 뜻이 아니다. 약한 규칙을 어겼다는 이유만으로 미적 FAIL을 만들지 않는다. **미확인/해당 없음**을 PASS/FAIL로 바꾸지 않는다.
- 연구의 [사실]은 H3에서 외부 원문을 재확인한 사실이 아니다. 연구가 검색 요약으로 분류한 내용이라는 의미다. 본문 접근 불가·D4 px 실측0·2020 설계와 출시판 차이 가능성을 연구도 명시한다(02_hud_ui.md:9–16). 비례 수치는 모두 [제안]이다.

## 4. 연구 규칙 자체의 약점

1. **근거 강도:** 검색 요약2곳 일치는 독립 원문2개 검증과 다르다. 같은2020 공식 글을 여러 매체가 재보도할 수 있다. 시대·플랫폼·상태가 다른 자료를 단일 HUD 명세로 합치지 않는다. 다른 게임 공통 관례 대조도 남았다(02_hud_ui.md:11–16,203–206,214–244; G0_BRIEF.md:18). 채용 요구·팬 글·외부 재현만으로 “D4가 쓴 도구”를 확정할 수 없다(02_hud_ui.md:112,161–164,254–256).

## 7. Mac 보고·축소 이미지 반영 후 남은 검수

이미 보고된 관찰은 §1.1에, 이번에 직접 본6장과 독립 판단은 §1.2에 구분했다. 원본1x·3840·동적 상태와 새 C 캡처가 남아 있다. H3-C는 문서 제안뿐이므로 캡처 인자가 없다.

1. **무인자 동일성:** 파일 해시 차이/일치98.12~99.89%/최대6의 원인을 동일 배경·틱·시드·카메라·렌더 조건 또는 배경 분리 UI 마스크로 좁힌다. 배경 원인 추정만으로 닫지 않는다(mac_20261104.md:24).
2. **HP 빈/부분·동적 상태:** HP 부분/빈, 쉴드, 포이즈, 쿨다운, 분노, 클릭, 10초 무음 영상, 상태 설명의 Hahmlet을 확인한다. 충전3단·ST210/240 관찰을 이 상태 전체의 PASS로 확대하지 않는다(mac_20261104.md:19,25).
3. **U1↔H1 직접 대조:** 아직 하지 않은 나란히 비교와 CSS computed rect로34/38/46 대36/40/48 아이콘·덮개를 확인한다. 실제 PNG 잉크·border/padding box·clip-path/그림자를 분리한다(mac_20261104.md:25).
4. **글자 실측·입력:** 이미 “수치 읽힘/보조 라벨 흐림” 판정은 반영했다. 추가로13키·최대값·쿨다운의 ink 높이/폭/대비,720p,작은 마우스 그림, 클릭/공격차단 영역과 칩의 관계를 확인한다. B가 조금 낫다는 관찰도 같은 조건에서 비교한다(mac_20261104.md:17).
5. **바닥·적·탄막 가림:** 검은 판·직선 빈 영역은 이번 축소판에서도 확인했다. 현재 MP에도 위쪽 직선 경계가 있으므로 C에서 현재 방식 전체를 답으로 삼지 않는다. 실제 근접/먼 적·탄막이 HUD 근처에 있는 장면에서 가림 영향을 평가한다. A/B의 밝은 중심과 동심 명암이 유리구슬처럼 보인다는 판단은 기록하지만, Mac의 별도1x 동심원 띠가 표시 과정 산물인지 여부는 원본03-전투공터.png 확인 전 확정하지 않는다(mac_20261104.md:22–23; §1.2).
6. **색·장식 수정 후보:** 구현된 H4 C 041e8e47b5의 full HP 상단 띠·partial/empty 액체, MP/ST 분리, 크레스트/가고일 톤, 금속 밝기·배경 대비, 회색 빈 소켓과 10.5px 키를 새로 판정한다. 현재/A/B 축소판도 C의 개선 증거가 아니며 c1b51cda5의 Metal 정상 표시를 C의 PASS로 옮기지 않는다(§6.2).
7. **좌표·성능:** 3840 중앙/레일 무잘림 관찰은 반영했으나 정확한 폭·x+960·조건부 HUD 겹침은 별도다.60프레임1회 fps만으로 성능 PASS/회귀 원인을 확정하지 않는다(mac_20261104.md:20,26).
8. **절차·연구:** Mac은 H1 지시의 -batchmode를 뺐으므로 다음 비교도 실제 촬영 조건을 기록한다(mac_20261104.md:9). D4 원문·플랫폼/상태·다른 게임 연구는 남아 있으며 Mac의 우리 HUD 판정이 연구 제안px를 D4사실로 바꾸지는 않는다.

## 8. 작업 범위·검증

산출물은 이 문서1개다. 이번 H3 갱신에서 코드·Unity·U1/H1/H2/H4 파일 수정0, Unity/브라우저/게임 러너 실행0, 그림·유료 생성0이다. 기존6개 PNG를 직접 열람했으며 수정·재인코딩하지 않았다. 최초 H3의 Node 산술·소스 분석, Mac 글 보고, U1-C r2 사전 대조, 이번 축소 비교판 직접 판단과 H4 구현 보고 대조를 구분했다. 이는 Mac 담당의 앞선 Unity 실행을 부정하지 않는다. 근거 링크·관찰 범위·단일 파일 범위·LF 줄 끝을 확인하며 공용 문서/CHANGELOG는 변경하지 않는다.

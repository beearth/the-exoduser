**Mac 판정 기준 — 판정 대상 c1b51cda5, 보고 커밋 51080f9f6.** 이번 갱신에서 Codex가 직접 읽은 것은 Mac의 글 보고다. 비교판 이미지는 Mac에만 있고 Git에 없어 직접 열람하지 않았다. 아래 시각 관찰은 모두 Mac 보고 인용이며 Codex의 독립 이미지 판정이 아니다. 수치·코드 분석은 별도 근거로 유지하고, 보고된 범위를 넘겨 본선 채택 PASS를 주지 않는다.

- 단위: 1920×1080 논리 px, 화면 y는 아래 방향. k=min(W/1920,H/1080), 원점=((W−1920k)/2,(H−1080k)/2). 3840×1080은 같은 크기에 x+960, 1280×720은2/3배다. 기존 아트 배율0.9를 다시 곱하지 않는다(current_measure.md:19–31, H1_unity_prototype.md:10).
- **확정(코드)**는 상수·식·분기, **계산**은 그 수치의 산술, **추론**은 미실행 CSS box model 등이다. **Mac 보고**는 타 검수자가 해당 화면에서 관찰했다고 기록한 근거이며, 직접 이미지 열람·원본 픽셀 재측정과 구분한다. 보고에 없는 잉크 치수·정량 대비·동작·조작 등은 계속 **미확인**이다. 원화 Rect/코드 알파 모델/액체 원/실제 고리 잉크를 같은 측정량으로 합치지 않는다(current_measure.md:45–65,201,216–217).
- **부분**은 원리 일부 충족과 수치/기능 미충족이 함께 있다는 뜻이다. **미충족**은 적힌 제안 계약과 다르다는 뜻이지 곧 나쁜 디자인이라는 뜻이 아니다. 약한 규칙을 어겼다는 이유만으로 미적 FAIL을 만들지 않는다. **미확인/해당 없음**을 PASS/FAIL로 바꾸지 않는다.
- 연구의 [사실]은 H3에서 외부 원문을 재확인한 사실이 아니다. 연구가 검색 요약으로 분류한 내용이라는 의미다. 본문 접근 불가·D4 px 실측0·2020 설계와 출시판 차이 가능성을 연구도 명시한다(02_hud_ui.md:9–16). 비례 수치는 모두 [제안]이다.

## 4. 연구 규칙 자체의 약점

1. **근거 강도:** 검색 요약2곳 일치는 독립 원문2개 검증과 다르다. 같은2020 공식 글을 여러 매체가 재보도할 수 있다. 시대·플랫폼·상태가 다른 자료를 단일 HUD 명세로 합치지 않는다. 다른 게임 공통 관례 대조도 남았다(02_hud_ui.md:11–16,203–206,214–244; G0_BRIEF.md:18). 채용 요구·팬 글·외부 재현만으로 “D4가 쓴 도구”를 확정할 수 없다(02_hud_ui.md:112,161–164,254–256).
2. **R1/R3/R4 기하:** D132·바닥여백4~8이면 중심은 바닥 위70~74px. 판72~76 위로 반지름20~30%=13.2~19.8만큼 중심을 올리면 중심85.2~95.8, 꼭대기151.2~161.8로140을 넘는다. y 아래 방향의 덧셈으로 읽으면 “구체 중심이 판 윗선보다 위”와 반대다. §1에서는 틀 잘림29.6을 허용하고 액체여백4~8로 대상을 바꾸기도 한다(02_hud_ui.md:26,28–29,57,78–89).
3. **R2 산식:** 132+18+671+18+132=971의 중심간격은839, 중심x540.5/1379.5다. 같은 연구의 약800/560·1360은 다른 배치다. 목표를 하나로 확정해야 한다. :89의 첫 목업1x 판정 후±10% 조정도 허용 범위일 뿐, 실물 판정을 대체하지 않는다(02_hud_ui.md:27,83,89,98).
4. **R4·R5 원인 단정:** 원화 Rect236.7과 hit Rect33.3의 폭비가 “안 맞음 1순위 원인[사실]”은 아니다. key fontSize15와 label Rect16.2도 다르다. 빈 칸 제거로 줄 길이가 변한다는 가설은 H2의 고정13칸 측정으로 입증되지 않는다(02_hud_ui.md:29,97,180–189; current_measure.md:48–50,69,99–101,201).
5. **R6·R7 측정 정의:** 밝기12/15/32%·채도10%가 HSV/HSL/선형 휘도 중 무엇인지, 어느 픽셀을 재는지 불명확하다. 인벤토리 관례를 전투 HUD에 일반화한 것도 추론이다. 전 둘레 크롬 윤곽선과 상단만 저대비 하이라이트 사이의 디자인 충돌을 먼저 풀어야 한다(02_hud_ui.md:30–32,109–120; DESIGN_CONCEPT_SILVER_HELL_20261028.md:39).
6. **R8 자기 모순:** 최소18×0.85=15.3이며 제안 최대1.25는 본문에서 인용한200%와 다르다. XAG 인용은 몸높이이고 fontSize/Rect높이가 아니다. 형식상18을 넣었다고 통과시킬 수 없다(02_hud_ui.md:33,97,132,136,139,188).
7. **R9·R10 기능 오인:** 섬광·소수·무채색·최대8버프·상태3종은 우리 제안이며 최적값 실험은 없다. 강화/취약도 대응 Core 있을 때만이다. S5의 회색 GUI.color 곱은 밝기를 낮출 뿐 채도0이 아니다: (1,0,0)×(.5,.5,.5)=(.5,0,0)(02_hud_ui.md:34–35,147–154,296).

따라서 10규칙의 PASS 개수를 같은 가중치로 더해 승자를 정하지 않는다. 우선 판정 대상은 **입력 글자, 생존·상태 구분, 적 탄막 가림, 접지/정렬**이고 장식 비례는 그 뒤다.

## 7. Mac 보고 반영 후 남은 검수

이미 보고된 접지·소켓 정리·B 어긋남·색/톤 우열·3840 중앙·3x 낱점 관찰은 §1.1과 R표에 반영했다. 아래는 아직 남은 항목이다. 원본 이미지가 공유되면 Codex 직접 열람 여부와 독립 판정을 따로 갱신한다. H3-C는 문서 제안뿐이므로 캡처 인자가 없다.

1. **무인자 동일성:** 파일 해시 차이/일치98.12~99.89%/최대6의 원인을 동일 배경·틱·시드·카메라·렌더 조건 또는 배경 분리 UI 마스크로 좁힌다. 배경 원인 추정만으로 닫지 않는다(mac_20261104.md:24).
2. **HP 빈/부분·동적 상태:** HP 부분/빈, 쉴드, 포이즈, 쿨다운, 분노, 클릭, 10초 무음 영상, 상태 설명의 Hahmlet을 확인한다. 충전3단·ST210/240 관찰을 이 상태 전체의 PASS로 확대하지 않는다(mac_20261104.md:19,25).

# G0 브리프 — 전투 HUD 재디자인 (2026-11-05, 레인 U1: 설계·시안만)

- 배정: 클라우드 CTO. 출발점: 사용자 지시 "HUD 디자인도 다시 해야 할 듯"(unity/main `795869009` 실게임 캡처). 사용자 평가: "다 붕붕 뜨고 안 맞고 듬성듬성, 색도 이상하게 구리다."
- 데모 v0 연결: ① Steam 키샷(전투 화면 하단 HUD가 모든 키샷에 들어감) ② 1-1 한 판(10~15분 동안 계속 보이는 UI).
- 이 레인의 산출물: `defects.md`(비교·결함·관례), `mock_A.html`, `mock_B.html`, `compare.html`(현재·A·B 같은 크기 비교판), `current.html`(현재 재현), `layout_3840.svg`, 공용 `_stage.css`·`_hud_mock.js`. Unity·Core는 고치지 않았다. **사용자가 A나 B를 고른 뒤 Mac이 구현한다.**

## 1. 목표 장면

1-1 숲(ForestA2 피치 34° 원근, LOCK)에서 전투 중인 1920×1080 화면. 하단 HUD 한 덩어리가 화면 바닥에 붙어 있다. 체력 구체가 왼쪽, 마나·스태미나 구체가 오른쪽에 있고, 그 사이 스킬판이 두 구체 고리 밑으로 들어가 이어진다. 금속은 은빛 크롬과 흑철이고, 빨강은 HP 액체와 선택·위험 표시에만 쓴다. 1x로 봐도 키 라벨 13개가 같은 크기로 읽히고, 빈 슬롯도 판에 파인 소켓으로 보인다. 먼 적과 탄막은 HUD보다 늘 눈에 띈다(실버 헬 217행).

## 3. 공통 관례 (defects.md 4절 요약)

1. 구체와 스킬바는 화면 바닥에 붙은 **하나의 덩어리**다.
2. 체력은 빨강, 보조 자원은 채도를 낮춘 다른 색이다.
3. 키 라벨은 슬롯 아래 같은 크기 칩이고, 마우스 버튼은 그림으로 나타낸다.
4. 빈 슬롯은 어두운 함몰 소켓이다. 구멍이나 기호로 처리하지 않는다.
5. 쿨다운은 원형 쓸기와 가운데 숫자로 보여 준다.
6. 전투 중 장식은 기능 칸보다 작다.

## 4. 가장 큰 차이

1. **접지가 없다.** 구체는 29.6px 잘리고 바는 10px 떠서 바닥선이 40px 어긋난다.
2. **비례 규칙이 없다.** 장식(가고일 69px, 뿔 해골 약 50px)이 슬롯(33px)보다 크다.
3. **색**: 금속 명도가 토큰의 1/4 수준이다(p60 30 vs 117). 원색 파랑·초록과 네온 초록 게이지가 있고, M4 뿔 해골이 4번 쓰였다.

## 6. 첫 실물 판정 시점

- **T0 (사용자 선택)**: `compare.html`과 `compare.html?x3`로 A/B 중 하나를 고른다(섞기도 가능, 예: A 비례 + B 주공격 받침).
- **T1 (Mac 첫 빌드, 구현 1일 차 안)**: 고른 안의 구체 1개 + 판 + 소켓 13개만 넣고, 원화는 그대로 둔 채 1-1 실게임에서 캡처한다. 1920×1080·3840×1080, 1x·3x 크롭, 먼 적과 탄막이 HUD 근처에 있는 장면을 포함한다. 시안과 같은 크기로 나란히 놓은 비교판을 만든다.
- T2: 색 상수와 숫자·칩까지 마친 뒤 10초 무음 영상을 찍고 최종 판정한다.

## 7. 합격 조건

1. F1: 구체·판·레일 아래 끝이 모두 화면 안에 있고, 바닥선 차이가 ≤ 4px다(의도한 묻힘만).
2. F2: 판 높이 ÷ 구체 지름 = .39~.40, 판 끝이 고리 밑으로 들어가 틈이 0이다. 슬롯 중심이 정한 식에서 ±1px 안이다.
3. F3: 기능 칸 비율 ≥ 80%, 빈 슬롯이 채운 슬롯과 같은 소켓이다. 키 칩 13개가 같은 높이·같은 글꼴이고 가로 눌림이 0이다.
4. F4: 금속 색이 토큰 값만 쓴다(픽셀 표본 대조). 원색 초록·네온 0, 주황 0, 빨강은 지정한 5곳만, M4 뿔 해골 0이다.
5. 1x(1920)에서 키 라벨·HP 숫자를 읽을 수 있고, 3x 크롭에서 잔점·디더·그레인이 0이다.
6. 1-1 판정 캡처에서 먼 적과 탄막이 HUD보다 먼저 눈에 들어온다(실버 헬 217행).
7. 3840×1080에서 묶음이 가운데 16:9 안에 있고 늘어나지 않으며, 양옆이 월드 그대로다(`layout_3840.svg`).
8. 사용자 판정: "기존 화면 옆에 놓아도 같은 게임인가" + 사용자 평가 4항목이 해소됐는가.

## 8. 중단 조건

- T1 캡처에서 1-1 숲 바탕 위 판이 바닥 덩어리로 읽히지 않고 또 "떠 보이면", 레일 방식을 멈추고 판을 화면 끝까지 내리는 방식(판 바닥 = 1080)으로 바꾼다.
- 벡터 크롬이 1x에서 "싸 보인다"(사용자 "구리다" 재발)는 판정이 같은 결함으로 두 번 나오면 제작법을 바꾼다. 다음 방법은 3D 금속 메시를 실시간 조명으로 구운 원화(무료 도구, 유료 생성 없음)다.
- MP 제안 토큰이 반려되면 MP를 `--sv-lt` 은빛 + ST를 `--tx-2` 뼈빛으로 바꾸는 명도 구분안을 다시 그린다. 색이 하나 줄어드는 만큼 라벨 구분을 강화한다.

2026-10-01 스킬 강화 악의 검사 동기화: `game.html`과 `game-easy-test.html`의 수동 강화 `canUp` 및 일괄 강화 `_matGate`가 실제 차감 `_malCost(sk.upMat||0)`과 일치한다. 현행 `upMat=0` 스킬은 악의 0에서도 SP·레벨 제한을 충족하면 강화된다. 기존 게이트의 `upMat||100`은 악의 50을 요구하던 계산 적용 오류였으며, 확정 강화 비용이나 보유 악의를 변경하지 않았다.

현재 로비는 데모로 고정되어 본편 전 구간의 실플레이 성장값을 이 표의 검증 결과로 간주하지 않는다. 세 판의 실행 구분과 남은 측정은 [BALANCE 팀 대장](../14밸런스+수치테이블/BALANCE_ECONOMY_TEAM_MASTER.md)에 기록한다.

## 2026-10-21 DEMO11-27 네이티브 대장간

META-02 견적 정책을 재사용해 G 대장간의 실제 장착 item.enh/State 악의 차감·유료 RNG·결과 UI를 연결했다. 실행 시 live 견적→잔액검사→차감→RNG1→성공만+1이며 실패에도 지출은 유지하고 단계하락/파괴는 없다. HP 물약 탭도 단건 강화로 연결: level0→1은 Lv100·악의3·기본회복100→150이며 이후 요구레벨200은 현재 데모100 cap에서 잠긴다. 자동 물약 25b와 같은 runtime POT_LV를 공유한다. 물약 수동 퀵슬롯은 폐지 유지다.

강화 이전은 원본 equip의 선행 거래이므로, 이전 규칙 API·견적 UI까지만 제공한다. 실제 장비 교체 caller 미인수 상태에서 독립 유료 이전 버튼을 만들지 않는다. 실장착·유물전승·장비 통계 refresh·저장 호출 인계는 DEMO11-22와 연결 후 검증해야 한다. 이번 메모리 거래 결과를 저장/재시작 보존 완료로 확대하지 않는다. SFX·입자·펫 후처리는 미연결로 남겼다. [DEMO11-27 보고서](../engine/orders/reports/demo11-27_REPORT.md), 원로그 _out/demo11-27 및1920×1080/1x캡처 참조.

## 2026-10-21 DEMO11-19ui 네이티브 성장 화면

J 성장 화면은 19r의 `Main.read_native_growth/request_native_growth`만 사용한다. 원본 `stat-panel-ui.js:25–62,204–274`의 6경로·31중심·260단계·효과표를 추출한 `demo_growth_ui.json`과 인체 선화를 사용한다. 선택/계획/전체 환불 확인은 실제 할당을 변경하지 않고, 적용 이벤트에서만 19r→PC `apply_stats` 거래를 호출한다. 닫기·J·ESC는 미적용 계획 폐기, 예약은 기존 FIFO 큐 이벤트를 사용한다. 저장 성공은 표시하지 않으며 저장 IO 자체는 이 UI 범위 밖이다. 상세 검증·원본 근거·눈 검수 상태는 [보고서](../engine/orders/reports/demo11-19ui_REPORT.md).

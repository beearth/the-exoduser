# 2-8. 퀵슬롯 + 물약 시스템

## 2026-10-21 Godot DEMO11-25 — 자동 HP 물약 런타임

웹 원본은 변경하지 않았다. QS-02/03은 선행 구현이 없었으며, 이번에 QS-01 계산 모듈 위에 `potion_recovery_source/auto_phase.gd`와 `native_potion_recovery.gd`를 추가했다. State가 별도 런타임 `autoPotCd=0`·HP 강화레벨0을 소유하고, HP 회복은 State entry에서 기존 resource authority의 신규 HP-only sink로 위임한다. 저장 스키마·QSLOTS·수동 물약·피해 경로는 변경하지 않는다.

최신 main `game.html:35893–35910` 순서를 따른다. 양수 CD만 sp 감쇠(0 하한 clamp 없음) → 회복 임계 계산 → 레슨/CD/HP/악의오브/부족HP gate → 악의오브1 차감 → 장갑·벨트·pRegen 및 CD → 회복량 재조회 → 최대HP clamp. 미발동 시 장갑·벨트·패시브와 두 번째 회복량은 조회하지 않는다. `OPT.autoPotThr`·qsAuto는 읽지 않는다. 회복/CD 계산은 QS-01을 재사용한다.

Main `_physics_process`에서 한 줄로 지연 호출해 child Player의 자연회복 뒤에 실행한다. 원본의 PHYS_STEP=1000/60 update 틱과 32715–32720 자연회복→35893 자동 물약 순서에 맞춘 native60 경계다. sp는 그 physics delta×60이며 양수 CD만 감쇠한다. physics serial당 1회로 제한해 고FPS 렌더에서 CD를 중복 소비하지 않는다. 기존 source-clock 결과가 stage/playTime까지 CONTINUE이고 sp 계산 단계까지 통과한 경우만 입장하며, 최신 G.on/paused와 tree pause도 재확인한다. 원본 32108–32132 gate·32680–32683 sp·32742 stageTime→35893 순서의 부분 연결이다. 원본 accumulator/catch-up·미이식 중간 전투 단계 전체를 재현했다는 뜻은 아니다. 휴면 하니스에서 레슨 tick owner가 없으면 SKIP을 유지하고 gate를 우회하지 않는다. 실제 인트로 부팅/연습 건너뛰기 경로에서 자연 호출을 검증한다.

잔여: SFX.potion은 미연결로 PARTIAL 영수증에 기록한다. 시스템 튜토리얼 native owner는 없으며 callback 발명을 하지 않는다. 전설 벨트는 PC 소유 피해 consumer를 건드리지 않고, 활성 장비이면 `_lBeltT` 생성 없이 HOLD를 기록한다. HP·악의오브·CD의 이미 수행된 prefix는 되돌리거나 재시도하지 않는다. 실제 표시에는 기존 FloatingText owner를 사용하고 거절 시 미표시를 기록한다. 상세 검수·범위는 [DEMO11-25 보고서](../engine/orders/reports/demo11-25_REPORT.md)를 참조한다.

## 물약 강화 (POT_LV)
- 대장간(G키) → 물약 탭에서 강화
- 최대 10단
- 강화 비용: `_malCost((lv+1) × 5)` 악의오브 = `max(1, ceil((lv+1)×5×_MALICE_COST_MUL))`, `_MALICE_COST_MUL=0.5` → 실제 3, 5, 8, 10, 13, 15, 18, 20, 23, 25 (기준값 5, 10, ... 50의 50% 올림)
- **레벨 요구**: 1단=Lv.100, 2단=Lv.200, ... 10단=Lv.1000 (`(lv+1) × 100`)
- 회복량: 0강=100, 1강=150, 2강=200, 3강=300 ... 10강=1000 (`lv<=0?100:lv===1?150:lv*100`)
- 즉시회복/마나물약/물약제작 삭제 — 대장간에 강화만 존재
- 퀵슬롯 불필요 — HP가 물약 회복량 이상 빠지면 악의오브 1개 소모로 자동 섭취
- 쿨다운: 7초 기본 (장갑/벨트/회복력 패시브로 감소)
- potionPower 어픽스로 회복량 증가

## 자동 물약 (auto-potion) — 트리거 + `autoPotThr` 설정 감사 (2026-08-17)

**실제 트리거 (game.html update 루프 "Auto-potion" 블록, 2026-10-28 기준 ~L36087, 설계대로 동작)**: `autoPotCd<=0 && P.hp>0 && G.mats>0 && (P.mhp-P.hp) >= _apHealAmt` — 즉 **"부족 HP ≥ 물약 회복량"**이면 악의오브 1개 소모로 자동 섭취(위 "물약 강화" 섹션 문서와 일치). 임계 % 방식이 아님.
- `_apHealAmt = ~~(potHeal('hp')×(1+potionPower))`. 쿨다운 `_potCdBase=420f`(장갑·벨트 각각 숫자 소비 후 최대0.2, 회복력 `min(pRegen×0.03,0.3)` 감소; 최종 기존 ~~ 정수화·최소6f). 실제 코드에 있던 회복량 정수화 표기도 동기화한 것이며 회복량/발동식 변경은 없다.

**`OPT.autoPotThr` = 오펀(orphan) 설정 (미배선)**:
- 정의 `OPT.autoPotThr:0.99`(0~1 비율, game.html `let OPT` ~L6349), 슬라이더 `#optAutoPot`, oninput(`/100`)·populate(`×100`)만 존재. **자동물약 트리거(L29262)는 이 값을 읽지 않음**(grep: autoPotThr 참조 3곳=default/oninput/populate, 런타임 소비 0).
- 런타임 확증: 80% HP에서 threshold 0.10 vs 0.99 모두 트리거 조건 `missing(1479)≥heal(100)`로 동일 발동 → **임계값 무시**(설정 조작 무효). 기본 동작이 "부족≥회복량"(≈98.6% 이상 상시 발동)이라 기본값 99%와 우연히 근사 → 오배선이 눈에 안 띄었음.

**이번 수정 (UI 정합 correctness만, 2026-08-17)**:
- 슬라이더 범위 불일치 해소: `min=30 max=95 step=5 value=99` → `min=30 max=99 step=1 value=99`. 기존엔 기본값 99%가 max=95·step=5로 **표현 불가**(브라우저가 95로 클램프)했음.
- 저장 단위/기본값 불변(0~1 비율, 0.99). **세이브 마이그레이션 없음** — 기존 값 0.30~0.99 전부 신규 범위 내 표현·round-trip.
- 검증(Playwright): clamp 99→99·100→99, round-trip 30/60/99→0.30/0.60/0.99, populate 0.99/0.95/0.60/0.30→99/95/60/30, 스테이지 전환·pageerror 0.

**⚠ 미결(별도 결정 필요, 이번 미수정)**: `autoPotThr` 슬라이더는 여전히 **런타임 무효**(오펀). 실제 기능화하려면 트리거에 `P.hp/P.mhp ≤ OPT.autoPotThr` 게이트 추가가 필요하나, 이는 **문서화된 heal-amount 설계를 변경**(GAME-DESIGN, 자동물약 거동 변경) → 사용자 승인 필요. 대안: 오펀 슬라이더 제거. 본 작업은 UI 정합만 처리(거동 불변).

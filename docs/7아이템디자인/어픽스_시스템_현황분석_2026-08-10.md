# 어픽스 시스템 현황 분석 (T1~T10 개편 사전조사)

> 2026-08-10 | game.html 전수 조사 결과 요약 | 코드 무수정 분석
> 핵심 결론: **402엔트리 중 236종(59%)이 미적용 데드 옵션** — 개편 1순위 과제

---

## 1. 시스템 개요

| 항목 | 값 |
|---|---|
| 원본(SSOT) | game.html `AFFIX_POOL` 하드코딩 배열 (11483행~) |
| 규모 | **402엔트리 / 400고유 id** (critDmgW·antiRevive 2중 등재) |
| 티어 | 이미 5-티어 (`tiers:[T1..T5]`) — T10 확장의 원형 존재 |
| 접두/접미 | `type:0`=PRE / `type:1`=SUF |
| 전투 적용 | ✅ 166엔트리만 실제 작동, ❌ 236엔트리 미적용 |
| 표시명 | `AFFIX_NAMES_KO` 400종 전부 / 설명 `_AFFIX_DESC` 259종만 (약 140종 설명 없음) |

### 엔트리 스키마
```js
{id, type, tiers:[5], unit, slots:[], group, weight,
 tierW:[40,30,20,8,2](선택), skewRoll(선택), brType:'demon'|'life'(선택)}
```
- rarity 제한 / level 제한 / 클래스 제한 / 무기타입별 제한: **전부 없음**
- 중복: `group` 단위로 아이템 내 중복 금지. 부위 간 같은 id는 **합산**
- DEMO 금지 7종: sharpAtk·brutalAtk·ruinAtk·overkilDmg·staggerExplosion·parryExplosion·elemConvert

## 3. 등급 → 어픽스 개수 (고정)

| 등급 | 개수 | 티어 하한 | 추가 |
|---|---|---|---|
| 0 일반 | 0 | — | |
| 1 고급 | 2 | T1 | 접두부터 교차 |
| 2 희귀 | 3 | T1 | 접미부터 교차 |
| 3 영웅 | 5 | T2 | |
| 4 전설 | 6 | T3 | +legendarySpecial 고정 1 |
| 5 유니크 | 7 | T3 | +legendary +uniqueSpecial 고정 1 |

- 티어 상한 = `min(4, 등급하한 + ⌊P.lv/200⌋)` → **T5값은 전설+Lv400↑에서만**
- 등급별 전용 풀 없음 — 같은 풀에서 개수만 증가. end* 계열이 w8~20으로 유사 상위 역할
- 값 롤: tierW 있으면 이산(T5 확률 2%), 없으면 T1~상한 연속 보간(+skewRoll 저값편중)

## 4. 생성 흐름

```
몬스터 사망 → rollDrop [24767]
  몹티어: normal/elite/mini(etype90~99)/stageBoss/chapterBoss
  등급 가중치: 일반[65,22,9,3,1,0.01] 엘리트[25,35,25,12,3,0.03] 미니[10,25,30,25,10,0.1]
              장보스[0,0,30,50,20,0.2] 챕보스[0,0,0,30,70,0.7](첫드랍 전설보장)
  드랍수 1/1/2/3/5, 일반몹 45%×dropBonus / slot 15균등 / el 6균등 / tier=e.dropTier(챕터 0~4)
→ mkItem [12449]
  ATK롤: max=(200+tier×200+lv)/4, floor=[0,5,15,25,40,50]%, skew²
  base스탯 → bStr/bDex/bInt(비무기, 어픽스 밖) → affixes=rollAffixes() [12668]
  → 임플리싯 1 → 전설/유니크 특수
→ 월드드랍 → pickup → INV → 저장
```

## 5. 전투 적용 (풀 모델)

- 장착 15슬롯 affixes 합산 → `_eqAffixCache{id:Σvalue}` → 각 전투/스탯 코드가 `_eqAffix(id)` 직접 호출 (**선언적 매핑 없음**, 163곳 산재)
- 장착/해제/리롤 시 캐시 무효화+applyStats → 즉시 반영
- 조건부 뎀업: docs 규칙은 "합연산 후 1회 곱연산"이나 실제 코드는 어픽스별 곱연산 연쇄인 곳 다수 (**docs-코드 불일치 소지**)
- 캡: DR 75%만. 크리확률/회피 캡 없음
- 특수 경로: sharpAtk/brutalAtk/ruinAtk→`_slotFlatAtk`, 크리→`statCrit/statCritDmg`, 속성DmgPct+DmgBns→속성 인덱스 배열 매핑

## 6. CORE / AFFIX 분리 — 이미 분리됨

아이템 = CORE(atk/def/spd/base) + 스탯보너스(bStr류) + 임플리싯 + **affixes[{id,tier,value}]** + 전설/유니크 고정효과 + 결정소켓(crystals) + 강화(enh). 계층 명확.

## 7. 문제점 총정리

1. **미적용 236/402 (59%)** — 정의·드랍·툴팁·itemPower까지 되지만 소비 코드 없음
   - 스킬강화 20종 전멸 / 아키타입 20종 전멸 / 엔드게임 22종 중 21종(endCooldownAll만 생존)
   - 플랫뎀 9종(flatPhysDmg w80!), 원소 Pen/Burst/Duration 15종, 리젠 9종, 원소DR 5종 등
2. **드랍 불가 2종**: lastStand·reviveOnce — tiers[0]=null인데 롤 필터가 `tiers[0]!=null` 요구 → 효과 코드는 있는데 영원히 등장 안 함
3. **덮어쓰기 데드코드**: mkItem 반지/목걸이 어픽스 선부여(12612~12635)가 12668 `affixes=rollAffixes()` 대입으로 통째 소멸 (+필드명 val/value 불일치)
4. **레거시**: critDmgA/B(풀에 없는데 읽음), armorPen(주석상 폐기), legacy/legacySuf
5. **리롤 버그성**: rerollAffixes가 brType 미전달 → 팔찌 리롤 시 악마/생명 전용 어픽스 소실 가능
6. **중복 기능군** (T10 통합 후보): 크리뎀4(critDmgW/neck/gloves/end) · 경험치4 · 드랍률3 · 골드3 · 공속4 · 시전3 · 쿨감4 · ST/MP플랫 이중 · onFullManaDmg=fullManaDmg2 · standingDmg=whileStationaryDmg
7. **한글명 충돌**: '사슬의'(dashBoost/extraST) '절약의' '행운의' '재생의' '처형의'(overkilDmg/executeDmg) '침식의' '처치질주의' '부활의'(revivePow/reviveOnce) '관통의' 등
8. 기타: unit 표기 비일관(atk/hp/dmg 산재) · val/cnt 연속롤로 티어 경계 무의미 · 설명 140종 누락

## 8. T10 전환 — 재사용 가능 / 위험

**재사용**: tiers 배열 10칸 확장만으로 롤 로직 대부분 동작(`tiers.length-1` 기준) · group/weight/tierW/skewRoll/brType 메커니즘 · _eqAffixCache 풀 모델(id 유지 시 소비부 무수정) · _fixItem 마이그레이션 체인 · 슬롯별_어픽스_풀.md 인덱스

**위험**:
1. 미적용 236종 처분 결정(구현 vs 삭제)이 최대 변수 — 삭제 시 구세이브 고아 어픽스
2. 세이브에 rolled value+tier(0~4) 저장 → T10 재매핑 마이그레이션 필수, 신구 아이템 수치 단층
3. 효과 코드 163곳 인라인 산재 — 스케일 변경 시 UI 공식 문자열(41815~)까지 수동 동기화
4. 티어 게이팅이 P.lv 의존(lv/200) — 게이팅 주체 재정의 필요
5. 이름/설명/lang 26개 파일 번역 전파 · DEMO/EA 3벌 동기화

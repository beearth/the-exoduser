## Unity 완료 정의 (2026-10-28 사용자 지시, CTO 문서 `docs/engine/UNITY_DONE_BUILD_PLAYTEST_RULE_20261028.md`)

보스 작업(RB1-x, RM-B0~B4 구현, 보스 3D·애니메이션)은 6단계를 모두 지나야 "완료"다. 하나라도 빠지면 "병합만 됨" 또는 "빌드 미확인"으로 적는다. 이 보드의 상태 `3 실플레이 인수`는 ⑥까지 끝난 것만 쓴다.

| 단계 | 보스 쪽 기준 |
|---|---|
| ① 병합 전 빌드 | 작업 브랜치에 최신 `unity/main`을 합친 상태로 Windows 플레이어 빌드 오류 0. 병합 요청에 **빌드 영수증**(오류 0, 포함한 `unity/main` SHA)을 붙인다. "사후 검증" 병합 요청은 받지 않는다 |
| ② 병합 | 유니티 총괄이 `unity/main`으로 병합한다 |
| ③ 통합 빌드 | 병합 직후 `unity/main` HEAD 빌드(영수증에 SHA) |
| ④ 실제 렌더 스모크 | 실제 GPU(Null 장치 금지). 로그의 셰이더 패스 누락·셰이더 못 찾음·예외·`LogError` 0 |
| ⑤ 배포 | 바탕화면 `unity-latest` 갱신 |
| ⑥ 플레이 판정 | 보스전 총괄이 `unity-latest`에서 보스전을 **직접 플레이**해 1x로 본다. 에디터 batchmode 캡처·수치 하니스만으로는 인수하지 않는다(하니스는 필요조건). 판정은 이 보드와 해당 RM-B 명세 기록 절에 남긴다 |

## 6. 작업 방식

- Core 계산은 B군과 같은 방식: 원본 함수 줄 범위 추출 → Node VM oracle → C# 새 파일 대조. Codex 소유 `Simulation.cs`·`NativeGame` 수정은 patch + PC_TO_MAC_INBOX(main·codex 브랜치 두 곳).
- 테스트의 강제 스폰·임의 HP·강제 패턴은 자연 플레이 증거가 아니다. 상태 `3`은 사람이 직접 보스를 잡아 확인했을 때만.
- 구현은 Sonnet 세션 1단위씩, 실패 2회면 중단하고 원인 보고.

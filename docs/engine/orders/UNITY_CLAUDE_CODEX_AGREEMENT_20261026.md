## 4. 병합 주기

1. Codex는 작업 단위를 하나 마칠 때마다 INBOX 맨 위 항목을 확인한다. 미처리 요청을 쌓아 두지 않는다.
2. 병합은 `git merge`(rebase·force 금지). patch는 INBOX에 적힌 순서대로 적용한다.
3. 병합 후 Mac 빌드 errors 0을 확인하고, 그 SHA를 WORK_BOARD에 기록한다.
4. PC는 다음 단위를 최신 통합 SHA 위에서 시작한다.
5. 거절하거나 수정이 필요하면 사유를 WORK_BOARD에 적는다. PC가 그 사유를 받아 고친다.

## 7. 3D 맵 환경 분담 (2026-10-26 추가)

사용자 최신 지시(Codex 맵/Steam 담당 경유): 현재 2D 합성 화면은 생동감·입체감·원근감이 부족하다. 그래서 **맵 환경만 실제 3D로 제작**하고, 아트 품질 목표는 No Rest for the Wicked 수준으로 잡는다. 해당 작품의 에셋이나 고유 디자인은 복제하지 않는다. 높은 고지 지형은 요구하지 않았고, 넓은 CH1-1 생체지옥 전투 공간은 유지한다. 기반은 PC-MAP3D S1 `6d0227a65`(`claude/unity-pc-map3d-20261026`)이다.

### 7.2 통합 순서

1. Codex가 PC UI 누적 병합 요청(`cc39eb672` + patch 8개)을 먼저 처리한다. NativeGame patch는 순서가 있으므로 UI가 먼저 들어가야 한다.
2. 그 위에 MAP3D patch(S1 → S2 …)를 이어지는 순서로 적용한다. PC가 매 단계 "UI 8개 + MAP3D n개" 순서로 적용·컴파일을 확인한 뒤 INBOX에 올린다.
3. 기본 화면은 2D를 유지한다. 3D를 기본으로 바꾸는 시점은 Codex 카메라 QA가 통과하고 사용자가 판정한 뒤로 한다.

### 7.3 좌표·충돌·카메라 합의

| 항목 | 규칙 |
|---|---|
| 좌표 | 시뮬레이션(웹·Godot과 동일한 2D px 좌표, 40px 타일, 시작 (4020,7420))이 유일한 기준이다. 3D는 XZ = 시뮬 (x, y), 1유닛 = 1px. 높이(Y)는 표현 전용이다 |
| 충돌 | 충돌은 계속 시뮬의 canMv/isW와 맵 데이터로 판정한다. 3D 메시에서 충돌을 만들지 않는다. 걸을 수 있는 영역을 메시가 가리거나 막아 보이면 안 된다. PC가 canMv 격자를 3D 위에 겹쳐 보는 충돌 오버레이 QA 모드를 만든다 |
| 높이 제한 | 걸을 수 있는 면은 높이 0 근처(완만한 기복만 허용)로 둔다. 큰 높이는 걸을 수 없는 바깥 mass와 경계에만 쓴다. 고지대 플레이 공간은 만들지 않는다 |
| 전투 카메라 | Godot 원근 값(yaw 0, pitch .85, distance 1400, near 32, FOV = 2·atan(H/(2·d·zoom)))을 그대로 써서 초점면에서 1px = 1유닛을 맞춘다. 2D와 화면상 거리·판독성을 같게 하기 위해서다. 마우스 조준은 지면(y=0) 광선 교차로 계산한다. 카메라 값을 바꾸려면 Codex 카메라 QA 결과와 사용자 판정을 거친다 |
| 캐릭터·적·이펙트 | 이번 범위는 환경만이다. 캐릭터·적·VFX는 기존 스프라이트를 빌보드로 유지한다 |

### 7.5 결정 필요 (사용자)

- 3D 메시와 PBR 텍스처를 어떤 방식으로 만들지 정해야 한다. 후보는 AI 3D 생성 서비스, 수작업 모델링, 에셋 스토어 구매다. 서비스를 쓰면 어느 것을 쓸지와 크레딧 한도도 정해야 한다. 정해지기 전까지 PC는 렌더러·셰이더·임포트 파이프라인과 S2-2 조명을 진행하고, 지면은 기존 원본 텍스처로 임시 운용한다.

### 7.6 QA

- Codex: 카메라 QA 컷 목록(START / EARLY / ARENA / ALTAR / SIDE L / SIDE R / LATE / EXIT)과 각 컷의 시각 기준 이미지를 준비한다.
- PC: 매 단계 같은 컷을 1920×1080·1x 크롭으로 찍고, 충돌 오버레이 컷과 정지 장면 30초 FPS를 함께 제출한다.

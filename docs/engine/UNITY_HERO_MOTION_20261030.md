# 전사 3D 모션 표현 — 2026-10-30

소유 범위는 `Runtime/NativeHeroMotion.cs`다. `NativeGame` 연결·모델·프리팹·빌드·실게임 판정은 영웅 담당의 통합 검수와 함께 확인한다. **현재 이 문서의 모션은 검증 전 표현 후보이며 실게임 동작 PASS가 아니다.** 전투 규칙은 변경하지 않는다.

## 입력과 판정 시각

| 대상 | 실제 Core 입력 | 표현 계약 |
|---|---|---|
| 공개 연결 | `Sync(Simulation sim, bool moving)` | 매 `UpdateViews` 뒤 호출. `sim` 인스턴스가 바뀌면 이전 시전·피격·사망 이력을 지운다. 루트 위치·yaw·충돌은 호출자가 관리 |
| 대기·달리기 | 실제 이동 여부, `TickCount` | 기존 Animator의 `Speed=0/4`를 쓰되 자동시간 `animator.speed=0`. 아래 두 레이어를 Core틱의 절대시각으로 표본화. Root Motion 끔·AlwaysAnimate. 흉곽 호흡 `sin(tick×.025)×.025`만 덧붙임 |
| 일반 대검 | `wSwing`, `StateTicks` | 5틱, `phase=clamp((5−remaining)/5)`. HitArc는 남은3 교차이며 접점 phase=.4 |
| 기검참 3타 | 위 상태·`KiComboStep` | 콤보1~3을 읽는다. 검기는 진입 때 발사하므로 접점 phase=0. 일반 공격은 관찰된 신규 진입마다 표현용1~3 순환 |
| 평타 회복 | `wRecover` | 진입 당시 실제 남은틱을 길이로 저장, `phase=1−remaining/length`. 장비 공속을 별도 추측하지 않음 |
| E 타격·회복 | `sBash/sRecover` | 전용 `Bash`20틱, 남은12 교차가 접점 phase=.4(8/20). `BashRecover`는 평타 끝자세 대신 E 타격 끝자세에서 실제 남은틱 길이로 복귀 |
| 충전 | `wWindup/kiGather/sDraw`, `KiChargeTicks/KgChg` | `phase=clamp(charge/120)`. 충전 해제·공격 시각을 바꾸지 않음 |
| 지옥강타 | `gSlamWindup/gSlam1/gSlamRecover` | Core의10/10/12틱을 읽고 각 상태의 남은틱으로 진행률 계산 |
| 구르기 | `RollActive/RollMoveT` | 18틱, `phase=1−remaining/18`. 충전 상태를 유지한 구르기도 우선 표시 |
| 일반 시전 | `SkillCastCount` 변화 또는 `iceOrb` | 상태를 바꾸지 않는 실제 시전은18틱 제스처. Core 이동/입력/스킬을 잠그지 않음. `sBash`는 별도20틱 공격 |
| 피격 | `stagger/pStun` 또는 `Hp+Shield` 감소 | 상태 피격은18틱, 자원 감소 제스처는12틱. 피해는 재계산하지 않음 |
| 쓰러짐·사망 | `fallen/dead` 또는 합계자원0이하 | 다른 표현보다 우선. 공통 사망군 최초 진입시각부터48틱에 최종 자세 도달·유지. `fallen→dead`의 상태명이 바뀌어도 다시 일어나지 않으며 정상 부활/새 Simulation에서는 초기화 |

우선순위는 사망→구르기→명시적 전투 상태→피격→일반 시전→이동/대기다. 진행률은0~1이며 NaN·Infinity 입력은0으로 제한한다. 실제 Core의 `Simulation.cs`, `Simulation.Roll.cs`, `Skills/Simulation.Skills.cs`를 읽고, `docs` 전체에서 `wSwing`을 검색하여 `UNITY_SOURCE_CORE_20261024.md`의5틱·접점·회복 계약과 대조했다.

### Core 정지·재개와 기본포즈 복원

| Animator 표본 | 실제 자산·시각 |
|---|---|
| `Base Layer.Run` | `Warrior_Run.anim`, 현재 길이.6333334초. 정규화시각 `(TickCount/(60×실제 clip.length)) mod1` |
| `Base Layer.Idle` | 원래 controller의 speed0인 정지포즈. 실제 이동이 없거나 사망이면 정규화시각0 |
| `ArmR_HoldWeapon.HoldWeapon` | `Warrior_Walk_ArmR_Hold.anim`, 현재 길이1.0333334초, 레이어 비중1. 이동이면 같은 Core틱 공식, 정지면0. 기존 무기 운반파지 레이어 유지 |

`Sync`와 모든 `LateUpdate`에서 `Animator.Play` 후 `Animator.Update(0)`로 해당 기본포즈를 재평가하고 그 위에 HumanPose·수동 IK를 적용한다. 따라서 Core가 멈춘 동안 Unity의 프레임 시간이 흘러도 표본시각을 앞으로 보내지 않으며, 같은 tick의 이전 절차적 오프셋을 다시 기반으로 삼지 않는다. `Running` 플래그에 의존하지 않으므로 검수용 `Running=false`에서 수동 `StepInput`이 실제 Core틱을 늘려도 진행한다. 새 Simulation의0틱은 같은 처음 포즈로 돌아간다. 음수틱·0/NaN/Infinity 길이는 시각0이다. 루트 위치와 yaw에는 쓰지 않는다. 이 변경은 모션 컴포넌트의 기본포즈 시간 계약이며, 별도 `CapeSpring`의 물리 시간 정지를 보장하지 않는다.

**기존 타이밍 한계:** `ActivateGiantSlam`은 `gSlamWindup=10` 설정과 같은 호출에 `GiantSlamHit`를 실행한다. 따라서3D 예비 동작과 실제 피해가 물리적으로 같은 접점에 놓인다고 주장할 수 없다. 기검참은 진입 발사와2틱 뒤 일반 HitArc가 함께 있으므로 한 번의 칼 접점으로 양쪽을 동시에 일치시키지 못한다. 본 후보는 Core를 바꾸거나 피해를 지연하지 않는다.

## 수동 자세·파지

위치는 모델 루트 기준 m, 방향은 정규화 전 벡터다. 보간은 `t²(3−2t)`의 부드러운 곡선이며 칼 방향은 구면 보간한다. `HumanPoseHandler`가 같은 프레임의 Animator 자세 위에서 흉곽을 덮고,2본 해석 IK로 오른손과 보조손을 맞춘다.

- 굽힘·회전은 Spine60%·Chest40%로 분배한다. 충전은 `min(1,.5+phase)`까지, 일반 시전은 `sin(phase×π)`까지, 강타 발동은 첫35% 안에 아래 자세로 내려간다. 회복은 해당 끝자세에서 준비자세로 보간한다.
- 구르기는 몸 기준 X축360°, 사망은 X축84°·Z축−8°를 보간한다. 구르기 하강은 `.20×sin²(π×phase)`m로 시작/끝0·중앙.20m이며 끝에.20m를 한꺼번에 복원하지 않는다. 위치 하강은 `humanScale`로 나눈 HumanPose 단위다. **발 최저점·경사면 접지 보정은 이 컴포넌트가 하지 않는다.**
- 회복3종은 진행률 후반50%에 `1−smoothstep((phase−.5)×2)` 비중으로 원래 Animator 보행/운반 자세에 돌아간다. 피격은 `1−smoothstep(phase)`, 시전·구르기는 `sin(π×phase)` 비중이다. 흉곽 근육·양팔 로컬 회전·자세 하강에 비중을 적용하므로 준비파지에서 칼 아래 운반파지로 갑자기 교체하는 종료 경계를 줄인다. 비중 끝점0은 원래 Animator 자세다. 실제 연속 영상의 부드러움은 별도 검수한다.
- 소켓 `Socket_Weapon_R`의 `−up`을 칼날 방향으로 쓴다. 보조손은 소켓에서 폼멜 쪽 `+up×.09m`, 시전 왼손은(−.18,1.26,.48)m이다. 기존 손잡이 중심−.15m 기준이며 실제 손바닥/손가락 일치는 Unity에서 확인한다.
- IK 팔꿈치 힌트는 오른쪽 `right+forward×.25`, 왼쪽 `−right+forward×.20`. 팔 길이가.001m 미만이면 생략하고 팔 길이 양끝에.001m 여유를 둔다. 제로 벡터는 forward·교차곱으로 처리한다.
- 실행 순서90으로 기존 `CapeSpring`100보다 먼저 적용한다. 원래 대기·달리기 다리 클립은 유지하며, 이동 루트·캐릭터 yaw·판정/세이브/Core에는 쓰지 않는다.

## 검증과 남은 게이트

순수 C# 타이밍 시험은 `I:/EXODUSER-Storage/demo-art/hero/motion-tests/`다. 최초 임시 Idle 구현의 구르기 우선순위 RED 뒤, 검토에서 발견한 사망 재기립·E 타격 분류·복귀 혼합·Core 정지시 보행시각 계약 결함을 각각 `out/red-death.log`, `out/red-bash.log`, `out/red-blend.log`, `out/red-freeze.log`로 재현했다. 최종 `out/green-final.log`는169개 검사 통과·C# 빌드 오류0/경고0이다. 상태 전환·공속 회복·콤보·시전·피격·새 Simulation 초기화·비정상 입력 경계, 사망군 연속성·20틱E접점·복귀 끝점/단조성·구르기 하강 끝점과 같은 tick의 여러 렌더프레임 정지·재개·두 레이어 루프를 검증한다. 이 시험은 Unity Animator 실제 재평가·Humanoid·IK·클리핑 검사가 아니다. 실제 Player에서 정지 중 본 행렬 변화0과 재개·재시작 포즈를 확인해야 한다.

필수 후속은 같은 후보의 실제 게임 카메라8~10% 높이에서 대검 파지·발 미끄러짐·망토 관통·낮은 포즈 접지·모션 전환을 영상으로 확인하는 것이다. 프리팹의 한 손 파지와 손가락 없는 리그, 강타의 선행 피해는 현재 위험이다. 기존 TM-A 유료 원형을 재생성하거나 새 크레딧을 사용하지 않았다.

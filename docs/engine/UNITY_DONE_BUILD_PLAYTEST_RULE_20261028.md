## 2. 완료의 정의 (Unity, 오늘부터)

작업은 아래 6단계를 모두 지나야 "완료"다. 하나라도 빠지면 "병합만 됨" 또는 "빌드 미확인"이라고 보고한다.

| 단계 | 내용 | 기준 |
|---|---|---|
| ① 병합 전 빌드 | 작업 브랜치에 최신 `unity/main`을 합친 상태로 Windows 플레이어 빌드 | 빌드 오류 0. "사후 검증" 병합 금지 |
| ② 병합 | `unity/main`으로만 병합 | 경로 지정 커밋, 비강제 push |
| ③ 통합 빌드 | 병합 직후 `unity/main` HEAD로 플레이 빌드를 다시 만든다 | 빌드 영수증에 커밋 SHA 기록 |
| ④ 실제 렌더 스모크 | 실제 GPU로 실행(Null 장치 금지). 로비 → 1-1 진입 → 전투 → 보스 → 클리어까지 자동 진행하고, 단계마다 1600×900 캡처 | 플레이어 로그의 셰이더 패스 누락·셰이더 못 찾음·예외·`LogError` 0. 0이 아니면 실패 |
| ⑤ 배포 | 사용자가 바로 열 수 있는 곳에 최신 빌드를 갱신 | 바탕화면 바로가기 빌드(`unity-latest`) 갱신 + 빌드 SHA·시각·바뀐 점 3줄을 보고 |
| ⑥ 플레이 테스트·피드백 | 담당 총괄이 실제 빌드를 직접 실행해 해당 작업 화면을 1x로 보고 판정. 사용자 피드백은 다음 작업 단위로 바로 반영 | 판정 기록은 해당 SSOT에 남긴다 |

## 3. 바로바로 피드백 고리 (목표 구조)

| 고리 | 방식 | 주기 | 담당 |
|---|---|---|---|
| 로컬 최신 빌드 | `unity/main`이 바뀌면 자동으로 ③~⑤ 실행 → 바탕화면 바로가기 빌드 교체 | 병합마다 (Unity 실행 큐 최우선) | 개발툴 총괄 (실행 기반 1순위에 포함) |
| 웹 테스트 빌드 | Unity Web(WebGPU/WebGL) 빌드를 테스트 주소에 배포 → PC·Mac·폰 브라우저에서 바로 플레이 (웹 시절과 같은 고리) | 하루 여러 번 | 개발툴 총괄 조사 → 배포는 사용자 승인 후 |
| 빌드 상태판 | 최신 빌드 SHA·시각·스모크 결과·캡처·바뀐 점을 한 화면에 | 빌드마다 갱신 | 개발툴 총괄 |

- 웹 빌드 주의: VFX Graph는 컴퓨트가 필요해 WebGL에서 안 돌 수 있다. WebGPU 경로·대체 표현 여부를 먼저 조사한다.
- 외부 주소에 올리는 배포는 사용자 확인을 받은 뒤에만 한다 (CLAUDE.md §총괄 자율 결정).

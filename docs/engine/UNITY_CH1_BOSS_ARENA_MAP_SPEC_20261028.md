# Unity 1장 보스 아레나 맵 제작 명세 — 2026-10-28

상태: **제작 명세 / 화면 구현·Player 검수 전**. 맵 구조·재질·모델은 맵 담당, 공격 판정·기둥 충돌·페이즈는 보스전 Core 담당, 공유 런타임 연결과 `unity/main` 병합은 Unity 통합 담당이 맡는다. 아트 최종 판정은 디자인총괄이 기준 이미지와 1x 화면을 나란히 보고 내린다.

기준: `UNITY_BOSS_RM1_DARK_DRUID_20261027.md`, `UNITY_BOSS_RM2_POISON_MUSHROOM_GIANT_20261028.md`, `UNITY_BOSS_RM3_HELL_ABERRANT_20261028.md`, `UNITY_BOSS_RM4_FINAL_DARK_DRUID_20261028.md` 각 §5; `MAP_ART_BIBLE_v2_20261026.md`; `EXODUSER_MAP_PRODUCTION_GUIDELINE_v0.9.md`; `UNITY_MAP_BOARD_20261026.md`. 이 문서는 그 계약을 맵 제작 순서와 검수 단위로 묶는다. 수치가 충돌하면 각 보스 명세의 현재 LOCK과 Core의 실행 좌표를 먼저 대조하고, 양쪽 문서를 함께 정정한다.

## 6. 구현·검수 게이트

1. **입력 고정:** 각 si의 `BossArenaLayout.Generate(si)` 타일·진입·출구 SHA/좌표, 보스 Core 세트와 동적 소품 읽기 API를 receipt로 남긴다. RM-2~4 필드 슬라이스의 걷기 격자를 보스 아레나 격자로 재사용하지 않는다.
2. **MASTER/OUTER:** 각 방의 역할·주 시선·외곽 질량과 북/남 개구부를 탑뷰에 그린다. 1-1 독액 숲 / 1-4 근원의 심장 / 1-2 열린 밭 / 1-3 사냥터·애도 장소가 한 장씩 다른 장소로 읽혀야 한다.
3. **구조:** 메시와 독액·데칼을 붙인 뒤 Core 걷기 격자와 실제 이동/전투 바닥을 비교한다. 타일 변화 0, 입구·출구 폐쇄 0, 의도 밖 보이지 않는 벽 0. Core 소품의 중심·반지름과 보이는 메시의 접지·실루엣 오차를 표로 남긴다. NavMesh와 Core가 다르면 좌표별 목록으로 설명하고 수정한다.
4. **기술 연결:** 1-1/1-4 기둥 차단 3종(탄·균열·박동), 1-4 매듭 4상태·발치 안전 고리, 1-2 씨앗/물길, 1-3 그루터기 돌진·둥지 접근을 실제 보스 플래그 켠 플레이에서 검수한다. Core만의 하니스 PASS를 표현 PASS로 옮겨 적지 않는다.
5. **화면:** 1600×900 전투 캡처와 1920×1080 비교 컷, 1x 크롭 3곳, START/진입·중앙·좌우 외곽·랜드마크·출구 카메라 보드, 독 스킬 VFX 동시 프레임, 움직임 5초 또는 연속 6프레임. 목표 START v2·Godot C/D와 나란히 놓고 디자인총괄 판정을 받는다. 1x에서 바닥의 옥스블러드, 젖은 접지, 작은 진홍·독액 빛, 공격 예고 우선순위가 읽혀야 한다.
6. **아트 수치 보조:** 바이블 V1~V7·C1~C8·독액 §6을 현재 Linear/Neutral 렌더의 실제 캡처에 적용해 기록한다. 특히 바닥 R/G 1.5~1.8, 독액 색상각 40~65°, 독액 표면 화면 12% 이하, 빛 웅덩이 화면당 2~4개, 과한 원색·남색 void 0. 수치 충족만으로 시각 PASS를 내지 않는다.
7. **실행·반영:** Unity는 `unity/Tools/devtools/exo-unity.ps1`의 무창·무음·세이브 격리 경로만 사용하고 PC 전체 동시 1개 규칙을 지킨다. 고유 I: 출력에 컴파일 로그·캡처·30초 FPS·셰이더 오류를 남긴다. 변경 코드가 있으면 `docs/` 관련 키워드를 전수 검색해 해당 수치·상태를 같은 커밋에 맞춘다. 자기 파일만 정확한 경로로 stage/commit하고 비강제 branch push; `unity/main` 병합은 통합 담당에게 SHA와 검수 증거를 넘긴다.

각 단계의 보고는 제작 가이드 §23 `MAP PRODUCTION REPORT`의 MASTER / OUTER MASS / LARGE / MEDIUM / GROUND / PLAYABLE / LANDMARK / CAMERA QA / TECH QA / FILES / GIT / `VISUAL VERDICT: PASS | RETOUCH | FAIL`을 채운다. 지금 네 아레나 모두 **제작 전**이며, 이 문서의 수치와 기존 Core 구현만으로 화면 완성을 주장하지 않는다.

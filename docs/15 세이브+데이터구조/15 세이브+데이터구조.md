# 15. 세이브 + 데이터 구조

## 2026-09-28 공개 데모 진행 저장·복원 보완

`game.html`의 일반 공개 데모(`_startDemoNew`, `hellsave_demo`)는 같은 브라우저 origin에서 종료·새로고침·재입장해도 진행을 이어간다. 30초 자동저장과 주요 이벤트 저장, 로비 복귀·페이지 이탈 저장 경로는 유지한다. 스테이지 클리어에서는 SP 보상·타임어택·지옥 클리어 기록 반영 후 즉시 저장한다. 기존 저장 데이터는 삭제하거나 초기화하지 않는다.

| 저장 항목 | 직렬화 필드 | 복원 위치·규칙 |
|---|---|---|
| 레벨·경험치·성장 | `player.lv/exp/maxExp/sp/ap`, `transLvDate`, `transLvCount`, `apBossCleared`, `goddessGift` | 공용 `dbRestore(d)`의 플레이어 복원. 필드 없는 구세이브는 기존 기본값 |
| 근성 | `grit`, `gritCostModeV2:1` | 공용 `dbRestore(d)`에서 `_grit` 복원. 구버전 비용 환급은 v2 마커가 없을 때만 적용 |
| 스킬 숙련도 | `skProf`, `fuseProfSec`, `cardProf`, `catProf`, `activeTechSk` | 공용 `dbRestore(d)`에서 숙련도·기술 슬롯 복원 |
| 플레이 기록 | `game.stage/kills/mats/irisSz/taRecords/comboMax/playTime/cutsceneDone` | 공용 `dbRestore(d)`에서 복원. 데모 부트가 복원 직후 `mats`를 `1000`으로 덮어쓰던 코드를 제거. `mats`는 공용 공유풀 이관 규칙을 따른다 |
| 기존 진행 | `inv`, `stats`, `passives`, `qslots`, `bagMax`, `hellCleared`, `crystalBag`, `crystalDust`, `upgrades`, `potLv`, `skills`, `fused`, 활성 스킬·슬롯 | 기존 공용 복원 경로 유지 |

격리된 Chrome 브라우저 컨텍스트에서 Lv.7·근성 3·숙련도 25·처치 41·악의 4,321·플레이시간 777을 `doAutoSave()` 경로로 저장한 뒤 페이지를 새로고침해 모두 동일하게 복원됨을 확인했다. 실제 사용자 브라우저의 저장 데이터는 수정하지 않았다. 이 변경 전 저장에서 누락됐던 필드는 과거 값이 없어 소급 복원할 수 없지만, 기존에 저장돼 있던 레벨·장비 등은 유지한다.

## 2026-09-28 공개 데모 자동저장 표시 점검

| 항목 | 현재 동작 |
|---|---|
| 공개 진입점 | `index.html`의 `_LOBBY_BUILD='demo'`, `game.html`의 `_DEMO_MODE=true`가 기본값. `?char=`가 포함돼도 게임 부트는 데모 분기를 먼저 사용한다 |
| 실제 저장 | 데모 진행은 브라우저 origin별 `localStorage.hellsave_demo`에 30초 주기 및 주요 이벤트·로비 복귀 시 저장한다. 이 공개 데모 경로의 `?char=`는 Supabase `characters` 저장을 뜻하지 않는다 |
| 로비 카드 | 로그인 세션이 남아도 데모 빌드는 `OFFLINE`·단일 `대검전사` 캐릭터 정보을 표시한다(내부 슬롯명 `DEMO CHARACTER`). 왼쪽 `선대 소환체 · 묘왕 바르칸`과 영체 설명은 저장 슬롯 이름과 분리한다. 이전 고정 문구 `Lv.1 START`는 저장된 진행과 무관했다. 이제 유효한 `hellsave_demo`의 레벨·처치수를 표시하고 브라우저 저장임을 밝힌다. 데이터가 없거나 깨졌으면 시작 문구를 표시한다 |
| 데모 입장 URL | 온라인 계정 UUID를 데모 게임에 전달하지 않고 `game.html?test=1&slot=demo&demo=1`로 보낸다. 계정 목록을 보여 주면서 실제로는 브라우저 저장을 쓰던 혼동을 없앤다 |
| 검증 | 실제 열린 데모 탭에서 현재 레벨·처치수와 `hellsave_demo`의 값 일치, 저장 시각 갱신 확인. 수정 후 Chrome 로비에서 `OFFLINE` 및 저장된 Lv.46·처치 1,795 표시 확인. 관련 31개 테스트 통과 |

로컬 개발 주소와 온라인 사이트는 브라우저 origin이 달라 이 데모 저장을 자동으로 공유하지 않는다. 과거의 3슬롯(`hellsave_demo_0~2`) 설명은 구 빌드 이력이며 현재 `game.html` 공개 데모의 단일 슬롯 계약은 위 표를 따른다.

1. **세이브에 창고 저장 금지** — `storage:{}` 고정. `storage:STORAGE` 절대 안 됨

#### 🐞 32비트 오버플로우 수정 (2026-04-11)
**증상**: 캐릭터 삭제 후 신규 시작 시 악의가 음수(예: -1555936894)로 표시

#### 🛠️ 악의 경제 전수 감사 + 서버 동기화 강화 (2026-04-12)

**1. 서버 동기화 (source of truth)**

## 복원 시 강제 덮어쓰기 (dbRestore 후)

로드 후 유효성 검증으로 일부 값이 덮어써짐:
- **스킬 미소유 시 기본값 복귀**: activeMagicSk→fireball, activeTechSk→giantSlam 등 (구세이브의 activeTechSk=spikeTrap은 giantSlam으로 마이그레이션)
- **합체 관련 LMB 강제**: whirlDet/slamStorm/stormBeam 합체 시 → whirlwind 강제
- **삭제된 스킬 마이그레이션**: fanShot→fireball, galeSlash→charge 등
- **레벨 자동해금**: Lv300→blueShot, Lv700→burstLoop
- **선택 슬롯 계약 복구**: `_repairAreaSkillSlot()`이 일반 스킬은 `[0~3]`, 지옥강타 계열과 `cat:'rage'` 액티브(천공쇄기)는 Space(`[4]`), 영역은 F(`[5]`)에만 남긴다. 전용 칸의 추가 후보는 슬롯에서만 해제하며 습득/레벨은 유지한다.

| 구 저장값 예시 | 복원 결과 | 데이터 손실 |
|---|---|---|
| `skillSlots[5]='ancestorSummon'`, `[0~3]` 빈칸 있음 | 전대 소환을 `[0~3]` 첫 빈칸으로 이동, F=null | 없음 |
| `skillSlots[5]='ancestorSummon'`, `[0~3]` 모두 사용 중 | F=null, 전대 소환은 L/K 배정 목록에서 재선택 가능 | 스킬 습득/레벨은 유지 |
| `skillSlots[5]='holyDome'` | 그대로 유지 | 없음 |
| `[0]='holyDome'`, `[1]='weakPhys'`, F=null | `holyDome`을 F로 이동하고 `[0]`, `[1]` 해제 | 두 스킬의 습득/레벨은 유지 |
| F=`holyDome`, `[0]='weakPhys'` | F의 `holyDome` 유지, `[0]`의 `weakPhys` 장착 해제 | 두 스킬의 습득/레벨은 유지 |

| Space=`giantSlam`, `[0]='giantSlam2'` | Space의 `giantSlam` 유지, `[0]`의 `giantSlam2` 장착 해제 | 두 스킬의 습득/레벨은 유지 |

### EA 게스트 세이브 경로
- Windows: `C:\Users\<유저명>\AppData\Roaming\EXODUSER-HELL\saves\`
- node-main.js가 `process.env.APPDATA` 사용
- API: `POST /api/save`, `GET /api/load/:slot`, `DELETE /api/save/:slot`, `GET /api/slots`
- 게임 재설치/폴더 이동 후에도 세이브 유지 ✅
- Steam Cloud 연동 시 이 폴더를 동기화 대상으로 지정

### EA OAuth 흐름 (NW.js)
1. `sb.auth.signInWithOAuth({provider:'google', skipBrowserRedirect:true})` → URL 획득
2. `nw.Shell.openExternal(url)` → 외부 브라우저에서 Google 인증
3. Google → `http://localhost:3333/oauth-callback#access_token=...&refresh_token=...`
4. `/oauth-callback` JS → `POST /oauth-deposit` {access_token, refresh_token}
5. 게임 폴링 `GET /oauth-poll` → 토큰 수신
6. `sb.auth.setSession({access_token, refresh_token})` → 로그인 완료

### 로그인 자동저장 보호 (2026-09-08)

에디터·DEMO·테스트 캐릭터의 전용 부팅 분기는 유지한다. 위 표는 일반 게임 부팅 기준이다.

| 항목 | 코드 계약 / 적용 위치 |
|---|---|
| 로컬 로그인 우선순위 | 일반 부팅의 `(_isLocal&&!_charId)` 조건으로 로그인 캐릭터를 로컬 세이브로 전환하지 않는다. 명시적 `test=1`은 로컬 테스트 우선 |
| SDK 로딩 | head의 `window._supabaseReady` Promise. 로그인 캐릭터는 로컬 호스트여도 CDN 로드, 로컬 게스트/`test=1`은 생략. `_isTestMode`도 정확히 `test=1` 판정 |
| 클라이언트 준비 | `sb`는 지연 초기화 가능. `startGameFromDB()`는 SDK 로드 완료 후 클라이언트 생성·인증 확인. 로드 실패 시 오류 안내 후 중단하며 로컬 신규 게임으로 대체하지 않음 |
| 조회 실패 보호 | 인증 후 `dbLoad()` 성공을 확인한 다음 `mkP()` 등 기본 초기화. 조회 실패/null/예외는 오류 안내 후 중단. `_dbReady`/자동저장 시작 전이므로 빈 데이터로 덮어쓰지 않음. 조회 성공한 빈 객체는 신규 캐릭터로 인정 |
| 진행 표시 | 클라우드 조회 15%, 기본 준비 25%, 복원 55%. 연결 실패는 0%에서 안내 |

#### ⚠ 창고 중복 방지 규칙 (2026-05-23 버그픽스)
1. **세이브에 창고 저장 금지** — `storage:{}` 고정. `storage:STORAGE` 절대 안 됨
2. **로드 시 concat 금지** — localStorage가 비어있을 때만 세이브→localStorage 이관
3. **모든 배열 push에 MAX 체크** — STORAGE_MAX, BAG_MAX, CRYSTAL_BAG_MAX

## 복원 시 강제 덮어쓰기 (dbRestore 후)

로드 후 유효성 검증으로 일부 값이 덮어써짐:
- **스킬 미소유 시 기본값 복귀**: activeMagicSk→fireball, activeTechSk→giantSlam 등 (구세이브의 activeTechSk=spikeTrap은 giantSlam으로 마이그레이션)
- **합체 관련 LMB 강제**: whirlDet/slamStorm/stormBeam 합체 시 → whirlwind 강제
- **삭제된 스킬 마이그레이션**: fanShot→fireball, galeSlash→charge 등
- **레벨 자동해금**: Lv300→blueShot, Lv700→burstLoop
- **선택 슬롯 계약 복구**: `_repairAreaSkillSlot()`이 일반 스킬은 `[0~3]`, 지옥강타 계열과 `cat:'rage'` 액티브(천공쇄기)는 Space(`[4]`), 영역은 F(`[5]`)에만 남긴다. 전용 칸의 추가 후보는 슬롯에서만 해제하며 습득/레벨은 유지한다.

| 구 저장값 예시 | 복원 결과 | 데이터 손실 |
|---|---|---|
| `skillSlots[5]='ancestorSummon'`, `[0~3]` 빈칸 있음 | 전대 소환을 `[0~3]` 첫 빈칸으로 이동, F=null | 없음 |
| `skillSlots[5]='ancestorSummon'`, `[0~3]` 모두 사용 중 | F=null, 전대 소환은 L/K 배정 목록에서 재선택 가능 | 스킬 습득/레벨은 유지 |
| `skillSlots[5]='holyDome'` | 그대로 유지 | 없음 |
| `[0]='holyDome'`, `[1]='weakPhys'`, F=null | `holyDome`을 F로 이동하고 `[0]`, `[1]` 해제 | 두 스킬의 습득/레벨은 유지 |
| F=`holyDome`, `[0]='weakPhys'` | F의 `holyDome` 유지, `[0]`의 `weakPhys` 장착 해제 | 두 스킬의 습득/레벨은 유지 |
| Space=`ancestorSummon`, `[0]='giantSlam2'` | `giantSlam2`를 Space로 이동, `ancestorSummon`을 `[0]`으로 이동 | 없음 |
| Space=`giantSlam`, `[0]='giantSlam2'` | Space의 `giantSlam` 유지, `[0]`의 `giantSlam2` 장착 해제 | 두 스킬의 습득/레벨은 유지 |
| Space 비어 있음, `[0]='skyCrusher'` | `skyCrusher`를 Space로 이동하고 `[0]`을 비움 | 천공쇄기 습득/레벨 유지. 전투 중 충전 `P._scCharges`(0~3)와 다음 충전 타이머 `P._scCd`(최대 900f)는 다른 런타임 쿨다운과 같이 저장 대상 아님 |

> 일반 `dbRestore()`뿐 아니라 DEMO500의 로컬 `skillSlots` 복원 직후에도 동일한 `_repairAreaSkillSlot()` 계약을 적용한다.

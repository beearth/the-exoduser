# SND-10 AD2 3단계 — UI 상호작용 소리 계약 (2026-10-28)

기준: `AD2_UI_SOUND_INVENTORY_20261028.md` A-08·A-09·B-09·입력 방식별 표·§4의 16~18·27번, 현재 `game.html`의 `gameConfirm`(3451행), 버튼 소리 위임(12726행), 패드 UI 탐색(13915행 이후). 이 문서는 구현 범위와 검수 기준이다. 새 파일 생성·웹 코드 반영·사용자 청음·Unity 이식은 아직 하지 않았다.

## 1. 장면과 소리 우선순위

| 순서 | 장면 | 현재 확인된 동작 | 3단계 계약 | 보류할 판단 |
|---|---|---|---|---|
| 1 | `gameConfirm` 열기·확인·취소 | 열릴 때 무음, 두 버튼은 같은 `ui_button_confirm` 위임음. 분해 확인 뒤에는 `ui_salvage`도 남 | 열림은 기존 `ui_panel_open`을 조용히 1회만 시험한다. 확인은 기존 확정음을 유지하고 분해 완료음과의 시간·크기를 한 장면에서 비교한다. 취소는 기존 채택 `ui_cancel`을 **후보**로 장면 비교한다. 확인·취소를 서로 다른 결과로 전달하며 1클릭에 위임음과 직접음이 겹치지 않게 한다 | `ui_cancel`은 전투 캔슬 소리라 확인창 취소에 맞는지 사용자 귀 판정 전 재사용 확정 금지 |
| 2 | 필터·체크박스·설정 토글 | 켜기와 끄기가 같은 확정음 또는 무음 | 상태가 실제로 바뀐 경우에만 1회. 켜짐과 꺼짐을 장면에서 구별하고 같은 상태 재클릭은 별도 성공음으로 오인하지 않게 한다. 패널 전환음 `ui_tab`과 겹치면 결과 상태음 하나를 우선한다 | 새 온·오프 음색과 파일은 후보 청음 뒤 선택 |
| 3 | `.dis`로 비활성처럼 보이는 버튼 | `disabled` 속성이 아니므로 위임 확정음이 날 수 있음 | 사용 불가 상태라면 성공 확정음을 내지 않는다. 실제 동작 실패는 기존 `ui_fail` 한 번으로 표현할지, 침묵할지 기능별로 결정한다. CSS 클래스만으로 판정하지 않고 실제 핸들러 결과·접근성 상태를 맞춘다 | 기능별 실패 이유·시각 피드백은 UI 담당과 합의 |
| 4 | 패드 UI 포커스 이동 | 마우스 `pointerover` 위임은 패드 이동에 반응하지 않음. 패드 탐색은 DOM focus와 가상 커서를 함께 사용 | **실제 선택 대상이 달라진 1회**에만 짧은 탐색 소리. 마우스 hover·패드 focus·가상 커서가 같은 대상을 가리켜도 중복 재생하지 않는다. 누르고 있는 방향의 반복 이동은 화면 선택 변화와 함께 검수한다 | 패드 물리 입력과 가상 커서 경로를 실제 Player에서 확인한 뒤 음량·쿨다운 확정 |

## 2. 구현 경계

- 소리 요청 위치는 공통 버튼 위임과 각 UI의 결과 처리 중 하나로 정한다. 직접 소리가 난 클릭에서는 기존 `_lastSfxAt` 규칙과 `setTimeout(0)` 순서를 확인해 확정음 중복을 없앤다.
- `gameConfirm`의 확인·취소는 현재 같은 버튼 위임을 거친다. 버튼 텍스트나 번역 문자열을 읽어 결과를 추정하지 않고 각 버튼 처리 결과를 기준으로 한다. 부모 DOM 내용 교체는 하지 않는다.
- 패드 입력은 브라우저 `button` 번호를 물리 버튼 매핑으로 가정하지 않는다. `NextJust` 등 의미 입력과 실제 포커스 변경을 각각 확인한다.
- 선택한 효과음만 현재 `sfx/ui/`의 채택본을 재사용할 수 있다. 새 음색이 필요하면 한 장면씩 후보를 만들고 사용자 귀 판정 뒤에만 실제 게임에 채택한다. 유료 생성은 별도 상한 확인 전 실행하지 않는다.

## 3. 완료 증거

| 항목 | 최소 검수 |
|---|---|
| 확인창 | 키보드·마우스·패드 각각 열기→확인, 열기→취소를 수행하고 요청 키·호출 횟수·결과를 남긴다. 분해 확인은 `ui_salvage`와 함께 듣는다 |
| 토글 | 켜기·끄기·같은 상태 선택을 비교하고 상태 변화당 소리 0~1회, 중복 0을 로그로 확인한다 |
| 비활성 | `.dis`와 `disabled` 양쪽의 실제 클릭 결과·위임음을 비교한다. 성공 확정음이 잘못 나오는 곳을 기능별로 수정한다 |
| 패드 | 포커스 이동·가상 커서·확정·취소를 별도 기록한다. 물리 버튼 검증은 실제 장치와 Player에서 수행한다 |
| 귀 판정 | 게임 BGM·전투음이 있는 정상 음량에서 확인·취소·토글·탐색을 사용자가 듣고 선택한다. 정적 수치나 headless 호출 기록으로 대체하지 않는다 |

이번 단계는 계약 작성까지 완료했다. 코드 변경과 실행 검증은 미착수다.

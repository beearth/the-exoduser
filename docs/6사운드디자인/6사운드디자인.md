## BGM 시스템 — 스테이지별 큐 재생 (장 우선 → 공용 혼합)

### 재생 방식 (auto 모드, hell1~7)

1. **장 진입 시** (`BGM.play('hellX')` 호출): played set 초기화 → 장 BGM만 셔플 재생 (미재생 트랙 우선, 연속 같은 곡 방지)
2. **장 BGM 전곡 소진 후**: 전체 랜덤 (`_pickAllRandom` — hell1~7 + gameplay 전곡 풀에서 랜덤, 2026-05-20 변경: 기존 장+공용 혼합 → 전체 랜덤)
3. **boss/forge/death/victory**: 별도 키로 분기, 장 BGM queue 영향 없음

`_playedSets` = 장별 재생 완료 Set, `_actDone` = 전곡 소진 플래그. 장 재진입마다 초기화.

## 사운드 우선순위 시스템 (_SFX_PRI)

채널 포화(`_MAX_ACTIVE_NODES`: 데스크탑 48 / 모바일 16 노드) 시 낮은 우선순위 노드를 stop()하고 높은 것 재생.

| 우선순위 | 값 | 대상 | 비고 |
|---|---|---|---|
| SKILL | 10 | _SKILL_SFX_KEYS + chain_* + electric_storm* + fire_magic* + boss_* | 항상 재생 |
| VOICE | 9 | voice_* + male_grunt + **player_dead*** | 캐릭터 대사 + 플레이어 사망 |
| DEATH | 4 | death_* + monster_die* + death_grunt | 몬스터 사망 |
| HIT | 2 | monster_hit* + flat_hit + player_hit* + melee_hit1 | **동시 최대 3개** |
| PROJ | 1 | bullet_hit + bean_hit + bolt_hit + **투사체 히트 chain_fly(오버라이드)** | **동시 최대 5개** |
| AMB | 0 | amb_* + m_* | 환경음/이동음 |

- 채널 포화 시: 새 pri > 재생 중 최저 pri → 최저 stop() 후 교체. 같거나 낮으면 스킵
- HIT 하드캡: _MAX_HIT_NODES=3 (우선순위 HIT 이하만 제한)
- PROJ 하드캡: _MAX_PROJ_NODES=5 (우선순위 PROJ 이하만 제한)
- 플레이어 사망 사운드(player_dead1~4): VOICE(9) 우선순위 + pri=1 플래그로 프레임 제한/중복 방지 무시 → **100% 재생 보장**
- 30ms 중복 방지: 같은 키 30ms 내 재발사 차단 (스킬 사운드 제외 — `chain_*`/`electric_storm*`/`fire_magic*`는 dedup 우회)

### 우선순위 오버라이드 (2026-08-13) — 투사체 히트음 `playSampleAt(...,priOverride)`

`playSampleAt`/`_playSampleNow`에 6번째 인자 `priOverride` 추가. 미전달 시 기존 `_sfxPri(key)`와 동일(하위호환). 특정 호출부가 키의 기본 우선순위를 무시하고 캡을 적용받게 함.

**적용 이유(성능)**: 독사/칼날파편/악의사냥/얼음보주 칼날 히트음은 `chain_fly` 키를 쓴다. `chain_fly`는 `chain_` prefix라 SKILL(10)로 분류돼 **PROJ/HIT 동시재생 하드캡과 30ms dedup을 모두 우회** → 대량 명중(예: 얼음보주 오비탈 수십 발이 밀집한 적 무리 관통)에서 한 프레임에 수백 회 호출, `_MAX_ACTIVE_NODES=48` 포화까지 WebAudio 노드를 생성해 **pProjs 업데이트가 최대 40~50ms 스파이크**(playSampleAt 본체가 스파이크 프레임의 74%).

## SFX 부트 프리로드 정책 (2026-08-10)

| 항목 | 구현 |
|---|---|
| 대상 | `_sampleFiles`의 짧은 SFX `AudioBuffer`만. BGM은 선택/스테이지 재생 시 기존 경로에서 별도 로드 |
| 부트 차단 | 금지. 부트는 `void _loadAudioBuffers()`로 작업만 시작하고 렌더러·게임 시작으로 즉시 진행 |
| 동시성 | 최대 4개 (`_AUDIO_LOAD_CONCURRENCY=4`) fetch+decode 워커 |
| 제스처 상태 | AudioContext가 `suspended`여도 decode 준비를 시작하며, 사용자 제스처에 의한 실제 재생 허용을 기다리지 않음 |
| 미준비 SFX | `_playSampleNow()`의 기존 lazy load/무음 폴백 유지. 게임 로직·입력·전투 진행을 막지 않음 |
| 중복 방지 | `_audioLoadPending[key]`를 프리로드와 lazy load가 공유해 같은 파일의 중복 요청을 방지 |

기존 방식은 부트에서 AudioContext 재개를 최대 10초 기다린 뒤 데스크톱에서 모든 SFX를 직렬 fetch/decode했다. 이 정책은 그 대기를 부트 임계경로에서 제거한다. 오디오가 모두 준비되기 전 첫 짧은 순간에는 일부 파일 SFX가 생략될 수 있으나, 전투/스킬의 상태·판정·시각 효과에는 영향을 주지 않는다.

#### 이벤트 디렉터 규칙

1. **중요도 선점**: 사망(100) > 궁극·위기(85~75) > 패링(80) > 피격·강공격(65~60) > 정예 처치(55) > 경공격·회피(35) 순이다. 더 높은 줄이 재생되면 낮은 줄은 끊지 않고 해당 이벤트만 생략한다.
2. **중복/과밀 방지**: 기존처럼 같은 실제 파일은 10초 내 재생하지 않는다. 별도로 보이스 군별 최소 간격을 둔다. 공격 35% 확률과 가족 간격을 함께 적용해 평타를 보이스 기관총으로 만들지 않는다.
3. **상태 전환 1회성**: 저체력은 30%를 **처음 통과할 때만**, 회복 후 다시 30% 아래로 내려갈 때 재무장한다. 부활·정예 처치도 한 사건당 한 줄만 허용한다.
4. **패링은 보상, 실패는 무음**: 성공 패링의 대사는 금속 충돌 SFX보다 80~120ms 뒤에 붙여 타격감을 보존한다. 패링 실패에는 별도 대사를 넣지 않는다.
5. **스킬은 속성별 말투를 분리**: 어둠=`낮고 위협적`, 신성=`또렷하고 단호함`, 광선=`전방으로 쏘는 호흡`, 폭발=`짧은 명령`, 궁극=`0.9~1.3초의 선언`. 같은 문장을 여러 스킬에 돌려 쓰지 않는다.

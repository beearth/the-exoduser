> ## 현행 투사체 원본 분류 SSOT (`parryClass`, 2026-09-04)
>
> `spawnProj()`가 생성 직후 `physical` / `magic` / `forbidden`을 저장한다. 이후 **탄속·렌더 외형·Q/E 패링**은 모두 이 한 값을 읽는다. 따라서 `redBean`·색상·`EL` 하나만으로 입력을 추측하면 안 된다.
>
> | `parryClass` | 정확한 원본 분류 | 외형 | 입력 | 속도 |
> |---|---|---|---|---|
> | `physical` | `EL.P` 일반/관통탄, `redBean+EL.P`, `titanEye` (`EL.F` 색이어도 예외적으로 물리) | **회백색 이빨입** 또는 혈안 눈알 | **E(sBash)** | 이동탄 300px/s |
> | `magic` | `blackBean`, `redBean+EL.F`/`_closeBean`, `fireMagic`, `waterBean`, `gbBean`, 비물리 일반 원소탄, `mine`/`trap`, `fbEnergy`/`fdEnergy` | 무지개·속성 혜성·보라 암흑 구체·물 탄두 | **Q(sBlock/해제/peaceShield)** | 이동 마법탄 500~600px/s; 정지·대형탄은 전용 |
> | `forbidden` | `noParry`, `bomb`/`web`/장판류, 일반 `elemBall` | 전용 위험물 | Q/E 반사 불가 | 전용 |
>
> `blackBean`은 **무지개 전용** `magic` 탄종으로 Q 패링한다. `gbBean`은 `EL.D`의 보라 암흑 구체다. `elemBall`은 전속성 표기가 아니라 단일 `el` 대형탄의 형태 플래그이며, `fbEnergy`/`fdEnergy`만 일반 `elemBall` 금지보다 앞서는 대형 에너지 Q 예외다.

## 1-B. 탄막 데미지 3-Tier 시스템 (2026-04-17)

### 개요
**이전 시스템의 문제**:
- Caller의 dmgMult(변수: 0.8~1.5) × beanRoll의 배율(1.0~1.5) = 최종배율 0.8~2.25배 (불규칙적 & 예측 불가)

**새 시스템**:
- **탄 종류에만 고정된 3단계 Tier** 적용
- **Caller의 dmgMult 수치는 완전히 무시**
- 최종 데미지 = `floor(ATK × Tier배율 × 엘리트배율 × dmg버프)`

### Tier 정의

| Tier | 분류 | 포함 탄막 | 데미지 배율 | 설계 의도 |
|------|------|----------|----------|---------|
| **Tier 1** | 일반탄/들러리 | 이빨 일반탄(`EL.P`), 다크볼(gbBean), 노랑탄, 보라탄 | **×1.2** | 약한 기본 공격, 플레이어 유리. 화이트볼 제거 |
| **Tier 2** | 중거리 특수탄 | 빨콩(redBean), 근접빨콩(_closeBean) | **×1.5** | 중간 난이도, 패링 필수 |
| **Tier 3** | 강력 추적탄 | 무지개탄(blackBean, 150px 밖만) | **×2.0** | 최강 탄막, 리듬게임 난이도의 핵심 |

### 예시 계산

**보스 Lv500, ATK=1025**

| 탄막 | Tier | 기본배율 | 엘리트배율 | 최종 데미지 |
|-----|------|--------|----------|----------|
| 이빨 일반탄 | T1 | ×1.0 | ×1.0 | 1025×1.0 = **1025** |
| 빨콩 | T2 | ×1.5 | ×1.0 | 1025×1.5 = **1538** |
| 무지개탄 | T3 | ×2.0 | ×1.0 | 1025×2.0 = **2050** |

**보스 부활 1회 이후** (ATK ×1.5 = 1537):
| 탄막 | Tier | 기본배율 | 엘리트배율 | 최종 데미지 |
|-----|------|--------|----------|----------|
| 이빨 일반탄 | T1 | ×1.0 | ×1.0 | 1537×1.0 = **1537** |
| 무지개탄 | T3 | ×2.0 | ×1.0 | 1537×2.0 = **3074** |

### Tier 적용 규칙

1. **특수탄(원소구, 팬텀소드, 함정류)**: Tier 미적용, 각자 고정 배율 사용 (×3.0, ×1.8, ×0.3 등)
2. **엘리트 보너스**: Tier 배율 적용 후, 엘리트 atkMul 곱셈 (예: T1 ×1.2 × 엘리트 ×1.3)
3. **부활 기간**: ATK 상향으로 자동 증가 (Tier 배율 고정)

## 3. _beanRoll — 탄 종류 결정 로직 (2026-04-17 dmgMult 무시)

### 근거리 자동 선택 (dst < 150px)
150px 이내면 무조건 **화속성 빨콩(redBean, `EL.F`)** → `_closeBean=true`, raw `spd=max(4,기본)`, `homing=true`. `parryClass=magic`으로 화상·속성을 유지하며, 최종 **500~600px/s·약 90°/s·혜성 외형·Q 패링**이다.

### 교대 카운트 기반 (e._beanCnt)
**3-way 순환 (2026-09-01, 물 파란콩 변주 — 화성송은 랜덤 잔존):**
| 조건 | 결과 |
|------|------|
| `_beanCnt % 3 === 0` | 무지개탄(blackBean) |
| `_beanCnt % 3 === 1` | **화속성 빨콩(redBean, `el:EL.F`)** — 화염 혜성 렌더, **Q패링**, 화상 |
| `_beanCnt % 3 === 2` | **물 파란콩(`waterBean`, `el:EL.I`, `col:#317cec`)** — 기존 4×2 비행(8프레임) + Water Impact 4×4, **Q패링**, `dmgM 1.2`, `sz 1.6`, Q 패링 시 16프레임 Water Impact(`r96/72f`), 피격 시 16프레임 Water Impact(`r72/66f`) + ❄빙결 60f |

- 구 3-way의 화성송 슬롯을 물 파란콩으로 교체해 빨강 일색을 끊는다. 각 ~30% 균등 + 10% 들러리.
- 이빨(E)과 전용 얼음 시트(Q)는 형태·색이 달라 패링 입력이 읽힌다. `waterBean` ≠ 패링반사 `blueBean`.
- 화성송(`fireMagic`)은 무참조 랜덤 8%와 `_fireChargedProj('fire')` 핸들러에 남긴다.

### dmgMult 파라미터 (현재 무시됨)
- **이전**: `eProjAt(e, ang, spd, dmgMult, ...)`에서 dmgMult 값이 beanRoll과 곱해짐
- **현재**: dmgMult 파라미터는 함수 시그니처에만 남아있고, **실제 데미지 계산에 미반영**
- **이유**: Tier 고정 시스템으로 전환하여 예측 가능한 밸런싱 달성
- **마이그레이션**: 호출처의 dmgMult 값을 변경해도 최종 데미지 영향 없음

### 물리탄 크기·패링 자원 배율 (2026-09-10)

`_physicalProjectileMultiplier(p,physicalScale=3)`는 적대 `parryClass='physical'`이면 지정 배율, 그 외는 **1**이다. 본체·꼬리 굵기는 `(p,2)`로 **2배** 표시한다. 자원 보상은 `(p)`의 기본 **3배**를 유지하며, 반사 전 `_physicalResourceMul`에 저장한 값을 기존 `doParry`의 여섯째 인자로 전달한다. 일반 E 충돌·칼등치기·실버테일 차징 전진·파워웨이브의 기존 보상 경로에 공통 적용한다.

혈안탄(titanEye)은 기존 빨콩 경로를 우선하며, 별도 titanEye 및 레거시 bwBean 경로는 기존 일반 보상×3이다. 반사 후 friendly 블루콩의 표시 크기는 기존값으로 돌아간다. 마법탄·무지개·지뢰·덫·근접 E 보상은 기존값, 대형 Q 에너지탄은 기존×10이다. 반사 피해·parryBank·쿨다운 감소·광원 반경은 이번 배율 대상이 아니다. 기존 보상 호출이 없는 무스킬 일반탄 반사 분기는 새 보상을 만들지 않는다.

상세 시각 수치와 검증은 [물리탄 크기 2배·자원 3배 계약](PHYSICAL_PROJECTILE_SCALE_REWARD_20260910.md)을 따른다. 수정 금지인 `2_3` 문서는 보존하며 최신 사용자 지시의 물리 투사체 배율은 이 계약을 우선한다.

### pParryProjDmg 공식
```javascript
function pParryProjDmg(bulletDmg, isQ){
  const scale = isQ ? magicRef()*statInt()*pMagicMul()    // Q: 마법 기반
                     : meleeRef()*statStr()*pAtkMul();     // E(칼등): 물리 기반
  const _gearBonus = Math.min(1, scale/300);               // 장비보너스 0~100%
  const _base = bulletDmg * (1 + _gearBonus) * 0.5;       // 탄뎀 50% 감소
  const _afxPB = 1 + _eqAffix('parryBonus');               // 패링보너스 어픽스
  const _legSP = sh()._lShieldParry || 1;                  // 레전더리 패시브
  const _calc  = ~~(_base * pParryDmg() * _afxPB * _legSP);
  const _kiFloor = ~~(meleeRef()*14*statStr()*pAtkMul()); // 최소: 기검참 1방(14×)
  return Math.max(_calc, _kiFloor);
}
```
> **플로어 규칙 (2026-05-19 추가)**: 탄막이 약해도 반사 데미지는 기검참 1방(14×)을 항상 보장.

## 11. 회전참 중 탄 흡수

회전참(whirlwind) 상태에서 범위 내 탄을 자동 흡수:
- **흡수 대상**: 무지개탄 제외 일반탄 (blackBean/bwBean/gbBean/poisonZone/mine/elemBall/dimRift 제외)
- **흡수율**: pGuardAbsorb (보호막 흡수율과 동일)
- **parryBank 축적**: 흡수 데미지의 100%
- **무지개탄**: 회전참 흡수와 별개로 **Q 패링 가능**. Q 창이 활성화되면 접촉 폭발보다 Q 공통 반사 경로가 우선한다.

### 회전기폭(whirlDet) 합체 시 추가
- 흡수한 탄 → 회전참 데미지·범위 성장 (parryBank/500 비례)
- Q 홀드 기폭은 2초 도달 시 홀드당 1회만 발동한다. Q를 놓고 다시 눌러야 다음 1회가 재무장된다.
- 회전참 중 2초 주기 자동폭파 트리거는 별도 동작으로 유지한다.

## 13. eProjAt — 적 탄 발사 함수

```javascript
function eProjAt(e, ang, spd, dmgMult, el, life, col, sz){
  life = ~~(life * 1.5);              // 수명 1.5배
  const b = e.s==='eShootWind' ? {el,col:ELC[el]||col,sz,spd,dmgM:dmgMult} : _beanRoll(el, col, sz, spd, dmgMult, e); // 특수는 예고 속성 유지
  _emitEnemyShot(e, {
    x, y,                             // 입 위치(_eMouthXY)
    vx: cos(ang)*b.spd, vy: sin(ang)*b.spd,
    dmg: ~~(e.atk * b.dmgM),
    el: b.el, friendly: false,
    life: b.blackBean ? 400 : life,    // 무지개탄 수명 고정
    col: b.col, sz: b.sz,
    redBean, blackBean, bwBean, gbBean, homing, fireMagic, waterBean,
    _closeBean, _commit:true
  });
}
```

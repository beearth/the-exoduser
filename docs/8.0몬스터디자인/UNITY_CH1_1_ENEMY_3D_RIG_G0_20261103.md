## 0. 문제와 목표 장면

- **문제**: "1-1 맵 후보" 빌드에서 영웅은 리깅 3D를 실시간 픽셀로 렌더해 1x에서 또렷하다. 적은 아직 옛 PixelLab 8방향 아틀라스(256px 칸, 정지 1장 + 걷기 4프레임)다. 둘을 나란히 놓으면 질이 갈린다. 적에게는 공격·피격·사망 프레임도 없다.
- **목표 장면**: 34° 원근 카메라(LOCK)로 본 1-1에서 영웅과 적이 같은 렌더 규칙(같은 픽셀 밀도·외곽선·조명·접지 그림자)으로 보인다. 화면 위쪽의 먼 적은 작아도 형체가 읽힌다. 적이 공격하기 전에 몸으로 예고하고, 맞으면 움찔하고, 죽으면 무너진다. 노레위·D4·PoE2의 공통점대로 **같은 생김새의 적은 같은 행동을 한다**.
- **현재와의 가장 큰 차이**: 외형이 행동과 따로 논다. 지금 1-1 적의 외형 칸은 `EnemyFactory._assignMobSkin`이 `(etype×7 + 스폰 x×31) mod 40`으로 40칸 아틀라스에서 고른다. 같은 etype도 위치에 따라 생김새가 달라지고, 생김새로 행동을 알 수 없다.

## 3. 디자인 기준과 3D 입력 이미지 현황

| 항목 | 현황 |
|---|---|
| DESIGN LOCK | 일반 적은 LOCK 문서가 **없다**. 1차 G1에서 종마다 LOCK 대조표(실루엣·재질·발광 위치·색 3개·금지)를 시트와 함께 만든다. |
| 3D 입력 이미지(정면·측면·후면) | **0종.** 아틀라스 칸(256px, 한 방향 64~120px 크기)과 웹 절차 그림 설명만 있다. 다안 육괴만 사용자 원화 8방향 시트가 있다. |
| 색 규칙 | 1장 = 초록·갈색 주색, 화염·얼음·심해 금지, 네온 금지. 발광은 웹 칸의 주조색을 탁하게 낮춘다(보스 호박색 규칙과 같은 원칙). |
| 크기 | 표시 크기는 Core 반경 `ETYPE_R`(1장 10~22px)에서 정한다. 영웅 표시 약 1.31u(Mac 실측)를 기준으로, 메시 높이 = 1.85m × (적 r ÷ 영웅 r) × 체형 보정이다. 종마다 G1 표에 적는다. |

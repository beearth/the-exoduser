### WebGL2 8방향 배치 계약 (2026-08-09)

| 항목 | 값 |
|---|---|
| CPU 전송 버퍼 | `_ens8GLCpu: Float32Array(16 × 512 × 9)` — 시작 시 1회 할당, 프레임 중 신규 배열 생성 없음 |
| 총 가시 인스턴스 한도 | 적 본체 512개 + 이동 walk 오버레이 512개 = 최대 1,024 스프라이트 인스턴스(`_ENS8_GL_MAX`); 버킷별 저장 공간은 512개 |
| 버킷 | `south`, `south-east`, `east`, `north-east`, `north`, `north-west`, `west`, `south-west`의 idle 8개 + walk 8개 |
| 프레임 규칙 | idle은 `col × cell`, walk는 `(col × framesPerMob + frame) × cell`; 기존 Canvas와 같은 `_walkDist/128` 프레임 선택 |
| 회전 | 8방향 원본 프레임이 이미 방향을 포함하므로 셰이더 회전값은 0 |
| 제외 | 보스(`e.ib`), 구울, 슬라임은 기존 전용 경로 유지 |
| 시각 보존 | 그림자는 배치 준비 단계에서 Canvas로 유지하고, 공격 전조·상태 효과·UI도 기존 Canvas 경로 유지 |
| 실패 폴백 | WebGL2/셰이더/아틀라스가 준비되지 않았거나 배치가 거절되면 `e._ensGLMode`를 세우지 않아 Canvas 8방향 본문이 그대로 렌더됨 |

## CH1-1 시작 다안 육괴 예외 경로 (2026-09-04)

`stage 0`에서만 쓰는 사용자 제공 중형 몬스터는 공용 8방향 atlas에 패킹하지 않는다. `_ch1StartMedium=true`인 두 개체는 WebGL 적 배치와 일반 atlas 경로를 건너뛰고 Canvas 직접 렌더러 `_drawCh1StartMediumEyeMass`가 `img/ch1_1_eye_slime_8dir_4frame_clean.png` 단일 시트를 사용한다. 이 시트는 `1024×2048`, `4×8`의 `256×256` cell이며 col 0/1/2~3이 idle/attack/walk·approach·charge loop다. 사용자 보드의 맨 위 예시 행은 사용하지 않고 `N,NE,E,SE,S,SW,W,NW` 8행을 개별 alpha bbox로 crop한다. 렌더러는 `drawH=max(240,r×7)`과 `drawW=drawH×(fw/fh)`를 사용한다. 전용 경로가 일반 적의 facing 갱신을 우회하므로, 렌더러는 매 프레임 `atan2(P.y-e.y,P.x-e.x)`를 계산해 canvas angle 순서를 `[2,3,4,5,6,7,0,1]` source 행으로 변환한다. 숫자·방향명·체크무늬·보드 배경은 alpha 0으로 제거하고 각 셀의 최대 연결 본체만 상하 중앙 정렬한다. 상세 수치·좌표·검증은 `CH1_1_START_다안육괴_중형몬스터.md`가 SSOT다.

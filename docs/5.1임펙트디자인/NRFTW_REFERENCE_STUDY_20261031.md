# No Rest for the Wicked 실물 연구와 EXODUSER 적용 검토

작성일: 2026-10-31 KST · 담당: 이 채팅 Codex · 범위: 설치본 읽기, 사용자 플레이 화면 관찰, 공식 자료, 현재 원격 코드·설계 대조.

**핵심 제안: CH1-1의 큰 외곽 형태·바닥 접합·국소광을 먼저 완성하고, 대표 타격 한 개의 동작·VFX·피격 반응을 같은 시간축에서 마감한다.** EXODUSER의 다수 적 전투·루팅·빌드와 Q/E 계약은 유지한다. 이 문서는 연구 결과이며 제작·통합·빌드 개선 완료 보고가 아니다. 장시간 전 구간 플레이, 모든 무기·보스·경제·네트워크의 완전 검증은 아직 아니다.

## 3. 타이틀 화면 분해

사용자 원본은 **4964×1438**, 실행 창은 **5120×1440**이다. 원본에 좌표를 딱 맞춘 UI 사양을 추출한 것은 아니며 아래 위치는 육안의 대략적 정규화 값이다.

| 요소 | 실제로 보이는 구성 | EXODUSER에 옮길 원리 |
|---|---|---|
| 큰 명암 | 양쪽 절벽·하단 바위는 큰 어둠, 중앙 먼 구름은 밝은 덩어리 | 작은 소품보다 장소 전체의 명암을 먼저 설계 |
| 시선 유도 | 밝은 하늘 틈에서 먼 성으로 이어지는 경사·수평선 | CH1-1 진행 목표의 빛과 바닥 방향을 한 축으로 연결 |
| 전경·중경·원경 | 가까운 검은 바위, 중간 절벽, 먼 성·안개 | 레이어마다 크기·대비·움직임의 차이 확보 |
| 색 역할 | 청회색 음영과 국소 적색, 금속 로고, 낮은 채도 글자 | 재질·기능별 색을 보존하고 큰 명암으로 묶음 |
| 로고 | 화면 폭 약 30% 부근, 세로로 결합한 금속·검 형태 | 우리 흑철 로고의 재질·외곽·배경 대비를 완성 |
| 메뉴 | 로고 아래의 짧은 세로 목록, 큰 외곽 상자 적음 | 기본 메뉴는 조용하게, 선택 상태의 소재·밝기로 위계 형성 |
| 캐릭터 자리 | 화면 오른쪽 중심 부근, 배경과 별도 공간 확보 | 캐릭터 발·실루엣·배경을 한 무대로 구성 |
| 하단 안내 | 조작키와 동사가 같은 기준선 | 입력 장치별 안내가 즉시 바뀌고 역할이 일관되게 읽혀야 함 |

타이틀의 넓은 검정 영역은 의도된 프레이밍이다. 이를 CH1-1 외곽의 미제작 검정 구멍 허용 근거로 쓰지 않는다. 메뉴가 적은 타이틀과 다수 적 전투 HUD의 정보량도 다르다.

## 5. 사용자 플레이에서 본 화면

실제 관찰은 5120×1440 창의 스냅샷이다. 창 캡처는 GPU 렌더 결과의 시각 증거이나 연속 영상·원본 HDR 측정·FPS 계측은 아니다.

| 장면 | 직접 관찰 | 적용할 점 |
|---|---|---|
| 세계 생성·난이도 | 짧은 단계로 이름과 난이도를 나눔. 선택 설명의 큰 여백과 선명한 포커스 | 첫 진입에서 한 번에 결정해야 할 항목을 줄이고 설명을 행동 바로 옆에 배치 |
| 캐릭터 선택 | 캐릭터 전신과 배경의 별도 자리, 같은 하단 입력 안내 | 캐릭터를 카드 썸네일로만 소비하지 않고 무대의 주인공으로 보여줌 |
| 해변 진입 | 열린 밝은 모래면, 어두운 큰 암석·난파물·식생, 대각선 비·물결 | CH1-1 전투 바닥은 조용하게, 경계의 큰 형상·깊이·움직임은 풍부하게 |
| 인벤토리 안내 | 오른쪽 상황 안내에 키·동사·짧은 설명, 게임 장면이 계속 남음 | 최초 사용 순간의 조작 안내, 반복 팝업·긴 설명문 최소화 |

### 5.1 후속 실제 장면 — 동굴과 지원 룬

동굴 교전 스냅샷에서는 오른쪽 모닥불의 따뜻한 빛과 왼쪽 차가운 바닥이 나뉘고, 플레이어와 적 체력바가 중앙 전투부에 남아 있었다. 동굴의 좁은 전투 폭과 화면 밖 거대한 어둠은 장소 표현의 참고이며 우리 주요 다수 적 전투장 규격으로 복제하지 않는다. 후속 관찰에서는 청색 환경 구조와 큰 선·링·입자 효과, 치유 룬의 상황 안내·시연 영상·장치별 키를 확인했다. 큰 효과가 인물 일부를 가리는 순간도 있으므로 효과 크기 자체를 성공 기준으로 삼지 않는다.

두 교전 스냅샷과 지원 룬 화면 사이에는 간격이 있고, 회복·이동·사망/부활의 원인을 연속 관측하지 않았다. 정확한 전투 시간·치유량·소모량·사망 여부는 이 화면만으로 확정하지 않는다. 보존 파일은 runtime_cave_combat_01.png, runtime_cave_combat_02.png, runtime_beach_large_blue_effect.png, runtime_support_rune_tutorial.png이며 관찰 시각은 observation-log.json에 기록했다.

### 우리 타격 한 개를 완성하는 단위

1. 준비: 몸통·골반·무기가 공격 방향과 힘을 미리 보여준다.
2. 가속: 무기 끝이 힘의 방향을 따라 빠르게 지나가며 궤적은 필요한 순간에만 보인다.
3. 접촉: 실제 Core 명중 이벤트에 접점 섬광·피격 포즈·타격음·짧은 카메라 반응을 맞춘다.
4. 후속: 팔·몸통·무기가 관성을 풀고 다음 입력으로 자연스럽게 연결된다.
5. 정리: 먼지·불꽃·연기·조명은 서로 다른 수명으로 사라지고 위험·적 실루엣이 다시 읽힌다.

위 단계는 제작 문법이다. NRFTW의 실제 준비 시간·히트스톱·무적 프레임 수치를 얻은 것이 아니다. 전체 공격을 느리게 만들어 무게감을 흉내 내지 않는다. EXODUSER 템포 안에서 포즈 차이·가속 곡선·발 접지·피격 반응을 강화한다.

무기 소재별 공격 시작·접촉·후속 소리를 같은 타임라인에서 청취하고, 일반 전투와 다수 적·보스 전투를 따로 비교한다. 새 오디오 미들웨어 도입을 선행 조건으로 만들 필요는 없다.

## 12. 성능·엔진 분석

Breach와 Together의 공식 패치 기록에는 스트리밍·상주 자산·할당·풀링·물리·그림자 광원·가시성 관련 최적화가 나뉘어 있다. 고품질 환경은 많은 오브젝트를 무조건 실시간으로 돌리는 방식과 동일하지 않다. 실제 병목별로 예산을 관리한다는 점을 배운다. [Breach 공식 패치](https://forum.norestforthewicked.com/t/patch-notes-the-breach/15046/1), [Together 공식 패치](https://forum.norestforthewicked.com/t/no-rest-for-the-wicked-together-update-patch-notes-sneak-peak/21726).

| 우리 항목 | 검토 방향 | 금지할 판단 |
|---|---|---|
| 배경·미세 움직임 | 화면 밖 업데이트·그림자·물리 필요성부터 분리 | 모든 소품에 Rigidbody·실시간 광원 부착 |

## 17. 적용에서 제외하거나 후순위로 둘 것

- NRFTW의 고유 캐릭터·보스·장비·문양·지명·음악·셰이더·텍스처·모델 복제/반입.
- 좁은 통로·사다리·낙사 중심 구조를 넓은 핵앤슬래시 전투장에 강제.
- 참고작의 스태미나·장비 무게·소수 적 교전·패링 페널티를 그대로 이식.
- 밝은 숲/황금빛을 생체지옥 전체의 승인 팔레트로 간주.
- 현 데모 전에 협동 월드·하우징·거점 제작·PvP까지 범위 확장.
- 유료 생성·도구 설치·게임 업데이트/파일 교체·사용자 세이브 분석/변환을 이 조사와 묶어 실행.

공식 협동 설명은 지속 공유 월드·거주/거래의 사회적 경험을 강조한다. 이는 네트워크·저장·운영 범위가 큰 별도 제품 선택이다. 현 EXODUSER 핵심 루팅 ARPG 포지션을 대체할 이유는 없다. [공식 협동 설계 설명](https://norestforthewicked.com/news/being-wicked-together).

우리 적용에서는 기존 세이브 호환·격리 실행·정상 Git 복구 지점이 우선이다. 캐릭터와 월드의 버전·마이그레이션·실패 복원은 시각 개선과 별도 게이트로 둔다.

## 21. 이번 연구의 판정

타이틀·맵·임팩트의 직접 시각 근거와 공식 시스템 설명을 EXODUSER의 실제 코드·보호 설계에 연결했다. 게임 전체의 동일조건 우열·현재 제품 아트 PASS·후반 밸런스·완전 분석 완료는 주장하지 않는다. 첫 개선의 성공 조건은 **현재 게임 카메라에서 큰 외곽이 장소로 읽히고 발이 바닥에 붙으며, 타격 순간의 몸·궤적·접점·피격이 같은 사건으로 느껴지는 것**이다.

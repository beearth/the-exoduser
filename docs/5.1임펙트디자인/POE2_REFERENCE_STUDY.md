## 3. PoE의 제작 방식 — "전부 데이터로 조립" (커뮤니티 공개 문서 기준)

| 파일 종류 | 역할 | 배울 점 |
|---|---|---|
| `.ao` / `.aoc` (Animated Object) | 캐릭터·보스 하나의 정의. 모델·뼈대·애니메이션·이펙트를 연결하는 텍스트 | 오브젝트 = 부품 목록. 코드가 아니라 데이터로 조립 |
| `.ast` (스켈레톤·애니메이션) | 뼈대와 동작. 동작 안에 **이벤트 마커**(이 프레임에 이펙트·사운드·판정 발생) | 동작·이펙트·판정·소리가 같은 프레임에 맞물림 |
| `.epk` (Effect Package) | 이펙트 하나 = 여러 파티클을 **뼈의 특정 위치에 붙여** 묶은 목록 | 칼끝·손·발에 붙어 동작 궤적을 따라감 |
| `.pet` (Particle Effect) | 파티클 하나의 텍스트 정의: 텍스처, 수명, 속도, 크기·색 변화 **곡선**, 합성 방식 | 곡선만 바꿔 변형을 대량 생산 |
| `.trl` (Trail) | 무기 궤적·잔상 정의 | 휘두름의 무게감 |
| `.mat` / `.fxgraph` | 재질과 셰이더 노드 그래프 (빛남·왜곡·디졸브) | 열기·공간 일그러짐 같은 화면 효과 |
| `.ot` / `.otc` (Object Type) | 몬스터·보스 구성 요소 조립 (체력·스킬·AI·이펙트 묶음) | 보스 공격 = 같은 틀로 정의 → 패턴이 일관되게 읽힘 |
| `.dat` 테이블 | 스킬 수치, 몬스터 스탯, 보스 스킬 목록 | 숫자는 전부 표로 분리 |

### 3.1 VFX 한 개의 층 구조 (업계 공통)

| 층 | 역할 | 만드는 법 |
|---|---|---|
| 코어 섬광 | 맞는 순간 0.05~0.1초 번쩍임 | 밝은 원형 텍스처, 덧셈(additive) 합성 |
| 충격파·링 | 퍼져 나가는 원 | 링 텍스처를 빠르게 키우며 투명하게 |
| 플립북 | 불길·번개·연기 | 연속 프레임 시트(예: 8×8) 재생 |
| 파티클 | 불똥·파편·피 | 작은 조각 수십 개, 무작위 속도·중력 |
| 왜곡 | 열기·공간 일그러짐 | 노이즈 텍스처로 화면을 비트는 셰이더 |
| 잔광·데칼 | 바닥 그을음, 남는 빛 | 바닥 반투명 그림이 서서히 사라짐 |
| 피드백 | 손맛 | 히트스톱(몇 프레임 정지), 화면 흔들림, 피격 번쩍임 |

손맛은 텍스처 품질보다 **타이밍(몇 프레임에 무엇이 터지는지)** 에서 나온다.

### 3.2 모션·보스

- 모델: Maya/3ds Max 모델링 → 리깅. 동작: 모션캡처 + 수작업 키프레임.
- 공격 리듬: **준비(예고) → 순간 가속 → 정지 → 회복** 을 과장.
- 보스 공격 = **예고 모션 + 바닥 장판(텔레그래프) + 판정 구간 + 빈틈** 을 한 단위로 설계하고 패턴으로 묶음.

## 4. 우리 게임 대응 (2D 캔버스)

| PoE 방식 | 우리 게임 |
|---|---|
| 3D 모델 + 애니메이션 | PixelLab 등 스프라이트 시트, 프레임 타이밍 조정 |
| `.epk` 뼈 부착 | **스프라이트 앵커**: 프레임마다 칼끝·손 위치를 기록해 이펙트 부착 |
| `.ast` 이벤트 마커 | **프레임 이벤트**: 공격 프레임에 판정·이펙트·사운드·히트스톱을 박아 한 번에 맞물림 |
| `.pet` 곡선 정의 | **이펙트 정의 JSON**: 층·타이밍·크기·색 곡선을 데이터로 (현재는 game.html 곳곳 하드코딩) |
| 덧셈 합성 | 캔버스 `globalCompositeOperation='lighter'` |
| 왜곡 셰이더 | WebGL(GPU 프록시) 쪽에서 가능 |
| 히트스톱·흔들림 | 이미 있음 → 수치 조정 |

## 3. PoE의 제작 방식 — "전부 데이터로 조립" (커뮤니티 공개 문서 기준)

| 파일 종류 | 역할 | 배울 점 |
|---|---|---|
| `.ao` / `.aoc` (Animated Object) | 캐릭터·보스 하나의 정의. 모델·뼈대·애니메이션·이펙트를 연결하는 텍스트 | 오브젝트 = 부품 목록. 코드가 아니라 데이터로 조립 |
| `.ast` (스켈레톤·애니메이션) | 뼈대와 동작. 동작 안에 **이벤트 마커**(이 프레임에 이펙트·사운드·판정 발생) | 동작·이펙트·판정·소리가 같은 프레임에 맞물림 |
| `.epk` (Effect Package) | 이펙트 하나 = 여러 파티클을 **뼈의 특정 위치에 붙여** 묶은 목록 | 칼끝·손·발에 붙어 동작 궤적을 따라감 |
| `.pet` (Particle Effect) | 파티클 하나의 텍스트 정의: 텍스처, 수명, 속도, 크기·색 변화 **곡선**, 합성 방식 | 곡선만 바꿔 변형을 대량 생산 |
| `.trl` (Trail) | 무기 궤적·잔상 정의 | 휘두름의 무게감 |
| `.mat` / `.fxgraph` | 재질과 셰이더 노드 그래프 (빛남·왜곡·디졸브) | 열기·공간 일그러짐 같은 화면 효과 |
| `.ot` / `.otc` (Object Type) | 몬스터·보스 구성 요소 조립 (체력·스킬·AI·이펙트 묶음) | 보스 공격 = 같은 틀로 정의 → 패턴이 일관되게 읽힘 |
| `.dat` 테이블 | 스킬 수치, 몬스터 스탯, 보스 스킬 목록 | 숫자는 전부 표로 분리 |

### 3.1 VFX 한 개의 층 구조 (업계 공통)

| 층 | 역할 | 만드는 법 |
|---|---|---|
| 코어 섬광 | 맞는 순간 0.05~0.1초 번쩍임 | 밝은 원형 텍스처, 덧셈(additive) 합성 |
| 충격파·링 | 퍼져 나가는 원 | 링 텍스처를 빠르게 키우며 투명하게 |
| 플립북 | 불길·번개·연기 | 연속 프레임 시트(예: 8×8) 재생 |
| 파티클 | 불똥·파편·피 | 작은 조각 수십 개, 무작위 속도·중력 |
| 왜곡 | 열기·공간 일그러짐 | 노이즈 텍스처로 화면을 비트는 셰이더 |
| 잔광·데칼 | 바닥 그을음, 남는 빛 | 바닥 반투명 그림이 서서히 사라짐 |
| 피드백 | 손맛 | 히트스톱(몇 프레임 정지), 화면 흔들림, 피격 번쩍임 |

손맛은 텍스처 품질보다 **타이밍(몇 프레임에 무엇이 터지는지)** 에서 나온다.

### 3.2 모션·보스

- 모델: Maya/3ds Max 모델링 → 리깅. 동작: 모션캡처 + 수작업 키프레임.
- 공격 리듬: **준비(예고) → 순간 가속 → 정지 → 회복** 을 과장.
- 보스 공격 = **예고 모션 + 바닥 장판(텔레그래프) + 판정 구간 + 빈틈** 을 한 단위로 설계하고 패턴으로 묶음.

## 4. 우리 게임 대응 (2D 캔버스)

| PoE 방식 | 우리 게임 |
|---|---|
| 3D 모델 + 애니메이션 | PixelLab 등 스프라이트 시트, 프레임 타이밍 조정 |
| `.epk` 뼈 부착 | **스프라이트 앵커**: 프레임마다 칼끝·손 위치를 기록해 이펙트 부착 |
| `.ast` 이벤트 마커 | **프레임 이벤트**: 공격 프레임에 판정·이펙트·사운드·히트스톱을 박아 한 번에 맞물림 |
| `.pet` 곡선 정의 | **이펙트 정의 JSON**: 층·타이밍·크기·색 곡선을 데이터로 (현재는 game.html 곳곳 하드코딩) |
| 덧셈 합성 | 캔버스 `globalCompositeOperation='lighter'` |
| 왜곡 셰이더 | WebGL(GPU 프록시) 쪽에서 가능 |
| 히트스톱·흔들림 | 이미 있음 → 수치 조정 |

#### 6.2.5 맵 쪽 핵심 정리

1. **두 층의 랜덤**: (a) 사람이 그린 뼈대 그래프 5~12장 중 선택 + (b) 빈 노드·빈 공간을 규칙으로 채움. 완전 절차 생성이 아니라 "설계된 뼈대 + 랜덤 살".
2. **이음매는 이름으로 맞춘다**: 모든 조각의 네 변에 가장자리 타입이 붙어 있어, 같은 이름끼리만 붙음. 전이(숲→강)는 "가상 가장자리" 하나로 해결.
3. **손으로 만든 방은 재사용 단위**: 보스·입구·이벤트는 고정 방, 그 사이를 표준 조각이 메움. 보스 아레나도 변형 4종을 만들어 반복 플레이 피로를 줄임.
4. **소품도 방 단위로 묶어 재사용**(타일 0개짜리 소품 방).
5. **조명·안개·음악은 지역 데이터**, 보스전은 차분 파일로 덮어씀.

### 6.5 EXODUSER 적용 제안 (우리 방식, 우선순위 순)

우리 게임: 2D 캔버스 + WebGL 프록시, 스프라이트 시트(PixelLab/AI), 맵은 지역별 대형 구운 이미지(8192² 마스터 → 64청크, `docs/4.1맵디자인+설정/MAP_RUNTIME_ARCHITECTURE.md`).

#### P0 — 보스 공격 정의 템플릿 (즉시 효과 큼)

PoE2에서 배운 핵심: 공격 하나 = **조준추적 구간 + 고정(예고) + 판정 + 회복** + 연출 이벤트가 판정보다 조금 먼저. 우리 보스(`docs/8.1보스디자인바이블/`)에 아래 형식을 표준화한다.

```js
// 우리 형식 예시 (PoE2 파일 아님 — 우리 설계)
BOSS_ATK.slamWide = {
  anim: 'slam', dur: 1.60,                 // 초. 프레임은 스프라이트 fps로 환산
  track: [0, 0.75],                        // 플레이어 방향 추적 구간
  lock:  0.75,                             // 방향 고정 = 회피 창 시작
  hits:  [{ t: 1.05, shape: 'circle', r: 220, dmg: 1.4 }],
  tele:  { t: 0.20, kind: 'groundRing', grow: [0.20, 1.05] },  // 바닥 예고, 판정 시각에 꽉 참
  fx:    [{ t: 0.98, id: 'slamBurst' }],   // 판정 60~90ms 전
  sfx:   [{ t: 0.20, id: 'warn' }, { t: 0.98, id: 'impact' }],
  shake: [{ t: 1.00, amp: 10, dur: 0.12 }, { t: 1.12, amp: 3, dur: 0.6, damp: 'lin' }],
  recover: 0.55, unblockable: false,
};
```

| 수치 가이드 (PoE2 실측에서 우리 템포로 환산) | 값 |
|---|---|
| 고정→판정 | 일반 0.25~0.35s, 보스 강공 0.35~0.5s (PoE2 중앙 0.31s) |
| 첫 판정 시각 | 잡몹 0.5~0.8s, 보스 0.8~1.2s (PoE2 0.82 / 1.08s) |
| 회복 | 판정 후 0.5~1.2s (빈틈 = 보상) |
| 연출 선행 | 이펙트·사운드는 판정 −60~−90ms |
| 단계 강화 | 같은 구조 + 흔들림 진폭만 상승(예 1.0→1.6배) |
| 막을 수 없는 공격 | 공용 "위험 패스"(보스 스프라이트 전체 붉은 펄스 + 경고음) 하나를 모든 보스가 공유 |

#### P0 — 이펙트 정의 데이터 형식 (game.html 하드코딩 정리)

| PoE2 개념 | 우리 형식 |
|---|---|
| aoc 타임라인 | `FX_DEF[id].events: [{t, type:'layer'|'sfx'|'shake'|'hitstop'|'decal'|'light', ...}]` |
| pet 이미터 | `layers: [{start, life, count, shape:'point'|'ring'|'line'|'disc', blend:'lighter'|'source-over'|'multiply', face:'screen'|'ground', curves:{alpha, scale, speed}}]` |
| 곡선 | 키 배열 `[[t, v, 'lin'|'smooth'|'flat'], ...]` — 기본 프리셋 3개: **섬광** `[[0,1],[0.2,0.22],[1,0,'smooth']]`, **올랐다 빠짐** 정점 0.17, **커지기** `[[0,0.6],[1,1.4]]` |
| 공용 도형 메시 | 우리 공용 **원·링·반원·부채꼴·평면 스프라이트** 6~8장(직접 제작)으로 대부분 레이어를 만들고 색·곡선으로 변주 |
| 충격 기본 스택 | 섬광(0→0.25s, lighter) · 링(0.05→0.3s) · 중간 불길/파편(0.05→0.8s) · 연기/그을음 데칼(0.03→3s) — 4층, 대형 기술만 8층까지 |
| 레이어 시작 | 0~0.15s 사이 흩뿌림(동시 시작 금지) |
| 속성 변형 | 같은 FX_DEF + 색 팔레트/텍스처만 교체 + 속성 사운드 1겹 |

시범 대상: §5 단계 5대로 **기검참** 하나를 이 형식으로 옮겨 전후 비교.

#### P1 — 스프라이트 앵커 + 프레임 이벤트

| PoE2 | 우리 |
|---|---|
| 스킨 메시의 본 그룹 20개(표준 이름) | 스프라이트 시트 프레임마다 **앵커 좌표 표**: `blade`, `handR`, `handL`, `head`, `chest`, `feetC`, `root` — 표준 이름 7개 고정 |
| 이펙트팩을 "칼날" 그룹에 붙이면 모든 무기에 적용 | 무기 궤적·인챈트 이펙트는 `blade` 앵커 하나만 참조 → 시트가 바뀌어도 재사용 |
| .ao 이벤트(contact, footstep, move…) | 시트 메타 JSON에 `events: {frame: ['hit','step','fxStart']}` — 판정·발소리·이펙트·히트스톱을 같은 프레임에 박음 |
| 30fps 기준 애니 | 우리 시트 fps(보통 12~16)에서 **판정 프레임을 시각(초)로 저장**해 fps 바뀌어도 판정 시각 유지 |
| 와일드카드 부착 | `grp_*` 같은 "모든 앵커" 지정 → 버프·디버프 오라를 몸 전체에 한 번에 |

PixelLab/AI로 시트를 만들 때 **앵커는 생성 후 사람이 1회 찍는 데이터**(프레임당 7점)로 둔다.

#### P1 — 맵: 구운 대형 이미지 + "방 단위 조립" 혼합

현재 방식(지역마다 8192² 구운 한 장)은 아트 품질은 좋지만 반복 플레이 다양성이 없다. PoE2식을 그대로 3D 타일로 따라갈 필요는 없고, **2D에 맞는 축소판**을 제안한다.

| 단계 | 내용 |
|---|---|
| 1 | 지역 = **방(room) 3~6종 × 뼈대 그래프 2~3장**. 방은 지금처럼 구운 이미지(예 2048²)로 만든다 |
| 2 | 방 네 변에 **가장자리 타입 이름**(숲길, 강, 절벽, 동굴문)을 붙여 같은 이름끼리만 연결. 이음매는 1타일(64~128px) 겹침으로 숨김(PoE2 실내 9×2−1=17 규칙과 같은 원리) |
| 3 | 보스 아레나·입구·이벤트 방은 고정, 그 사이 일반 방만 랜덤. 보스 아레나는 변형 2~4종 |
| 4 | 소품 군락(나무·바위·뿌리)을 **소품 방**(타일 없이 소품만)으로 묶어 재사용 |
| 5 | 방마다 태그 지점: `bossSpawn`, `entrance`, `checkpoint`, `rare`, `killzone` — 스폰·체크포인트를 데이터로 |
| 6 | 조명·안개·색보정·음악은 지역 데이터 1개 + **보스전 차분 데이터**(음악·안개 색만 덮어쓰기) |

우선은 CH1 한 지역에서 "방 3종 + 그래프 2장"으로 프로토타입 → 64청크 스트리밍과의 호환(방 경계 = 청크 경계 정렬) 확인.

#### P2 — 기타

| 항목 | 제안 |
|---|---|
| 화면흔들림 | 2단 구조 표준화: 짧은 강타(0.075~0.15s) + 긴 여진(약하게 0.6~1.0s, 선형 감쇠) |
| 장판 | 지속 방출 1~3층 + 바닥 정렬, 시작 0.3s 페이드 인 |
| 바닥 예고 | 데칼 링 + 코어 2층, 사운드 3박(시작·충전·끝) |
| 트레일 | 세그먼트 수명 0.2~0.4s, 사라짐은 텍스처 램프로 |
| 보스 페이즈 | "자세(stance)" 개념: 페이즈마다 이동속도·대기/달리기 애니·공격 목록만 덮어쓰기 |

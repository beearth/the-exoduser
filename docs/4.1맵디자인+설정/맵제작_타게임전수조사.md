# 맵 제작 전수조사 — 다른 게임은 맵을 어떻게 만드는가

> 2026-08-17 | 대상: D1 / D2 / D3 / D4 / PoE·PoE2 / Grim Dawn / Last Epoch / Hades / 엘든링 / Lost Ark
> 목적: **제작 방법**(파이프라인·레이어·충돌). 분위기 벤치는 `맵디자인_벤치마크.md`.
> 적용: `맵제작_SSOT.md`. 엔진 수치: `game.html`.

이 문서는 “그 게임을 베끼자”가 아니다.
**출시된 ARPG가 공통으로 하는 일 / 절대 안 하는 일**을 고정하고, 우리 엔진에 그대로 옮긴다.

---

## 0. 한줄 (전수조사 결론)

출시된 핵슬래시·아이소·오픈월드 전부 **통이미지 한 장을 맵 크기로 늘려 밟지 않는다.**

맵은 항상 **레이어의 합**이다.

```
[1] 바닥 재료     타일 / 스플랫 / 왕타일     ← 반복돼도 티 안 나게
[2] 키트 조각     방·복도·절벽·벽 모듈      ← 같은 세트로 여러 맵
[3] 소품·문화킷   나무, 수레, 제단, 시체     ← 장소를 만든다
[4] 히어로 1개    성, 거목, 용해골           ← 멀리서 보이는 것
[5] 데칼·빛·VFX  핏자국, 웅덩이, 안개        ← 그림에 굽지 않음
[6] 충돌·내비     별도 볼륨 / 서브타일 플래그 ← 그림 실루엣에서 계산 금지
```

우리가 4장 플레이트를 붙여  squish 한 것은 **[1]~[6]을 한 장에 구운 것**이다. 다른 게임은 그걸 런타임 맵으로 쓰지 않는다. 플레이트는 **설계도·룩 타깃**이다.

---

## 1. 절대 안 하는 것 (전 작품 공통)

| 안 함 | 이유 | 우리가 한 실패 |
|-------|------|----------------|
| 컨셉 그림 1장을 8000×8000에 늘려 걷기 | 캐릭터가 난쟁이, 해상도·VRAM 파탄, 이음·왜곡 | 헬스케이프 통스탬프 |
| 그림 실루엣으로 충돌 자동 추출 | 늪/그림자/원근이 벽이 됨 | “비율 조절 + 충돌” 제안 |
| 4장 AI 플레이트를 그냥 이어 본맵 | 흙이 안 이어지고 사이드가 잔재 | 세로 4장 / 2×2  squish |
| 바닥을 유니크 페인팅으로 채움 | 반복 금지하려고 그림을 키우면 스케일 붕괴 | 플레이트 = 바닥 |
| 카메라 모르는 투시 그림을 탑다운으로 밟기 | 소실점 그림은 걸을 수 없음 | 16:9 시네마틱 비스타 |

다른 게임이 그림을 쓰는 자리: **컨셉, 키아트, 원경 카드, 로딩.** 플레이 면이 아니다.

## 2. 작품별 — 실제로 만드는 단위

### 2.1 디아블로 1 (1996) — 방 타일 + 서브피스

출처: BorisTheBrave, dungeon generation 분석.

- 레벨은 **40×40 타일 격자**로 먼저 생성된다.
- 렌더 때는 타일 1칸을 **4개의 던전 피스**로 쪼갠다 (그래픽 재사용).
- 타일 종류가 100장을 넘는다. 거의 전부 **이음용 변형**(이 벽이 저 벽과 붙는 경우).
- 걸을 수 있는 칸은 생성 격자가 아니라 **더 고운 서브격자**.

교훈: 예쁜 방 그림이 아니라 **붙는 조각의 변형**이 맵이다.

### 2.2 디아블로 2 — DT1 / DS1 (아이소 ARPG의 원형)

출처: Phrozen Keep (DT1/DS1/LvlTypes/LvlPrest/LvlMaze).

| 파일 | 역할 |
|------|------|
| **DT1** | 타일 **그래픽 라이브러리**. 같은 테마(숲, 묘, 마을)의 바닥·벽 조각. 아이소 다이아몬드 |
| **DS1** | **배치**. 어느 칸에 어느 타일을 올릴지. 여러 레이어 |
| **LvlTypes.txt** | 테마당 DT1 최대 32개 |
| **LvlPrest / LvlMaze** | 고정 프리셋 vs 랜덤. 랜덤 청크는 대략 **25×25 타일** |
| 서브타일 플래그 | 충돌·시야. **그림에서 계산하지 않음** |

레이어(한 DS1 안):

1. 바닥
2. 벽
3. 그림자
4. 특수(워프, 문)

야외(피의 황야 등)는 DS1 **여러 장**을 Vis로 잇는다. 트리스텀 같은 마을은 DS1 **한 장 손배치**.

캐릭터 스케일은 **타일 크기**로 잠긴다. 그림을 맵에 맞춰 키우지 않는다.

이게 유저가 말한 “중심 타일 하나 + 커스텀을 하나씩 확장”의 원형이다.

```
DT1 흙 바닥 몇 장  →  DS1에 깔기  →  나무/뼈/오두막 타일·오브젝트 추가
```

통그림 금지. **같은 DT1로 맵 수십 장.**

### 2.3 디아블로 3 — 3D 아이소 + 큰 청크

- 카메라는 고정 쿼터뷰. 바닥은 **타일링 3D 머티리얼**.
- 던전: 모듈 타일셋 + **큰 세트피스 청크**를 퍼즐처럼 조립 (절차).
- 야외 허브(뉴 트리스트럼, 칼데이움)는 **손배치**.
- 나무: 살짝 굽은 평면에 그린 알파 카드. 시점 하나라 3D 나무가 필요 없다 (simonschreibt).
- 실패로 욕먹은 점: 청크가 너무 커서 “또 그 방”이 보임.

교훈: 야외 본맵은 D3 **허브**처럼 손배치. 던전 미로 생성기는 본맵에 쓰지 않는다 (`genGauntlet` 폴백만).

### 2.4 디아블로 4 — 타일셋 + 문화킷 + 전이 장면 (공식)

출처: Blizzard Quarterly Update, 2022-03 (환경 아트). Behind the Pretty Frames: Diablo IV.

**오픈월드 (손제작)**

- 지형 스컬프트 + 바이옴 머티리얼(풀/흙/바위/눈).
- 그 위에 **건축 키트** (같은 벽·지붕을 지역마다 재료만 바꿈).
- 그 위에 **문화킷(props/interactives)** — 어부 마을이면 그물·선착장, 슬럼이면 찢어진 천.
- 빛·날씨·젖은 지면은 **셰이더**. 그림에 안 굽는다.
- 고정 카메라 덕분에 **전경 가림(foreground)** 을 플레이 공간을 막지 않고 심는다.

**던전 (150+개, 재사용)**

> “tile-sets. mix and match them with props, interactives, and lighting”
> — Brian Fletcher, D4 Environments

같은 타일셋으로 던전을 여러 개 만든다. 바꾸는 것:

| 레이어 | 예 |
|--------|----|
| 타일셋 (기하) | 동굴 키트, 성채 키트 |
| 테마 레이어 on/off | 드루이드 부적 / 비어 있는 동굴 |
| 문화킷 | 익사한 자의 유물 vs 고딕 갑옷 |
| 빛 | 선택적 어둠 vs 독녹 노란빛 |
| **타일셋 전이 장면** | 지하실 구멍 → 침수 동굴. 두 키트를 잇는 **손만든 문** |

렌더(프레임 분석): 지형 타일 메시 + 하이트 + 스플랫 + 데칼 + 버추얼 텍스처. 미니맵/내비는 **아티스트가 만든 SDF 타일**. 런타임에 그림에서 뽑지 않음.

교훈: **키트 1세트 + 소품 레이어 + 빛**이 맵 150개다. 맵마다 그림을 새로 그리지 않는다.

### 2.5 Path of Exile / PoE 2 — 룸 그래프 + 타일 키 + 왕타일 바닥

출처: GGG Dev Diary 2010 (타일 텍스처). ExileCon Rhys Abraham (월드 생성). 2010 랜덤 레벨 발표.

**레이아웃**

1. **그래프**: 입구 방 / 전투 방 / 출구 방 같은 **방 타입 노드**.
2. 각 노드는 손만든 **룸 프리팹 풀**에서 뽑힌다.
3. 방은 픽셀 타일이 아니라 **타일 키(tile key)** 로 되어 있다.
4. 두 방이 **키 1칸 겹침**. 키가 합쳐지는 규칙 → 새 타일을 찾아 **이음**.
5. 그래서 방과 방이 끊기지 않는다.

캠페인: 그래프가 조밀하고 방이 손맛.  
엔드 맵: 같은 키트를 느슨히 조립 → “예쁜 타일 + 게으른 길”로 욕먹음.

**바닥 머티리얼**

- 일반 심리스 1장 반복은 멀리서 격자처럼 보임.
- **왕타일(Wang tile) 16장**: 변 색깔끼리만 붙음 (파란 변↔파란 변).
- GPU가 큰 비주기 바닥을 만듦. 반복이 눈에 안 띔.
- 아티스트 작업: 사진 바닥 → 광도 평탄화 → 이음 변 복사 → 노멀/스펙큘러.

교훈: 바닥은 **재료 세트**. 장소는 **룸+소품**. 플레이트 12장을 바닥에  squish 하지 않음.

### 2.6 Grim Dawn (Titan Quest 계열)

- 캠페인 맵 **전부 손배치**. 절차 생성 없음.
- 3D 아이소. 모듈 지형 타일 + 고유 세트피스 + 비밀 길.
- 유저가 “맵이 좋다”고 하는 이유 = **손맛**, 타일 공장이 아님.
- 제작비: 맵 한 장에 사람이 오래 앉음. 대신 반복 플레이 가치가 있음.

우리 본맵(1-1~7-4 필드)은 이쪽에 가깝다. 손배치 필드.

### 2.7 Last Epoch

- Unity 3D 아이소. 존은 대체로 손배치.
- 키트 + 소품. PoE보다 그래프가 약함.
- 욕먹는 맵: 같은 복도가 비어 보임 = **소품·랜드마크 부족**. 그림이 없어서가 아님.

### 2.8 Hades / Hades 2

출처: Supergiant 레벨 비하인드, Hades-like 기술 개요.

- **방 프리팹을 손으로 통째 만듦** (바닥, 충돌, 스폰, 출구 소켓).
- 절차는 “어느 방을 어떤 순서로 이을지”만. 방 안을 랜덤 카빙하지 않음.
- 정적 방(존 첫 방, 전이) + 동적(보상, 출구 개수).
- 챔버 그래프는 액트마다 방 풀이 정해져 있다.

교훈: 절차 ≠ 그림 생성. 절차 = **손만든 조각의 조립 순서**.

### 2.9 엘든링 (참고 — 3D 오픈월드)

스케일은 다르지만 레이어는 같다.

| 레이어 | 내용 |
|--------|------|
| 하이트맵 + 스플랫 | 풀 / 흙 / 바위 / 모래 3~5장 |
| 건축 키트 | 벽, 아치, 계단 (스톰베일 성벽이 이 키트) |
| 히어로 메시 | 황금 나무, 성 실루엣 |
| 내비메시 | 별도. 그림 아님 |

멀리서 읽히는 주 앵커 + 빈 중앙 = 현행 1-1의 단일 `m_c1tree` HERO 구조. 여섯 side POI는 외곽/shoulder에 붙고 중앙 전투공터를 채우지 않는다.
차이는 엔진이지, “그림 한 장으로 땅을 만든다”가 아니다.

### 2.10 Lost Ark / 로드 오브 더 폴른

- Lost Ark: 손배치 3D, 바닥 머티리얼 +  dens한 소품. 통그림 아님.
- LotF: 언리얼 던전 키트 + 히어로 룸.

## 4. 스케일이 안 무너지는 이유

다른 게임이 캐릭터를 난쟁이로 만들지 않는 이유.

1. **타일/미터 단위가 먼저 잠긴다.** D2는 아이소 타일, D4/엘든은 미터, 우리는 `T=40`.
2. 캐릭터 스프라이트 높이가 타일 N칸. 그 비율을 안 바꾼다.
3. 큰 그림이 필요하면 **원경 카드 / 스카이박스 / 전경 오클루더**로 뺀다. 바닥을 안 키운다.
4. 히어로 소품(성, 거목)만 크게. 바닥 텍셀은 그대로.

통그림을 맵에 맞추면 텍셀이 캐릭터보다 커진다 → 난쟁이.  
이게 우리가 반복한 실패다.

## 5. “4장 붙이기”가 다른 게임에 있다면

있다. 다만 **런타임 맵이 아니다.**

| 다른 게임의 4장 | 실제 용도 |
|-----------------|-----------|
| D4 컨셉 / 오버헤드 키아트 | 바이옴 룩, 발표, 조명 가이드 |
| PoE 존 컨셉 | 타일셋 색·소품 목록 |
| 엘든 맵 디자인 도면 | 하이트·길·랜드마크 위치 |
| 우리 MASTER 4×3=12 | **설계도.** SSOT §5 |

런타임으로 쓰는 4장:

- D2: 야외 DS1 4개를 **같은 DT1**으로 이어 큰 필드. 그림 4장이 아님.
- D4: 타일셋 전이 장면. 키트 A와 키트 B 사이의 **손만든 문**.
- PoE: 룸 4개를 키 겹침으로 이음.

우리가 한 것: 카메라·흙 방향이 다른 그림 4장을 JPEG로 이어 밟기.  
그건 위 표의 어느 칸에도 없다.

## 6. 우리 엔진에 그대로 옮기면

이미 있는 것 = 다른 게임의 레이어.

| 다른 게임 | 우리 | 상태 |
|-----------|------|------|
| 타일 바닥 / 왕타일 / 스플랫 | `_gtFloorImg` + `T=40` 타일 | **있음.** 1장 `ground_dark_soil.png` |
| DS1 / 룸 / 청크 배치 | `tileRLE` + `genFromTemplate` + `_MAP_COMPOSE` | 있음. 본맵 200×200 |
| 문화킷 / 소품 | `_CH_DECO` / `MAP_OBJS` / 유저 괴기 PNG | 있음. 손배치(`hand`) |
| 히어로 | `m_c1tree` | 1-1 중앙 HERO 1개. 나머지는 side POI, mega 0 |
| 전경 오클루더 | Y소트 스프라이트 | 일부 |
| 충돌 | tileRLE + 오브젝트 col | **그림에서 뽑지 말 것** |
| 스트리밍 | `_STREAM_CHUNK` | 있음 |
| 빛·VFX | 엔진 VFX | 그림에 굽지 말 것 |
| 왕타일 16장 | 없음 | 바닥이 반복되면 그때 추가 |
| 룸 그래프 / 타일 키 이음 | 없음 | 본맵 필드엔 불필요. 던전(si 11/16/33)용 |

**본맵 제작 순서 (다른 게임과 같음)**

```
1. 장 타일셋 LOCK     ground + 소품 팔레트 + 히어로 1개
2. 미니맵/설계도      6시 시작, 12시 문, 빈 흙, 랜드마크 위치
3. 바닥을 타일로 깔기  _gtFloorImg 반복.  squish 금지
4. 히어로 1개 배치    용해골 급. 화면의 절반
5. 프레임 소품        거목·철창은 가장자리. 전투면을 안 먹음
6. 충돌 손작성        타일 + 콜 박스. 이미지 실루엣 금지
7. 데칼·VFX          핏자국, 독, 불씨
```

12 플레이트 / 2×2 테스트 JPG는 **2번 설계도의 룩 타깃**이다.  
런타임 5번에 소품을 뽑을 때 참조한다. 맵 텍스처로  squish 하지 않는다.

## 7. 우리 테스트가 실패한 이유 (이 조사로 설명)

| 시도 | 다른 게임이면 | 왜 깨짐 |
|------|----------------|---------|
| 시네마틱 16:9를 맵에  squish | 로딩/키아트 | 투시는 걸을 수 없음. 난쟁이 |
| 검정 패드를 그림으로 채움 | 원경 스카이/카드 | 화면 정렬 스탬프가 됨 |
| 세로 4장 | D2 세로 던전 DS1 | 우리 플레이트는 사각형 쿼터. 세로가 아님 |
| 2×2  squish | MASTER 미리보기 |  squish 자체는 설계도. 그걸 본맵 텍스처로 씀 |
| 흙을 그림에서 찾음 | 바닥은 타일 재료 | 그림마다 흙 위치가 다름 → 사이드 잔재 |

플레이트 4장은 **한 장의 사각형 설계도**가 맞다 (유저 지적).  
다만 그 사각형은 **런타임 디퓨즈가 아니다.** D4 키아트 / PoE 존 컨셉과 같은 층.

## 8. 지금 잠글 제작법

SSOT와 같음. 이 조사가 근거.

1. **바닥** = 장당 심리스 흙 1장 (`ground_dark_soil.png`). 필요하면 왕타일 16장으로 업.
2. **설계** = MASTER 4×3 또는 지금 2×2 룩. 인게임에  squish 금지.
3. **본맵** = 200×200 타일 + 히어로 1 + 빈 흙 + 가장자리 소품.
4. **충돌** = tileRLE / 콜 박스. 이미지에서 추출 금지.
5. **던전(11/16/33)** 만 나중에 룸 키트. 본맵에 미로 생성 금지.
6. 캐릭터 스케일 = `T=40` 고정. 그림을 맵에 맞추지 않음.

테스트 URL(`?stage=0`)은 **키트 필드** (`_buildKitFieldTest`). 타일 흙 + 갈비 1 + 가장자리 소품. 출시 1-1이 아니다. 2×2 JPG는 룩 타깃으로만 남긴다.

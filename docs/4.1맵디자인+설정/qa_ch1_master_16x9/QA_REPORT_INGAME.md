## 1. CAMERA SCALE

비교 기준: 같은 1920×1080, 같은 플레이어 `P.r=15`, FIELD_ONE은 36×27 / 1440×1080에 그림 1448×1086(거의 1:1).

| | FIELD_ONE | PROD |
|---|---|---|
| 월드 px | 1440×1080 | 2200×1240 |
| 그림 px | 1448×1086 | 2176×1224 |
| 그림/월드 | ≈1:1 | ≈1:1 |
| 1920 화면이 커버하는 월드 | 가로 100%+양옆 보이드, 세로 100% | 가로 87%, 세로 87% |

- 캐릭터 크기는 안 변한다. 맵이 플레이어를 줄이지 않음.
- PROD 흙 크랙이 FIELD_ONE 알갱이보다 **한 단계 크다.** 발밑 석판처럼 읽힘. 플레이 불가는 아님.
- 같은 월드를 4K로 다시 칠하면 크랙은 더 잘게 보임. 월드를 키우며 이 그림을 늘리면 크랙이 더 커져서 더 나빠짐.

샷: `cmp_fieldone_1920_center.png`, `prod_1920_center.png`

## 2. COMBAT SPACE

| 항목 | 실측 |
|---|---|
| 월드 | 2200×1240 |
| 1920×1080 카메라 | 월드의 87% × 87% |
| 한 화면 적 | 이 세션 13~15 |
| 4방향 길 | 중앙에서 N/S/E/W 흙길이 보임 |

15마리+스킬은 남는다.  
**100~300 + 투사체 + 대형 스킬은 맵 전체를 채운다.** 본편 200×200(8000×8000)과 비교하면 이 테스트베드는 한 장면 아레나다.

왜: 그림이 곧 맵이다. 2176px 한 장을 1:1로 밟으면 1920 모니터에 거의 다 들어간다. 구도가 틀린 게 아니라 **그림 한 장 = 스테이지 전체**인 사용법이 본편 오픈필드와 안 맞는다.

SSOT (`맵제작_SSOT.md` §0): 통이미지 한 장을 8000×8000에 늘려 밟지 않는다. 이 QA가 그 이유를 인게임에서 확인한 것이다.

## 5. DISPLAY QA

카메라 = `innerWidth × innerHeight`. 배경을 창에 맞추지 않음. UW는 좌우 월드를 더 보여 줌 → 맵보다 창이 크면 보이드.

| 해상도 | VW×VH | 보이는 것 |
|---|---|---|
| 1920×1080 | 1920×1080 | 맵이 화면을 거의 채움 |
| 3440×1440 | 3440×1440 | 맵 전체가 중앙 사각형. 좌우·상하 보이드 |
| 5120×1440 | 5120×1440 | 맵이 더 작은 섬. 동일 원칙 |

샷: `prod_3440_center.png`, `prod_5120_center.png`

강제 스트레치 없음 = PASS.  
UW에서 전장이 우표처럼 보임 = 월드가 작다는 같은 문제의 다른 얼굴.

|---|---|---|---|
| FIELD_ONE 1920 | 22 | 35.78ms | 273.9ms |
| PROD 1920 | 23 | 35.77ms | 293.7ms |
| PROD 3440 | 6 | 40.61ms | 369.8ms |

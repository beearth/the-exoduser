## 에셋 경로 규칙

### 원칙: 챕터 폴더 = 해당 챕터의 유일한 에셋 소스
- **CH1**: `assets/map/ch1/` — CH1에서 사용하는 모든 오브젝트 에셋은 이 폴더에서 로드
  - `floor_objects/` — 비충돌 장식 에셋
  - `collision/` — 충돌 에셋 (저주나무, 구덩이, 썩은나무, 애니나무, 보스게이트)
- **CH2~CH7**: `assets/map/ch2/` ~ `assets/map/ch7/`가 각 챕터의 유일한 소스. 현재 CH2·CH3는 collision/floor 세트가 실사용 중이며 나머지는 해당 폴더 registry를 따른다.
- 장별 최소 세트·제작 순서: `맵유형_확장기획.md` §4.2 (바닥2+벽1+엣지1, 대형8+유니크4). `_CH_DECO`는 hell 0~6 전부 등록. 1-1 유니크 21종 + 장별 테마 대형(prop_a/b + 신규 랜드마크).
- **`assets/objects/`는 창고(아카이브)**. 게임 런타임에서 직접 로드하지 않음. 원본 보관·백업 용도

### 코드 적용
- `_OBJ_SPR_MAP`: 모든 경로가 `assets/map/ch1/...`로 지정됨
- `_CH_DECO`: `assets/map/ch{N}/` + `(dir||'floor_objects')` + `file`로 자동 합성. `dir:'collision'` 등으로 서브폴더 지정 가능
- 벽 나무/눈깔 등 프로시저럴 장식도 `assets/map/ch1/` 경로 사용
- 새 챕터 추가 시: 해당 챕터 폴더에 에셋 넣고 `_OBJ_SPR_MAP` 경로를 챕터별로 분기하거나, `_CH_DECO` 시스템 활용

### 에셋 추가/교체 절차
1. 새 에셋 파일을 해당 챕터 폴더에 저장 (예: `assets/map/ch1/new_object.png`)
2. `_OBJ_SPR_MAP`에 경로 등록 또는 `_CH_DECO` 배열에 추가
3. `_OBJ_META`에 sz/collision/light/anim 등 메타 설정
4. `assets/objects/`에도 백업 복사 (선택)

### CH3 IMAGE CROP / SLICE 우선순위 LOCK

1. 기존 CH3 에셋 그대로 재사용
2. 기존 이미지의 alpha tight crop / slice / atlas extraction
3. rotation·scale·허용 대상 mirror·20~50% composite 재조합
4. 위 세 단계로 실루엣을 만들 수 없을 때만 신규 원화 제작

신규 제작 전 `그대로 사용 / crop / rotation / mirror / composite / 신규 필요` 6분류 asset audit를 남긴다. 긴 벽은 stretch하지 않고 cap/repeat/cap 또는 모듈 반복을 사용한다. 글자·방향광·입구·강한 원근 랜드마크는 mirror 금지이며, 3/4 원근 원본은 4방향 회전 모듈로 강제 사용하지 않는다. crop 후 `sourceSize/trimOffset`으로 pivot·ground contact를 복원하고 collision은 투명 canvas가 아닌 실제 crop 실루엣 기준으로 별도 정의한다.

- 에디터 폴더: `docs/4.1맵디자인+설정/objects/`
- 카테고리: 에디터는 `장식-대형`/`장식-중형`/`장식-소형` 3분류, 자동 배치는 챕터별
- 크기 배율(scale): 에디터에서 0.3~3.0x 슬라이더로 조절 가능, MAP_OBJS에 `scale` 프로퍼티로 저장

## 자동 배치 시스템 (`_CH_DECO`)
- `initMapObjects()`에서 해당 챕터 에셋을 바닥 타일에 자동 배치
- 시드 기반 난수로 동일 스테이지 = 동일 배치
- **hand 맵** (`hand:1`): 통바닥 + compose에 적은 커스텀만. 1-2 = 예배당+눈나무 4기
- **path 맵** (`path`): 길 타일 + 길 밖 이미지. 지금은 1-2에 안 씀

### 대형 에셋 자동 배치 (1차 패스)
- `_CH_DECO`에서 `large:1` 플래그가 있는 에셋만 대상
- 필드 맵당 대형 28~56 (간격 **760px**), 던전은 최대 22·간격 900px. 사이드 35% + 중앙 65% (필드)
- 벽에서 2~4타일 범위가 사이드 판정. `_gridNear`는 보이는 크기(`sz×0.55`)로 검색 반경을 늘림 — 200px 칸 3×3만 보면 중첩됨
- **소환굴 200px 이내 배치 금지** — 소환굴 스폰 영역 보호
- **복도(좁은 통로) 배치 금지** — 주변 6타일 범위에 바닥 120칸 이상 확보 필수 (통로 막힘 방지)
- 충돌 판정: `isW()`에서 `col:1` 또는 `collision:true` 모두 벽으로 처리. 코드: `_pm.collision||_pm.col`
  - **원형 충돌** (기본): 배치 인스턴스 반경 = (`colSz` || `sz × 0.4`) × (`MAP_OBJS[i].scale` || 1)
  - **타원 충돌**: 배치 인스턴스 가로/세로반경 = `colW`/(`colH` || `colW`) × (`MAP_OBJS[i].scale` || 1). 수식: `(dx²/scaledColW²) + (dy²/scaledColH²) < 1`
  - 스케일이 `undefined` 또는 `0`이면 `1`로 폴백한다. `_rebuildColObjs()`가 충돌 캐시 생성 시 `_colW`/`_colH`/`_colSz`를 인스턴스에 1회 저장하고, 게임루프 `isW()`는 저장값만 읽는다.
  - **타원 오프셋**: `colOy` — 충돌 타원 중심을 Y방향으로 오프셋 (이미지 중심과 콘텐츠 중심이 다를 때)
  - **회전 모듈 충돌**: `colParts:[{x,y,w,h,rot}]` — module-local offset과 각도에 인스턴스 `rot`을 합성해 oriented rectangle로 판정한다. `_CH_DECO` loader는 `colParts`, `pivotX/Y`, `squareDraw`, `wallKit`, `wallUnit`, `edgeErase`를 `_OBJ_META`에 보존한다.
  - **runtime crop / atlas**: `srcRect:[sx,sy,sw,sh]`, `sourceSize:[w,h]`, `trimOffset:[x,y]`를 보존한다. `_drawMapObjectCrop()`이 tight-crop cell을 원본 canvas 좌표계의 pivot/ground contact로 복원한다. `sharedAtlas:1` 경로는 `_objImageByPath`에서 URL당 `Image` 1개만 생성한다.
  - **규칙**: 충돌 크기는 이미지 실측 기반으로 산출. 이미지의 불투명 영역(alpha>30) 바운딩박스를 구하고, 게임 스케일(sz/이미지폭)을 곱한 뒤 ×0.45 축소하여 타원 반경으로 사용. 오프셋은 콘텐츠 중심 - 이미지 중심 × 스케일.
- 대형 에셋: m_ctree1~12 (저주나무 12종, sz:400, col:1)

### 2. 게이트 배치 로직 (맵 생성 시)

#### 게이트 방향 결정
```
genFromTemplate: 보스방 4방향 스캔 → 복도 연결이 가장 많은 방향 = 입구
  → _entryDir = 'top'|'bot'|'left'|'right'
  → 해당 방향 경계에 게이트 타일 3칸 배치 (_gateTiles)
  → _gateY = 게이트 타일 Y좌표
```

#### 출구 타일 배치
```
위치: gateY + 7 (= 게이트 이미지 하단 blood trail/mouth 위치)
폭: 3칸 (게이트 타일과 동일 X좌표)
타일값: map[ey][ex] = 2 (출구 타일)
바닥 확보: gateY ~ gateY+8까지 벽(1) → 바닥(0) 자동 카빙
```
- genFromTemplate: `_mouthOff=2`, 게이트 타일별 X좌표 유지, Y = gateY+2
- genGauntlet: `_mouthOff=2`, 3칸(iCx-1, iCx, iCx+1), Y = gateY+2

#### 충돌 오브젝트
```
type: 'boss_gate_col'
위치: X=(bossCx+0.5)*T, Y=(gateY+0.5)*T — 실시간 렌더 나무 중심과 동기화
크기: sz=250, 충돌반경 = 250×0.4 = 100px
효과: 나무 본체 통과 차단, mouth(gateY+2)는 포탈과 동일 위치
```

#### 게이트 이미지 렌더 (맵 캐시 — buildMapCache)

**3곳에서 렌더됨** (스트리밍/풀빌드/아레나):

```
[1] 스트리밍 맵 캐시 (변경 없이 맵 유지 시)
    조건: G._bossArena → 아레나 12시 출구에 게이트 이미지
          else G.bossGate → 던전 게이트에 이미지
    크기: 600px 폭, 비율 유지 높이
    오프셋: gateY*T - bgH + 350 (하단이 gateY*T+350)

[2] 풀 맵 캐시 (buildMapCache 풀 리빌드)
    ── Pass 3.5: 보스방 대문 (tile=3) ──
    - tile=3 타일 찾기 → 게이트 영역 계산
    - _bossGateImgs[hell] 있으면: 챕터별 이미지 렌더
    - 없으면: 프로시저럴 지옥문 (철문+리벳+균열+보라빛)

    ── Pass 3.7: 보스문 앞 장식 ──
    - 범위: bossCx 중심, gateY+1 ~ gateY+9 (5×8 타일)
    - 1) 바닥 핏자국/균열 (40% 확률 타원, 15% 룬)
    - 2) 양쪽 악마 동상 (삼각형 실루엣 + 뿔 + 눈)
    - 3) 보스문 앞 경고 룬 원 (큰 마법진)

[3] 아레나 맵 캐시
    조건: G._bossArena && G._bossArenaGate
    위치: 아레나 12시 최상단 (exitX, exitY)
    오프셋: gateY*T - bgH + 40
```

```

```

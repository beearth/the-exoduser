## 3. 진전이 없는 원인

1. **3D 형태를 만들 수단이 없었다.** 텍스처·조명·데칼은 다 들어갔지만, 화면 인상을 결정하는 외곽 벽·랜드마크의 실루엣이 임시 메시라 품질이 올라가지 않는다. Meshy 연결이 1순위 병목이다.
2. **아트 기준 이미지가 없다.** "AAA처럼"이라는 말만 있고, 우리 게임 고유의 무드보드·팔레트·명도 기준이 없다. 그래서 판정이 따뜻한 조명 ↔ Godot 톤 사이를 오갔다.
3. **한 화면만 반복해서 다듬었다.** 에셋 키트(재사용 부품) 없이 START 한 컷만 손보면 지역 확장으로 이어지지 않는다.
4. **협업 경로가 끊겨 있었다.** Codex는 자기 브랜치 문서만 읽는데 요청은 main에만 있었다. 지금은 두 곳에 게시하는 것으로 고쳤다.

## 4. 제작 방식 (AAA 환경 파이프라인)

### 4.1 아트 바이블 (먼저 고정)

> **2026-10-26 작성 완료 → [MAP_ART_BIBLE_v2_20261026.md](MAP_ART_BIBLE_v2_20261026.md) (디자인총괄 소유).** 아래 세 줄은 요청 당시 초안이며, 명도 순서는 바이블 §4.2 V1·V3이 대체한다(바닥이 외곽 몸통보다 밝고, 캐릭터는 어두운 실루엣 + 테두리광).

- 무드보드: 우리 게임 기존 확정 아트(인트로·CH1 웹 맵·Godot LOOK-001), GPT 콘셉트 wall_A/B. 외부 작품 이미지는 넣지 않는다.
- 팔레트·명도 스크립트: 바닥(어두운 적갈, 평균 RGB 83,68,64 기준) < 외곽 벽 < 광원 웅덩이 < 캐릭터·적. 전투 가독성(G2)을 위해 캐릭터 명도 대역은 비워 둔다.
- 재질 라이브러리 정의: 살덩이, 썩은 껍질, 힘줄, 뼈, 마른 피, 뿌리, 독액. 재질마다 albedo 범위·roughness·normal 강도를 표로 정한다.

### 4.3 생성 → 게임 반영 흐름
1. 콘셉트: GPT 이미지(gpt-image-2.5-sunburst), 단일 오브젝트·3/4 시점·중성 회색 배경. 우리 게임 아트만 참조한다.
2. 3D 변환: Meshy image-to-3D(meshy-7.1, PBR on, 2K, GLB). 결과는 3일 안에 삭제되므로 받는 즉시 저장한다.
3. 정리: 스케일(1유닛 = 1px), 바닥 접지 평면, 폴리 감축, LOD0~2, 충돌 없음(표현 전용).
4. 재질: 레이어드 셰이더에 연결하고, 바닥과 닿는 아래쪽 20%는 바닥 재질로 블렌딩한다(접지감).
5. 배치: 맵 데이터에서 자동 배치한다(canMv 경계 거리·외곽 비보행 구역·원본 prop 좌표). 이후 QA 컷에서 수작업으로 보정한다.

### 4.4 조명·대기·움직임
- 구역별 조명 설계(G8): 광원마다 색·반경·깜빡임, 캐릭터 테두리광, 광원 밖 어둠 유지.
- 대기: 높이·거리 안개, 포자 파티클, 광원 주변 산란광(S3에서 볼류메트릭).
- 움직임(G4): 살덩이 맥동(vertex), 뿌리 미세 흔들림, 독액 흐름, 광원 깜빡임. 서로 동기화되지 않게 한다.

### 4.5 생동감 기법 — 평범한 맵을 살아 보이게 만드는 장치 (사용자 참고: 《黄天逆途》 Downfall of Yellowsky 트레일러, 2026-10-26)

최신 쿼터뷰 액션 게임은 지형 자체가 단순해도 아래 장치를 겹쳐 입체감·역동성을 만든다. 우리 생체지옥 버전으로 옮긴다. 메시 품질과 무관하게 지금 바로 적용할 수 있다.

| # | 기법 | 원리 | 생체지옥 적용 |
|---|---|---|---|
| L1 | 바람 정점 셰이더 | 월드 좌표 노이즈 + 인스턴스별 위상 차 + 2단 주파수(큰 흔들림 + 끝의 떨림). 정점 색으로 뿌리=고정, 끝=크게 움직임 | 뿌리 덩굴·촉수·마른 풀·매달린 살막 |
| L2 | 상호작용 흔들림 | 플레이어·적 위치를 셰이더에 넘겨 주변 풀·덩굴이 밀려났다가 돌아옴. 타격 시 짧게 출렁임 | 발밑 촉수 풀·포자 덤불 |
| L3 | 움직이는 그림자(고보) | 화면 밖에 있는 가지·뿌리의 그림자 텍스처를 바닥에 투사해 천천히 흔들고 흐르게 함. 평평한 바닥도 살아 보이는 가장 싼 장치 | 머리 위 거대 뿌리·살막 그림자, 붉은 광원 일렁임 |
| L4 | 공기 중 입자 | 떠다니는 포자·재·불씨, 광원 근처에서만 반짝임. 깊이마다 속도·크기를 다르게 해서 시차를 만듦 | 붉은 포자, 재, 독액 증기 |
| L5 | 전경 프레이밍 | 카메라 가까이에 흐릿한 전경 덩굴·가지가 화면 가장자리를 가리고 천천히 흔들림 → 깊이 3층(전경/전투면/배경) | 화면 테두리 뿌리 커튼. 전투 바닥 가림 3% 이하(기존 원칙) |
| L6 | 2차 애니메이션 | 매달린 것·흐르는 것: 사슬, 살막, 피·독액 방울, 박동하는 혹 | 살덩이 벽 맥동(vertex), 뚝뚝 떨어지는 피, 도랑 독액 흐름 |
| L7 | 빛의 리듬 | 광원 깜빡임·숨쉬기, 캐릭터 테두리광, 광원 밖 어둠 유지(G8) | 붉은 웅덩이 박동, 제단 빛 숨쉬기 |
| L8 | 밀도 있는 작은 산포물 | 풀포기·돌·뼈 조각 등 작은 메시를 맵 데이터 기반 규칙으로 촘촘히 깔아 빛을 받게 함. 크기·회전·색 무작위 | 촉수 풀포기, 뼈 부스러기, 뿌리 싹 |
| L9 | 비동기화 | 모든 움직임의 위상·속도·진폭을 개체마다 다르게(G4). 동시에 움직이면 가짜처럼 보임 | 전 항목 공통 규칙 |

적용 원칙: 전투 가독성(G2)이 먼저다. 움직임은 캐릭터·적·탄막보다 눈에 덜 띄게(채도·대비 낮게) 둔다. 성능은 GPU 인스턴싱과 정점 셰이더 중심으로 하고, 파티클 수에 상한을 둔다.

### 4.6 Moon Studios(Ori → No Rest for the Wicked) 방식에서 배울 것 (2026-10-26 조사)

사용자: "오리부터 맵디자인이 맘에 든다, 완전 카피는 아니고 어떻게 제작하는지 배워라." 공개 인터뷰·포럼 기록 기준이며, 공식 기술 문서로 확인한 내용은 아니다. 에셋·디자인은 복제하지 않고 제작 방식만 가져온다.

| 그들의 방식 | 근거 | 우리 적용 |
|---|---|---|
| 자동 normal 맵 대신 **손으로 칠한 빛 방향 맵**(에셋 약 7천 개에 라이트맵 약 3만 장). 자동 방식은 "싸구려 플라스틱" 느낌이라고 판단 | TheGamer 인터뷰 보도 | 큰 에셋(외곽 벽·랜드마크)은 칠한 빛·그림자 마스크를 텍스처에 넣는다(위쪽 밝음·아래 AO·가장자리 테두리광). 셰이더는 칠한 빛 70% + 동적 조명 30%로 섞어, 조명이 바뀌어도 회화 톤을 유지한다. Meshy PBR 결과는 그대로 쓰지 않고 회화풍으로 한 번 다시 칠한다 |
| 그룹 단위로 빛·그림자를 칠하고, 조명이 바뀌어도 동작 | 아트 리드 인터뷰 | 구역 단위 "빛 칠하기" 레이어(지면·벽에 걸치는 큰 빛 웅덩이·그늘 마스크)를 둔다 |
| 바닥에 **텍스처 하나를 반복해 깔지 않음**. 서로 붙도록 설계한 여러 장으로 이음 없이 구성 | Moon 아티스트 발언 | 지면 기본색은 웹/Godot 원본의 **손그림 청크(64청크)**를 그대로 쓴다. 반복 타일(GPT 바닥)은 세부 질감·normal 보조로만 쓴다. Godot C가 가장 좋아 보인 이유가 바로 이 원본 청크였다 |
| 2D 패럴랙스가 아니라 **실제 3D 공간에 그림 레이어를 배치**하고, 일부 에셋은 깊이용 추가 레이어 | Moon 관계자 포럼 글 | 전경 덩굴 카드·배경 실루엣 카드를 3D 공간에 배치한다(§4.5 L5). 큰 메시 앞뒤로 얇은 그림 카드를 겹쳐 실루엣을 풍부하게 만든다 |
| 반응하는 환경, 동적 조명 | Wccftech 보도 | §4.5 L2·L7 |
| (NRftW 모작 분석) 미드폴리 + 손그림 텍스처 + 셰이더 | 외부 아티스트 재현 프로젝트 | 하이폴리 사실감 대신 40~80k 미드폴리에 큰 형태를 우선하고, 질감은 칠한 텍스처로 낸다 |

결론: 우리가 놓친 핵심은 **"사실적인 PBR + 반복 타일"이 아니라 "칠한 빛 + 고유 손그림 바닥 + 3D 공간의 그림 레이어"**라는 점이다. 이후 슬라이스는 원본 청크 지면부터 되살린다.

## 7. Meshy API 연결 공조

| 항목 | 방식 |
|---|---|
| 키 발급 | 사용자가 https://www.meshy.ai/developers/keys 에서 생성한다(유료 플랜 필요). 이름 `exoduser`, 월 크레딧 상한을 설정한다 |
| PC 등록 | PowerShell `setx MESHY_API_KEY "키"` → 새 터미널에서 적용 |
| Mac 등록 | Codex가 같은 키를 쓰는 경우 `~/.zshrc`에 `export MESHY_API_KEY=...`. 사용자가 직접 넣는다 |
| 보안 | 키는 Git·문서·로그·채팅에 남기지 않는다. 스크립트는 환경변수만 읽고 값을 출력하지 않는다 |
| 호출 주체 | 이중 소비를 막기 위해 M1까지는 PC만 호출한다. Mac 호출은 PC `credits.log`를 공유한 뒤 합의해서 연다 |
| 기록 | `E:/exoduser-wt/_out/meshy/credits.log`(호출마다 작업 ID·모델·크레딧). 마일스톤마다 docs에 요약 |
| 도구 | `meshy_i2m.py` (dry-run 지원, 키 없으면 안내만 하고 종료), 입력 `input/wall_A·B_pad1152.png` |

## 8. 예산 규칙

- GPT 이미지: 장당 약 $0.02. 단위마다 상한(3~7장)을 두고, 상한을 넘으면 보고한다.
- Meshy: meshy-7.1 + 2K 텍스처 = 30크레딧/회. M1 상한은 4회(120크레딧)이다. 같은 에셋이 2회 반려되면 그 에셋은 멈추고 콘셉트부터 다시 본다.

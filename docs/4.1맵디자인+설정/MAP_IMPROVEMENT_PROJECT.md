## 4. 운영 절차 (패스 단위)

1. **백로그에서 선정** — 팀장이 사용자 체감 영향 × 비용으로 다음 패스 결정 (§6 백로그).
2. **브리프** — 에이전트에 목표·품질 게이트·금지사항·검증 방법·커밋 규칙을 명시해 지시. 디자인 판단 기준은 CLAUDE.md §작업물 퀄리티를 그대로 인용.
3. **구현** — main 브랜치(game.html 규칙). 다른 세션 헌크 불간섭, LF/EOL 바이트 검증.
4. **QA** — QA 카메라 위치 전후 스크린샷 + 1x 크롭 + (움직임) 프레임 시퀀스 + 성능 실측.
5. **팀장 판정** — 스크린샷 직접 확인, 게이트별 PASS/RETOUCH. RETOUCH면 같은 패스에서 재지시.
6. **커밋·푸시** — 자기 파일만 경로 지정 커밋, `git push origin main` (force 금지).
7. **문서** — 패스 문서(MAP PRODUCTION REPORT §23) + 이 문서 §6 백로그·§7 결정 기록 + `_MAP_SSOT_INDEX.md` 상단 + `CHANGELOG_SYNC.md`.
8. **데스크톱 데모 빌드** — 사용자 확인용 빌드 동기화(요청 시 또는 마일스톤마다).

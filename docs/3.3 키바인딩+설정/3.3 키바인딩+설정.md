# 3.3 키바인딩 + 설정

## 키보드 이동 / 마우스 방향 분리 (2026-08-08)

- 키보드 WASD·방향키는 플레이어 **위치만** 변경한다.
- 키보드·마우스 입력 모드에서는 마우스 이동 또는 클릭 순간의 조준 방향을 `_mouseFacing`에 저장해 `P.facing`과 공격에 함께 적용한다. WASD는 이 저장값을 바꾸지 않으므로 이동만 담당한다.
- `ghostWalk`를 포함한 키보드 이동 상태에서 `dx/dy`로 `P.facing`을 덮어쓰지 않는다. 이 규칙은 대검전사와 실버테일을 포함한 모든 캐릭터에 공통 적용된다.
- 게임패드만 예외: 좌스틱은 이동과 facing을 함께 관리하고, 우스틱 조준 중에는 우스틱이 facing을 관리한다.

## 기본키 스왑: 칼등 처내기 ↔ 마법 (2026-07-27)

- **shield(칼등 처내기/패링)**: `mouse2`(우클릭) → **`KeyE`** / **beam(마법 탭=투사체·홀드=빔)**: `KeyE` → **`mouse2`(우클릭)**
- 변경 위치: ① `BINDS` 초기값 ② 설정 초기화 기본값(리셋 버튼) ③ 로드 마이그레이션 — 저장값이 **구 기본값 그대로일 때만** (`shield==='mouse2'&&beam==='KeyE'`) 자동 스왑, 사용자가 커스텀했으면 유지
- 패드 UX는 무변경 — 실제 패드는 `_GP_KEY` **키코드 주입** 방식(`GP_BINDS`는 미사용 레거시)이라 주입 코드를 함께 스왑: X버튼 `mouse2→KeyE`(칼등 유지), R3·우스틱 `KeyE→mouse2`(마법 유지), 저장된 `gpKeyMap`도 구 기본값이면 자동 마이그레이션. `_padifyHint` 글리프: '우클릭'(마법)→RS, 'E'(칼등)→Ⓧ. `keyName` 패드표시 mouse2→RS, 스킬바 키캡(`_SK_SLOTS`) kc 스왑(X=KeyE, RS=mouse2). 마법 홀드 해제(`_beamHold`)도 바인드 기반으로 변경(키보드 keyup + mouseup 양쪽)
- 안내문구 일괄 갱신: 게임 내 KO/EN 17종 + 26개 lang 값(각 언어 우클릭 용어→'E'), 스킬 desc('E탭:'→'우클릭 탭:' 등), 조작법 HTML/keyGuide/_hMap/_tkMap/인트로 키가이드/pParry 패시브 desc
- 이유: 시작 직후 탄막 패링(핵심 생존 액션)을 E키로, 마법을 우클릭으로 — 유저 결정 (2026-07-27)

## v7 패드/키마 피드백 분리 (2026-07-05)

키매핑 피드백을 입력모드(`_gpActive`)에 따라 패드/키마로 분리.

### ① 설정 키설정 UI 탭 분리
- `#keyBindList` 상단에 **[⌨ 키보드·마우스] / [🎮 게임패드]** 탭 추가 (`_bindTab` 상태, 기본은 현재 입력모드).
- 선택 탭만 렌더: kbm=키보드 BINDS 리바인딩, pad=`_GP_KEY` 패드버튼 설정.
- `keyName(code, forceKbm)` — `forceKbm=true`면 패드모드여도 **항상 키보드 키명** 표시. 키보드 탭 라벨·패드 탭의 "매핑된 키" 표시에 사용(패드모드에서 키보드 설정이 패드 글리프로 뜨던 혼란 제거).
- `_resetBinds`는 `window` 스코프로 승격(탭 블록 밖 F5 핸들러에서 참조).
- 탭 라벨: `_L('⌨ 키보드·마우스','⌨ Keyboard & Mouse')` / `_L('🎮 게임패드','🎮 Gamepad')` — 번역목록 No.2912/2913.

### ② 힌트 텍스트 패드 인지 — `_padifyHint(txt)`
- 펫 대사·튜토리얼 힌트가 패드모드에서 키보드 키 대신 **패드 글리프** 표시. `_petBubbleShow`의 텍스트 세팅에 적용.
- **렌더타임 치환**(번역키 추가 없음): 텍스트 내 키 토큰을 실제 패드 매핑(`_GP_KEY` 주입) 기준 글리프로 교체.
  - 좌클릭→Ⓐ, 우클릭→RS, Shift/쉬프트→LB, Space/스페이스→Ⓑ, TAB→Select, Q→Ⓨ, E→Ⓧ, K→D↑, G→D↓, J→D←, N→D→, R→L3, Z→RT, F→LT, **X→LT+RT(처형)**. (Right/Left click·RMB/LMB 영문도 커버)
  - `boss_exec` 힌트("…처형해. X.")도 이 치환을 통해 패드모드서 "…처형해. LT+RT."로 표시. `\bX\b`라 "DEX/STR/INT" 오치환 없음.
  - 라틴 단일키는 `\b…\b` 워드바운더리로 한글 조사 앞에서도 안전 치환("K를"→"D↑를"). "탭"은 "더블탭" 오치환 방지로 제외.
- 한계: 마우스 용어의 비영어권 번역은 미커버(KO/EN만). 완전 대응은 토큰 플레이스홀더+재번역 필요(추후).

### 알려진 불일치(추후 정리)
- `keyName` 내부 패드맵 일부가 GP_BINDS와 어긋남(예: `KeyQ`→`RT`로 표기하나 실제 parry=Y). 힌트 피드백은 `_padifyHint`가 자체 정확맵 사용해 영향 없음. HUD/스킬바는 `_SK_SLOTS` 별도맵 사용. keyName 패드맵을 GP_BINDS 단일소스로 정리 필요.

## 키바인딩 (BINDS / BINDS2)
- BINDS: 주요 키 (이동, 공격, 스킬, 인벤, 설정 등)
- BINDS2: 보조 키 (같은 액션의 대체 키)
- 리바인딩 시스템: 설정 화면에서 변경 가능
- **키 설정 초기화**: 키바인딩 목록 하단 "키 설정 초기화" 버튼 클릭, 또는 설정 패널(ESC) 열린 상태에서 **F5 키** → BINDS/BINDS2 전부 기본값 복원 (마우스 클릭 불가 상황 대비)

## 키바인딩 표시명 (BIND_NAMES / BIND_NAMES_EN)
- `BIND_NAMES`: 한국어 표시명 (위로 이동, 무기 공격, 칼등 처내기 등)
- `BIND_NAMES_EN`: 영문 표시명 (Move Up, Weapon Attack, Blade Parry 등)
- `_bindName(key)`: OPT.lang에 따라 한/영 자동 선택 헬퍼 함수
- 설정 화면 키바인딩 목록에서 사용

### 🔗 합체 라인 연결 SVG 오버레이 (2026-04-11)
- `#skillPanel` 내부에 `#skillGridWrap` 래퍼 + `#skillFuseLines` SVG 오버레이 추가 (`position:absolute; pointer-events:none; z-index:5`)

- `renderSkillPanel` 끝에서 `_drawSkillFuseLines()` 호출

**`_drawSkillFuseLines()` 동작 (2026-04-11 개정):**
1. `_skExpandedId` 없으면 SVG 비움
2. **`_canFuse(grp.key)` 통과한 합체 그룹만** 후보 (선행 합체 미완 = 라인 안 그림 → 사용자 혼란 방지)
   - `_allFuseGemGroups(_skExpandedId)`로 모든 그룹 후보 수집
   - `_isFused(g.key)===false && _canFuse(g.key)===true` 필터
   - 폴백: `_fuseGemGroup(_skExpandedId)` 단일 체크
3. 후보 그룹의 `_FUSE_PAIRS[g.key]`에서 펼친 스킬 외 파트너 ID 수집
4. `data-sk-id` 카드 순회 → 펼친 스킬은 소스, 파트너 ID 매칭은 타겟 push (그룹 색상 함께)
5. **박스 가장자리 좌표 계산 (`_edgePoint`)**:
   - 박스 중심에서 타겟 방향으로 박스 경계까지 t값 계산
   - `t = min(hw/|dx|, hh/|dy|)` → 박스 경계 교점 반환
   - 라인이 박스 중심 X, **가장자리에서 시작/종료**
6. 각 타겟마다 베지어 곡선 (`Q midX midY` 컨트롤 위로 휨) 그리기
7. 색상: 합체 그룹 색 (`_grp.color`), 점선 (`stroke-dasharray:6 4`), drop-shadow glow
8. 양 끝 마커: 시작점 5px 그룹 색 원, 끝점 4px 그룹 색 원

**자동 스크롤 (2026-04-11)**:

- `document.querySelector('#skillGrid [data-sk-id="..."]')`로 펼친 카드 찾아 `scrollIntoView({behavior:'smooth',block:'center',inline:'nearest'})` 호출
- 클릭한 스킬이 카드 펼침 후 즉시 화면 중앙으로 스크롤되어 사용자 시야에 들어옴

**선행 합체 시퀀스 예**:
- 악의사냥(maliceHunt) 펼침 → `bladeFuse`(악의보호자) 합체 가능 → 라인 1개

### 합체 선택 모드 (`_skExpandedId` 기반 페이드)
스킬 아이콘 클릭으로 `_skExpandedId`가 설정되면 (상세 펼침 모드 트리거) 해당 스킬과 합체 가능한 스킬만 강조, 나머지는 페이드 처리:
- **펼친 스킬 본인** (`_skExpandedId === sk.id`): 다른 분기로 이동 → 카테고리 컬럼 안에서 디아블로식 상세 카드 렌더
- **합체 가능 파트너** (같은 `_fuseGemGroup` or `_FUSE_PAIRS` 매칭): outline 2px dashed `_fGrp.color` + box-shadow 16px 그룹 색상
- **그 외 모든 스킬**: `opacity:0.15; filter:grayscale(1) brightness(0.4); pointer-events:none` → 회색/거의 사라짐
- 합체 가능 판정: `_selGrp.key === _fGrp.key` OR `_FUSE_PAIRS[_selGrp.key]?.includes(sk.id)` OR `_FUSE_PAIRS[_fGrp.key]?.includes(_skExpandedId)`
- 펼친 카드의 ✕ 닫기 → `_skExpandedId=null` (선택 해제, 모두 정상 표시)
- 패널 닫기 → `closeAllPanels` → `_skExpandedId=null`

### 펼친 상세보기 (디아블로식 D2/D3 스타일)

  2. **데미지** (학습 시): 기본 참조뎀(meleeRef/bowRef/magicRef) / 스탯 배율 / 패시브 배율 / 레벨 배율 / 예상 평균뎀

### 🔄 펼침 모드는 기존 기능 fall-through (2026-04-11)
- 펼친 상세보기 카드는 디아블로식 디테일 + +/- 버튼 + **기존 모든 기능을 같은 카드에 fall-through**
- 펼침 모드 분기 끝에서 `return`을 제거 → `_renderSkillRow`의 다음 로직이 펼침 카드 `d`에 그대로 append됨:
  - **클릭 합체 시스템** (`_hasGem` 블록): 합체 그룹 버튼들 + `_fuseSelId` 클릭 토글 + 파트너 선택 → 합체 발동
  - **슬롯 배정 버튼** (1/2/3/4/SP/F): 액티브 스킬을 단축키 슬롯에 배정/해제
  - **리셋 버튼** (🔄 리셋): 합체 그룹 자동 탐색 → 그룹 전체 리셋
  - **드래그 시스템**: 마우스 드래그로 슬롯 재배치

### + / - 버튼 (학습/강화/취소/레벨다운/합체해제)
펼친 상세보기 하단에 두 개의 버튼이 나타남:

| 버튼 | 조건 (우선순위) | 동작 |
|---|---|---|
| **+ 습득** | 미습득 + canLearn | `_skClick()` — **SP/악의 선검증**(부족 시 `자원 부족!` 후 중단) → `P.skills[sk.id]=1`, SP/악의 차감, 슬롯 자동 배정 |
| **+ 레벨업** | 학습됨 + canUp | `_skClick()` — **SP/악의 선검증**(부족 시 `자원 부족!` 후 중단) → `P.skills[sk.id]++`, SP/악의 차감 |
| **− 합체 해제** | 학습 + 합체 완료 (`_isFused(_fGrp.key)===true`) | `_unfuseAll()` — 해당 스킬이 속한 모든 `P._fused[fk]` 삭제, 합체 강화 누적 SP 복구 추정 환불 (`_fuseUpSpCost`) |
| **− 레벨** | 학습 + slv>1 | `_skUnclick()` — `P.skills[sk.id]--`, 직전 강화 비용(`_skillUpSpCost(slv-1)`) **환불**, `sk.upMat` 환불 |
| **− 리셋** | 학습 + slv===1 | `_skUnclick()` — `delete P.skills[sk.id]`, **학습 비용 전액 환불** (`sk.spCost` + `sk.matCost`), 모든 슬롯에서 자동 해제 (LMB/charge/bow/magic/Q/tech/ULT) |

- 우선순위: **합체 해제 > 레벨다운 > 리셋** (합체 상태가 가장 먼저 풀림)
- 환불 시 `SFX.pickup()` + `addTxt(...) '합체 해제 (+NSP)' / 'Lv.X (-)' / '리셋!'` 알림
- 패널 닫기 시 `_skExpandedId=null` 리셋 (`closeAllPanels`)
- `_unfuseAll` 헬퍼: `P._fused`를 순회하며 해당 스킬이 `_FUSE_PAIRS[fk]` 또는 `_FUSE_GEM_GROUPS[fk].skills`에 포함되면 `delete P._fused[fk]` + 누적 강화 SP 추정 환불
- **전역 상태**: `_skExpandedId` (한 번에 하나만 펼침)
- **코드 위치**: game.html `_skDetailHTML`/`_skSpecificDetails` (라인 ~28049), `_renderSkillRow` (라인 ~29097), `_skUnclick` (라인 ~29503 인라인), `_skClick` (라인 ~29720)

### UI 고정 디자인 시스템 (2026-04-17 개정)

**Reference Resolution**: 1920×1080
**스케일 방식**: Match Shortest Side (가로/세로 중 작은 쪽 기준)
**최종 스케일**: `--ui-scale = var(--ui-auto-scale)` (사용자 배율 제거, 순수 자동)

#### CSS 변수 (`:root`)
- `--ui-auto-scale`: 창 크기 기반 자동 배율, JS가 `applyUIScale()` 에서 주입
- `--ui-scale`: `var(--ui-auto-scale)` 의 alias (기존 스타일 참조 호환용)
- `--icon-sm / --icon-md / --icon-lg`: `calc(32|48|64 px * var(--ui-scale))`

#### JS 공식
```js
function applyUIScale(){
  const dw=1920, dh=1080;
  const autoScale = Math.min(innerWidth/dw, innerHeight/dh);
  const clampedAuto = Math.max(0.5, Math.min(3.0, autoScale));  // 극단 방어
  document.documentElement.style.setProperty('--ui-auto-scale', clampedAuto.toFixed(4));
}
window.addEventListener('resize', applyUIScale);
```

#### 왜 Match Shortest Side?
- FromSoft · Hades · Hollow Knight 등 인디/AAA 표준
- 21:9 울트라와이드 → 세로 기준으로 묶여서 UI는 중앙 고정, 맵만 가로 확장
- HUD는 겹침/잘림 없이 항상 기준 해상도 비율 유지

#### 시나리오별 결과
| 창 | --ui-auto-scale | 비고 |
|---|---|---|
| 1920×1080 | 1.000 | 기준 |
| 2560×1080 (21:9) | 1.000 (세로 기준) | UI 중앙 고정, 맵만 가로 확장 |
| 3840×2160 (4K) | 2.000 | 2배 선명 |
| 1366×768 | 0.711 | 축소 |

#### 적용 범위
- CSS `--ui-scale` 영향: `.hp-globe / .mp-globe / #skBar / .hud-top / #mmWrap / #bossBar / #mmLvl` 및 `--icon-sm/md/lg`
- Canvas/WebGL2 렌더러는 UI 스케일과 무관 — 월드 해상도는 DPR + `resScale` 관할
- `applyUIScale()` 호출 지점: 함수 정의 직후(초기 1회) / window resize

### 해상도 스케일 (`OPT.resScale`) — 줌+해상도 결합형 (구조 정리 2026-06-16)

월드 캔버스 백킹 해상도 배율. UI(`--ui-scale`)와 무관, 캔버스/WebGL2 렌더러만 영향.

- **공식** (`rz()`): 논리 시야 `VW/VH = innerWidth/innerHeight × (resScale/100)`. DPR을 시야에 곱하지 않음 (곱하면 고해상도에서 줌아웃 + 남쪽 스폰 시 캐릭터가 화면 하단으로 밀림). 2026-08-17.
- 카메라는 맵 가장자리에서도 **캐릭터 화면 중앙**. 바깥은 검정.
- **슬라이더 범위**: `min=50 max=100 step=10` (id=`optResScale`, game.html:2433) — 기본 100%, **상한 100% (의도된 제약)**
- **⚠️ 이 엔진에서 resScale은 순수 SSAA(선명도)가 아니라 "줌"이다**:
  - 스프라이트는 `C.width/2 + (e.x - cam.x)` 위치에 **월드 크기 그대로** 그려짐 (game.html:4239) → **1 월드유닛 = 1 백킹픽셀**
  - 화면 표시 월드 영역 = `C.width` 월드유닛 = `innerWidth × dpr × resScale`
  - 따라서 resScale↑ = **줌아웃(월드 더 넓게 보임) + 픽셀수↑**, resScale↓ = 줌인 + 픽셀수↓. 해상도와 줌이 물리적으로 결합됨
- **100% 초과 금지 이유**: resScale>100 → `C.width`가 맵 픽셀폭 `_mwPx`보다 커지면 카메라 클램프(game.html:27358 `if(_mwPx<=C.width){G.cam.x=_mwPx/2}`)가 **카메라를 맵 중앙에 고정** → 플레이어가 화면 밖으로. 작은 맵/보스방에서 즉시 발생. (2026-06-16 200% 실험 → 카메라 추적 깨짐 확인 후 100% 복원)
- **DPR 고정 (2026-06-16, game.html:3791)**: 과거엔 `_dpr=min(devicePixelRatio,1.5)`라 같은 게임도 100% 배율 모니터(DPR 1.0)와 125% 모니터(DPR 1.25)에서 보이는 월드 범위·줌·선명도가 달랐음 (DPR이 resScale처럼 `C.width`에 곱해지므로). 코드 차이 아닌 **모니터 Windows 배율 차이**였으나 혼란을 유발 → 데스크탑은 **`_dpr=1.25` 고정**으로 통일. 어떤 모니터 배율에서도 동일 화면비·줌·선명도. 추가 증상이던 "시작 화면이 로컬은 우측 쏠림 / 웹은 중앙"도 동일 원인(캔버스폭 차이가 카메라 클램프 27358 분기를 다르게 탐)이라 함께 해소. Mac은 Retina 성능 위해 `min(dpr,1.0)` 유지
- **순수 SSAA(줌 불변 슈퍼샘플링)는 별도 `OPT.ssaa` 옵션으로 구현 완료** (2026-06-29, 아래 SSAA 섹션 참조). resScale은 줌, ssaa는 선명도로 역할 분리됨
- **적용**: `optResScale.oninput`(game.html:38659) → `OPT.resScale` 갱신 → `rz()` → `saveSettings()`. origin별 localStorage(`hellcave_settings`) 저장

### SSAA 슈퍼샘플링 (`OPT.ssaa`) — 줌 불변 선명도 (2026-06-29 구현)

resScale(줌+해상도 결합)과 **독립된 순수 슈퍼샘플링**. 논리 시야(VW/VH)는 고정하고 백킹 픽셀만 Nx로 키워 다운샘플 → 줌 변화 없이 선명도만 상승.

- **옵션 값**: `1`(끄기/1x) / `1.5` / `2` — UI 셀렉트 `id=optSsaa`(game.html:2438), 기본 `1`
- **좌표계 분리** (game.html:3750~):
  - **논리 좌표** `VW/VH = rw/rh` (ss 미포함) — 게임 로직·컬링·UI 기준
  - **백킹 픽셀** `bw/bh = (VW×ss)&~1 / (VH×ss)&~1` — 메인 캔버스 `C.width/height`(GPU 백킹). `&~1`로 짝수 정렬
  - `ss=1`이면 `bw===rw`로 기존과 **완전 동일(회귀 0)**
- **월드 변환** `_xWorld()`(game.html:3761): `X.setTransform(ss,0,0,ss,(VW/2-cam.x)×ss,(VH/2-cam.y)×ss)`. draw() 진입부(game.html:40985)에서 `if(_ssaa!==1)X.scale(_ssaa,_ssaa)` → **이후 모든 월드 렌더는 논리좌표(it.x,it.y) 그대로 → 자동 ss배 백킹 확대**
- **오버레이 캔버스**: `CT`(텍스트), `burstCvs`는 논리(VW/VH) 유지 — UI는 SSAA 불필요
- **Three.js 보스 3D 오버레이**: 백킹 크기(VW×ss) 기준이라 프러스텀 계산 시 `((world-cam)+VW/2)×ss` 보정 (game.html:51761, 52030). 옵션 변경 시 `resize` 이벤트 디스패치로 동기화
- **적용 핸들러**: `optSsaa.onchange`(game.html:38908) → `OPT.ssaa` 갱신 → `_lastRw=_lastRh=-1` 강제 + `rz()` + 블룸/횃불/안개/조명 캐시 무효화 → `saveSettings()`
- **영속화**: `OPT.ssaa`는 `saveSettings()`(전체 OPT 직렬화)·`loadSettings()`(`for k in data.opt`)로 자동 저장/복원
- **산소방울(o2bubble) 렌더 경로 수정 (2026-06-29)**: 기존엔 `update()` 루프에서 백킹좌표(`C.width/2` 오프셋, 변환 없음)로 직접 그려 → draw()의 `clearRect`로 매 프레임 덮여 사실상 미표시 + SSAA 미적용 상태였음. → draw()의 worldItems 렌더 루프(game.html:41604)로 이동, 다른 월드아이템과 동일하게 월드좌표(it.x,it.y)로 그려 `_ssaa` 변환 자동 적용. update()측 죽은 렌더 제거

## 포커스 상실 시 입력 해제 — stuck-key 방지 (2026-08-18)

- **문제**: 키 held 상태(`KH`/`K`)는 오직 `keyup`에서만 해제된다. 홀드 중 창 포커스가 빠지면(alt-tab, OS 알림, 다른 창/모니터 클릭, 개발자도구 클릭 등) 브라우저가 **`keyup`을 전달하지 않아** 해당 키가 눌린 채로 잔류한다.
- **증상**: `KH['ShiftLeft']`(돌진=charge)가 잔류하면 사슬돌진 착지마다 **티어3 자동 재발사**(`if(KH['ShiftLeft']&&…)` 홀드 연속발사 로직)가 무한 반복 → "입력 안 했는데 쉬프트가 자동으로 자꾸 나감". Space/이동키/마우스 홀드(빔)도 동일 계열.
- **수정**: 전역 `blur` + `visibilitychange`(`document.hidden`일 때만) 핸들러 `_clearHeldInput()` 추가 — `K`/`KH`/`MB`/`MBjust` 전부 false, `_dashHold/_dashHoldF/_dashTier` 리셋(홀드 무장 해제), `P._beamHold`·`_cutSkipHolding/_cutSkipHold` 해제. 위치: `keyup` 리스너 직후.
- **불변**: 밸런스·조작 설계 무변경. 포커스 복귀 후 재입력(fresh `keydown`)은 정상 재무장 → 일반 돌진/이동 정상 작동. `visibilitychange`는 **hidden일 때만** 해제(표시 상태에선 held 유지). 게임패드는 매 프레임 폴링(level-triggered)이라 자기보정 → 미간섭.
- 브라우저 게임 표준 안전망(모든 상용 웹게임이 blur 시 입력 초기화). 검증: repro(Shift keydown→blur→KH 잔류=버그) → fix 후 KH 해제·auto-refire 무장해제, 이동키 held 정상 유지, 스테이지전환3회·pageerror0.

### ② 힌트 텍스트 패드 인지 — `_padifyHint(txt)`
- 펫 대사·튜토리얼 힌트가 패드모드에서 키보드 키 대신 **패드 글리프** 표시. `_petBubbleShow`의 텍스트 세팅에 적용.
- **렌더타임 치환**(번역키 추가 없음): 텍스트 내 키 토큰을 실제 패드 매핑(`_GP_KEY` 주입) 기준 글리프로 교체.
  - 기본 매핑 기준: 좌클릭→Ⓐ, 우클릭→RS, Shift/쉬프트→LB, Space/스페이스→Ⓑ, TAB→Select, Q→Ⓨ, E→Ⓧ, K→D↑, G→D↓, J→D←, N→D→, R→L3, Z→RT, F→LT, **X→LT+RT(처형)**. (Right/Left click·RMB/LMB 영문도 커버)
  - `boss_exec` 힌트("…처형해. X.")도 이 치환을 통해 패드모드서 "…처형해. LT+RT."로 표시. `\bX\b`라 "DEX/STR/INT" 오치환 없음.
  - 라틴 단일키는 `\b…\b` 워드바운더리로 한글 조사 앞에서도 안전 치환("K를"→"D↑를"). "탭"은 "더블탭" 오치환 방지로 제외.
- 한계: 마우스 용어의 비영어권 번역은 미커버(KO/EN만). 완전 대응은 토큰 플레이스홀더+재번역 필요(추후).

### + / - 버튼 (학습/강화/취소/레벨다운/합체해제)
펼친 상세보기 하단에 두 개의 버튼이 나타남:

| 버튼 | 조건 (우선순위) | 동작 |
|---|---|---|
| **+ 습득** | 미습득 + canLearn | `_skClick()` — **SP/악의 선검증**(부족 시 `자원 부족!` 후 중단) → `P.skills[sk.id]=1`, SP/악의 차감, 슬롯 자동 배정 |
| **+ 레벨업** | 학습됨 + canUp | `_skClick()` — **SP/악의 선검증**(부족 시 `자원 부족!` 후 중단) → `P.skills[sk.id]++`, SP/악의 차감 |
| **− 합체 해제** | 학습 + 합체 완료 (`_isFused(_fGrp.key)===true`) | `_unfuseAll()` — 해당 스킬이 속한 모든 `P._fused[fk]` 삭제, 합체 강화 누적 SP 복구 추정 환불 (`_fuseUpSpCost`) |
| **− 레벨** | 학습 + slv>1 | `_skUnclick()` — `P.skills[sk.id]--`, 직전 강화 비용(`_skillUpSpCost(slv-1)`) **환불**, 실제 악의 차감액 `_malCost(sk.upMat||0)` 환불 |
| **− 리셋** | 학습 + slv===1 | `_skUnclick()` — `delete P.skills[sk.id]`, **학습 비용 전액 환불** (`sk.spCost` + `sk.matCost`), 모든 슬롯에서 자동 해제 (LMB/charge/bow/magic/Q/tech/ULT) |

- 우선순위: **합체 해제 > 레벨다운 > 리셋** (합체 상태가 가장 먼저 풀림)
- 환불 시 `SFX.pickup()` + `addTxt(...) '합체 해제 (+NSP)' / 'Lv.X (-)' / '리셋!'` 알림
- 패널 닫기 시 `_skExpandedId=null` 리셋 (`closeAllPanels`)
- `_unfuseAll` 헬퍼: `P._fused`를 순회하며 해당 스킬이 `_FUSE_PAIRS[fk]` 또는 `_FUSE_GEM_GROUPS[fk].skills`에 포함되면 `delete P._fused[fk]` + 누적 강화 SP 추정 환불
- **전역 상태**: `_skExpandedId` (한 번에 하나만 펼침)
- **코드 위치**: game.html `_skDetailHTML`/`_skSpecificDetails` (라인 ~28049), `_renderSkillRow` (라인 ~29097), `_skUnclick` (라인 ~29503 인라인), `_skClick` (라인 ~29720)
- **아이콘 폴더**: `img/skillskin_upscaled/` (50+ 스킬 PNG, kiSlash/whirlwind/fireball 등 skill.id 매칭)

## 플레이어 지면 쌍 포탈 입력 (프로토타입, 2026-09-23)
- P는 현재 키 설정 목록과 저장형 `BINDS` 항목에 추가되지 않은 임시 포탈 배치 입력이다. 첫 입력으로 A, 다음 입력으로 B를 설치하며 기존 쌍에서 P를 다시 누르면 새 A부터 시작한다.

### UI 고정 디자인 시스템 (2026-09-29 창 크기 적응 보정)

**Reference Resolution**: 1920×1080
**스케일 방식**: Match Shortest Side (가로/세로 중 작은 쪽 기준)
**최종 스케일**: `--ui-scale = var(--ui-auto-scale)` (사용자 배율 제거, 순수 자동)

#### CSS 변수 (`:root`)
- `--ui-auto-scale`: 창 크기 기반 자동 배율, JS가 `applyUIScale()` 에서 주입
- `--ui-scale`: `var(--ui-auto-scale)` 의 alias (기존 스타일 참조 호환용)
- `--icon-sm / --icon-md / --icon-lg`: `calc(32|48|64 px * var(--ui-scale))`

#### JS 공식
```js
function applyUIScale(){
  const dw=1920, dh=1080;
  const autoScale = Math.min(innerWidth/dw, innerHeight/dh);
  if(!Number.isFinite(autoScale)||autoScale<=0)return;
  document.documentElement.style.setProperty('--ui-auto-scale', autoScale.toFixed(4));
}
window.addEventListener('resize', applyUIScale);
```

**현행 방어**: 0.5~3.0 고정 상하한을 제거했다. 유한한 양수 배율을 그대로 반영하며, 0/음수/NaN/무한 배율이면 직전 CSS 값을 유지한다. `toFixed(4)` 반올림은 유지한다. 이전 상한은 11252×5048 CSS viewport에서 필요한 4.6741을 3으로 잘라 HUD를 작게 만들었다. 페이지 줌 변화에 따라 CSS viewport가 달라져도 HUD의 화면 비율은 자동 유지한다. 브라우저 설정을 변경하거나 `devicePixelRatio`를 HUD 배율에 곱하지 않는다.

#### 왜 Match Shortest Side?
- FromSoft · Hades · Hollow Knight 등 인디/AAA 표준
- 21:9 울트라와이드 → 세로 기준으로 묶여서 UI는 중앙 고정, 맵만 가로 확장
- HUD는 겹침/잘림 없이 항상 기준 해상도 비율 유지

#### 시나리오별 결과

| 1920×1080 | 1.000 | 기준 |
| 2560×1080 (21:9) | 1.000 (세로 기준) | UI 중앙 고정, 맵만 가로 확장 |

#### 적용 범위
- CSS `--ui-scale` 영향: `.hp-globe / .mp-globe / #skBar / .hud-top / #mmWrap / #bossBar / #mmLvl` 및 `--icon-sm/md/lg`
- Canvas/WebGL2 렌더러는 UI 스케일과 무관 — 월드 해상도는 DPR + `resScale` 관할
- `applyUIScale()` 호출 지점: 함수 정의 직후(초기 1회) / window resize
- HUD 여백도 같은 배율로 조정한다. 기본 inset 위/오른쪽/아래 `10px×scale`; 미니맵 위/왼쪽 `8px×scale`; 시계 위 `17px×scale`와 기준 폭170px; 상태 위 `16px×scale`·오른쪽 `20px×scale`; 자원 위 `188px×scale`·왼쪽 `16px×scale`; 하단 스킬바 bottom `-15px×scale`. 실제 safe-area inset은 추가로 그대로 적용한다. 전체 계약은 [HUD 창 크기 적응](../3.1 ui hud 디자인/UI_SCALING_20260929.md)에 기록한다.

- 보스 HP 기준 폭500px·포이즈140px에 자동 배율을 적용하며 max-width600px의300px/80vw 재축소는 제거했다. 상단 HUD의 해당 미디어 쿼리도 중앙 앵커를 유지한다.

### 해상도 스케일 (`OPT.resScale`) — 줌+해상도 결합형 (구조 정리 2026-06-16)

월드 캔버스 백킹 해상도 배율. UI(`--ui-scale`)와 무관, 캔버스/WebGL2 렌더러만 영향.

- **공식** (`rz()`): 논리 시야 `VW/VH = innerWidth/innerHeight × (resScale/100)`. DPR을 시야에 곱하지 않음 (곱하면 고해상도에서 줌아웃 + 남쪽 스폰 시 캐릭터가 화면 하단으로 밀림). 2026-08-17.
- 카메라는 맵 가장자리에서도 **캐릭터 화면 중앙**. 바깥은 검정.
- **슬라이더 범위**: `min=50 max=100 step=10` (id=`optResScale`, game.html:2433) — 기본 100%, **상한 100% (의도된 제약)**
- **⚠️ 이 엔진에서 resScale은 순수 SSAA(선명도)가 아니라 "줌"이다**:
  - 스프라이트는 `C.width/2 + (e.x - cam.x)` 위치에 **월드 크기 그대로** 그려짐 (game.html:4239) → **1 월드유닛 = 1 백킹픽셀**
  - 화면 표시 월드 영역 = `C.width` 월드유닛 = `VW` (현행 DPR1: `innerWidth × resScale/100`, 짝수 픽셀 정렬)
  - 따라서 resScale↑ = **줌아웃(월드 더 넓게 보임) + 픽셀수↑**, resScale↓ = 줌인 + 픽셀수↓. 해상도와 줌이 물리적으로 결합됨
- **100% 초과 금지 이유**: resScale>100 → `C.width`가 맵 픽셀폭 `_mwPx`보다 커지면 카메라 클램프(game.html:27358 `if(_mwPx<=C.width){G.cam.x=_mwPx/2}`)가 **카메라를 맵 중앙에 고정** → 플레이어가 화면 밖으로. 작은 맵/보스방에서 즉시 발생. (2026-06-16 200% 실험 → 카메라 추적 깨짐 확인 후 100% 복원)
- **DPR 논리 시야 고정 (현행, 2026-09-24)**: `_dpr=1`, `_ssaa=1`을 일반 게임과 `mapqa=1`에 공통 적용한다. 창 크기 또는 `_renderRes`에 `OPT.resScale/100`을 곱해 짝수 픽셀로 정렬한 `VW/VH`가 메인 캔버스 백킹과 같다. DPR2/창1920×1080/100%는 logical=backing=1920×1080이며 CSS는 창 크기를 유지한다.
- **순수 SSAA(줌 불변 슈퍼샘플링)는 별도 `OPT.ssaa` 옵션으로 구현 완료** (2026-06-29, 아래 SSAA 섹션 참조). resScale은 줌, ssaa는 선명도로 역할 분리됨
- **적용**: `optResScale.oninput`(game.html:38659) → `OPT.resScale` 갱신 → `rz()` → `saveSettings()`. origin별 localStorage(`hellcave_settings`) 저장

### SSAA 슈퍼샘플링 — 테스트맵 HiDPI 전용 현행 계약

resScale(줌+해상도 결합)과 **독립된 순수 슈퍼샘플링**이다. 논리 시야(VW/VH)는 고정하고 백킹 픽셀만 Nx로 키워 다운샘플하므로 줌 변화 없이 선명도만 상승한다.

- **현행 적용 범위**: 일반 게임과 mapqa 모두 `_ssaa=1`. 레거시 `OPT.ssaa`는 호환용이며 `rz()` 렌더 배율을 바꾸지 않는다. 이전 QA 전용 DPR 최대2x는 2026-09-24 사용자 지시로 폐기했다.
- **좌표계 분리** (game.html:3750~):
  - **논리 좌표** `VW/VH = rw/rh` (ss 미포함) — 게임 로직·컬링·UI 기준
  - **백킹 픽셀** `bw/bh = (VW×ss)&~1 / (VH×ss)&~1` — 메인 캔버스 `C.width/height`(GPU 백킹). `&~1`로 짝수 정렬
  - `ss=1`이면 `bw===rw`로 기존과 **완전 동일(회귀 0)**
- **월드 변환** `_xWorld()`(game.html:3761): `X.setTransform(ss,0,0,ss,(VW/2-cam.x)×ss,(VH/2-cam.y)×ss)`. draw() 진입부(game.html:40985)에서 `if(_ssaa!==1)X.scale(_ssaa,_ssaa)` → **이후 모든 월드 렌더는 논리좌표(it.x,it.y) 그대로 → 자동 ss배 백킹 확대**
- **오버레이 캔버스**: `CT`(텍스트), `burstCvs`는 논리(VW/VH) 유지 — UI는 SSAA 불필요
- **Three.js 보스 3D 오버레이**: 백킹 크기(VW×ss) 기준이라 프러스텀 계산 시 `((world-cam)+VW/2)×ss` 보정 (game.html:51761, 52030). 옵션 변경 시 `resize` 이벤트 디스패치로 동기화
- **CSS 크기 계약**: 백킹 변경 후에도 `C.style.width/height`는 logical CSS 크기다. `_lastCssW/H`는 실제 style 적용 뒤에만 기록해 DPR 2에서 캔버스가 3840×2160 CSS로 확대되는 것을 방지한다.
- **산소방울(o2bubble) 렌더 경로 수정 (2026-06-29)**: 기존엔 `update()` 루프에서 백킹좌표(`C.width/2` 오프셋, 변환 없음)로 직접 그려 → draw()의 `clearRect`로 매 프레임 덮여 사실상 미표시 + SSAA 미적용 상태였음. → draw()의 worldItems 렌더 루프(game.html:41604)로 이동, 다른 월드아이템과 동일하게 월드좌표(it.x,it.y)로 그려 `_ssaa` 변환 자동 적용. update()측 죽은 렌더 제거

## 하드웨어 Tier 프리셋 (자동 감지)
데스크톱 브라우저는 GPU 모델 점수(S=4/A=3/B=2/C=1)와 연속 120프레임의 FPS 점수 중 낮은 값을 택한다. FPS 점수는 `120 이상=4`, `80 이상=3`, `45 이상=2`, `45 미만=1`이다. 첫 프레임을 제외한 119개 간격의 평균으로 FPS를 계산한다. 탭이 숨겨지면 부분 표본을 버리고, 보이는 탭에서도 프레임 간격이 `250ms`를 넘으면 측정이 중단된 것으로 보고 부분 표본을 버린 뒤 연속 표본을 다시 모은다. `250ms` 이하의 지속적인 저속 프레임은 유효하게 집계한다. Electron은 A, 모바일은 C로 벤치를 건너뛰며 빈 표본의 FPS 표시는 `벤치 미실시`(영문 `Benchmark skipped`)다. 데스크톱 브라우저에서 자동 프리셋은 저장 설정이 없는 첫 실행에만 적용하고, 저장 설정이 있으면 진단 표시만 갱신한다. 모바일의 `detectTier()`는 호출 시 C 프리셋을 즉시 적용한다.

| Tier | GPU/FPS 결합 점수 | 자동 프리셋 (`true`가 아닌 옵션은 `false`) |
|---|---|---|
| S | 4 | bloom/trail/slash/postfx/deathFx/lighting/torch/ambPart/fog/grain=true, parts=100, atmos=2 |
| A | 3 | S와 같은 효과, parts=80, atmos=2 |

- 조준 모드에서 A=발동(좌클릭), B=취소(우클릭), 기존 키 주입 차단
- `isAct('up')` 등에서 키보드/게임패드 동시 체크

### 진동 피드백 (Gamepad Haptics API)
- `shake(n)` 호출 시 자동 발동 — `_gpVibrate(intensity, durMs)`
- 일반 dual-rumble: t=min(intensity/30,1), weak=min(1,t×0.7), strong=min(1,t). durMs 지정값 우선; 미지정 지속시간 max(80,min(800,intensity×12))ms, 미지정 호출만 60ms 쿨다운. 컷신 별도 호출은 아래 source37 계약 참조.
- 지옥강타 1(60), 기동파괴(60), 대형 폭발(30~50), 일반 타격(4~8) 등 자동 적용

### 통합 구조
- `GP_BINDS` 객체: 버튼 인덱스 → 액션명 매핑
- `_gpAct(action)` / `_gpJust(action)`: 게임패드 버튼 상태 체크
- `isAct()` / `isJust()` / `isHeld()` 함수에 `||_gpAct()` / `||_gpJust()` 추가
- 기존 키보드/마우스 입력과 완전 병렬 — 게임패드+키보드 동시 사용 가능

### 코드 위치
- `GP_BINDS`, `_pollGamepad()`, `_gpAct()`, `_gpJust()`: game.html `isAct` 바로 위
- `_pollGamepad()` 호출: `loop()` 함수 매 프레임 시작부

## 0. 간헐 단절 (됐다 안 됐다) — 2026-07-05 코드 수정으로 해결

**증상**: 블루투스 Xbox 패드가 절전→엑스박스 버튼으로 깨울 때 **재연결이 될 때도 있고 안 될 때도 있음**. 로비에서는 되는데 게임(game.html)에서만 죽는 패턴.

**원인 (game.html 버그 2건, 2026-07-05 수정 완료)**:

| # | 버그 | 수정 |
|---|------|------|
| 1 | `_pollGamepad()`이 `if(!_gpConnected)return`으로 **`gamepadconnected` 이벤트에만 의존**. BT 재연결 시 크로미움이 이벤트를 안 쏘는 경우(페이지 비포커스 중 재연결 등) `_gpConnected=false`로 고정 → 리로드 전까지 패드 영구 사망. index.html은 무조건 폴링이라 로비만 멀쩡했음 | 이벤트 의존 제거 — 매 프레임 `getGamepads()` 직접 폴링으로 연결 감지 (`[GAMEPAD] 폴링 감지:` 로그). index.html과 동일 방식 |
| 2 | 패드 연결이 끊길 때(`gamepaddisconnected` / 폴링상 소실) **주입해둔 키를 해제 안 함** → 스틱으로 이동 중 BT 블립이 오면 `K['KeyW']` 등이 눌린 채 방치 = 캐릭터가 혼자 계속 걸음 | 단절 시 `_gpClearAll()` 즉시 호출 (이벤트 핸들러 + 폴링 소실 경로 양쪽) |

**추가 동작**: 폴링상 패드 소실 시(BT 블립/절전) `_gpActive`(패드모드)는 유지 → 재연결하면 패드모드 그대로 복귀. `gamepaddisconnected` 이벤트가 온 경우에만 KBM 모드로 전환.

**환경 요인 (코드 외)**: Xbox BT 패드는 ~15분 무입력 시 절전. 깨운 직후 재연결까지 수 초 걸리며, 이 동안 버튼 입력은 유실됨. 2.4GHz 간섭(USB3 허브·와이파이)도 블립 원인.

**크롬 한정 간헐 미인식 (2026-07-05 재발 사례)**: 같은 페이지가 엣지에서는 되는데 크롬에서만 됐다 안 됐다 반복 — 크로미움 버전 차이로 인한 크롬의 BT 패드 디바이스 레이어 문제로, **게임 코드에서 해결 불가**. 대응:
1. **유선(USB-C) 연결이 근본 해결** — BT 절전/재연결 문제 자체가 사라짐
2. 크롬이 패드를 놓치면: 페이지 새로고침 → 안 되면 크롬 완전 재시작 (트레이 프로세스 포함)
3. 개발 테스트는 엣지 또는 NW.js exe 권장 (사용자 환경에서 안정 확인됨)

**패드 상태 가시화 (2026-07-05 추가)**: 연결/재연결 시 `🎮 패드 연결됨`, 단절 시 `🎮 패드 연결 끊김` 토스트(notify) 표시 — 폴링 감지·이벤트 양쪽 경로 모두, `_gpConnected` 상태 전이 시에만 1회. 번역 26개 언어 전파 완료 (번역대상 목록 No.2906~2907).

## 1. 결론 (실사례 원인)

- **게임 코드 문제 아니었음.** game.html / index.html 게임패드 파이프라인 전 구간 정상 확인.
- 같은 코드가 엣지에서는 동작 = 크롬 브라우저 레벨에서 패드 디바이스를 못 잡고 있던 상태.
- **크롬 완전 재시작(트레이 프로세스 포함) 후 해결.** 정확한 트리거는 특정 불가하나 아래 중 하나:
  - 업데이트 대기 중인 구버전 크롬 프로세스가 백그라운드에 잔류
  - 버튼 미입력 상태로 스틱만 움직여 패드가 노출 안 됨 (아래 §2)
  - 블루투스 재연결 후 크롬이 디바이스를 다시 안 잡음

## 2. 크로미움 Gamepad API 필수 조건 (엣지/크롬/NW.js 공통)

| 조건 | 내용 |
|------|------|
| **버튼 1회 입력 필수** | `getGamepads()`는 **버튼을 한 번 눌러야** 패드를 노출. **스틱만 움직이면 절대 인식 안 됨** |
| **창 포커스 필수** | 포커스 잃은 창에는 게임패드 입력이 전달 안 됨 |
| `gamepadconnected` | 물리 연결 시점이 아니라 **첫 버튼 입력 시** 발화 |

## 3. 안 될 때 확인 순서

1. **진단 페이지**: `http://localhost:3333/_gamepad_test.html` (게임 코드 미사용, 순수 Gamepad API 뷰어 — `G:\hell\_gamepad_test.html`)
   - 창 클릭(포커스) → **버튼** 입력 → 감지 여부 확인
2. 진단 페이지에서도 미감지 → **브라우저/OS 문제**:
   - 브라우저 **완전 재시작** (트레이 프로세스까지 종료)
   - 시크릿 모드 테스트 (확장프로그램 배제)
   - 브라우저 업데이트
   - Steam / DS4Windows / reWASD 등 리매퍼 종료 (독점 점유 시 안 보임)
   - 블루투스 페어링 삭제 후 재페어링
3. 진단 페이지에서는 되는데 게임에서만 안 됨 → **게임 쪽 조사**:
   - 콘솔에 `[GAMEPAD] 연결:` (game.html) / `[GP] 연결:` (index.html) 로그 확인
   - localStorage `inputMode`, `gpKeyMap` 확인 (브라우저별로 따로 저장됨 — 손상 시 매핑 깨짐)
   - `gpKeyMap` 초기화: 콘솔에서 `_resetGpKeyMap()`

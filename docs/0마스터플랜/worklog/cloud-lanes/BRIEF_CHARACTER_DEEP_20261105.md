# 브리프 CH — 캐릭터 심화 (2026-11-05 15:05 KST)

사용자 원문: "모든 자원 투자해서 캐릭터 심화 작업한다." / "파트를 몇 개로 나눌지, 파트를 어떻게 만들어서 붙여서 리깅을 할지." / "거기에 아이템을 붙이는 것도 실험해 보고, 아이템 갈아입는 것까지 해 보는 거야."
게임 정체성: 33도 쿼터뷰 루팅 핵슬 탄막 액션 RPG. 루팅 게임이므로 **장비가 캐릭터에 보여야 하고 갈아입혀져야 한다**. 이것이 캐릭터 파이프라인의 첫 요구사항이다.

## 0. 범위·규칙
- 자원 배분: 캐릭터가 1순위. 동작(MO)·도구(TM) 레인은 이 브리프 아래로 합류한다. 시스템 트랙(IA·SK·CW)은 이미 승인된 범위만 계속한다.
- Core 수치·판정 변경 0. 장비 슬롯·아이템 데이터의 정답은 Core(`InventoryData.cs`·`EquipmentApplication.cs`·`ItemFactory.cs`)다. 표현은 그 슬롯을 따른다.
- DESIGN LOCK(`docs/17게임아트팀/ART_TEAM_MASTER.md` 색인, 영웅별 LOCK 시트)이 얼굴 문양·장신구·갑옷·머리의 정답이다. 생성 메시 금지(11-05 09:30), 스크립트 키 애니메이션 금지. 자리 채우기 0, 중간 조잡한 상태는 캡처로 올리지 않는다.
- 목표 렌더: 리깅 3D → 실시간 저해상도 픽셀 렌더(11-03). 엔진은 비교 실험 중이므로 **파트·리깅·장비 구조는 엔진 독립**(FBX/glTF + 공용 스켈레톤)으로 설계하고, 반입 절차만 Unity/UE 두 벌.
- 무창·무음, 유료 0, 로그인은 사용자.

## 1. 답해야 하는 질문 (조사 레인 → 결정안)
1. **파트를 몇 개로 나누나.** ARPG 관례(디아4·PoE2·Last Epoch·NRftW 공개 자료)에서 모듈러 캐릭터의 분할: 머리/얼굴·머리카락·몸통·팔(상완·하완)·손·다리·발·망토/천, 그리고 장비 슬롯별 덮개(투구·가슴·장갑·각반·신발·어깨·벨트·망토). **우리 Core 장비 슬롯 수와 1:1로 맞춘 분할안**을 1안(최소)·2안(관례)으로 낸다. 각 안의 파트 수·드로우콜·스키닝 비용·픽셀 렌더에서 이음새가 보이는지.
2. **파트를 어떻게 만들어 붙이나.** 공용 스켈레톤 1개(본 이름 표준, Humanoid/UE 호환) + 파트마다 같은 스켈레톤에 스키닝 + 조립 시 본 바인딩 공유. Blender에서: 기본 몸(베이스 바디) 조형 → 파트 분할 선(이음새는 장비 경계에 숨김) → 장비 파트는 베이스 바디 위에 모델링 후 가려지는 몸 부위는 **바디 파트 마스크**로 숨김(겹침 뚫림 방지). 무기는 소켓(손 본 자식). 망토·천은 본 체인 또는 엔진 클로스(픽셀 렌더에서 효과 확인).
3. **리깅은 어떻게.** Rigify(또는 기존 영웅 리그 정리) 1개, 웨이트는 베이스 바디에서 장비 파트로 **전사(Data Transfer)** 해 파트마다 다시 칠하지 않는다. 이것이 "파트별로 뽑아 작업하는 게 쉽지 않다"의 해답 후보이고, 실습으로 증명한다.
4. **아이템을 어떻게 붙이고 갈아입히나.** Unity: SkinnedMeshRenderer의 bones 배열을 베이스 스켈레톤으로 재매핑(메시 교체만으로 갈아입기), 재질 슬롯·텍스처 아틀라스 규칙, 등급별 색 변주(마스크 맵 틴트). UE: Leader Pose Component 또는 Skeletal Mesh Merge. 소켓 무기 교체. **Core 인벤토리 이벤트(장착·해제) → 표현 교체**의 연결 지점 명세(코드 변경은 승인 뒤).
5. **픽셀 렌더와의 관계.** 저해상도(PixelActorPass)에서 파트 이음새·장비 두께·실루엣 변화가 읽히는 최소 크기, 장비 갈아입었을 때 1x에서 구분되는지의 기준.

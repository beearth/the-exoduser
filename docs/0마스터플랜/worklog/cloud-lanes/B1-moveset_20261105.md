## Animator·클립·예고 구현 확인

- Animator 컨트롤러 전이로 기술 시간을 정하지 않는다. `NativeDruidRigAnimator.cs:64`의 Manual PlayableGraph와 `:142`의 `SetSpeed(0)`, `:145`의 `plan.Frame/60` → `SetTime`/`Evaluate(0)`가 실제 경로다. 표의 배속은 **유효 시간 비율**이며 `Animator.speed` 속성을 바꿨다는 뜻이 아니다. root motion은 꺼져 있고 Core 좌표는 쓰지 않는다.
- FBX `OldmanV91.fbx`의 AnimationStack 38개를 Node로 직접 읽어 LocalStart/LocalStop을 비교했다. 단순 JSON 자체 비교가 아니다. `OldmanV91.fbx.meta:33`은 `clipAnimations: []`(별도 자르기 없음), `:95`는 `animationType: 2`(Generic). Unity가 실제 임포트한 `clip.length`/Avatar 상태는 미확인이다.
- 공격 29클립 + Idle/Walk 2개 =31, 상태 overlay3·목숨 전환2·등장1·침강1을 더해38개다. overlay 각1f, collapse 각120f, intro165f→Core90틱, death150f→기존 SinkBodyTicks 창. 이번에는 공격 밖 전환 시간/이벤트를 변경하지 않았다.
- 클립 이벤트로 Core 타격을 구동하지 않는다. 신규 AnimationEvent도 넣지 않았다. 표현 샘플은 Core 상태를 읽기만 한다. 클립 길이와 Core 시간이 달라도 retiming으로 맞춘 항목은 Core 차이로 세지 않았다.
- 섬광은 Core `Elapsed` 2 이상 11 미만의9틱. 종전에는 첫 렌더 관측 tick을 시작으로 저장해 늦게 관측해도 새9틱을 재생했다. 수정 후 `[2,11)`의 원래 시간 구간만 표시한다. 바닥 예고는 `Total/Remaining` 기반, 마지막5틱 테두리 강조, grab 눈빛은 wind 동안이다. 이를 늘려 타격 시점을 숨기지 않았다.
- 회복·재예고 간격은 Core 45/36/30, 콤보12, 패링 보너스30 그대로다. `NativeDruidRigPolicy.cs`는 읽기만 했으며 변경하지 않았다.

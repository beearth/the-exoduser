`unity/Assets/Exoduser/Runtime/NativeGame.A2Redesign.cs:19`
`foreach(var root in r3Roots)if(root!=null)volumes.AddRange(...)` — 파괴된 루트를 건너뜀.
- 같은 `A2RSetup` 안에서 `r3Roots`·리스트 원소를 null 검사 없이 역참조하는 곳은 이 줄뿐이다(20~24줄에 r3Roots 사용 없음). 추가 가드 없음. 구조·Core 변경 0.

## 루트가 파괴되는 경로 (코드 추적)
1. `Remodel3DLoad`(NativeGame.Remodel3D.cs:52)가 `r3Roots = r3Scene.GetRootGameObjects()`를 한 번만 저장한다.
2. 이어 `HellLightingSetup`(NativeGame.HellLighting.cs:21~34)이 각 루트의 `GetComponentsInChildren<Transform>(true)`에서 이름이 `Shafts`·`Foreground Cards`·`Background Cards`인 오브젝트를 `Destroy`한다(34줄).
3. `RM1_Slice.unity`에서 `Shafts`는 **씬 루트**(Transform `m_Father: 0`)다. `Foreground Cards`·`Background Cards`는 루트가 아니다. 루트 `Shafts`가 Destroy되면 배열 원소가 Unity null(파괴된 객체)로 남는다. Destroy는 프레임 끝에 실행되므로 그 프레임의 루프는 통과하고, 이후 프레임에 호출되는 `A2RSetup`(19줄)에서 `root.GetComponentsInChildren`이 NRE가 된다.
4. 다른 `r3Roots` 루프 중 `Remodel3D.cs:93`·`HellLighting.cs:52`·`SteamKeyshotCapture.cs:41`은 이미 `root!=null` 검사가 있다. 검사가 없는 곳은 아래 목록이다(이번 범위 밖, 수정 안 함, Mac 확인 뒤 판단): `Remodel3D.cs:64,75`, `A2Forest.cs:31,56,58,308`, `A2Field.cs:21,28,37,270`. `A2Field`·`A2Forest`는 다른 시점에 실행되며 Mac 로그에는 해당 NRE가 없었다(미확인).

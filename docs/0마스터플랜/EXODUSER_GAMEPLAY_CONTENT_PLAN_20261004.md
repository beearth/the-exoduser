# EXODUSER 게임 방향과 콘텐츠 완성 기획서 초안

작성일: 2026년 10월 4일 KST. 작성 책임: 총괄 Codex. 대상: 사용자와 기존 제작 담당자.

이 기획서는 EXODUSER에서 플레이어가 경험할 재미와 앞으로 완성할 콘텐츠를 정한다. 첫 성과는 **썩은 숲에서 NPC 세 명을 만나 대화와 기능을 사용하고, 전투와 장비 선택을 거쳐 다크드루이드에게 도전하는 실제 플레이 구간**이다. 지옥의 틈은 모든 장 사이와 스테이지 사이에 둔다는 방향이 2026년 10월 5일 KST 사용자 최신 확정이다. 1장 전체 완료 뒤의 틈은 망자들이 머물며 다음 장의 상승을 준비하는 마을로 구성한다. 장 사이의 큰 거점과 스테이지 사이의 작은 쉼터 구분은 상세 제작 제안이다. 새 맵, 새 보스, 추가 캐릭터와 구체적인 제작 순서는 아래 제안을 검토한다.

**문서 전체는 검토용 초안이며, §11의 사용자 확정 결정은 별도로 구분한다.** 기존 확정 설계는 출처와 함께 유지하고, 확정되지 않은 신규 이야기·마을 상세·콘텐츠 수량·체험 시간·제작 순서는 제안으로 표시한다. 이번 작성은 기획서 제작이며 게임 구현이나 제작팀 재가동 완료를 뜻하지 않는다. 기존 마스터 바이블·LOCK·시스템 SSOT를 대체하지 않는다.

## 1 게임의 약속

EXODUSER는 **지옥 최하층에서 시작해 위로 올라가며 탈출을 향하는 PC 핵앤슬래시 ARPG**다. 다수 적을 돌파하고, 획득한 장비와 스킬로 다음 전투 방식을 바꾸며, 먼저 올라간 사람과 멈춰 선 망자들의 사연을 만난다. 탑을 오르는 성취감과 지하감옥을 빠져나가는 절박함을 함께 전달한다. 기존 제품 전략의 핵심 고객은 장르 경험과 유료 게임 구매 의향이 있는 글로벌 성인 이용자다.

플레이어가 한 구간을 마쳤을 때 다음 세 가지를 설명할 수 있어야 한다.

- 어떤 적의 공격을 읽고 어떻게 대응했는가.
- 어떤 장비나 스킬을 선택했고 전투에서 무엇이 달라졌는가.
- 누구를 만났고, 다음 장소로 가려는 이유가 무엇인가.

전투·성장·서사가 한 번의 플레이 안에서 연결되어야 한다. 콘텐츠를 추가할 때도 이 세 질문 중 무엇을 개선하는지 먼저 정한다.

## 2 현재 설계와 남은 제작 간격

아래는 기존 문서와 보존된 관측 근거를 읽은 결과다. 10월 4일 이번 기획서 작성 중 새 플레이 검수를 수행하지 않았다. 문서상 설계, 코드 구현, 실제 실행본의 인수를 구분한다.

| 분야 | 확인한 기준 | 이번 기획에서 해결할 간격 |
|---|---|---|
| 필드 NPC | 마렌·에단·이실라의 ID·역할·좌표·상호작용 데이터가 존재. 명단 문서는 런타임 생성·렌더 연결 대기로 표시 | 화면에서 만나고 정상 조작으로 기능을 사용하는 경험 완성 |
| 첫 필드 | CH1-1 썩은 숲의 기존 제작물과 확정 구조가 존재. 전체 맵의 RETOUCH 기록이 남음 | 길·NPC·적·보스 접근이 실제 카메라에서 읽히는 상태 인수 |

| 이야기 | 기존 세계관 코어와 소개 연출이 존재 | NPC와 필드 진행을 연결하는 짧은 현장 이야기 제안 |
| 1장 완료 후 지옥의 틈 | 이름은 ‘지옥의 틈’. 썩은 숲과 벌레굴 사이의 중간 이공간이며, 1장 전체 완료 후 진입과 망자들의 성격은 사용자 확정. 독립 이동 가능한 장간/스테이지간 후보는 제작. 본편 거점 연동은 미구현 | 정확한 공간 배치·서비스·진입 저장 조건·세계관 정합성과 실제 구현은 후속 설계 |
| 신규 캐릭터 | 헬거너·변성술사·창법사 설계 문서가 존재. 문서는 게임 미구현·캐릭터 아틀라스 부족으로 표시 | 한 캐릭터의 선택·전투·장비·저장까지 실제로 완성 |
| 통합 실행본 | 보존된 source29 관측은 INTRO에서 입력 정체. 후속 코드 개선이 그 실행본에 포함된 것으로 계산할 수 없음 | 첫 콘텐츠를 확인할 수 있는 동일 후보 실행 경로 확보 |

새 기획을 세우는 이유는 기존 작업을 폐기하기 위해서가 아니다. 이미 만든 설계를 실제 게임 경험으로 연결하고, 그 결과를 다음 콘텐츠의 출발점으로 삼기 위해서다.

## 3 플레이 순환

**목적 확인 → 필드 탐험 → 다수 적 전투 → 획득 → 장비와 스킬 선택 → 강한 적과 보스 도전 → 결과 확인 → 다음 목적**을 기본 순환으로 제안한다.

| 구간 | 플레이어 행동 | 재미와 판단 |
|---|---|---|
| 목적 확인 | 인물과 대화하고 갈 곳을 이해 | 이동할 이유를 얻음 |
| 탐험 | 넓은 전투공간과 선택 경로를 이동 | 위험을 감수할지, 준비할지 선택 |
| 전투 | 공격·회피·현행 패링으로 다수 적에 대응 | 밀집 전투의 압박과 능동적 대응 |
| 획득과 성장 | 얻은 장비를 비교하고 장착 | 선택이 실제 전투 방식에 영향을 줌 |
| 보스 | 전조를 읽고 공격 기회를 찾음 | 배운 대응과 빌드를 시험 |
| 결과와 재도전 | 실패 원인을 파악하거나 승리 결과 확인 | 다시 시도할 이유와 다음 목적을 얻음 |

첫 구간의 체험 시간은 **15~25분을 목표로 제안**한다. 기존 콘텐츠 길이의 실측값이나 확정 시간 제한이 아니다. 첫 정상 종주에서 측정한 뒤 지나친 반복과 이동 부담을 조정한다. 시간 목표를 맞추기 위해 현행 처치 조건이나 전투 수치를 임의 변경하지 않는다.

## 4 첫 완성 구간

첫 완성 구간은 기존 CH1-1을 기반으로 한다. 기본 순서는 기존 시작·서사 → 마렌 → 필드 전투와 획득 → 에단 → 지역 진행 → 이실라 → 보스문 → 다크드루이드 도전이다. 실제 이동 경로는 현행 NAV·LOCK에 따른다.

### NPC 세 명

NPC 이름·좌표·훅은 기존 명단의 확정 계약이다. 아래 체험 목표는 그 계약을 실제 플레이로 연결하는 제작 범위다.

| ID | 이름과 위치 | 기존 역할과 훅 | 플레이에서 보여줄 결과 |
|---|---|---|---|
| `ch1-merchant` | 마렌 `(92, 176)` | 시작 상인 `open_shop` | 이름과 상인 외형을 확인하고 상점을 열고 닫음. 기존 상품·가격·경제 규칙을 유지한 거래를 확인 |
| `ch1-survivor` | 에단 `(68, 131)` | 이동 구간 생존자 `start_rescue_hint` | 대화를 통해 생존자 상황과 진행 목적을 이해. 구조 힌트와 완료되는 퀘스트는 구분 |
| `ch1-guide` | 이실라 `(106, 54)` | 북쪽 관문 안내 `show_gate_hint` | 현재 보스문 조건을 안내하고, 개방 후에는 도전 목적을 이해할 수 있음 |

세 NPC의 충돌은 기존 계약대로 없다. 현행 이동·스폰·투사체 통로를 바꾸지 않는다. 상호작용은 현행 입력 체계를 조사해 연결하며 이 초안에서 새 고정 단축키를 지정하지 않는다. NPC를 보기만 하는 상태, 기능이 이름만 있는 상태, 클릭 후 닫을 수 없는 상태는 완료가 아니다.

### 짧은 현장 이야기 제안

이야기 제안은 **지옥에 남은 생존자들을 만나며 숲의 관문을 넘어야 하는 이유를 얻는 흐름**이다. 마렌은 준비의 이유를, 에단은 현장의 피해를, 이실라는 북쪽 관문의 위협을 전달한다. 세 인물의 대화가 같은 설명을 반복하지 않도록 역할을 나눈다.

별도 구조 퀘스트를 추가하는 경우에는 발견 → 해결 행동 → 생존자 반응 → 결과 확인이 모두 있어야 한다. 구체적인 구조 대상·행동·보상·완료 상태는 아직 제안 미정이다. 기존 `start_rescue_hint`만 연결하고 새 구조 퀘스트가 완성됐다고 보고하지 않는다. WORLD_CORE의 주인공·네메시아·악의 설정을 바꾸는 대사도 확정하지 않는다.

첫 NPC 완성 단계에서는 기존 대사와 훅을 우선 연결한다. 새로운 이야기 한 편은 다음 제작 단위로 분리해, 시작과 종료 및 재진입 시 중복 여부까지 확인한다.

### 전투와 성장

일반 적 전투에서 실제 처치·획득·장착을 수행하고, 장착 결과가 능력 표시와 전투에 일치해야 한다. 기존 어픽스·스킬·비용·합체·장비 공식은 해당 SSOT를 따른다. 첫 시연에서는 선택 이유를 설명할 수 있는 장비 비교 사례를 한 건 확보한다.

아이템 색상 시안은 아트 후보다. 채택된 에셋·런타임 연결·실제 화면 인수까지 끝난 아이템만 게임 적용 결과로 기록한다.

### 다크드루이드 도전

현행 보스의 핵심은 공격 전조를 읽고 회피·현행 패링·공격 기회를 선택할 수 있는 경험이다. 먼저 현행 동작의 실제 화면과 소리를 확인하고, 읽히지 않는 전조와 판정 불일치처럼 구체적인 결함을 수정 대상으로 삼는다. 새 패턴·HP·피해량·보상을 이 문서에서 확정하지 않는다.

일반 CH1-1과 데모 마지막 si3 피날레는 서로 다른 조건이다. 피날레 전용 규칙을 첫 보스에 그대로 가져오지 않는다. 필드 진행을 거쳐 열린 보스문, 보스전 사망, 부활, 재진입을 같은 후보에서 확인한다. 보스 처치 후 결과와 다음 진행은 별도 정상 플레이로 확인한다.

## 5 확장 콘텐츠 로드맵 제안

아래 제작 순서는 제안이다. 각 행을 하나의 완성품으로 끝내고 결과를 확인한 뒤 다음 행을 시작한다. 날짜·소요 토큰·출시일을 확정하지 않는다.

| 순서 | 완성품 | 콘텐츠 범위 제안 | 사용자에게 보여줄 결과 |
|---|---|---|---|
| 1 | 필드 NPC | 기존 세 NPC의 생성·표시·상호작용 | 세 명을 직접 만나 대화·상점·안내 사용 |
| 2 | 첫 이야기와 보스 종주 | 기존 필드 한 곳, 현장 이야기 한 편, 현행 보스 한 체험 | 목적을 얻어 전투·성장 후 보스 도전과 재도전, 처치 결과 확인 |
| 3 | 1장 완료 후 지옥의 틈 | 신규 거점 맵 한 곳. 실제 제작 착수 순서는 제안 | 1장 전체 완료 후 입장·이동·인물 대화·준비·다음 장 출발을 연결하는 장소. 귀환 기능은 후속 설계 |
| 4 | 새 전투 맵과 보스 | 후속 필드 한 곳과 독립 보스 한 종 | 첫 필드와 다른 공간·적 구성·전투 테마, 새 보스의 시작부터 승리까지 |
| 5 | 추가 플레이 캐릭터 | 신규 캐릭터 한 종 | 정상 선택·고유 전투·장비·저장·재진입이 가능한 캐릭터 |

### 1장 완료 후 지옥의 틈 — 사용자 확정 방향

첫 장간 마을의 진입 시점은 **1장 전체 완료 후**다. 사용자 후속 지시로 스테이지 사이에도 지옥의 틈을 둔다. 모든 틈의 이름은 같으며 장 사이의 큰 거점과 스테이지 사이의 작은 쉼터는 상세 제안으로 구분한다. 망자들이 머물며 회복하거나 다음 상승을 준비하는 장소로 사용한다. 주민은 변형이 진행 중이어도 괴물이 되지 않았으며 자아와 여정의 목적을 가진 존재들이다. 획득한 장비 정리, 상인, 이야기 인물, 다음 장 출발과 귀환 등 구체적인 서비스는 후속 설계 제안으로 구분한다.

거점의 정식 명칭은 **‘지옥의 틈’**으로 확정한다. 지옥의 지역 사이에 있는 중간 이공간이며, 첫 거점은 **1장 썩은 숲과 2장 벌레굴 사이**에 둔다. 마을처럼 망자들이 체류하고 다음 상승을 준비한다. 기존 초안의 ‘중간계’는 거점의 정식 명칭으로 사용하지 않는다. WORLD_CORE의 중층 설정과 별도 검토하며, 맵 제작에서 쓰인 `Rootworld` 명칭과 동일시하지 않는다. 1장 전체 완료 후 진입 결정을 CH1-1 한 지역 클리어 후 진입으로 축소하지 않는다. 모든 장 사이와 스테이지 사이에 틈을 두는 범위는 사용자 후속 확정이며, 정확한 배치·전환 방식·개별 틈의 규모와 서비스는 후속 설계다. 기존 스테이지 배정·클리어 판정·보스 수치와 지옥층 진행 데이터는 이번 기획 기록으로 변경하지 않는다.

마을 제작 전에는 전체 구성·공간 역할·출입 연결·필수 인물·현재 에셋으로 표현 가능한 범위를 먼저 정한다. 마을 화면 하나를 만든 것만으로 귀환과 진행까지 완성했다고 계산하지 않는다.

### 새 맵과 보스 제안

새 맵은 기존 스테이지와 구별되는 환경, 전투 공간의 리듬, 탐험 동기, 보스 접근을 함께 갖춘 한 곳으로 제한한다. 보스는 독립된 정체성·공격 테마·전조·대응·승리 결과가 있어야 한다. 구체적인 맵 배정과 보스 이름은 현행 배정표·기존 에셋·사용 보류 문서 여부를 확인한 뒤 선정한다.

맵 제작은 공통 가이드 순서인 **전체 구성 → 대형 외곽 질량 → 중형 연결 → 바닥 연결 → 플레이와 전투 → 랜드마크 → 소형 디테일 → 카메라 검수 → 기술 검수**를 따른다. 현재 좌표·크기·NAV·LOCK은 해당 stage SSOT가 우선한다. 제작 결과에는 가이드 §23 보고와 실제 `VISUAL VERDICT`를 남긴다. 이번 문서는 신규 맵 geometry·collision·배치를 확정하지 않는다.

### 추가 캐릭터 제안

첫 추가 캐릭터 후보는 기존 기획의 **헬거너**로 제안한다. 중거리 관통·차지·후방 도약이라는 전투 역할을 기존 스킬 프로젝트에서 검토하고, 기존 플레이 캐릭터와 체감 차이를 확인한다. 기존 문서의 킷·자원·배율 제안은 이 문서의 후보 선정만으로 확정되지 않는다.

현재 캐릭터 아틀라스 부족은 제작 의존성이다. 기존 에셋의 적합성을 먼저 확인하며 PixelLab 캐릭터 생성 금지를 유지한다. 플레이스홀더 검증은 로직 검증 단계이고, 사용자에게 완성 캐릭터로 전달하는 단계와 구분한다. 세 캐릭터를 동시에 시작하지 않는다.

## 7 제작과 자원 운영 제안

동시에 제작하는 최상위 완성품은 한 건으로 제한한다. 필요한 기존 담당자만 참여하며, 총괄은 구현·아트·검수의 의존성을 하나의 결과로 묶는다. 기존 관리 3명·전문 15명의 구조와 두 오더담당의 유일 송신 책임을 유지한다. 이 문서 작성으로 새 팀·채팅·실행 세션을 만들거나 기존 팀에 새 TASK를 송신하지 않는다.

각 작업 시작 전에 ‘이번에 플레이어에게 생기는 변화’, ‘완료를 보여줄 장면’, ‘필요한 의존성’, ‘남은 작업’을 적는다. 결과 보고는 완성품·실제 확인 범위·실패 이유·다음 한 작업으로 제한한다. 기존 통과검사와 같은 상태 점검을 반복해 성과 수를 늘리지 않는다.

이번 단계는 기획서 작성이다. 제작 재개와 무인 자동점검 운영은 별도로 정리해야 한다. 확인되지 않은 토큰 예산·복구 날짜·속도를 제작 일정으로 사용하지 않는다. 제작이 진행되더라도 한 건을 게임에 연결하고 인수하기 전 다음 대형 콘텐츠를 벌리지 않는다.

안전 기준은 기존 사용자 세이브·타인 WIP·복구 지점·보호 설계를 보존하는 것이다. Q 전용 magic 패링, E 패링 불가, 어택 티켓 금지, 보호 `2_3` 문서 수정 금지를 유지한다. 코드 변경은 관련 docs 전체 검색·정확한 동기화·소유 범위 commit/push·원격 SHA 확인까지 묶는다. Changes 80부터 완료 소유 체크포인트를 시작하고 100 전에 새 산출을 멈춘다.

## 11 사용자 확정: 지옥 상승 여정과 지옥의 틈 — 2026-10-05 KST

현재 단계는 중간 검토·목표 설정이다. 아래 결정은 기획 기록이다. 후속 직접 요청으로 지옥의 틈 원화·독립 맵 후보 제작만 진행하며 제작팀 배정·자동 실행은 재개하지 않는다. ‘마을처럼’이라는 초기 기능 비유는 건물 마을로 구현하지 않는다. 최신 사용자는 사람들이 머무는 기묘한 이공간으로 확정했다.

## 12 지옥의 틈 주민 이야기 — 2026-10-05 KST

| 이야기 유형 | 사용자 제시 방향 | 플레이 연결의 후속 설계 |
|---|---|---|
| 마지막 물건을 건네는 망자 | 더 올라갈 수 없다고 느낀 망자가 가진 하나뿐인 아이템을 주인공에게 건넨다. 대사 방향: ‘내가 가진 하나뿐인 아이템을 너한테 줄게. 나는 여기까지인 것 같다.’ | NPC 정체·물건 종류·아이템 ID와 수치·지급 조건·중복 수령 방지·이후 상태는 미정. 기존 지급 훅·보상 수치를 임의 변경하지 않음 |

위로 향하는 여정에 주민의 물건과 부탁이 연결되는 이야기 방향을 사용한다. 실제 시간 제한 없이 대사·외형·지역 진행으로 부패를 표현할지, 별도 진행 조건이 필요한지는 추가 결정 사항이다. 기존 WORLD_CORE의 인물 관계·반전·보스 배정과 확정 시스템은 이번 이야기 제안으로 변경하지 않는다. 중간 검토·목표 설정과 EXODUSER 자동 실행 일시중지 상태를 유지한다.

## 13 여정의 경험 설계 — 검토 제안

**플레이어는 자신이 한 층 더 올라갔다는 사실을 길, 전투 결과, 만난 인물의 변화로 느낀다.** 장을 넘길 때 장소 이름만 바뀌는 것으로 끝내지 않는다. 앞 구간에서 얻은 장비가 다음 전투의 선택을 바꾸고, 망자가 건넨 물건이나 부탁이 다음 장소에 개인적인 의미를 만든다.

| 설계 축 | 플레이어에게 전달할 경험 | 구체적인 연결 제안 |
|---|---|---|
| 상승 | 아래의 지옥을 벗어나 다음 위험에 도달했다는 성취 | 장 완료 결과와 다음 장 목적을 함께 전달. 기존 장 순서 유지 |
| 전투 | 다수 적을 상대하면서 자신의 대응과 빌드가 성장함 | 필드 전투에서 선택을 배우고 보스에서 시험. 기존 전투 규칙 유지 |
| 획득 | 얻은 물건이 다음 도전을 준비하는 이유가 됨 | 비교·장착·전투 변화와 주민에게 받은 물건의 사연을 연결 |
| 사람 | 이 길을 먼저 걸었거나 아직 걸으려는 존재를 만남 | 주민마다 멈춘 이유, 올라갈 이유, 주인공에게 원하는 것을 다르게 구성 |
| 다음 목적 | 강한 적을 잡는 일과 누군가를 찾는 일이 같은 여정에 놓임 | 구출 부탁이 다음 장의 선택적 탐험 목적이 되는 흐름 제안 |

탑의 감각은 세계의 상승 방향에서 얻는다. 모든 지역을 좁은 계단이나 같은 복도로 만드는 뜻이 아니다. 기존 세계 SSOT의 넓은 전투지역과 지역 간 전환을 유지하며, 35지역의 정확한 배정은 해당 SSOT를 따른다. 장마다 지역 수가 다르므로 7장에 5지역씩 균등 배분하지 않는다. 이번 기록은 신규 맵 도면·경계·좌표·충돌·랜드마크 배치를 제작하지 않는다.

세계관 코어에 있는 주인공의 지옥 강하와 복수는 동기의 층위이고, 현재 플레이 구조의 최하층 시작·상승·탈출은 진행의 층위다. 두 층위를 함께 유지한다. ‘지옥의 틈’을 천계와 지옥 사이의 중층이나 새로운 에너지원으로 정의하지 않는다. 새 인물과 대사는 기존 악의 법칙·인물 관계·반전을 검토한 뒤 연결한다.

## 14 지옥의 틈의 역할과 첫 방문 — 검토 제안

지옥의 틈은 **한 지옥을 벗어났지만 아직 탈출하지 못한 자들이 다음 상승을 준비하는 장소**다. 주민은 이미 괴물이 된 적이 아니라, 변형 중에도 자기 의지와 사정을 가진 망자다. 쉬는 사람, 준비하는 사람, 더 올라갈 힘이 없다고 느끼는 사람이 함께 존재할 수 있다. 주민 모두를 포기한 자로 만들지 않는다.

거점은 전투의 압박을 잠시 낮추고 획득물을 정리하며 다음 목적을 이해하게 한다. 이 휴식이 세계관상 영구 안전이나 부패를 완전히 멈추는 효과를 뜻하지는 않는다. 부패의 원인과 속도는 미정이며, 기획 제안만으로 플레이어에게 시간 압박이나 벌칙을 적용하지 않는다.

첫 장간 큰 거점 방문은 다음 흐름을 제안한다. 스테이지 사이의 작은 쉼터는 도착·잠시 정비·다음 스테이지 출발로 간소화하는 후보로 만든다. 아래는 경험 순서이며 맵 배치 순서나 신규 클리어 조건이 아니다.

| 단계 | 플레이어의 경험 | 반드시 연결할 결과 |
|---|---|---|
| 1장 완료 확인 | 썩은 숲 전체를 돌파한 결과를 확인 | 기존 모드별 장 완료 판정과 저장 정책을 조사해 사용. CH1-1 한 지역 완료와 구분 |
| 틈 도착 | 다른 망자들도 이 길을 올라가고 있음을 이해 | 거점 명칭과 다음 지역이 벌레굴이라는 정보 전달 |
| 주민과 만남 | 외형만으로 적인지 판단하기 어려운 존재에게서 의지와 사정을 들음 | 주민과 적대 몬스터의 상호작용 구분, 대화 종료 후 정상 조작 복귀 |
| 정비 | 앞 장에서 얻은 장비와 자원을 살펴봄 | 채택한 기능만 제공. 기존 장비·경제·자원 규칙과 일치 |
| 사연을 받음 | 물건을 받거나 위층 사람을 찾아 달라는 부탁을 들음 | 무엇을 받았고 무엇을 해야 하는지 짧게 확인. 선택적 이야기와 필수 진행 분리 |
| 다음 상승 | 준비를 마치고 벌레굴로 출발 | 다음 목표와 출발 조건이 읽힘. 대화를 전부 듣지 않아도 필수 안내 확인 가능 |

## 15 주민 이야기의 플레이 구조 — 검토 제안

### 마지막 물건을 건네는 망자

이 인물의 핵심은 값비싼 보상을 얻는 사건보다 **자신이 더 가져갈 수 없는 것을 다음 사람에게 맡기는 순간**이다. 아직 자아가 있고 물건을 건네기로 스스로 선택한다. 이후의 운명을 즉시 사망·괴물화·소멸로 고정하지 않는다.

이야기 흐름은 상태를 알아봄 → 물건이 그에게 남은 이유를 들음 → 양도 의사를 확인 → 물건과 사연을 받음 → 다시 만났을 때 반응으로 제안한다. 수락과 거절의 선택을 제공할지는 미정이다. 기존 물건 하나를 이야기와 연결할지 새 아이템이 필요할지는 아이템 담당 설계에서 결정한다. 이름·등급·성능을 먼저 정해 이야기에 끼워 맞추지 않는다.

| 진행 구분 | 제안하는 반응 | 구현 전에 정할 사항 |
|---|---|---|
| 처음 만남 | 올라가지 못하는 이유와 아직 남은 의지를 드러냄 | 정체·관계·부패 표현·대사 길이 |
| 양도 제안 | 하나뿐인 물건을 맡기는 이유를 전달 | 대화만으로 지급할지 수락 행동이 필요한지 |
| 지급 가능 | 물건을 받을 수 있는 조건을 확인 | 인벤토리 부족 시 처리, 선행 조건 |
| 양도 완료 | 획득 안내와 NPC 반응을 함께 전달 | 아이템 지급과 완료 기록의 일관성 |
| 다시 만남 | 물건을 이미 건넨 사실을 기억 | 재지급 방지·후속 반응·인물 존속 |

아이템을 받은 뒤 저장 실패나 재접속이 일어났을 때 물건은 사라졌는데 이야기는 끝난 상태, 또는 이야기는 초기화됐는데 물건만 남아 반복 지급되는 상태를 막는 것이 인수 목표다. 저장 필드·트랜잭션·보상 회수 방식은 아직 지정하지 않는다.

### 위층의 누군가를 구해 달라는 망자

이 인물은 **주인공의 상승에 다른 사람을 찾는 이유를 더한다.** 부탁을 받는 장면보다 대상에게 도달한 뒤 무엇을 할 수 있고 결과가 누구에게 전달되는지가 중요하다.

| 진행 구분 | 제안하는 경험 | 결과 확인 |
|---|---|---|
| 부탁을 들음 | 관계와 찾는 이유를 이해 | 대상의 단서와 목적을 짧게 다시 볼 수 있음 |
| 부탁을 받아 둠 | 다음 장의 선택적 목적을 얻음 | 메인 진행과 혼동하지 않도록 표시 |
| 위층에서 발견 | 부탁의 대상 또는 연결된 상황을 만남 | 발견만으로 구출 완료를 계산하지 않음 |
| 구출 행동 | 구출에 필요한 실제 행동을 수행 | 전투·상호작용·이동 중 채택한 조건을 명확히 정의 |
| 결과 확인 | 대상의 상태와 사건의 결과를 확인 | 성공·보류·실패를 쓰는 경우 각 조건과 재시도 가능성 지정 |
| 소식 전달 | 부탁한 주민의 반응을 확인 | 귀환 미채택 시에도 결과를 전달할 수 있는 방식 설계 |

위 표의 상태는 설명용 구분이며 코드 enum이나 세이브 스키마가 아니다. 구출 대상·장·행동·보상·실패 규칙은 모두 미정이다. 실제 시간에 따른 퀘스트 실패, 구조 불가능한 선택, 되돌릴 수 없는 NPC 사망은 별도 결정 없이 넣지 않는다. 필수 진행을 이 이야기의 수락 여부로 막을지도 확정하지 않는다.

| 주민 유형 제안 | 여정과의 관계 | 대화가 해야 할 일 |
|---|---|---|

이 목록은 캐릭터 제작 수나 NPC 확정 명단이 아니다. 기존 필드의 마렌·에단·이실라를 틈으로 이동시키거나 새 역할로 덮어쓰는 근거로 사용하지 않는다.

## 16 부패의 표현과 플레이 규칙 — 검토 제안

‘빨리 올라가지 못하면 썩는다’는 세계관 설정은 확정 방향이다. **그 압박을 플레이어가 체감하는 방식은 아직 선택해야 한다.** 초안에서는 대사·외형·진행 단계별 반응을 먼저 검토하고, 실제 시간 제한은 별도 시스템 제안으로 분리한다.

| 표현 후보 | 기대 효과 | 채택 전 확인 |
|---|---|---|
| 주민의 외형과 움직임 | 변형 중에도 사람이었음을 알아봄 | 전투 적과 혼동하지 않는 표시·상호작용, 기존 에셋 적합성 |
| 개인적인 대사와 물건 | 추상적인 위험을 한 사람의 사정으로 이해 | 같은 부패 설명 반복을 줄이고 주민별 목적을 드러냄 |

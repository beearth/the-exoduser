## Mac 재촬영 방법과 판정 한계

1. 이 커밋으로 Mac 빌드를 만들 때 **-remodel-scenes,1 필요**. 실행기에 전달되는 빌드 옵션은 -remodel-scenes 1이다. PortVerification.cs:253에서 RM1_Slice를 동봉하고 :254에서 BuildPlayer를 호출한다. 장면이 빠지면 NativeGame.Remodel3D.cs:115의 2D fallback이 발생할 수 있으며 :116이 실제 장면 load 경로다.
2. 공통 촬영 인자: **--unity-a2-clean-shots -output <dir> --remodel3d --unity-qa-sandbox <절대경로>**. base는 clean 옵션 없이, M0는 --a2-clean --a2-clean-m0, M1은 --a2-clean으로 각각 촬영한다. 각 결과의 receipt.mode를 확인한다. Mac에서는 -batchmode 없이 창 모드로 촬영한다. NativeGame.SteamKeyshotCapture.cs:162–169가 최종 화면을 PNG로 저장하고 actualScreen=true를 기록하며, :171의 배치 모드 별도 카메라 경로는 최종 화면 판정에 쓰지 않는다.
3. start=(4200,7460), bridge=(4320,7180), swamp=선정 좌표를 사용한다(:90). 세 모드의 같은 구도를 위해 첫 물가 좌표를 확인하고 후속에는 --a2-clean-swamp <x:y>로 고정한다. 자동 물가 선택은 :54–69의 Map.CanMove·다리 거리·물 경계 조건을 사용한다.
4. 현재 촬영 구현의 해상도는 **1920×1080 / 3840×1080**이다(:91–100). 3840×2160이 아니다. 각 지점에서 72프레임 후 저장(:103–105)하며 output/1920x1080 및 output/3840x1080 아래 start/bridge/swamp 컷을 남긴다. renderers.csv(:114), receipt.json(:117), pitch/dist/swamp/bridgeY와 끈 렌더러 수(:88,89)를 함께 본다.
5. 출력 경로가 없거나 QA sandbox 미활성이면 exit 2(:75); RemodelReady는 최대 240초를 기다린 뒤 실패하면 exit 3(:81–83)이다. 촬영은 AudioListener.volume=0(:76). receipt.passed는 오류 0·6컷·장면/해상도 같은 기계적 조건(:116)일 뿐 화면 합격이 아니다.
6. 기준 412bdee09의 옵션 없는 화면과 이번 커밋의 옵션 없는 화면을 같은 환경·구도에서 전후 픽셀 비교한다. M0/M1은 바닥 얼룩, 실제 제거 수, 남은 충돌, 캐릭터 높이·다리 상판, 원경 가독성을 별도로 확인한다. **옵션 없을 때 동일은 미입증(Mac 전후 픽셀 비교 대기)**이며 **_A2_CLEAN_GROUND 변형 컴파일 미확인**이다.

**이전 PC 촬영본은 실행기 가드 우회 결과이고 현재 코드와 달라 판정 근거가 아니다.** 이번 커밋의 성능·화면·기본 경로 동일성 증거로 재사용하지 않는다. 이 인수에서는 PC 촬영이나 실행기 우회를 재현하지 않았다.

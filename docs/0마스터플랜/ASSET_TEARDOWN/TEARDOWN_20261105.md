# 공개 자산 분해 — 우리 1-1 에셋과 차이표 (2026-11-05, Mac)

브리프: [BRIEF_ASSET_TEARDOWN_20261105](../worklog/cloud-lanes/BRIEF_ASSET_TEARDOWN_20261105.md). 도구: Blender 4.5.15 LTS `--background`, [`tools/teardown/teardown.py`](../../../tools/teardown/teardown.py). 비교 대상 기준 커밋: `7587ebe54`.

## 1. 결론

- **문제는 "폴리곤이 모자람"이 아니다.** 전경 로그는 45,719△로 플레이 거리 기준 삼각형 하나가 약 1.2px²로, 화면 해상도보다 촘촘하다. 같은 부류인 FB Root_01은 1인칭 게임인데도 11px², 몸통·바위는 41~96px²이다.
- **로그의 원인은 리토폴로지가 없었기 때문이다.** 전경 로그는 Poly Haven `dead_tree_trunk_02`(83,128△, 4.051×1.056×1.055m)와 크기·UV 섬 수(158)가 같고 삼각형만 ×0.55이다. `UNITY_KEYSHOT_A2_20261030.md`에도 decimate .55로 기록되어 있다. 스캔을 줄이기만 했고, 조형과 베이크로 다시 만들지 않았다.
- **이끼 바위와 다리는 텍스처를 7~10%만 쓴다.** 이끼 바위 UV 사용률 6.7%(노멀맵의 92.6%가 평면), 다리 9.9%. FB 바위·뿌리는 63~64%이다. 머티리얼 UV 배율은 1이라 늘려 쓰는 것도 아니다. 다리는 유효 66px/u로 1080p 1:1(75px/u)에도 못 미친다.
- **A2 메시에는 LOD가 없다.** 런타임 코드에 `LODGroup`이 없고 측정한 FBX 5개도 단일 메시이다. FB는 전부 ×0.5 사슬이다(예: 7,651→3,775→1,849→891→430).
- **거목 삼각형 수는 곧바로 비교할 수 없다.** FB Tree_04 몸통 2,870△ + 알파 카드 225△ 구조이고, 우리 거목은 맨가지를 전부 지오메트리로 만들어 표면이 5.4배(401.7 vs 74.7m²)이다. △/m²는 원본 기준 비슷하다(49.5 vs 38.4). 다만 우리는 배치 때 축소해 화면 밀도가 FB의 약 2.7배가 된다(27 vs 72px²/△).

## 2. 측정 조건과 한계

- 플레이 화면 밀도: A2 카메라 pitch 34°, 거리 16.5u(`NativeRemodel3D.DistU`), FOV 46.9453°(`remodel_camera.json`), 1080p에서 **75.4px/u**, 4K에서 150.7px/u. 화면 중앙·정면 기준 명목값이고, 시선 기울기와 카메라에 더 가까운 전경은 반영하지 않았다.
- `remodel_camera.json`의 pitch 48.7°/거리 14는 비A2용이다. A2 값은 코드에서 확인해 브리프 값과 일치한다.
- 우리 배치 배율은 코드에서 고른 **대표값**이다: 거목 (.405, .585, .405), Hollow (.75, 1.15, .75), 로그 (1.7, ~.95), 이끼 바위 1.2, 다리 상판 (.72, .64). 인스턴스마다 다르므로 표 2는 자릿수를 보는 용도이다. FB는 프리팹 배율(Tree_04 .698)을 썼다.
- 유효 텍셀 밀도는 임포트 상한을 반영했다. 우리 거목 원본 4096 → 임포트 2048, FB Bark_04 원본 2048×4096 → 1024×2048. FB Tree_04 몸통 값은 타일링 포함이다.
- **FB는 1인칭·PS4 1080p30 목표 데모이고 카메라가 다르다.** README 기준이다. 그대로 예산이 되지 않으며 관례의 근거로만 쓴다. **Poly Haven은 원본 보관용 스캔(LOD 없음)이라 예산 기준이 아니다.**
- M7 노멀 이득: 낮은 태양빛의 회색 재질 렌더에서 고주파 에너지를 맵 켜고/끄고 비교한 내 지표이다. 화면 채움에 따라 달라지므로 같은 부류끼리만 비교한다.
- 교차 검증: `dead_tree_trunk` 4K 측정 2,613.6px/m = Poly Haven 공개값(8K 5,227.1)의 절반.
- 게임 안 렌더링 비용·프레임은 재지 않았다. 이 표는 에셋 수치이고, 고치면 FPS가 얼마나 오르는지는 **미확인**이다.
- **Book of the Dead·Megascans는 미측정**이다(로그인 필요, 사용자 전달 대기). 합격 기준의 공개 자산 3개·Unity 데모 1개·우리 자산 2개는 충족한다.

## 7. 질문 답

1. **같은 급 고목은?** 몸통 2,870△ + 카드 225△, 38△/m². 형태는 굵은 줄기와 넓은 밑동만 조형하고(`img/fb_Tree_04-wire.png`), 잔가지·잎은 카드, 잔주름은 노멀맵과 512 디테일맵이 맡는다.
2. **텍셀·채널은?** FB 유효 133~143(바위), 962(뿌리). 우리 바위 110, 거목 166, 다리 66. 밀도보다 **UV 낭비와 마스크 해상도**가 다르다. 마스크는 우리가 16배 픽셀(2048² vs 512²)이다.
3. **피벗·접지·LOD는?** 5절.
4. **조명·안개는?** 6절. 가장 큰 차이는 베이크 GI와 볼류메트릭 안개이다.
5. **어떤 숫자를 쓰나?** 8절.

## 8. 제안 — 상한 수정 (게임 안 미검증)

1. **삼각형은 화면 면적으로 정한다:** 상한 = 플레이 화면 표면적 ÷ 40~100px²/△. 큰 소품 6~12k는 유지(거목 약 9k), 전경 로그 5~10k(현재 45.7k), 바위 3~5k(현재 8.3k), 다리 8~10k(현재 16.9k).
2. **텍셀 밀도:** 일반 150px/u(4K 1:1), 근경 300px/u까지. 원본 4096은 임포트 2048이므로 만들지 않는다.
3. **UV 사용률 60% 이상을 합격 조건으로 삼는다.** 이끼 바위는 다시 패킹하면 1024로도 현재보다 선명해진다(계산값).
4. **채널:** BC·N 1024~2048 + 마스크 패킹 512~1024. AO·거칠기를 별도 2048로 두지 않는다.
5. **LOD·접지:** ×0.5 사슬 2~3단, 화면 높이 .5/.2/.01. 피벗 z=0, 밑동은 치마 또는 발판으로 닫는다.
6. **1-1 거목 LOD (추정치, 실측 아님):** ×0.5 사슬 3단(19,888/9,944/4,972△), 전환 .5/.2/.01을 적용하면 배치 기준 **1,078만△ → 약 587만~616만△**(Ultra lodBias 2, 약 45% 감소), lodBias 1이면 약 380만~389만△. 542그루의 실제 위치와 카메라 4곳으로 계산했다. 배치 합계이므로 프레임 절감은 이보다 작다: 시작 지점 한 프레임에서 보이는 거목은 55그루(약 109만△)이고 그중 가까운 나무는 LOD0에 남는다. FPS 효과는 미측정이다.

## 9. 스캔 기반 자산을 우리 것으로 만드는 절차 (초안)

Tripo/Meshy 폐기 후 대안. 아직 한 번도 돌려 보지 않은 초안이다.

1. **원본:** 라이선스를 확인한 스캔을 Git 밖에 보존한다. 그대로 쓰지 않고 잘라 붙이고 조형해 지옥 숲 실루엣으로 바꾼다(`dead_tree_trunk_02`를 줄이기만 한 로그의 재현 금지).
2. **리토폴로지:** decimate 금지. 대상 △는 8-1 공식으로 정하고(거목 약 9k, 로그 5~10k, 바위 3~5k), 실루엣과 밑동에 먼저 배분한다.
3. **UV·베이크:** 사용률 60% 이상, 150px/u(근경 300), 고폴리→저폴리로 노멀·AO를 베이크하고 빈 영역과 무효 노멀을 검사한다.
4. **채널:** BC·N 1024~2048 + 마스크(AO·거칠기·금속) 512~1024, 색은 우리 톤으로 다시 칠하고 점·디더링을 검사한다.
5. **LOD·접지·판정:** ×0.5 사슬 2~3단, 피벗 z=0, 치마·발판 포함. 합격은 `teardown.py` 수치 + 실제 게임 캡처로 판정한다.

## 10. 미해결·확인 안 된 것

- `img/our_Ancient_Tree_A-normal.png` 오른쪽 몸통의 검은 점(렌더 픽셀의 .25%)은 원인 미확인이다. 노멀맵에 검은 픽셀은 없다(near-black 0%). 축퇴 UV로 탄젠트가 깨졌을 수 있으나 추정이고, **게임 화면에서 보이는지 안 봤다.**

- `channels` 시트는 Git 용량 때문에 폭 1024로 축소했다(`sips`). 나머지 이미지는 1x이다. `wirezoom`과 나머지 원본은 Git 밖 `~/exoduser-wt/_out/AT/m/`에 있다.

# 터미널 장애 대체 절차

2026-11-03 규칙 정리 때 AGENTS.md "터미널 시작 실패 시 대체 작업 경로"(2026-09-27·29)를 이 문서로 옮겼다. 당시 오류 기록·예제 코드·브라우저 경유 절차는 [터미널 장애 대체 작업 가이드](../13출시·마케팅/TERMINAL_FAILURE_FALLBACK_20260927.md)에 있다.
이 문서의 정본은 origin/unity/main이다(docs 정본 브랜치, 11-03). 상위 규칙은 [운영 매뉴얼 §2.8](AGENT_OPERATIONS_MANUAL.md)이다.

## 1. 원칙 (모든 에이전트)

- 셸 하나가 시작하지 못해도 작업 전체를 멈추지 않는다. PowerShell은 필수 도구가 아니다(2026-09-29 사용자 확정). 다른 셸과 파일 도구로 원래 작업을 이어 가고, 사용자에게 서버 실행·환경 복구를 떠넘기지 않는다.
- **권한 거부는 다른 실행 경로로 우회하지 않는다.** 이미 허용된 작업 디렉터리와 도구 범위에서만 진행한다.
- **실행하지 못한 Git 확인·커밋·테스트는 성공으로 보고하지 않는다.** 미완료로 남기고, docs 동기화 의무는 그대로 지킨다.
- 같은 시작 오류를 반복 재시도하지 않는다. 한 번 실행됐다고 영구 복구를 선언하지 않는다.
- 대체 실행도 무창·무음이다. 창 숨김 옵션을 붙인다.
- Node는 `C:\nvm4w\nodejs\node.exe` 전체 경로로 실행한다.

## 2. Claude 세션

- 위 원칙을 그대로 따른다. 셸 도구가 실패해도 파일 읽기·쓰기 도구는 따로 동작하므로 파일 작업은 이어 간다.
- 권한 확인이 거부된 명령을 다른 셸이나 도구로 바꿔 다시 실행하지 않는다.

## 3. Codex `exec_command` (11-04까지)

증상: `exec_command`가 명령 본문 실행 전에 `CreateProcessW`, `pwsh.exe`, `OS Error -1073283067`로 실패한다. 지정한 Windows PowerShell 대신 WindowsApps의 PowerShell 7 경로가 오류에 나타났고, 권한 상승 재시도도 실패했다(2026-09-27). 파일 작업 전체가 불가능하다는 뜻은 아니다.

| 순서 | 실행 경로 | 확인과 다음 행동 |
|---|---|---|
| 1 | `exec_command`에 `shell:'C:\\Windows\\System32\\cmd.exe'`, `tty:false`, `login:false` | `echo shell_probe`로 시작을 확인한 뒤 CMD 문법으로 읽기·검색·Git을 계속한다. PowerShell 문법을 CMD에 그대로 넣지 않는다 |
| 2 | CMD에서 Node 전체 경로 실행 | 파일 처리·테스트·서버에 쓴다. 기본 `node` shim은 쓰지 않는다 |
| 3 | PowerShell이 꼭 필요한 명령만 Node `spawnSync`·`execFileSync`로 시스템 `powershell.exe` 호출 | 인수는 배열로, `-NoProfile`·`-NonInteractive`·`-WindowStyle Hidden`·`windowsHide:true`를 붙인다 |
| 4 | `functions.exec` 안에서 `tools.apply_patch(...)`로 작업 디렉터리 파일 직접 수정 | 셸과 따로 동작한다. 실제 디스크 내용을 다시 읽어 확인한다(로컬 서버로 읽으면 `cache:'no-store'`) |
| 5 | 모든 허용 경로에서 불가능한 단계 | 오류와 미완료 단계만 구체적으로 보고한다 |

- 정상일 때 기본 설정은 운영 매뉴얼 §4의 Windows 창 숨김 설정이다. 시작에 실패하면 위 표로 바꾸고 PowerShell만 고집하지 않는다.
- 로컬 서버 연결 거부는 서버가 응답하지 않는다는 증거일 뿐이다. 서버가 필요하면 허용된 경로로 자기 작업본의 `server.cjs`를 창 숨김으로 띄우고 `/`·`/api/slots` 응답을 확인한다. 웹 3333은 예약 작업 `EXODUSER_LatestWeb3333`이 관리하므로 검수 서버는 다른 포트로 띄운다.
- 브라우저 메모리에만 적용한 변경을 원본 수정으로 보고하지 않는다. 디스크 응답과 새로고침 뒤 동작으로 따로 확인한다. 브라우저·CDP는 해당 도구 문서를 먼저 읽고 로컬 개발 작업에만 쓴다.
- 2026-09-29 기록: 시스템 PowerShell 5.1 실행에 성공한 뒤에도 같은 호출 경로에서 WindowsApps 시작 오류가 재발했다. CMD 파일 읽기·Git 조회는 성공했다.

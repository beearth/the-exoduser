# 게임 연구 — Phantom Blade Zero(팬텀 블레이드 제로)의 임팩트·전투 (2026-11-05, 레인 PB)

- 사용자 결정(11-05): "임팩트나 전투 요소는 팬텀블레이드를 배운다." 이전 지시: "임팩트가 다 엉망, 팬텀블레이드 참고."
- 방식: **공부, 복제 아님.** 공개 자료(개발자 인터뷰·매체 리뷰·프리뷰·공략)만 읽었다. 게임 파일·프레임 캡처 분석, 영상·이미지 반입은 하지 않았다. 코드 수정 없음.

- 표기: **[사실]** = 서로 독립된 출처 2개 이상이 같은 말을 한다. **[추정]** = 출처 1개, 공략 위키만, 또는 우리 해석. 수치 단위는 60fps 틱(1틱 = 0.0167초).
- PBZ 출시: 2026-10-29 PS5·PC(Steam·Epic). 메타크리틱 88, 오픈크리틱 91(리뷰 모음 기준). 전투가 가장 많이 칭찬받았고, 타격의 무게감은 평이 갈린다(§2).

## 0. 우리 게임에 바로 적용할 임팩트·전투 규칙 10개

전제: 우리는 **탑다운 피치 34° 원근 카메라(LOCK), 캐릭터 키 = 화면 높이 약 5.6%, 적이 많은 핵앤슬래시**다. PBZ는 어깨 뒤 3인칭 카메라에 캐릭터가 화면의 30~50%를 차지하는 1:1~1:소수 결투다. 그래서 **몸 동작의 미세한 결(손목·옷자락·얼굴)로 손맛을 파는 방식은 옮길 수 없고**, 옮길 수 있는 것은 ① 예고의 색 문법 ② 방어 성공 등급의 구분 ③ 끊기지 않는 흐름(정지 대신 반응) ④ 자세 붕괴 → 반격의 보상 고리 ⑤ 소리 층 분리다. 아래 수치는 표현 쪽 목표값이며 Core 판정·수치는 바꾸지 않는다. 2_3 설계도 바꾸지 않는다(패링은 표현만).

### 0.1 이 연구가 11-03 결정을 바꾸는 점 (보고 — 판정은 임팩트 총괄)

| 11-03 결정 | 이 연구의 발견 | 제안 |
|---|---|---|
| R3 히트스톱·슬로 없음 | PBZ도 거의 없다(일치). 다만 그 때문에 "접촉이 약하다"는 평이 여러 곳에서 나왔고, 히트스톱을 더하는 사용자 모드가 생겼다 | R3 유지. 대신 규칙 2·3(등급별 빛·스파크·소리 차이, 대상 히트 플래시)을 **필수**로 올린다. 없으면 PBZ가 받은 비판을 그대로 받는다 |
| R4 진동 대신 푸시인 | 11-03 실측은 **런치 트레일러**였다. 개발사는 트레일러에 별도 "시네마틱" 카메라·특수 앵글을 썼다고 밝혔다 [사실: 개발사 인터뷰 + 매체 비교]. 트레일러의 컷·푸시인은 실제 게임 카메라가 아니다 | R4의 근거를 "트레일러 편집"으로 정정. 푸시인 2~3%는 우리 카메라 LOCK(거리만 변경) 안의 선택으로 유지 가능하나, PBZ 근거로 쓰지 않는다 |
| 11-03 PBZ 수치 전반 | 홍보 편집 영상 1편에서 잰 값 | 정점·코어 지속(R1)은 도타2와 겹쳐 유지, 카메라 관련(R4)만 근거 약함으로 표시 |

### 1.2 추정

- **무기 궤적·피:** 공개 자료에 궤적 길이·피 수치는 없다. 11-03 트레일러 실측(코어 75~83ms, 무광 적갈 피 `#532a1e~#682927`, 바닥 피 ≥3.5초, 따뜻한 백색 가는 스파크)이 유일한 근거라 [추정·자체 실측 1]이다.
- **왜 히트스톱을 뺐나:** 디렉터가 "입력 정밀함보다 빠른 흐름"을 택했다고 말했으므로(§2), 정지 프레임이 연타·패링 리듬을 끊는 것을 피한 선택으로 본다.

### 2.2 추정

- **예비·발동·회복 비율:** 공개 프레임 데이터 없음. 11-03 트레일러 실측의 예고 큐→접촉 117~397ms(7~24프레임), 큐 지속 33~150ms가 유일한 값 [추정·자체 실측 1].
- **"모션캡처 그대로"가 아니라 게임용으로 깎았다:** "입력 정밀함 포기"와 "빠른 흐름" 발언을 같이 보면, 캡처한 실제 무술 동작에서 예비동작을 줄이고 캔슬 지점을 넣은 것으로 본다.
- 감속(Ghoststep 때 시간이 느려짐), Ghoststep 뒤 1.5초 피해 +50% 같은 수치는 위키 1곳뿐 [추정].

### 2.3 탑다운 Unity 번역

- **판정과 모션의 관계:** PBZ는 "모션이 판정을 붙잡지 않는" 쪽을 택했다. 우리는 Core가 판정 틱을 정하고(전사 기검참은 입력 즉시 발사), 리깅 모션은 그 틱에 맞춘다(G1 §6). 규칙 4의 "블렌드 아웃 ≤3틱"이 이 원리를 표현 쪽에 옮긴 것이다.
- **패링 표현(2_3 설계 무변경):** 우리 E 칼등처내기 패링 창(앞 16틱)과 Q 방패는 그대로 둔다. 바꿀 수 있는 것은 성공 등급별 빛·스파크·소리(규칙 2)와 "반격 창이 열렸다"는 무기 표시(규칙 7)뿐이다.
- **무기 교체 콤보:** 우리 게임 시스템이 아니므로 옮기지 않는다. 원리만 남긴다: "콤보를 이어 가는 선택지가 많을수록 흐름이 산다."
- **NRFTW와의 공통점:** NRFTW 연구(5.1 `NRFTW_REFERENCE_STUDY_20261031`)의 "무게 있는 예비동작, 끝까지 가는 공격, 큰 동작 뒤 빈틈"은 **적·보스 쪽** 원칙이고, PBZ의 "빠른 흐름·캔슬"은 **플레이어 쪽** 원칙이다. 둘은 충돌하지 않는다: 플레이어는 가볍게 끊고, 적은 무겁게 커밋한다.

### 3.3 탑다운 Unity 번역

규칙 6의 4단계를 표로 둔다. 판정(경직 시간·포이즈)은 Core 값을 따르고 표현만 정한다.

| 단계 | 언제(Core) | 보이는 것 | 소리 |

### 4.2 추정

- **먹선 화풍의 위치:** 회상 장면(굵은 먹선 스케치)과 무림 지도(수묵화)에 쓰인다는 보도가 각 1곳씩 있다. 전투 이펙트 본체는 사실적 조명·입자로 보인다 [추정].
- 공식 VFX 색 팔레트·수치는 공개 자료에 없다.

### 4.3 탑다운 Unity 번역

- 우리 톤은 실버 헬(은빛 강철)이다. PBZ의 "어두운 세계 + 밝음은 접점에만"은 VFX 마스터 §2.7.2 원칙(국소 코어, 화면 나머지 어둠 유지)과 같으므로 그대로 확인한다.
- 잉크·먹선을 타격 이펙트에 넣지 않는다. 이유: ① PBZ도 전투 본체에는 쓰지 않는 것으로 보임 ② 1x 탑다운에서 가는 먹선은 점·잡티로 읽혀 4.2-7 점 금지와 충돌 ③ 탄막 가독성(§5 탄막 가림 0)을 해친다.
- 적 예고 색(파랑)은 가져오지 않는다(R8: 네온·시안 금지, 우리 뼈색·무지개 유지).

## 7. 남은 일

1. 임팩트 총괄: §0.1 제안(R3 유지 + 규칙 2·3 필수화, R4 근거 정정)을 판정해 VFX 마스터 §2.7.2b·G1 §8에 반영.
2. 패링 재기획 G1 담당: 규칙 2·5·7의 표현 틀을 G1 타이밍표 연출 열에 넣는다(설계 수치는 G1 담당 결정).
3. 보스 담당: 드루이드 채찍 연타 길이 변주(§5.3) 검토.
4. 사운드: 접촉·무게·꼬리 3층과 패링 금속음 믹서 그룹 분리(규칙 8)를 `6사운드디자인/` 장면 목록에 올린다.
5. 이 연구는 화면 패치 동결(11-05) 기간의 산출물이다. 실제 적용은 "살릴 것/버릴 것" 표와 사용자 결정 뒤 키샷 장면에서 한다.

## 8. 한계

- 이 클라우드 세션은 웹 페이지 본문을 열 수 없어(네트워크 허용 목록 밖) **검색 결과 요약으로만** 읽었다. 인용은 원문이 아니라 요약 기준이며, 원문 확인은 PC·Mac 세션에서 다시 해야 한다.

## 10. 도구·방식 결정안 (CTO 추가 요청 11-05: "어떤 도구로 어떤 방식으로 만들지 정확하게 정하라")

기준 환경(unity/main `0d7a4ac` 확인): **Unity 6000.6.7f1, URP 17.6.0, Cinemachine 6.6.0, VFX Graph 17.6.0, Timeline 6.6.0, Input System 1.20.1.** 오디오는 Unity AudioMixer(`Resources/Audio/Exoduser.mixer`, SFX 그룹 Tell·PlayerHit·Skill·Voice·EnemyHit·Death·Step·UI, Tell이 EnemyHit·Ambience를 −4dB 덕킹)가 이미 있다. VFX Graph 자산(`VFX_ImpactBurst`·`VFX_KiSlash`·`VFX_PoisonBurst` 등)과 `KiImpactView.cs`·`NativeGame.Impact.cs`가 현재 임팩트 진입점이다. FMOD·Wwise는 없다.

공통 원칙 3개 (모든 행에 적용):
1. **Core가 사건을 말하고 화면은 듣기만 한다.** 명중·패링·그로기 등은 Core 이벤트 틱에 맞춰 표현을 재생한다. 표현이 Core 시간·위치·판정을 바꾸면 FAIL(리플레이·oracle 결과가 표현 켜고 끈 상태에서 같아야 한다).
2. **`Time.timeScale`을 건드리지 않는다.** 전역 시간은 Core·탄·다른 적·UI를 함께 멈춘다. 멈춤이 필요하면 대상 하나의 표시만 멈춘다.
3. **정렬 순서 고정:** 적 예고 > 적 탄 > 플레이어 피격 표시 > 플레이어 타격 효과 > 장식(G1 §5). 어떤 도구를 쓰든 이 순서를 지킬 수 있는 출력만 고른다.

### 10.2 이 결정안의 미확인

- 필드 카메라가 Cinemachine 구동인지, 현재 카메라 흔들림·히트스톱 구현이 어느 파일에 있는지 이 세션에서 다 확인하지 못했다(sparse checkout, 원격 파일 검색 시간 초과). T2 추천은 그 확인 뒤에 확정한다.
- URP Decal 기능이 현재 Renderer 자산에 켜져 있는지 미확인(T8).

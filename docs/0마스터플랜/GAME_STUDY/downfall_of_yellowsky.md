# 게임 연구 — Downfall of Yellowsky《黄天逆途》(황천역도)

- 작성: 2026-11-05 레인 YS(클라우드, 연구·문서만). 근거: [DIRECTION_RESET_20261105](../DIRECTION_RESET_20261105.md) 2단계.
- **위상(11-05 사용자 확정, CTO 전달):** "분위기·광원·안개 등을 황천(=이 게임)처럼 만드는 게 지금 목표다." → **이 게임이 우리 최상위 분위기 기준**이다. 문서 우선순위: ① 분위기·광원·안개·색 보정(장면 유형별) ② 그것을 만든 렌더링 방식·도구 ③ 피치 34° 탑다운에서 같은 분위기를 내면서 먼 적을 지키는 법(카메라 LOCK 충돌 지점). 동작·UI는 짧게.

### 1.2 UE5라면 썼을 렌더 구성 [추정 — 엔진 자체가 미확인이므로 참고용]

아래는 **엔진이 UE5라고 가정할 때** 탑다운 다크 판타지에서 쓰는 일반 구성이다. 엔진이 미확인이고, 이 게임이 이 구성을 썼다는 공개 근거도 없다. 우리 URP 구성(1.4)은 이 표와 무관하게 우리 기준으로 정했으므로 엔진 판정 결과가 바뀌어도 유지된다.

| 층 | UE5 일반 구성 | 화면에 주는 것 |
|---|---|---|
| 전역광 | Lumen GI·반사(동적) | 주광이 바닥·벽에 튕겨 그림자 속도 색을 가짐(검정으로 안 죽음) |
| 주광 | Directional Light 1개 + Sky Light | 방향성 있는 광영, 긴 그림자 |
| 안개 | Exponential Height Fog(높이 감쇠) + Volumetric Fog | 지면에 고인 안개, 광원 주위 산란·빛줄기 |
| 국소광 | Point/Spot + 이펙트 발광 | 전투 순간 주변이 밝아짐(입자가 장면을 비춤) |
| 후처리 | Bloom·Exposure·Color Grading·Vignette·(DoF) | 하이라이트 번짐, 톤 통일. DoF·과한 Bloom은 "흐림" 평의 원인 후보 |

**우리 URP와의 차이(중요):** Unity 6 URP에는 Lumen 같은 동적 GI와 **기본 체적 안개(Volumetric Fog)가 없다.** 같은 결과를 내려면 1.4의 대체 구성을 써야 한다.

**카메라 LOCK과의 관계:** 이 게임은 시야 거리를 사용자에게 맡긴다. 우리 LOCK은 "피치 34° 고정, 보스 아레나는 거리만"이다. 거리 조절 자체는 LOCK과 충돌하지 않지만, 범위를 넓히면 먼 적 크기·안개 차폐가 바뀌므로 **데모 v0에서는 사용자 거리 조절을 넣지 않는다**(넣으려면 사용자 결정. 넣을 경우 기본값 ±10% 안에서만, 모든 거리에서 규칙 1·2·10 재판정).

**우리에게 주는 의미:** 이 게임의 분위기는 **3D 환경 + 실시간 광원**에서 나오는 것으로 보인다 [추정]. 우리 월드도 3D 지형·소품 + 실제 조명·안개(HD-2D)이므로 **환경 쪽은 그대로 같은 길**이다. 차이는 캐릭터(우리는 픽셀 RT)뿐이고, 캐릭터가 같은 주광·환경광을 받도록 픽셀 RT 카메라에 **같은 주광 방향·색**을 넣어야 "같은 장면에 서 있는" 느낌이 난다 [기준].

## 7. 도구·방식 결정안

전제: Unity 6000.6 URP, Mac M5 Pro(판정·빌드), PC 컴파일, Blender, 승인된 생성 도구(이미지·Kling·Meshy·Tripo — [API연결_가이드](../../API연결_가이드.md)), 유료 에셋은 사용자 승인. 확정은 사용자 승인 뒤(DIRECTION_RESET 3단계).

### 7.1 분위기 판정 기준판 만들기 (가장 먼저)

- (a) 이 게임: 공개 영상(실기 데모)과 고해상 스크린샷 2장.
- (b) 후보: ① **사람이 영상을 보고 장면별 "분위기 판정표"를 쓰는 방식**(추천) ② 영상 프레임 색 측정.
  - 추천 이유: 레인 규칙상 게임 파일·프레임 캡처 분석과 이미지 반입이 금지다. ②는 쓸 수 없다. 판정표는 말과 숫자만 남긴다.
- (c) 절차: 입력 = 공개 영상(사용자 또는 Mac 세션이 시청) → 장면 유형(A~D)마다 "주광 방향(시계 방향 표기)·색온도 느낌(차/중/따)·안개 위치(지면/중간/전체)·그림자 깊이(얕/중/깊)·하이라이트 위치·먼 쪽 처리" 6칸 기록 → 출력 = 이 문서 1.3 표 갱신 → Unity 반입 없음.
- (d) 합격: A·B·D 3장면 판정표 완성, 1.3 [기준] 값과 차이가 있으면 표를 고친다.

### 7.2 전역광·주광·그림자

- (a) 이 게임: 미확인(엔진 UE5는 단일 출처·원문 미재확인, Lumen은 그 위의 추정).
- (b) 후보: ① **APV 굽기 + 실시간 주광 1개 + SSAO**(추천) ② 완전 실시간(주광 + 환경광만).
  - 추천 이유: Lumen의 "그림자 속에도 색이 있는" 결과를 URP에서 가장 가깝게 낸다. 1-1은 정적 지형 위주. 비용 0. ②는 그림자 속이 평평해져 규칙 5를 맞추기 어렵다.
- (c) 절차: 1-1 장면 → Light Probe/APV 볼륨 배치 → 굽기(Mac) → Volume 프로필(장면 유형별 1개) → 출력 = `.asset` 프로필 + 굽기 데이터 → 반입: 캐스케이드 4, 그림자 거리 규칙대로.
- (d) 합격: 규칙 3·5 수치, 먼 적 3마리 캡처 L* 대비 ≥ 20, Mac 60fps(1920×1080).

### 7.3 높이 안개·대기 원근

- (a) 이 게임: 미확인(UE5라면 Height Fog + Volumetric Fog일 것이라는 추정뿐).
- (b) 후보: ① **커스텀 Full Screen Pass Renderer Feature + Shader Graph**(추천) ② 유료 체적 안개 에셋(예: Asset Store 체적 안개 계열 — 가격 미확인, 사용자 승인 필요).
  - 추천 이유: 적 레이어 상한(15%)·지형 마스크·먼 적 구역 감쇠 같은 **LOCK 전용 제어**를 직접 넣을 수 있다. 유료 에셋은 거리 안개 중심이라 C1·C2 충돌을 우리가 다시 막아야 한다. 비용 0, 구현은 Sonnet 서브에이전트 1개(브리프 파일, Core 수정 금지).
- (c) 절차: 입력 = 1.3 레시피 값 → Renderer Feature(깊이 → 월드 Y, 높이 감쇠, 주광 방향 산란 근사, 렌더 레이어 마스크) → 출력 = Feature 스크립트 + 머티리얼 + 장면별 파라미터 프로필 → 반입: URP Renderer에 등록, 후처리 전 단계(AfterRenderingTransparents 이전, 캐릭터 RT 합성 전).
- (d) 합격: 규칙 1·2·7, C1·C2·C4 체크, 레퍼런스 영상 옆 비교판 "같은 계열 분위기"(사람 판정) + 먼 적 보임.

### 7.4 빛줄기·국소광

- (a) 이 게임: 비공개(광영 좋음 평만).
- (b) 후보: ① **메시 카드(가산·깊이 페이드) + Point Light 소수**(추천) ② 화면 공간 빛줄기 Renderer Feature.
  - 추천 이유: 위치를 손으로 고정해 C7(주행로 가림)을 피하기 쉽다. 이미 HellLighting에 같은 계열이 있다. 비용 0.
- (c) 절차: 배치도(위에서 본 그림)에 빛줄기 위치 표시 → 카드 배치 → 출력 = 프리팹 → 반입: 정렬 = 투명, 깊이 페이드 0.5m.
- (d) 합격: 규칙 8, C7.

### 7.5 색 보정·후처리

- (a) 이 게임: 비공개. "흐림" 평이 있으므로 그 반대로 간다.
- (b) 후보: ① **URP Volume(Tonemapping 1개 고정 + LGG·SMH + Bloom + Vignette 마스크 제한)**(추천) ② 외부 LUT 제작(DaVinci 등)으로 LUT 반입.
  - 추천 이유: 장면별 프로필을 Unity 안에서 바로 비교판으로 판정할 수 있다. LUT는 확정 뒤 굳힐 때 선택. 비용 0.
- (c) 절차: 장면별 Volume 프로필 → 규칙 6·9 값 → 출력 = Volume Profile 에셋 → 반입: 전역 1 + 보스방 국소 Volume 1.
- (d) 합격: 규칙 6·9, DoF·그레인·색수차 0, 3x 크롭 점 0.

### 7.6 캐릭터 픽셀 RT의 광원 일치

- (a) 이 게임: 해당 없음(캐릭터도 같은 3D 장면 광원).
- (b) 후보: ① **픽셀 RT 카메라도 같은 주광·APV를 받게(같은 장면, 렌더 레이어만 분리)**(추천) ② 별도 스튜디오 조명.
  - 추천 이유: 이 게임처럼 "인물이 장면 빛 안에 서 있는" 느낌은 같은 광원에서만 난다. ②는 붙여 넣은 스티커처럼 보인다.
- (c) 절차: 렌더 레이어 분리 → RT 카메라 → 합성(안개 상한 15% 적용) → 출력 = 기존 픽셀 렌더 설정 갱신.
- (d) 합격: 숲·늪 두 장면에서 캐릭터 그림자 방향 = 지형 그림자 방향, 림 위치 일치.

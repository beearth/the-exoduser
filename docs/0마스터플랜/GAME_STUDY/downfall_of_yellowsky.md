## 0. 우리 게임에 바로 적용할 규칙 10개

## 2. 분석 — 무엇을 → 왜 → 어떻게 → 우리 Unity URP에서

> 이 게임에 대한 **기술 해설·개발 블로그·GDC 발표는 찾지 못했다.** "어떻게"는 공개 서술에서 확인된 것만 [사실]/[단일]로 적고, 나머지는 같은 결과를 내는 일반 기법을 [추정]으로 적었다.

### 2.1 (우선순위 1) 전투 임팩트 — 破刃 칼 맞대기

- **무엇:** 적과 칼이 맞부딪히는 순간을 독자 시스템 "破刃"으로 만들고, 바닥에 원형 충격파와 보라색 불꽃을 터뜨린다 [사실].
- **왜:** 기사 표현으로 "俯视角 플레이에 맞추기 위해" 시각 효과를 넣었다 [사실]. 탑다운에서는 칼날 각도가 안 보이므로 **'부딪혔다'는 사실을 바닥 평면 정보로 바꿔야 읽힌다.** 시연 평은 이를 "빠른 난타도 소울식 턴제도 아닌, 타이밍을 시험하는 전투"로 요약했다 [단일].
- **어떻게(공개 근거):** 원형 충격파 + 보라 불꽃이라는 구성만 공개됐다. 수치·셰이더 정보는 없다.
- **어떻게(추정):** UE5 Niagara로 바닥 정렬 링 메시(반경·알파 커브) + GPU 스파크 + 짧은 히트스톱/카메라 셰이크가 일반적이다 [추정].
- **우리 URP:** 
  1. 접점 위치는 **Core 패링 판정 이벤트**에서만 받는다(표현이 판정을 만들지 않음).
  2. 링: 평면 메시 + Shader Graph(URP Unlit, Additive, 반경·두께·알파를 머티리얼 프로퍼티로) — 바닥에 0.02m 띄우고 ZTest LEqual(가림 존중). Shuriken 파티클 1개(메시 렌더 모드, Size over Lifetime)로 구동하면 코드가 거의 없다.
  3. 불꽃: Shuriken Stretched Billboard 6~10개, 은백→청회 Gradient, Speed 8~14m/s, 수명 0.15~0.25초.
  4. 히트스톱: Core 시간은 멈추지 않고 **표현 레이어 애니메이터 speed만** 0.06~0.09초 0으로(규칙 8).
  5. 카메라: Cinemachine Impulse Source(진폭 작게, 0.12초).
  6. 캐릭터는 저해상도 픽셀 RT로 그리고 링·불꽃은 **풀해상도 월드 레이어**에 그릴지, 픽셀 RT 안에 그릴지는 4절 결정(추천: 링은 월드, 불꽃은 픽셀 RT 안 — 점 금지 규칙과 픽셀 톤을 같이 맞추기 위해).

### 2.2 보스 연출 — 카메라 늘이기·진법 장판

- **무엇:** 보스 대기술 때 렌즈를 당겼다 늘이며 강타 이펙트, 대범위 진법 영역 공격 [단일 — 17173 시연 해설].
- **왜:** 탑다운 고정 시점의 단조로움을 깨고 "큰 공격이 온다"는 신호를 카메라로 준다 [추정].
- **우리 URP:** 카메라 LOCK을 지켜 **피치 34° 고정, 거리만** Cinemachine 3 `CinemachinePositionComposer` 거리 블렌드로 +8~15%(규칙 6). 진법 장판은 Decal Projector(URP Decal Renderer Feature) + Shader Graph로 테두리 선행 → 안쪽 채움(규칙 7). 드루이드(1-1) 보스의 큰 동작 뒤 빈틈과 맞춰 "늘이기 → 강타 → 빈틈 동안 원위치"로 묶는다.

### 2.3 캐릭터·몬스터 동작

- **무엇:** "写实的动作设计(사실적 동작 설계)"[단일·백과], 공중 파생기 다수(조충곤 비유)[단일], 빠른 회피·검기 투사체[단일·Playfront].
- **약점(외부 평):** 기본 이동이 느려 보임[ResetEra·Playfront, 각 단일], "전투 손맛·콘텐츠·완성도 더 다듬어야"[단일·기사].
- **우리 URP:** 리깅 3D를 Animator로 돌리고 저해상도 RT로 픽셀화하는 우리 방식은 그대로. 배울 점은 **이동 속도 체감(규칙 4)**과 **공격 끝까지 가는 동작 + 큰 동작 뒤 빈틈**(이미 CLAUDE.md 보스 방향)을 같은 템포 표에서 관리하는 것. 이 게임의 공중 파생기는 우리 범위(1-1 데모) 밖이므로 보류.

### 2.4 아트 스타일·렌더링

- **무엇:** 완전 3D 실시간, 스타일라이즈드, 수묵화 요소, 전통 문양[사실/단일]. **3D→픽셀 처리는 없다.**
- **결론:** **우리 "리깅 3D → 실시간 저해상도 픽셀 렌더" 방식의 레퍼런스로는 쓸 수 없다.** 그 부분은 D4·PoE2 연구와 별도 기술 연구(픽셀 렌더 사례)로 채워야 한다. 이 게임에서 가져올 수 있는 것은 "작은 팀이 한 가지 문화적 모티프(황하·수묵)를 건축·의상·무기 전부에 일관되게 입힌다"는 **모티프 일관성** 원칙뿐이다 → 우리에게는 실버 헬(은빛 강철) 모티프를 바닥·소품·UI·패링 색까지 같은 언어로 묶는 규칙(규칙 2)으로 옮긴다.
- 화면 품질 변화: 2026-08 "画面质感升级" 고해상 스크린샷 2장(전투 1·아트 1) 공개[사실, 游侠·GamerSky]. 초기 데모 대비 1년 반 만에 "눈에 띄게 진화"[사실, 二柄·233乐园]. → **스크린샷은 전투 1장 + 분위기 1장으로 나눠 낸다**(우리 Steam 키샷 계획에 반영).

### 2.5 맵·환경·광원·안개·색

- **공개 근거 거의 없음.** "场景建模·交互式场景(상호작용 장면)"이라는 문구뿐[단일·3DM]. 광원·안개·색 수치는 추정할 근거가 없어 **적지 않는다.** 이 분야는 D4 연구(`D4_STUDY/01`)와 PoE2 연구를 따른다.

### 2.6 UI

## 4. 도구·방식 결정안

전제: Unity 6000.6 URP, Mac M5 Pro(판정·빌드), PC 컴파일, Blender, 승인된 생성 도구(이미지·Kling·Meshy·Tripo — [API연결_가이드](../../API연결_가이드.md)), 유료 에셋은 사용자 승인. **이 게임의 도구는 엔진(UE5, 단일 출처) 외에 공개된 것이 없다.** 그래서 (a)는 대부분 "공개 근거 없음"이고, 우리 결정은 우리 방식(픽셀 렌더)과 이 게임에서 배운 전투 가독성 기준으로 정했다. 확정은 사용자 승인 뒤(DIRECTION_RESET 3단계).

### 4.1 충돌·패링 임팩트 VFX (우선순위 1)

- (a) 이 게임: UE5(→ Niagara 추정). 공개된 건 "원형 충격파 + 보라 불꽃" 구성뿐.
- (b) 후보: ① **Shuriken + Shader Graph**(추천) ② VFX Graph.
  - 추천 이유: 이펙트 하나당 입자 ≤ 수십 개라 GPU 시뮬이 필요 없고, Shuriken은 URP·Metal에서 정렬·가림·RT 렌더가 가장 단순하다. VFX Graph는 대량 입자(비·재)에서만 쓴다. 비용 0.
- (c) 절차: 입력 = Core 패링 이벤트(위치·방향·종류) → Shader Graph 링 머티리얼 1개 + 스파크 프리팹 1개 + Cinemachine Impulse 1개 → 출력 = `Prefab`(VFX_Clash_Parry) + 타이밍 표(예고→접점→본체→잔여, `5.1임펙트디자인/`) → 반입: Additive, HDR 색, Bloom 임계 1.1, 링은 ZTest LEqual, 풀링(동시 4개).
- (d) 합격: 규칙 1·2·3 수치, 1x·3x 크롭에서 흰 원판·점 0, 먼 적 쪽 패링도 읽힘, 이전·이후 같은 장면 비교판 "나아짐".

### 4.2 보스 연출 카메라

- (a) 이 게임: 대기술 때 카메라 늘이기 + 강타(도구 비공개).
- (b) 후보: ① **Cinemachine 3 (PositionComposer 거리 블렌드 + Impulse)**(추천) ② 자체 카메라 스크립트.
  - 추천 이유: 피치 고정·거리만 변경을 설정으로 강제할 수 있고 Unity 기본 패키지라 비용 0. 자체 스크립트는 LOCK 위반 위험이 커진다.
- (c) 절차: 입력 = 보스 무브셋 표(동작별 예비동작·타격·빈틈 시간) → Timeline 또는 이벤트로 거리 블렌드(+8~15%) → 출력 = 카메라 프로필 에셋 → 반입: 피치 34° 값은 잠금 필드로.
- (d) 합격: 규칙 6, 늘이는 동안 먼 적이 화면 밖으로 안 나감, 10초 무음 영상 판정.

### 4.3 장판·예고(진법)

- (a) 이 게임: 대범위 진법 영역 공격(도구 비공개).
- (b) 후보: ① **URP Decal Projector + Shader Graph**(추천) ② 바닥 평면 메시.
  - 추천 이유: 3D 지형 굴곡에 붙고(평면 메시는 다리·늪 경계에서 뜸), 테두리→채움 진행을 머티리얼 파라미터 하나로 제어. 비용 0. Mac 성능은 1-1 키샷에서 확인.
- (c) 절차: Core 공격 범위(반경·각도) → 데칼 크기 1:1 → 출력 = 데칼 머티리얼 + 진행 커브 → 반입: Decal Renderer Feature(DBuffer 또는 Screen Space 중 Mac 측정 후 1개).
- (d) 합격: 규칙 7, 화면 범위 = Core 판정 범위(오차 ≤ 0.1m), 3x 크롭 테두리 계단·점 없음.

### 4.4 캐릭터·몬스터 동작(템포)

- (a) 이 게임: "사실적 동작 설계"(도구 비공개).
- (b) 후보: ① **Blender 키프레임 + Rigify**(추천) ② Cascadeur(물리 보조, 유료 플랜 있음·가격 미확인 → 사용자 승인 필요).
  - 추천 이유: 우리 리깅 3D → 픽셀 렌더 파이프라인이 이미 Blender 기준이고, 저해상도 픽셀 출력에서는 미세 물리 보정 차이가 거의 안 보인다[추정]. 무게감은 도구보다 **템포 표(예비동작·끝까지·빈틈 프레임)**가 결정한다.
- (c) 절차: 입력 = DESIGN LOCK + 동작 목록·타이밍 표 → Blender 애니 → 출력 = FBX(Y-up 변환, 30fps 베이크, 루트모션 분리) → 반입: Humanoid 또는 Generic(보스 Generic), Resample Curves off, 압축 Keyframe Reduction.
- (d) 합격: 규칙 4(이동 체감)·8, 발 미끄럼 ≤ 5%, 픽셀 렌더 결과로 판정(3D 뷰포트 판정 금지).

### 4.5 아트·렌더링(3D→픽셀)

- (a) 이 게임: **해당 없음**(완전 3D, UE5 단일 출처).
- (b) 결정 보류: 이 게임에서 근거가 없으므로 이 절에서 정하지 않는다. D4·PoE2 연구와 픽셀 렌더 사례 연구 뒤 매뉴얼에서 1개로 정한다. 이 문서에서 넘기는 조건 1개: **패링·임팩트 VFX가 픽셀 RT 안/밖 어디서 그려지는지 렌더 설계에 명시**(4.1 추천: 링=월드 풀해상도, 불꽃=픽셀 RT 안).

### 4.6 데모 영상·스크린샷

- (a) 이 게임: "100% 실기" 데모 1편 + 고해상 스크린샷 2장(전투 1·아트 1).
- (b) 후보: ① **Unity Recorder(Mac, 공용 실행기 무창·무음 캡처)**(추천) ② OBS.
  - 추천 이유: 실행기 규칙(창 0·소리 0)과 맞고 프레임 고정 캡처 가능. OBS는 창을 띄워야 한다.
- (c) 절차: 장면 목록 → Recorder(1920×1080 60fps, 3840×1080 별도) → 출력 = MP4·PNG → 편집은 컷만(렌더 컷·합성 금지).
- (d) 합격: 규칙 9, 첫 5초 전투 접점, 먼 적이 보이는 컷 포함, 점 금지 규칙 통과.

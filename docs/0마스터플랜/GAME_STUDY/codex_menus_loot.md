## 1. 읽는 법과 조사 범위

- **[사실]**: 연결한 공개 자료가 명시하는 기능·입력·변경 사항. 과거 자료에는 버전·시기를 붙였다. **[추정]**: 그 사실을 비교해서 얻은 해석·설계 시사점이며, 개발사의 의도를 확인했다는 뜻이 아니다.
- **미확인**: 조사한 자료에서 해당 정보를 확인하지 못했다는 뜻이다. 기능이 없다는 판정이 아니다. 특히 실제 글자 높이, 대비, 메뉴 애니메이션 시간, 최신 빌드의 모든 버튼 배열은 미확인이다.
- 공식 설명·지원 문서·패치 노트를 우선했다. 개발자 답변과 필터 제작자의 자기 설명도 사용했다. 보충적인 직접 플레이 가이드는 공식 규격과 구분하여 **[사실·관찰 자료]**로 표시했다. 아래 인용 링크의 D/P/L/H/X 식별자는 §9의 출처 목록에 연결된다.
- 게임 실행·로그인·유료 서비스·이미지 및 게임 파일 다운로드·에셋 삽입·영상 프레임 측정을 하지 않았다. 직접 인용 없이 요약했다. 따라서 이 문서에는 영상·이미지에서 측정한 숫자가 없다.
- 비교에서 ‘로비’는 접속 전 캐릭터·진행 선택 또는 출격 준비 공간을 뜻한다. **[추정]** 세 ARPG의 캐릭터 선택과 Hades의 거점은 기능상 비교할 수 있지만, 동일한 형태의 멀티플레이 로비라고 보면 안 된다. 근거: 캐릭터/계정 선택 안내와 Hades의 반복 도전 설명. [D2] [P1] [L1] [H1]

### 2.2 전리품 이름표·필터·빛·소리

- **[사실]** 기본 드롭은 애니메이션과 희귀도를 나타내는 색으로 전달한다. 드롭 시, 커서가 아이템 위에 있을 때, 바닥에 남아 있을 때의 오디오 단서를 구별하며 재생 대상 희귀도를 조정할 수 있다. 이름표의 정확한 RGB 및 전체 등급별 색 대응표는 이 공식 설명만으로 미확인이다. [D3]
- **[사실·과거 가이드의 색 명칭]** 기본 관례는 Normal 흰색, Magic 파랑, Rare 노랑, Legendary 주황, Unique 금색으로 서술된다. 이것은 가이드에 적힌 색 이름이며 최신 이름표를 직접 검사한 결과가 아니다. 이 자료의 등급 총개수·속성 수·장착 제한 설명은 현재 사양의 근거로 채택하지 않았다. [D11]
- **[사실·2024 사례]** Mythic Unique는 다른 드롭과 구별되는 빛기둥을 사용한다고 공식 시즌 안내가 명시했다. 해당 문장은 빛기둥의 정확한 색·높이·수명을 명시하지 않는다. 따라서 여기서 ‘보라 RGB’나 몇 초라는 값을 보충하지 않는다. [D6]
- **[사실·3.0 안내]** 장비 필터는 표시·숨김·재색상을 지원하며, 바닥뿐 아니라 인벤토리·보관함·상인의 장비에도 관련 표시를 적용한다. 비장비 재료·보석·화폐 등에는 적용되지 않는다. 위쪽 규칙이 아래보다 우선하며 필터를 끄면 숨긴 바닥 장비를 확인·습득할 수 있다. [D2]
- **[사실·3.1 시즌 설명]** Mythic은 독립 희귀도 대신 변경 가능한 품질로 설명된다. **[추정]** 옛 화면의 ‘색=단일 희귀도 단계’만 복제하면 현재의 희귀도·품질·사용자 필터 색을 혼동할 수 있다. [D7] [D2]

### 2.3 툴팁 정보 위계와 입력

- **[사실·관찰 자료]** 인벤토리 또는 보관함에서 대상 아이템을 가리킨 뒤 PC Shift, PlayStation △, Xbox Y로 착용 장비와 비교한다. 비교값의 증가를 녹색으로 표시한다. 이는 해당 가이드의 기본 입력 설명이며 사용자 재지정까지 검증한 결과는 아니다. [D8]
- **[사실·2.1]** 현재 클래스에서 작동하지 않는 속성은 비활성으로 표시하고 사용할 수 있는 클래스를 아이콘으로 알리도록 변경했다. **[사실·2.5]** 명품화의 Refinement도 툴팁에 표시하도록 변경했다. [D9] [D10]
- **[추정]** 읽기 순서는 `이름·분류 → 기본 성능 → 속성·고유 효과 → 현재 장비와의 차이 → 사용 조건·가공 상태`로 설계할 근거가 있다. 이것은 비교·제약·가공 정보를 종합한 연구상의 위계이며 최신 툴팁의 실제 픽셀 순서를 그대로 전사한 것은 아니다. [D8] [D9] [D10]
- **[사실·2020 개발 설명]** 키보드/마우스와 컨트롤러의 배정 유연성, 콘솔 협동 중 양쪽 플레이어가 관련 UI를 동시에 열 수 있는 설계를 다뤘다. **[추정]** PC의 호버 설명을 콘솔에서는 포커스 선택과 명시적인 비교 버튼으로 대응시키는 것이 핵심 비교점이다. [D5] [D8]

### 3.2 전리품 이름표·필터·빛·소리

- **[사실·관찰 자료]** Ctrl+좌클릭은 소지품/보관함의 스택 이동, Shift+좌클릭은 스택 분할이다. UI의 Show Full Descriptions와 소켓 표시도 따로 설정한다. [P4] [P3]
- **[추정]** 아이템 읽기에서는 `아이템 정체성 → 기본 속성·소켓 → 개별 옵션 → 사용 조건`, 스킬 읽기에서는 `행동 요약 → 젬/서포트 조합 → 상세 계산·키워드 설명`을 나누는 것이 타당하다. 전자는 정보 설계 제안으로, 모든 아이템 툴팁의 실제 세로 순서는 미확인이다. [P2] [P3] [P5]
- **[사실·0.2.0]** 패드의 지도 이동, 빠른 아이템 이동, 협동 중 UI 패널 행동 및 스킬 도중 아이템 습득을 개선했다. **미확인**: 최신 빌드의 동적 입력 전환 조건 및 모든 비교/고급 설명 패드 버튼. ‘접속 화면에서만 입력을 바꿀 수 있다’는 과거 설명을 현재 사실로 쓰지 않는다. [P5]

### 7.4 나중에 측정할 경우의 기록 방법 — 이번 조사에서는 미실시

- **[사실·방법 근거]** XAG 101은 최고 ascender부터 최저 descender까지의 보이는 높이를 측정하는 방식을 설명한다. **[추정·연구 절차]** 원본 해상도·UI 배율·언어·플랫폼·버전·자료 URL을 고정하고, 글자/행 박스/테두리를 구별해 `보이는 글자 높이 [추정]`으로 기록해야 한다. 축소된 웹 썸네일로 엔진 폰트 크기를 역산하지 않는다. [X1]
- **[사실·방법 근거]** XAG 102는 전경과 배경의 대비를 구별하며 배경·불투명도·테두리 조절을 제안한다. **[추정·연구 절차]** 이름표는 밝은 바닥·어두운 바닥·효과가 겹치는 상황의 합성 결과를 따로 기록하고, 압축 영상이나 HDR→SDR 변환 자료의 결과는 원래 게임 대비가 아닌 `자료상 대비 [추정]`으로 한정해야 한다. [X2]
- **[추정·연구 절차]** 전환은 ‘화면 변화 시작→시각적으로 정착’과 ‘선택 확정→다음 입력 수락’을 별개로 재야 한다. 향후 영상 측정값을 넣는다면 URL·시작/종료 타임코드·실제 프레임률·프레임 수·로딩 포함 여부·경계 판독 오차를 함께 써야 한다. 입력 시점이 없는 영상에서는 입력 지연을 측정할 수 없다고 남긴다. UI의 화면 전환과 포커스/단계적 닫기가 별개임을 보여 주는 근거: [L2] [H3]

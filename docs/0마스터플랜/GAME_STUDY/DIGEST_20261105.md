# 게임 연구 요약

입력만 종합하고 불일치 수치는 제외했다. 화면 직접 판정은 아니다. 코드 항목은 체크리스트 작성 시점 기준이라 이후 병합은 빠졌을 수 있다.

## 게임별 배운 것

**D4(디아블로 4)**

- 작은 장식보다 큰 지형과 길을 먼저 잡는다.
- 배치·재질·빛을 바꿔 소품 반복감을 줄인다.
- 나무 뒤에서도 내 위치를 알아야 한다.
- 화려한 효과보다 적과 위험이 먼저 읽혀야 한다.
- 체력·기술·상태를 묶어 한눈에 보여 준다.

**PoE2(패스 오브 엑자일 2)**

- 어두운 분위기와 적이 안 보이는 화면은 구별한다.
- 빛은 배경·인물·장소마다 역할을 정한다.
- 주변에 반사된 빛의 효과를 과장하지 않는다.
- 내 기술이 적 공격과 바닥 위험을 덮으면 안 된다.
- 과거 작품의 제작법을 후속작 사실로 옮기지 않는다.

**황천(黄天逆途, 황천은 사용자 별칭)**

- 분위기·빛·안개의 목표로 삼되 영상을 먼저 본다.
- 흐림과 인물·배경의 뒤섞임도 함께 살핀다.
- 엔진은 UE5로 보임(2024-09 개발사 모집글 '引擎：虚幻5' 1건, Mac이 원문 확인) — 현재 유지·버전·Lumen 등 세부는 미확인. 조명·안개 제작법도 확인되지 않았다.
- 상점의 이용자 분류표는 실제 제작 방식의 증거가 아니다.
- 팀 규모·기간 보도를 우리 완성 일정으로 바꾸지 않는다.

**팬텀블레이드 제로**

- 공격과 방어가 매끄럽게 이어지는 흐름을 배운다.
- 맞힌 순간의 동작·빛·소리를 함께 맞춘다.
- 막기·회피·반격의 결과를 구별해 보여 준다.
- 홍보 영상의 카메라를 실제 전투 카메라로 보지 않는다.
- 이용자 수정판의 존재로 원작의 정지 시간을 단정하지 않는다.

**기타(하데스·데드 셀·소규모 팀 사례)**

- 동작은 그림 수보다 핵심 자세와 박자가 중요하다.
- 위험 소리가 다른 소리에 묻히지 않게 한다.
- 필요한 정보부터 보여 주고 상세 정보는 따로 연다.
- 대표 구간을 끝까지 만든 뒤 제작 범위를 정한다.
- 핵심 인원과 외부 협력자, 시제품과 완성판을 구별한다.

## 제일 먼저 고칠 것

데모 v0 제안. **화면 패치 동결 중: 아래 착수는 사용자 승인 필요.**
카메라 34° 고정(LOCK·확인: 입력 확정 결정)을 유지한다. 공격 차례를 제한하는 ‘어택 티켓’을 넣지 않고 규칙·판정도 유지한다.

1. 가림 처리 확인·마무리: 들어온 반투명을 먼 적·영웅이 보이는지 화면으로 판정한다.
2. 첫 장면의 빛·안개·바닥 연결: 현재 구도로 Steam 대표 화면·첫인상을 만든다.
3. 위험 예고·특수 적 표시: 공격 규칙을 바꾸지 않고 대응할 정보를 준다.
4. 전리품 이름·획득 알림: 발견부터 보상 확인까지 이어지게 한다.
5. 데모 배포 묶음 정리: 연결된 자료를 확인한 뒤 설치·로딩 부담을 줄인다.

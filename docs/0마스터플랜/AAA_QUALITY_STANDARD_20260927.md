## 2026-10-29 실행 규칙 — 시각 완성도와 재작업 책임

사용자 지시: “보스디자인은 전체 리마스터 리모델링 해야한다니까”, “완성도높은 디자인은 죽어도 안나오네”, “md를 해두던가 작업물이 다 어설프고 대충대충만들고 심각하다”. 기존 AAA 목표를 현재 제작·인수·완료 판단에 아래처럼 적용한다. 이 문서를 쓴 사실은 작업물 개선 실적이 아니다.

### 제작 전·후에 반드시 하는 일

1. 현재 실제 게임 화면·동작, 해당 시스템 SSOT·DESIGN LOCK, 사용자가 제공한 품질 참고를 먼저 확인한다. 참고의 구도·명암·재질·동작 원리를 분석하고 EXODUSER의 정체성에 맞게 적용한다. 다른 게임의 자산·고유 디자인을 반입하거나 복제하지 않는다.
2. 지금 결과에서 가장 크게 완성도를 낮추는 결함을 구체적으로 정한다. “더 고급스럽게”, “AAA 느낌”으로 끝내지 않고 해당 위치·원인·고칠 방법을 제작자가 실행할 수 있게 적는다. 후보 선택·세부 조정은 담당이 판단하며 같은 질문을 사용자에게 반복하지 않는다.
3. 구현한 후보를 실제 게임에 연결해 전체 화면과 1x 세부를 직접 본다. 장식·디테일을 추가하기 전에 구도·실루엣·명암·비례·재질·접지를 바로잡는다. 한 장의 확대 렌더만으로 게임 화면의 완성도를 판정하지 않는다.
4. 움직이는 대상은 영상이나 연속 프레임으로 검수한다. 정지 PNG로 동작의 무게·부드러움·발 미끄러짐·전환을 PASS하지 않는다. 소리는 실제 청취 전 음질·타격감 검수 완료로 기록하지 않는다.
5. 발견한 결함은 제작자가 수정하고 총괄이 같은 후보를 다시 확인한다. 실행 조건이 막히면 승인된 다른 경로와 독립 제작을 계속하고, 못 한 실행·판정만 미검증으로 남긴다. 안전 기준을 낮추거나 같은 원인의 실패를 무한 반복하지 않는다.

### 합격선 — 기준 샘플과 단계별 탈락 조건

2026-10-29 사용자 추가 지시: “작업물 퀄리티 뭔가 기준을 만들어야할듯 너무 들쑥날쑥도 아니고 최악으로만 만들어”. 아래는 제작자가 스스로 매기는 점수표가 아니라 **실제 결과의 최소 인수선**이다. 이전 후보보다 좋아졌다는 사실이나 비용·제작 시간이 적다는 사실은 합격 근거로 쓰지 않는다. 알려진 중대한 결함을 다른 항목의 장점으로 상쇄하지 않는다.

#### 비교 기준을 먼저 고정한다

| 기준 | 현재 기준 자료 / 역할 |
|---|---|

| 내부 완성도 기준 샘플 | 현재 보스의 실제 게임 장면에서 확정된 완성 샘플은 없다. 현재 후보를 편의상 합격 예시로 지정하지 않는다. 기존 아트 채택 절차와 아래 검수를 통과한 첫 실제 게임 장면·동작을 정확한 SHA·화면·조명·카메라와 함께 고정하고 후속 보스의 마감 비교에 사용한다 |
| 불합격 예시 | 드루이드 `body_game.png`의 넓은 수평 어깨·갑옷 같은 흉곽·튼튼한 팔다리. `gaunt_v2_game.png`는 비율 탐색 자료이며 완성 샘플이 아니다. 두 파일은 `I:/EXODUSER-Storage/codex-takeover/design/druid_review/`에 보존한다 |

#### 한 단계라도 핵심 결함이 있으면 다음 마감으로 넘어가지 않는다

| 순서 / 평가 축 | 최소 합격선 | 즉시 FAIL 또는 미검증으로 남길 조건 |

UI는 위의 정체성·구도·재질·조명·게임 가독성을 자신의 화면 계약에 맞춰 적용하고, 5번은 선택·호버·누름·비활성·화면 전환과 입력 피드백으로 검사한다. 맵·VFX·사운드는 기존 전문 SSOT의 상세 검수를 추가한다. 이 표로 맵 생산 순서·충돌 계약·보스 Core 수치를 바꾸지 않는다.

#### 판정의 의미와 제작 중단점

- **미검증:** 필요한 대상·장면·동작·청취 증거가 없다. 확인한 일부 항목을 기록하되 전체 등급을 올리지 않는다.
- **FAIL:** 콘셉트·큰 형태·재질·동작 등 핵심 축에 위의 결함이 있다. 디자인 채택 대상에서 제외하고 원인이 있는 제작 단계로 돌아간다. 실루엣 실패를 조명·색·발광·폭 축소로 반복 포장하지 않는다.
- **RETOUCH:** 평가한 범위의 정체성과 큰 형태가 이미 성립하고, 남은 결함을 부위·원인·수정 방법으로 한정할 수 있다. 완성으로 보고하지 않는다. ‘정적 비율 탐색 RETOUCH’와 ‘게임용 보스 RETOUCH’는 서로 다른 평가다.
- **PASS:** 평가 범위를 명시하고 적용 항목 모두가 위 최소선을 충족하며, 확인된 품질 결함이 없고 필요한 실제 화면·동작 증거가 있다. 대상이 아직 실게임 미검증이면 ‘모델 형태 PASS’처럼 부분 판정만 가능하다. 전체 보스 완료·사용자 채택·배포로 확대하지 않는다.
- 같은 핵심 결함을 같은 방법으로 고친 두 후보가 연속 FAIL이면 제작 방법을 바꾼다. 큰 형태가 문제면 실루엣·조형 단계로, 재질이 문제면 재질 분리/마스크·텍스처 단계로 돌아가며 세 번째 비슷한 후보를 양산하지 않는다. 원본은 보존하고 유료 상한을 임의로 늘리지 않는다.
- 한 보스의 형태 합격 전에는 나머지 보스로 같은 제작법을 대량 전파하지 않는다. 이후 전문 담당의 독립 작업은 계속하되 첫 보스의 모델→리그→모션→실게임 마감이 연결된 결과를 완성도 기준으로 삼는다.
- 기존 정책이 RETOUCH 기술 통합을 허용하는 경우의 통합 여부는 기존 담당이 판단한다. 이 절은 거절된 아트를 승인하거나 RETOUCH를 완료로 승격하는 근거가 아니다.

| 원본 본체 / 형태 | 넓은 수평 깃털 어깨, 갑옷처럼 부푼 흉곽, 굵은 팔·발, 정면 대칭 직립 | 현행 LOCK v0.4의 형태 FAIL. 기준 샘플·런타임 채택 대상으로 쓰지 않음 |
| v2 / 정적 비율 탐색 | 원본보다 폭은 줄었으나 정면 직립·대칭 외투·견고한 발이 남고, 측후면·변형·실게임 모션은 이번 CTO 관찰에 없음 | 탐색 자료로만 보존. 최종 본체 합격 근거 없음. 처진 비대칭 어깨/굽은 체중선·꺼진 흉곽·가느다란 손발을 실제 조형한 형태 후보를 제작자가 다음 산출물로 제출 |
| 게임용 보스 전체 | 현재 자료에는 지팡이를 잡고 실제 3D 보스방에서 대기·보행·내려찍기를 하는 증거가 없음 | 미검증. 형태를 통과한 같은 후보의 리그·재질·실게임 동작으로 다음 단계 검수 |

이 예시의 FAIL과 미검증을 표준의 불합격 앵커로 사용한다. 비율 탐색의 개선을 부정하거나 폐기하는 뜻은 없으며, 그 개선을 완성된 아트의 합격으로 잘못 읽는 것을 막는다.

숫자·자동 검사·재질 파라미터는 보조 근거다. 위 항목의 실제 화면·동작을 직접 확인한 판정을 대신하지 않는다. 최신 게임별 LOCK·SSOT가 구체 수치·색·타이밍의 정본이며 이 표로 임의 변경하지 않는다.

### 증거와 책임

- 제작 담당: 자기 후보 SHA·실행 경로·변경 장면의 1600×900 이상 전체 캡처와 1x 세부를 연결하고 직접 확인한다. UI·화면 비율을 바꾼 경우 해당 비율도 확인한다. 보스 동작은 기존 SSOT의 실제 게임 카메라에서 영상 또는 연속 프레임을 붙인다. 강제 상태·검수용 조명·모형 화면은 실제 플레이와 구분한다.
- 디자인 총괄: 같은 후보를 직접 보고 `VISUAL VERDICT: PASS / RETOUCH / FAIL`을 판정한다. RETOUCH/FAIL에는 눈에 보이는 결함·담당·다음 수정 산출물을 적고 재작업을 이어간다. 맡은 총괄이 자리를 비운 동안 기존 정책이 담당 Codex의 자체 판정을 허용하면 검수자와 그 범위를 명시한다. 별도 검수자 확인을 했다고 꾸미지 않는다.
- 기술/통합 담당: 소스·oracle·컴파일·빌드·Player·디자인·원격 반영을 각각 보고한다. 기능 검증이 통과해도 디자인 미검수이면 그대로 적는다. 기존 통합 정책이 RETOUCH 후보의 반영을 허용할 때는 기능·성능·시각 회귀 조건을 확인하고 반영하되, 품질 상태와 후속 재작업을 유지한다. 이 규칙은 새 병합 중단 조건을 만들지 않는다.
- 최종 완료: 승인된 작업 범위가 구현되고, 필요한 기술 검증과 실제 화면·동작 검수가 충족되며, 알려진 품질 결함이 해소됐을 때만 완료로 보고한다. 사용자 아트 채택·유료 생성·배포의 기존 승인 경계는 그대로 지킨다.
- 보고는 기존 보드·SSOT·REPORT에 `후보 / 실제로 본 근거 / 판정과 구체 결함 / 수정 담당·다음 산출물 / 통합 단계`를 짧게 남긴다. 매번 새 계획·역사 문서를 만들거나 문서량을 진척으로 세지 않는다.

### 현재 보스 작업의 범위

전체 보스를 디자인 리마스터·3D 리모델링한다. 주 범위는 모델·리깅·Animator·움직임·공격 템포·예고·VFX/SFX·등장/퇴장 연출과 실제 게임 검수다. 개별 버그 검사나 기존 2D 시트의 피상적 조정으로 목표를 축소하지 않는다.

기존 순서·정본은 `docs/engine/UNITY_BOSS_BATTLE_BOARD_20261026.md` §8, RM-B1~B4 문서와 보스별 DESIGN LOCK이다. 드루이드 기존 모델·리그를 실제 게임에 연결해 외형·기본 이동·승인 공격 동작을 완성하는 것부터 진행한다. No Rest for the Wicked는 무게·동작 감각의 참고이며 EXODUSER의 세계관·미술 방향을 유지한다. 전체 보스 리모델 승인과 보스별 유료 생성 상한은 별개다.

사용자 제공 캐릭터 선택 화면은 재질·조명·배경·UI가 한 장면으로 맞물리는 완성도 참고다. 원본은 PC 저장소 `I:/EXODUSER-Storage/codex-takeover/cto-quality-20261029/user-quality-reference.png`에 별도 보존하며, 제3자 화면을 프로젝트 에셋으로 사용하지 않는다. 문서 보존과 작업 배정만으로 현재 결과가 이 수준에 도달했다고 선언하지 않는다.

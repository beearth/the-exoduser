## 2. 성능 원본 인수

`tmp/qa-perf-20261001/`의 QA JSON을 직접 읽었다. 다음은 `COMBAT2` 구간의 원본 값이다. 모두 해상도 1920×1080, 목표 적 수 120으로 기록됐으나 실제 적 수·부하와 계측 조건이 같지 않다. `valid:true`는 개별 측정 도구의 유효성 결과이며 인과 비교 조건 일치를 보장하지 않는다.

횟수는 각 샘플 내 횟수이며 시간당 빈도로 환산하지 않았다. B0b의 측정 콘텐츠 SHA-256은 `b82e6824baf4f194542de208427d733722f6a89a553da6153e99ea9a45cd9fa5`, B2/C1은 `9a8258e5bdadcc485eeb57e31f3b210e12f0c64e166f6953f756f18ccaf9a127`이다. C1 실행 시 디스크/정적 응답 SHA와 별도 측정 variant SHA도 달라, 현재 배포본의 성능이라고 단정하지 않는다.

다른 샘플인 A4-disk-1080-warm의 COMBAT은 시스템 CPU 94.9%, 최대 간격 662.9ms가 기록됐다. 동시 부하가 성능 해석에 중요하다는 관찰이며, 그것만으로 게임 자체 병목이 없다고 판단하지 않는다. 추가 게임 실행이나 새 대형 빌드는 총괄이 시작하지 않았다.

**총괄 판정:** 전체 최적화 완료 미확정. 유효한 비교 묶음, 장시간 긴 프레임의 원인 분리와 실제 통합 패키지 검수가 남았다.

## 4. 승인 대기와 후속 인계

BUILD의 실제 CLI에는 빌드 스크립트·증거 도구·패키징 문서·팀 MD의 네 파일만 `git add` 하는 권한 승인 질문이 표시됐다. 총괄은 필수 도구 승인을 대신 누르지 않았고, 같은 명령을 다른 경로에서 실행하지 않았다. 이 시점의 `git diff --cached --name-only` 출력은 비어 있었다. 향후 승인 여부와 스테이징은 새 상태로 확인해야 한다.

ENEMY 다음 작업 지시 전송·착수, QA 보고·빌드 인계 요구의 대기열 등록, BALANCE 연속 진행 수신, SOUND 클라우드 후속 작업 실행을 실제 UI로 확인했다. 다른 활성 팀에는 중복 진행 지시를 보내지 않았다. 10분 후속 관리 자동화 `exoduser`는 기존 활성 상태를 유지한다.

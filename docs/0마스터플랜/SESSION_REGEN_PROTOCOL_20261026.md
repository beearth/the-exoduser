- 각 세션: 작업 단위가 끝날 때마다 `get_usage`(session_id `self`)를 1회 호출한다. 턴마다 호출하지 않는다.

- CTO: 사용자가 말을 걸 때마다 전 세션을 훑어보고, 임계값을 넘은 세션에 재생성을 지시한다.

## 4. 재생성 절차

### 4.1 인계 문서 작성 (공통, 필수)

경로: `docs/0마스터플랜/session_handoff/<역할>.md` (예: `map-lead.md`, `simple-sonnet-3.md`). 매번 덮어쓴다. 120줄 이하로 쓴다.

```
# <세션 제목> 인계 — <날짜 시각>
- 세션 id / 모델 / 역할 한 줄
- 기준 문서(SSOT) 경로
- 진행 중 작업 단위: 이름 · 현재 단계 · 남은 일 · 산출물 경로
- 대기 중: 누구에게 무엇을 요청했고 무엇을 기다리는지
- 소속·연결 세션: 이름 + id (단순 세션, 상위 총괄, CTO)
- 이번 대화에서 확정된 결정·사용자 지시 (메모리·docs에 아직 없는 것만)
- 금지·주의 사항
- 재개 후 첫 행동 1~3개
```

대화 기록을 붙여 넣지 않는다. 이미 docs나 메모리에 있는 내용은 경로만 적는다.

### 4.2 방식 A — 자기 자신 비우기 (기본)

1. 인계 문서를 쓰고 커밋한다(`git commit <경로>`).
2. 재개 담당에게 SendMessage를 보낸다. 재개 담당은 단순 세션이면 소속 총괄, 총괄이면 CTO(`local_7072229c-70cf-4fdf-ab35-c3c59e683d53`)다. 내용은 "재생성합니다. 인계 문서 <경로>. 비워진 뒤 재개 메시지 부탁"이다.
3. 그 턴의 마지막 호출로 `clear_session`(session_id `self`)를 부른다. 같은 id·모델·권한·고정 상태가 그대로 유지되므로 메모리와 보드의 id를 고치지 않아도 된다.
4. 재개 담당은 `SendMessage(to=<id>, notify_when_idle: true)`로 기다렸다가 `get_usage`로 컨텍스트가 줄었는지 확인한다. 줄었으면 "`docs/0마스터플랜/session_handoff/<역할>.md`와 MEMORY.md를 읽고 재개"라고 보낸다.
   - 줄지 않았으면 비우기가 취소된 것이다(그 사이 메시지가 먼저 도착한 경우 등). 그 세션에 다시 3단계를 요청한다.

### 4.3 방식 B — 부모가 자식 비우기

총괄이 직접 띄운 단순 세션이 idle이고 고정되지 않았으면, 총괄이 `clear_session(<자식 id>)`을 부르고 재개 메시지를 보낸다. 자식이 인계 문서를 먼저 써 둬야 한다.

### 4.4 방식 C — 비우기가 거부될 때 (후임 세션 교체)

Remote Control 연결이나 고정 상태 때문에 `clear_session`이 거부되면 CTO에게 보고한다. 다른 세션의 메시지로 시작된 턴에서는 새 세션을 만들 수 없기 때문이다.

1. CTO가 사용자 대화 턴에서 후임 세션을 만든다. `context: "fresh"`(fork 금지), 같은 모델·권한 모드, 제목은 "<원래 제목> #2"로 하고 브리프에 인계 문서 경로를 넣는다.
2. 구 세션은 소속 자식 세션을 `detach_session`으로 떼어 낸 뒤 보관한다. 부모를 보관하면 자식도 함께 보관된 사고가 있었다.
3. 메모리·보드·CLAUDE.md에 적힌 세션 id를 새 id로 바꾼다.

### 4.5 앱 제약 (2026-10-26 실측)

- 한 세션은 사용자가 마지막으로 입력한 뒤 다른 세션에 메시지를 **10건까지만** 보낼 수 있다. 11건째부터 거부된다. 재개 메시지와 통보는 꼭 필요한 대상에게만 보내고, 공지는 이 문서 경로 하나로 대신한다.
- 다른 세션의 메시지로 시작된 턴에서는 `start_session`이 거부된다(제안 카드만 가능). 그래서 후임 세션 생성(§4.4)은 CTO가 사용자 대화 턴에서 한다.
- 처리 대기 중인 메시지가 있으면 `clear_session("self")`가 거부된다("a clear would erase it"). 대기 메시지를 처리한 턴의 끝에서 다시 호출한다.
- 메시지 10건 상한 때문에 CTO의 재개 메시지는 사용자가 CTO에 다음으로 입력할 때 한꺼번에 보낸다. 그 전까지 비워진 세션은 idle로 대기한다(작업 손실 없음).
- Remote Control이 켜진 세션에는 `notify_when_idle`을 쓸 수 없다. 재개 담당은 `get_session`으로 대상의 `isRunning`이 false가 된 것을 확인한 뒤에 재개 메시지를 보낸다. 대상이 아직 작업 중일 때 보내면 비우기가 취소된다.
- idle 세션은 프로세스가 내려가 `get_usage`로 컨텍스트를 읽을 수 없다. 비워졌는지는 재개 메시지를 받은 세션이 스스로 `get_usage(self)`로 확인해 보고한다.

## 5. 금지

- `context: "fork"`로 새 세션을 만들지 않는다. 긴 대화가 통째로 복사된다. 디자인 총괄 `a1efbc31`은 생성 18분 만에 329K였다.
- 같은 역할의 Opus 세션을 둘 이상 두지 않는다. 지금 디자인 총괄 2개(`a1efbc31`, `eb8a8577`)가 동시에 돌고 있다.
- 인계 문서에 대화 기록을 붙여 넣지 않는다.

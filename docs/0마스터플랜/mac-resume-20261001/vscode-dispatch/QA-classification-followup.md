# QA 후속 한 건 — 진단 유효성과 비교 기준점 분리

기존 QA T1 세션에서만 이어간다. 이전 배정의 쓰기 소유권·게임 금지·원자료 보존·Git 쓰기 금지를 유지한다. 현재 HEAD 94b47f87은 root 배정 문서만 추가했으며 생산 소스는 30a204a7 기준과 같다.

총괄 검수에서 baseline_raw_validator.mjs가 품질 변화 caveat를 경고로 알리지만, 최상위 `valid:true`와 `VALID`, exit0 및 “유효한 기준점” 문구가 진단 유효성과 고정 조건 비교 자격을 혼합하는 것을 확인했다. normal-first-kill 원자료는 atmos1→2·프로파일러/관측 오버헤드·입력/막타 한계가 있다. 이 자료를 보존하며 명확히 분류한다.

1. 출력 JSON·콘솔·계획·result에서 `diagnosticValid`와 `comparisonEligible`(또는 동등한 명시적 분류)를 분리한다. 구조가 유효해도 품질 변화·최종 옵션 부재·계측 조건/대조 입력 미확인 상태는 비교 적격 PASS가 될 수 없다. true/false/unknown을 구분하거나 미입증은 false와 구체 사유로 표시한다. 스냅샷 동일만으로 측정 내내 고정됐다고 주장하지 않는다.
2. 구조검사 exit0은 진단 자료의 검사 성공임을 분명히 한다. 비교 적격을 요구하는 별도 CLI 모드와 실패 종료 코드를 제공한다면 그 계약을 테스트한다. 기존 `valid` 별칭을 유지하면 진단 전용임을 표시한다.
3. 실제 atmos1→2 raw는 진단 보존 가능하지만 비교 부적격으로 분류되는 회귀, 최종 옵션 누락, profiler/계측 조건 미기록·불일치, 미확인 대조 조건이 비교 PASS가 되지 않는 부정 fixture를 추가한다. fixture 입력을 실제 원자료처럼 꾸미지 않는다. 실제 raw와 테스트용 메타데이터는 분리한다.
4. `trusted` 입력이 사람의 물리 입력/막타 피해원 증명이 아니며, fpsCap=0이 GPU 완료·표시 FPS나 매 루프 draw를 증명하지 않는다는 경계를 문구에 반영한다. PC329ms 또는 과거 ring97ms 해결 주장 금지. 새 측정 release는 계속 없다.

완료 후 QA-result.md와 QA-receipt.json을 갱신하고 실행 명령·결과를 한국어로 보고한다. 다른 팀·생산 파일은 수정하지 않는다.

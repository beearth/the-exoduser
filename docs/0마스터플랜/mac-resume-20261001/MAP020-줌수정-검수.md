# MAP-020 실제 줌 draw/cull 수정·Mac 재검수 — 2026-10-01

**이번 그림자 사각 절단·뿌리 조기 소거 결함: VISUAL VERDICT PASS. 전체 MAP-020: RETOUCH 유지.** 남쪽 같은 카메라의 실제 .62줌에서 사각형 절단이 사라졌고 화면 가장자리의 뿌리가 이어진다. 같은 재질의 반복과 M5 주머니 전체 경로 미확인은 남아 있다. PC 첫 처치 329ms 문제의 해결을 뜻하지 않는다.

## 실제 화면과 불변 검증

Chrome / M5 Pro / 24GB, WebGPU, 1280×800·DPR1·높음·FPS 무제한. `localhost:3340`과 `map020-zoomfix-qa` 테스트 슬롯, 서버 저장 경로는 기존 `tmp/mac-migration-runtime/saves`다. 사용자 원본 저장·PC 작업은 사용하지 않았다. 테스트 캐릭터의 연습 안내를 UI로 건너뛰고 실제 update를 진행한 다음 일시정지했다. 남쪽 월드 플레이어/카메라 (2420,6600), isW=false, 정상1/.62 × 0/A/B 6장을 최종 촬영했다. 펫 대사·지역 배너·지역명은 촬영 중만 숨겼고 환경 효과는 유지했다. 초기 안내판이 덮인 예비 촬영은 최종 증거에서 교체했다.

- 수정본 A/B는 화면 가장자리까지 그림자가 이어지고 이전 사각 절단이 없다. 0은 효과 없는 비교군이다. B는 .62에서 1그림자+24뿌리=25draw, 이전은 1+15=16draw였다.
- 1배 전체 게임 화면은 정상이며, **실제 캐시를 사용한 경계 모듈 단독 Canvas2D 래스터 1,024,000픽셀의 RGBA 차이 0**이다. 이는 경계 레이어의 정확한 비교이고 시간에 따라 움직이는 전체 게임 화면의 픽셀 동일 주장과 구분한다.
- 모듈의 실제 캐시/앵커를 사용한 draw 범위 검사는 1/.62/.3/.04/4/.31(.5×.62)/.012(.04×.3)를 통과했다. 편집 최소 .04와 합성 값에서 맵 전체까지만 그리며 306draw(그림자1+뿌리305)로 제한된다. 이 검사는 모듈 유효 범위 검사이며 전체 게임을 .04 편집 모드로 종주한 검수는 아니다.
- 전후 305개 뿌리의 전체 변환 호출이 동일하고 G.map/정적 충돌 직렬화·SHA도 동일하다. `runtime-contract.json`과 `invariant-hashes.json`에 기록했다.
- 정상 etype0 적 2개를 QA fixture로 넣고 800ms 실제 update 후 .62에서 플레이어와 함께 판독했다. 기존 큰 몹/소환물도 화면에 있다. 정지 가독성 확인이며 밀집 전투 전체 승인은 아니다.
- 설치한 window error listener는 0. 브라우저 콘솔에는 부팅 때 설명 없는 Object 오류와 확장프로그램 출처 오류가 남는다. 전체 콘솔 0/전체 404 무결성을 주장하지 않는다. 모듈과 HTML의 HTTP 200 및 디스크 바이트 일치는 따로 확인했다.
- 이전 모듈은 Git의 기준 커밋 소스를 메모리에 로드해 동일 페이지에서 비교했다. 종료 때 수정본·기본 B·1배와 숨긴 UI를 복원했고 게임 탭을 빈 페이지로 전환, viewport를 해제했다. 임시 성능 래퍼도 해제했다.

## 짧은 동일 조건 성능 확인

준비 완료된 정지 장면 렌더 비용 검사다. G.paused=true, 같은 카메라/적 배치(15개), 환경 애니메이션은 진행. 각 구간 20 rAF 준비 후 5초 측정, 1배 old→new, .62 old→new→new→old 순서다. 모든 표본에서 visible/focus=true, 맵·충돌 불변을 확인했다. CPU 값은 경계 draw 함수의 제출 비용이며 GPU 시간은 아니다. 캐시 빌드는 측정 전에 끝났으며 캐시 추가·메모리 증가가 없다.

## 선정: CH1 일반몹 `windup→attack→recover` **발사 에지 단발 불변식** 재현

**근거 (읽은 실제 코드, game.html):**

| 위치 | 코드 | 역할 |
|---|---|---|
| `37228` | `…e.st2-=sp;` | updateE 프레임 선두, 상태 타이머 감소 |
| `39566` | `case'windup':if(e.st2<=0){e.s='attack';e.st2=e.etype===3?5:8}break;` | windup→attack 진입 시 attack `st2`를 **8**(요마 etype3=**5**)로 설정 |
| `39567` | `case'attack':if(e.st2<=5&&e.st2+sp>5){ …_spawnBossProjectile(근거리 탄) }` | 공격 "발사 에지"(st2가 5를 하향 교차하는 프레임 1회) |
| `39574` | `if(e.st2<=0){e.s='recover';e.st2=35}break;` | attack→recover |

**잠재 결함 가설 (재현 대상):** 발사 조건은 `st2`가 **5보다 위에서 아래로 교차**할 때만 1회 발동하는 에지 디텍터다. 그런데 **요마(etype3)** 는 windup→attack 진입 시 `st2`를 교차 임계값과 **정확히 같은 5**로 설정한다. 다음 프레임 `st2-=sp`로 즉시 5 미만이 되므로 `st2+sp>5`가 **한 번도 참이 되지 않아 발사가 0회**가 된다(일반몹은 8에서 시작 → 정상 1회). etype3은 `_meleeET`(접촉공격 집합 {0,2,4,5,6,10,12,18,19})에 없어 이 경로가 유일한 공격 출력일 수 있어, 요마가 windup/recover만 반복하고 **실질 공격이 누락**되는 상태 전이 결함일 가능성이 있다.

상태 필드(`e.s`, `e.st2`, `e.etype`, `sp`)만으로 결정적으로 재현되며, 수치·배율·티켓·패턴·공용 코드 변경이 전혀 필요 없다.

## 후보 재현 하니스 (미채택·미저장·미실행 — 답변 코드블록 한정)

```js
// test/enemyAttackFireEdge.test.js  — ENEMY 후보 (파일 저장/실행 안 함)
// 재현 대상: CH1 일반 필드몹 windup→attack 발사 에지 단발 불변식과 etype3(요마) 경계 누락.
// 연결 원본(game.html): 37228 st2-=sp / 39566 windup→attack st2=(etype===3?5:8)
//                       / 39567 attack 발사에지 st2<=5&&st2+sp>5 / 39574 st2<=0→recover
// 수치·배율·티켓·패턴·공용 update 수정 없음. 상태 필드만으로 결정적.
import { test } from 'node:test';
import assert from 'node:assert/strict';

// --- 소스 전이 블록을 그대로 복제한 결정적 하니스 ---
// attack 진입 직후(39566이 st2를 설정한 프레임 종료 시점)부터 recover까지 발사 횟수를 센다.
function runAttackCycle(etype, sp){
  const e = { s:'attack', st2:(etype===3 ? 5 : 8), etype }; // 39566 진입값
  let fires = 0, frames = 0;
  const GUARD = 100000;
  while(e.s === 'attack'){
    if(frames++ > GUARD) throw new Error('무한 루프 가드(sp<=0 입력 등)');
    e.st2 -= sp;                                   // 37228
    if(e.st2 <= 5 && e.st2 + sp > 5) fires++;       // 39567 발사 에지
    if(e.st2 <= 0){ e.s = 'recover'; e.st2 = 35; }  // 39574
  }
  return fires;
}

// sp(프레임당 진행량) 스윕: 정수·분수·과속 포함. loop()의 PHYS_STEP 기반 1틱 가정.
const SPS = [0.25, 0.5, 1, 1.5, 2, 3, 4, 6];

// ── 판정 1: 일반몹(진입 st2=8)은 모든 sp에서 정확히 1회 발사 (설계=구현 일치, PASS) ──
test('일반 근접/원거리몹 attack 발사=정확히 1회', () => {
  for(const sp of SPS){
    assert.equal(runAttackCycle(0, sp), 1, `etype0 sp=${sp}: 발사 1회여야 함`);
  }
});

// ── 판정 2: 단발 불변식 — 어떤 몹·sp에서도 이중 발사(>=2) 없음 (PASS) ──
test('attack 발사 에지는 절대 이중 발동하지 않음', () => {
  for(const et of [0,1,3,4,19]){
    for(const sp of SPS){
      assert.ok(runAttackCycle(et, sp) <= 1, `etype${et} sp=${sp}: 이중 발사 금지`);
    }
  }
});

// ── 판정 3(결함 재현·고정): 요마(etype3, 진입 st2=5)는 발사=0회 ──
// 현재 코드 기준 "기대값 0"을 고정해 누락을 명시적으로 드러낸다.
// 설계 기대(공격 1회 발사)와 불일치 → 결함 재현. 수정은 QA/총괄 판단 대기.
test('[결함 재현] 요마(etype3) attack 발사 누락(현행=0, 설계=1)', () => {
  for(const sp of SPS){
    const f = runAttackCycle(3, sp);
    assert.equal(f, 0,
      `etype3 sp=${sp}: 현행 코드는 경계값(st2=5=임계)으로 발사 0회. `+
      `설계 의도(1회)와 불일치 — 재현 성립`);
  }
});
```

### 기대 / 실패 판정표

| 판정 | 입력 | 기대(현행 코드) | 의미 |
|---|---|---|---|
| 1 | etype0, sp∈{0.25…6} | `fires === 1` | 정상몹 발사 정상 → PASS |
| 2 | etype{0,1,3,4,19} 전 sp | `fires <= 1` | 이중 발사 없음(단발 불변식) → PASS |
| 3 | etype3, 전 sp | `fires === 0` | **요마 발사 누락 재현 성립**. 설계(1회)와 불일치 |

- 판정 1·2가 PASS면 에지 디텍터 자체는 건전(누락·중복 없음)이고, **문제는 etype3의 진입 `st2`가 임계값과 같은 5라는 "값"에 국한**됨을 분리 증명한다.
- 판정 3이 PASS(=0)로 재현되면, 요마가 windup/recover만 반복하고 공격 출력이 누락되는 상태 전이 결함이 **결정적으로 고정**된다. 만약 향후 `fires===1`로 바뀌면 판정 3이 FAIL → 수정 반영 회귀 감지용으로 그대로 쓸 수 있다.

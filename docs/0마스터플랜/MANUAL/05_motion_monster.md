## 1. 목표 장면·레퍼런스 (무엇을, 왜)
- 목표 장면: 1-1 남→북 다리, 먼 적 여러 마리가 작게 보이다가 다가오는 화면. 먼 적도 "무슨 종류인지" 걸음으로 읽혀야 한다.
- 레퍼런스: 디아블로4 몬스터 가족 설계(가족마다 전투 방식·느낌이 다름 [사실]), 죽인 기술에 따라 다르게 죽는 데스 킷 [사실], PBZ 적 반응 4단계.
- 왜: 같은 걸음·같은 죽음이 반복되면 전투가 단조롭다.

## 2. 디렉션 원칙
1. 가족마다 걸음 성격이 다르다(뛴다·기어간다·끈다·떠다닌다). 이유: 실루엣보다 리듬이 먼저 종류를 알린다.
2. 공격 예비동작은 몸 밖으로 무기·팔이 나가는 큰 실루엣 변화다. 이유: 플레이어가 피할 근거.
3. 예비 길이는 Core를 줄이지 않는다. 표현은 그 안에서 앞 1/3에 큰 변화를 둔다. 이유: 가독성.
4. 피격 반응은 4단계: 움찔→경직→자세 붕괴→큰 반격(PBZ 규칙6). 이유: 단계가 보이면 보상이 읽힌다.
5. 사망은 몹당 2종 이상(주저앉음/날아감), 죽인 기술에 따라 고른다. 이유: D4 데스 킷.
6. 군집은 위상을 개체마다 어긋나게 한다(시작 위상 0~1 무작위). 이유: 동시 동작은 로봇처럼 보인다.
7. 먼 적을 지우지 않는다: 안개·어둠·비네트에 묻혀 먼 적이 안 보이면 FAIL(카메라 LOCK). 이유: 먼 적이 보이는 생동감이 핵심.
8. 소멸은 사망 포즈가 끝난 뒤. 점묘·디더 소멸 금지. 이유: 점 금지.
9. 피격 섬광은 1~3틱, 흰 원판 금지. 이유: 탄막·예고 가림 방지.
10. 몬스터 예비 시간은 플레이어 공격 비율과 통일하지 않는다. 위협 방향·범위·접근 속도까지 읽히는지로 정한다. 이유: 플레이어에게는 반응성이, 적에게는 플레이어가 반응할 예비동작이 필요하다 [사실 GDC 구분 / 추정 적용, codex_motion_direction]. 특정 게임의 몬스터별 예고 길이는 이 원칙에서 역산하지 않는다.
11. 숨긴 공격에는 대응 가능한 선행 동작을 붙인다. 이유: PBZ 개발자는 실제 무술이 의도를 숨기는 문제를 시각 신호로 푼다고 말했다(창병 숨긴 찌르기에 후방 회피 동작 연결) [사실 단일, codex_vfx_direction PB-INT].
12. 가장 먼 깊이(약 10타일)의 걸음·예비 정점이 픽셀 깜빡임에 지워지지 않는지 따로 본다. 이유: 원근에서는 기준 깊이만 안정되고 먼 팔·무기가 소실될 수 있고, Dead Cells도 픽셀 깜빡임을 해결하지 못했다고 명시했다 [사실 / 추정, codex_3d_pixel §6, codex_motion_direction].

## 5. 절차
### 5.1 공통
1. 입력: 가족 사양(§3.1), Core 상태 길이, 실루엣 스케치(1x 높이).
2. 작업: 걷기 4포즈 → 공격 키포즈 3~5 → 피격 2방향 → 사망 2종. 각각 1x 단색 실루엣 판정.
3. 출력: FBX, 클립명 `<가족>_<동작>`(예: `skel_walk`, `skel_death_b`), 제자리, 60fps 표본, 클립 길이(초) = Core 길이(틱)/60. 재생 속도 식은 04번 5.2(`speed = clipLengthSeconds / (coreTicks/60)`).
### 5.2 Unity 반입
- Generic, Bake Into Pose, 상태 = Core 1:1, 군집 Offset은 스폰 시 무작위, 렌더는 픽셀 RT 레이어(30). 현행은 적 액터당 RT(`NativeEnemyRigRenderer`)라 30마리 동시일 때 비용 구조 위험이 있다. D04-5 승인 뒤 PixelActorPass 아틀라스 1장으로 이전한다 — TOOLCHAIN a-1. 〔CX29 R07〕 "적 30+영웅+보스 ≤2.0ms [추정]"는 30체 **부분 비용 진단**이다. 몬스터 합격은 **Core 최대 N·V(15번 D15-13★)의 같은 SHA 실측**이며, 예산을 맞추려고 동시 적 수·가시 리그 수·공격 수를 제한하지 않는다(어택 티켓 금지와 같은 취지).
- 범위(소규모 팀 사례 반영): 가족 한 개를 6클립(이동·공격·피격·경직·사망A·B)까지 끝내고 1x 판정 PASS한 뒤 다음 가족으로 간다. 클립 라이브러리는 가족 공용 스켈레톤으로 재사용한다(Dead Cells는 장비 교체와 재수정이 쉽도록 3D 파이프라인을 택했다 [사실, codex_3d_pixel_small_team §3]).
### 5.3 UE5 반입 (대응만)
- Root Motion 끔, 공격은 Montage + Notify, 군집 Start Position 무작위, 풀링된 액터 재사용 시 상태 리셋.

## 6. 합격 기준
- 1x 비교판 〔CX29 R31〕: 한 가족의 걷기·공격 예비·피격·사망을 같은 크기로 D4 공개 영상 옆에 놓는다(감각 대조). **비교 장면 ID**: `MON-CMP-01`~`04`(걷기·공격 예비·피격·사망 각 1개)로 레퍼런스 영상 URL·시각(초)과 우리 캡처의 가족·클립·카메라 위치를 함께 적는다. **관찰 질문**: ① 정상 속도에서 공격 예비가 시작되는 순간을 알아보는가 ② 맞았는지 죽었는지 구분되는가. **판정 주체**: 사용자(Mac 실게임 시청). **기록**: 장면 ID·질문별 예/아니오·한 줄 메모를 비교판 옆 텍스트로 남긴다. 명도·px·ms 수치는 보조 근거이며 이 사용자 판정을 대체하지 않고, 수치 열만 통과해도 이 항목은 자동 PASS가 아니다.
- 1920×1080과 3840×1080에서 가장 먼 적(약 10타일)의 종류가 걸음으로 구분된다. 3x 크롭 점 0. 〔CX29 R31〕 **장면 ID `MON-FAR-01`**: 서로 다른 가족 3종을 가장 먼 깊이에서 같은 속도로 걷게 하고, 관찰 질문은 "1x 무음 영상만 보고 어느 칸이 어느 가족인지 맞히는가"(3종 모두 맞혀야 PASS). 판정 주체 = 사용자, 기록 = 맞힌 수와 틀린 쌍.
- 10초 무음 영상: 같은 종류 6마리가 군집일 때 동기화되어 보이지 않는다. 〔CX29 R31〕 **장면 ID `MON-SWARM-01`**, 관찰 질문 "한 번에 같은 발을 내딛는 개체 쌍이 눈에 띄는가", 판정 주체 = 사용자, 기록 = 눈에 띄는 쌍 수(0이어야 PASS).
- 원거리 깊이 판정(2차): 가장 먼 깊이에서 예비 정점이 구분되고 팔·무기가 픽셀 깜빡임으로 사라지지 않는다. 큰 VFX로 덮어 해결했다고 판정하지 않는다(codex_3d_pixel §4.5).
- 예산: 가족당 클립 ≥ 6, 화면 동시 애니메이션 몬스터는 Core 상한(`Core/EnemyCap`)을 따르며 60fps 유지.

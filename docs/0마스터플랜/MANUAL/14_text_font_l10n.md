## 1. 목표 장면·레퍼런스 (무엇을, 왜)

- 목표: 어떤 언어로 바꿔도 같은 게임처럼 보이는 글자. 1x에서 읽히고, 긴 문자열이 잘리거나 겹치지 않고, 두부(□)가 한 글자도 나오지 않는다.
- 글꼴 정체성: 본문은 세리프(Hahmlet/나눔명조 계열), 제목·숫자·영문은 Cinzel. 산세리프 단독과 시스템 폰트로 게임 UI를 만들지 않는다(CLAUDE.md 4.2-2).
- 레퍼런스: 디아블로4(2023-04에 산세리프 → 세리프 교체, "분위기 vs 가독성" 논쟁), 접근성 기준(XAG 101 글자 크기·XAG 102 대비), 엘든링·노레위(세리프/손글씨 질감 메뉴). 교훈: 분위기를 위해 가독성을 깎지 않는다. 크기·대비는 접근성 기준을 하한으로 둔다.
- 실제 위험(대조 완료): 나눔명조 한 글꼴만으로는 29개 언어 중 25개에서 글리프가 부족하다. 중국어 167자, 일본어 149자, 그리스어 44자, 베트남어 50자 등(`UNITY_SUBTITLE_FONT_COVERAGE`). 대체 글꼴 체인이 이 매뉴얼의 핵심 결정이다.

## 2. 디렉션 원칙

1. **본문은 세리프, 숫자·제목은 Cinzel.** 한 화면 글꼴 2종 이하. 이유: 정체성 + 위계(MANUAL 10 P5).
2. **크기는 단계로만 쓴다.** 임의 px 금지, 5단 고정. 이유: 비례가 흔들리면 "안 맞는다"로 읽힌다.
3. **1080p 본문 목표 18px(몸체 높이), 4K는 36px(높이 비례). 최종 값은 ★D14-3이 정한다.** 이유: XAG 101 PC/VR 권고. 18px는 어센더~디센더의 보이는 높이이며 엔진 `fontSize`와 같지 않다(캡처로 잰다).
4. **받침은 그림자 한 번, 외곽선은 4방향 금지.** 이유: 1x에서 글자가 뭉치고 점이 생긴다.
5. **글리프 없는 문자는 폴백 체인이 받는다.** 언어마다 대체 글꼴을 정해 두고, 두부 0을 검사로 강제한다. 이유: 누락은 눈으로 못 찾는다.
6. **길이는 40% 팽창을 기본으로 설계한다.** 고정 폭 글자 자리는 금지. 이유: 독일어·핀란드어 등은 한국어/영어보다 길다.
7. **줄바꿈은 언어 규칙을 따른다.** 한국어는 단어 단위(keep-all), 일본어·중국어는 글자 단위, 아랍어는 RTL. 이유: 낱말 중간 꺾임은 결함.
8. **글자가 UI를 이긴다.** 글이 넘치면 먼저 줄바꿈, 그다음 판 확대, 글자 축소는 마지막(하한은 ★D14-3: 승인 시 18px, 미승인 시 현행 16px). 이유: 틀 안의 정보가 장식보다 먼저다.
9. **새 표시 글자는 등록 후에 쓴다.** 번역대상 목록에 No.가 없으면 화면에 넣지 않는다. 이유: 한국어 고정 문자열이 누락의 주 원인.
10. **글자 크기 옵션은 3단(0.85/1/1.25)이다.** 이유: D4 접근성 3단, XAG 101의 확대 요건.
11. **색만으로 뜻을 말하지 않는다.** 경고는 색 + 기호/위치. 이유: XAG 102·GAG.

| 한국어(기준) | 1.0 | 기준 | 우리 기준 |

- 계수는 일반 현지화 관례의 추정치다 [추정, 연구 반영 대기]. 29언어 실제 최장 문자열을 측정해 이 표를 대체한다(5.1-6).
- 설계 규칙: 고정 폭 글자 칸은 한국어 폭의 140% 이상 확보. 한 줄 안내문은 2줄까지 허용. 버튼 글자는 판 폭의 85% 이하(좌우 12% 여유).
- 줄 높이: 라틴·키릴·그리스 1.3, CJK 1.4, 태국어·아랍어 1.5.
- 줄바꿈: 한국어 keep-all + overflow-wrap anywhere, 일본어·중국어 normal, 아랍어 RTL. 태국어는 사전 기반 분절.
- 자간: 영문 대문자 제목만 .2~.34em, 한글 본문 자간 0~.02em (제목 `.02em`).
- **아랍어(2차 연구)**: 방향 처리(UAX #9, 논리 순서 → 표시 순서)와 연결형 자형 선택(shaping)은 별개 문제다. 숫자·라틴 단어는 반대 방향 구간을 만들므로 문자열 전체 뒤집기로 처리하지 않는다 [사실: `codex_cinematic_text.md` §5.2 B01]. Unity 6.0 UI Toolkit의 Advanced Text Generator(HarfBuzz·ICU·FreeType)가 RTL·shaping을 지원하지만 **UI Toolkit 경로 한정**이고 기존 TMP/IMGUI에는 자동 적용되지 않는다. 현 프로젝트 버전에서의 동작은 미확인이므로 자동 전환을 확정하지 않는다 [사실 U04 / 미확인]. 검사 대상은 UI·자막·데미지 숫자 각각에서 연결형, 줄바꿈, 결합 부호, 괄호, 음수, 퍼센트, 라틴 아이템명, 키 아이콘 혼합이다. 타이핑 효과·문자 단위 강조가 연결형을 깨지 않는지도 본다 [추정].
- **CJK(2차 연구)**: 문장부호의 줄 시작/끝 금칙, 장문 버튼의 확장·줄바꿈·잘림을 따로 본다. GAG 자막 40자 권고를 언어별 행 너비가 같다는 근거로 쓰지 않는다 [추정].
- **태국어**: 위·아래 결합 부호 잘림과 사전 기반 분절을 확인한다(기존 줄 높이 +20%) [추정].

## 5. 절차

### 5.1 공통 (입력 → 작업 → 출력 형식)

1. **전수조사**: 코드·데이터의 모든 표시 문자열(한국어 리터럴, 토스트, 라벨, 버튼, 툴팁)을 수집. 출력 = No. 후보 목록.
2. **목록 완성**: `docs/16번역·로컬라이제이션/번역대상_전체목록.md`에 No. 번호로 등록. 목록이 없거나 불완전하면 다음 단계로 넘어가지 않는다. CRLF 파일은 줄바꿈 보존.
3. **번호 순서 번역**: 번호 순서대로 하나씩. 출력 = 29개 언어 값(ko·en + 27개).
4. **전파**: 같은 키를 29개 언어 전부에 넣는다(웹은 `_EN` + `lang_*.js` 27개, Unity는 `Resources/Data/*.json` 29개).
5. **전체 대조 검수**: 키 개수 일치, 빈 값 0, 글리프 누락 0(`l10n_glyph_audit`), 서식 자리표시자(`{s}` 등) 보존.
6. **길이 실측**: 언어별 최장 문자열을 화면별 최악 칸에 넣어 1x 캡처(1920×1080, 3840×1080). 3.4 계수를 실측으로 갱신.
7. **상태 갱신**: `번역대상_전체목록.md`·`번역_가이드.md` 상태를 갱신. 새 표시 글자가 예고 없이 들어오지 않게 PR/커밋 전 점검.
8. **글꼴 변경**: 글꼴 asset 교체는 모든 폴백 체인 검사를 다시 돌린다(5번).
9. **언어별 조판 검토(2차)**: 라틴 몸체 높이만 통과시킨 뒤 CJK·아랍어·태국어를 통과로 간주하지 않는다. 같은 설정에서 획 뭉침, 상하 결합 부호 잘림, 줄 간격, 버튼 안 문자, 200% 확대 후 말줄임을 언어별로 본다. 글리프 존재 검사(`l10n_glyph_audit`)는 조판 검사를 대체하지 않는다 [추정: `codex_cinematic_text.md` §4.1·§5].
10. **몸체 높이 측정**: 최종 출력 해상도(1920×1080)에서 확대 없이 1x로 캡처하고, 어센더~디센더 보이는 높이를 크롭에서 잰다(외곽선·그림자 제외). 창 크기·UI 배율·표시 장치를 함께 기록한다. 저해상도 월드 렌더의 논리 픽셀과 UI 표시 픽셀은 따로 관리한다. 축소 썸네일로 `fontSize`를 역산하지 않는다 [사실 방법: XAG 101 / 추정: 절차].

출력 파일 형식: UTF-8(BOM 없음), 키 안정 번호(No.) 유지, 줄바꿈 `\n`은 값에 이스케이프.

### 5.2 Unity 반입

- 글꼴: `Resources/Art/fonts/`의 기존 6 TTF에 언어별 Noto 서브셋을 추가. `Font` asset을 만들고 `GUIStyle.font`를 언어 변경 시 갈아 끼운다. 폴백은 `Font.fontNames` 체인 또는 언어별 asset 표.
- 크기: `GUIStyle.fontSize`는 배율 적용 뒤 실제 px로 계산(하한 12px@720p, 16px 논리).
- 설정 연결: `optLang`/언어 선택은 기존 메뉴(`NativeLobby.LanguageMenu.cs`), 글자 크기 옵션은 HUD 글자 배율 변수 하나.
- 데이터: `Resources/Data/*.json` 29개 언어 파일에 같은 키를 동시에 추가하는 스크립트를 쓴다(수동 파일 하나씩 금지).
- 검사: 컴파일 + `l10n_glyph_audit` + 언어 순회 캡처는 Mac에서 판정(PC는 컴파일까지).

### 5.3 UE5 반입 (대응만)

- 글꼴 = Font Asset(Composite Font), Fallback Font Family로 언어별 체인. 크기는 DPI 곡선(높이 기준 1080 = 1.0)에 맞춰 Slate 폰트 크기 사용.
- 문자열 = String Table 29 Locale. 키는 Unity 키와 동일, 번역 전파 스크립트는 JSON → CSV 변환.
- 수치·단계는 3절 그대로.

## 7. 금지

- 산세리프 단독 글꼴, 시스템 폰트, 이모지를 UI 아이콘으로 쓰는 것.
- 4방향 이상 외곽선 글자. 글자 위 그레인·노이즈. 이미지에 구운 글자(번역 불가).
- 번역 등록 없이 표시 글자를 추가하는 것. 언어 일부(ko/en만) 키 추가.
- 고정 폭 글자 칸. ★D14-3이 정한 하한(승인 시 18px, 현행 16px) 미만으로 줄이는 것. 글자를 가로로 눌러 넣는 것(가로 눌림 63% 결함 재발).
- 원색 초록/노랑 글자. 색만으로 상태 전달.
- 번역 문장·스토리 문구를 이 매뉴얼에서 임의로 고치는 것. 번역 감수 완료를 근거 없이 주장하는 것(글리프 확인은 감수가 아님).
- 라이선스 확인 없는 글꼴 반입. 사용자 세이브·Core 값 변경.
- `fontSize` 숫자를 XAG 몸체 높이와 같다고 보고하는 것. 라틴만 통과시키고 CJK·아랍어·태국어를 통과로 적는 것. 글리프 존재를 RTL·연결형 지원 완료로 적는 것.
- 연구의 공개 최소값(18px·28px·46px·40자)을 인스펙터 값으로 바로 옮기는 것(사용자 결정 전). GAG 28px(TV)를 PC 절대 합격선으로 쓰는 것.
- 비교 게임의 폰트명·글자 높이·외곽선 두께를 추정으로 단정하는 것(공개 자료 없음).

## 1. 목표 장면·레퍼런스 (무엇을, 왜)

- 목표 장면: 1-1 숲(피치 34° 원근, LOCK)에서 전투 중인 1920×1080 한 장. 하단 HUD가 화면 바닥에 붙은 한 덩어리다. 왼쪽 체력 구체, 오른쪽 자원 구체, 가운데 13칸 스킬판이 두 구체 고리 밑으로 이어진다.
- 금속은 은빛 크롬과 흑철(실버 헬 토큰). 빨강은 체력 액체와 선택·위험 표시에만 쓴다.
- 1x로 봐도 키 라벨 13개가 같은 크기로 읽히고, 빈 칸도 판에 파인 소켓으로 보인다.
- 먼 적과 탄막은 HUD보다 늘 먼저 눈에 띈다(카메라 LOCK). HUD 꼭대기가 먼 적 구역을 가리면 FAIL.
- 레퍼런스: 디아블로4(하단 가운데 묶음, 구체 2개), PoE2(구체가 바닥 모서리에 붙고 판과 이어짐), 노레위(절제된 장식), BG3(얇은 틀). 공통점만 따른다. 에셋 반입 금지.
- 해결할 사용자 평가: "붕 뜨고, 안 맞고, 듬성듬성, 색이 구리다". 아래 원칙 1~10이 각각 한 항목에 대응한다(7절 표).

## 2. 디렉션 원칙

1. **하단 HUD는 한 덩어리다.** 구체·스킬 줄·물약이 한 장의 베이스 판의 자식이고 같은 바닥선을 쓴다. 이유: 각자 앵커를 가지면 바닥선이 어긋나 "붕 뜬다".
2. **중앙 묶음, 화면 비율과 무관.** 묶음 가로 중심 = 화면 중심, 폭은 16:9·21:9·32:9에서 같은 논리 px. 이유: 양옆으로 퍼지면 시선 이동이 길고 울트라와이드에서 구체가 시야 밖으로 나간다.
3. **높이 상한을 둔다.** 판 높이 ≤ 화면 7%, 구체 꼭대기까지 ≤ 13%. 이유: 전투 시야와 먼 적을 지키는 것이 HUD보다 먼저다.
4. **비례를 고정한다.** 구체 : 슬롯 : 간격 : 장식 두께를 한 표로 묶고 부품마다 다른 선 두께를 쓰지 않는다. 이유: 구체가 슬롯의 7배이면 위계가 아니라 단절로 읽힌다.
5. **빈 슬롯은 파인 소켓이다.** 13칸은 늘 같은 길이·간격으로 그리고, 비면 어두운 홈만 남긴다. 이유: 칸을 빼면 줄이 변하고 "듬성듬성"이 된다.
6. **틀은 어둡고 낮은 대비, 내용이 가장 밝다.** 틀은 명암 3~4단계, 위쪽 모서리에만 은빛 하이라이트 1px. 이유: 채도·명도를 쓰는 면적을 줄이면 고급스럽게 읽힌다.
7. **채도 높은 면은 두 구체 안쪽뿐이다.** 체력 = 진홍, 보조 자원 = 채도를 낮춘 다른 색. 이유: "색이 구리다"의 원인이 금·원색의 넓은 면이다.
8. **글자는 1x에서 읽힌다.** 크기 3단 고정, 밝은 글자 + 어두운 받침, 가로로 눌러 넣지 않는다. 이유: 접근성 최소선(PC 1080p 18px)과 Space 63% 눌림 결함 때문.
9. **쿨다운 = 어둡게 + 시계 방향 + 숫자.** 이유: 장르 공통 관례이고 진행률이 한눈에 읽힌다.
10. **상태는 모양으로 말한다.** 색만으로 정보를 전하지 않고, 구체 위 상태는 3종 이하. 이유: D4 구체 상태가 복잡하다는 보도가 반면교사.
11. **장식은 구체에만, 기능 칸보다 작게.** 뿔 해골(M4)은 보스 체력바 등 특별한 곳 전용. 이유: 실버 헬 §4, 장식이 슬롯보다 크면 정보가 밀린다.
    - **[3차 충돌 ★D09-11]** Mac 실화면 판정(Unity `c1b51cda5`): M4를 뺀 시안 A·B는 톤이 약하고 현재가 낫다. 최신 판정 우선(CLAUDE.md 0절)으로 **C안 r2는 HUD 구체 틀의 뿔 해골(구체 지름의 약 1/3, 은빛 명도)을 유지**한다. 사용자 최종 선택 전까지 위 원칙은 "일반 HUD 금지, 구체 크레스트는 D09-11 결정 대기"로 읽는다.
12. **전투 요약과 점검 정보를 나눈다.** 상시 HUD는 전투용 요약만, 전체 목록·수치는 창으로. 현재 상태와 다음 행동은 색 이외의 모양·숫자·동작으로도 전한다. 이유: PoE2·Hades·D4 3종 공통(`codex_synthesis.md` §1.8 순위 1·2, [사실]).
13. **HUD는 끌 수 있어야 한다.** 키샷·구도 판정용 "HUD 끄고 캡처" 경로가 있고 디버그 표식·FPS도 함께 숨는다. 이유: `FIRST_SCENE_PLAN.md` 6단계가 HUD 없는 1920×1080·3840×1080 원본을 합격 조건으로 둔다 [단일].

## 5. 절차

### 5.1 공통 (입력 → 작업 → 출력 형식)

1. **G1 배치도(회색 상자)**: 입력 = 3.1 수치. 작업 = 한 HTML에 dock(≈971×140), 구체 2, 13칸, 버프 줄, 물약 상자. 출력 = 1920×1080·3840×1080 PNG(Git 밖), HTML만 커밋. 배경은 1-1 실화면 캡처(먼 적·발밑이 가려지지 않는지 본다).
2. **기능 상자 조립**: 단색 사각형으로 dock 구조를 엔진에서 먼저 바꾼다. 쿨다운 덮개·숫자·자원 부족·버프 줄 동작까지. 1-1 전투에서 먼 적 가림 확인.
3. **재질 원화**: Blender 모델 → 정사영 렌더. 표시 크기 ×2(구체 2×지름, 칸 2×칸 크기), RGBA PNG, 실버 헬 토큰만, 빨강 없음, 그레인은 디노이즈가 아니라 샘플 증가로 제거. 재질 Metallic 1, Roughness .35~.5, 조명은 위 왼쪽 키 + 뒤 림 1개.
4. **슬라이스**: 판은 가로 3조각(양 끝 장식 고정, 가운데만 늘림. 가운데 조각은 가로로 균일하게 렌더). 칸 틀은 크기별 9-slice 1개씩, 테두리 원화 24px(표시 12px). 구체 틀은 통짜 원(늘리지 않음). 명명 `hud_<부품>_<크기>@2x.png`.
5. **상태 표현 파라미터**: 구체 채움(0~1), 표면 물결(사인 2개, 진폭 2px), 위쪽 반사광 타원 1개. 파티클·노이즈 텍스처 금지. 쿨다운 덮개는 각도 0~1 한 값.
6. **판정**: 6절 절차.

### 5.2 Unity 반입

- 텍스처: Default 타입, sRGB, Alpha Is Transparency 켬, Mipmap 끔, Bilinear, Clamp, 압축 없음(Mac 판정에서 차이 없으면 High Quality), Max Size ≥ 원화.
- 9-slice: IMGUI `GUIStyle.border`는 2배 원화에 맞지 않으므로 9조각을 `GUI.DrawTextureWithTexCoords`로 직접 그리는 함수 1개(텍스처 좌표 24px, 화면 모서리 12px). 첫 조립 때 1x·3x 크롭으로 확정한다.
- 레이아웃: `NativeHudDockLayout`의 dock 사각형 하나를 유일한 기준으로 한다. 가로 중심 = `Screen.width/2/배율`. 구체·13칸·물약·버프 줄 모두 dock 상대 좌표.
- 액체: 기존 `NativeHud`의 RenderTexture + `HudOrb.shader` 모드 0·1 구조 유지, 색 상수만 교체. 쿨다운은 `Graphics.DrawTexture(rect, tex, mat)`로 각도 파라미터.
- 보존: 13칸 클릭 hit rect, `HudPixelProbe`, hud-blend-smoke 기하 검사(새 좌표로 갱신, 완화 금지).
- 건드리지 않음: Core 쿨다운·비용 값(읽기만).

### 5.3 UE5 반입 (대응만)

- 텍스처: UI 그룹, sRGB, Mip 없음, 압축 UserInterface2D, Never Stream. 슬라이스 JSON → Slate Brush(Draw As Box, Margin).
- UMG: 하단 가운데 앵커 Canvas Panel 하나가 dock, 자식은 상대 위치. 액체·쿨다운은 UI 머티리얼 파라미터(`Fill`, `Angle`). DPI Scaling Rule = Shortest Side 대신 높이 기준 곡선(1080 = 1.0).
- 상태·수치는 5.1과 3절 그대로.

- 중단 조건: 1-1 숲 위에서 판이 또 "떠 보이면" 레일 방식을 멈추고 판 바닥 = 화면 끝으로 바꾼다. **[3차]** 벡터 크롬이 1x에서 "싸 보인다"는 판정이 같은 결함으로 두 번 나오면 3D 금속 메시 원화로 바꾼다. 원화 사본에서 3x 크롭 번짐·점이 나오면 알파를 더 깎는다.
- 판정 순서 [3차]: T0 사용자 선택 → T1 Mac 첫 빌드(구체 1 + 판 + 소켓 13, 먼 적·탄막이 HUD 근처인 장면) → T2 색·숫자·칩 후 10초 영상. 하니스의 기하 PASS를 화면 합격으로 바꾸지 않는다.

## 7. 금지

- 구체·슬롯·물약에 각자 화면 앵커를 주는 것.
- 화면 양 끝으로 HUD를 늘리는 것. 검은 판·블러로 양옆을 채우는 것.
- 금·황동·원색 초록·네온·주황. 이모지 아이콘. 뿔 해골(M4)을 일반 HUD에 쓰는 것(구체 크레스트 예외는 D09-11 결정 전까지 C r2 시안 한정). HP 액체에 반사 하이라이트·흰 수면선(유리 재질)을 넣는 것. MP·ST를 같은 무채색 계열로 만들어 색상 구분을 없애는 것.
- 원화에서 글자를 색 조건으로 지우는 방식. 키 라벨을 가로로 눌러 넣는 것.
- 4방향 외곽선 글자. 잔점·점묘·디더·그레인(보정에 노이즈 추가 포함).
- 안개·비네트·어둠·HUD가 먼 적을 지우는 것 = FAIL.
- Core 쿨다운·비용·칸 배정 수치 변경. 어택 티켓. 무지개탄은 Q로만 패링(E 불가)이라는 표기를 HUD가 어기는 것.
- 레퍼런스 화면·에셋 반입. 유료 생성 승인 밖 사용.
- 코드 수정은 이 문서 범위 밖(구현은 사용자 확정 이후).

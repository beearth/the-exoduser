## 방법과 출처

| 단계 | 한 일 | 출처 |
|---|---|---|
| 클립 | X Bot, FBX for Unity, Without Skin, 30fps, Keyframe Reduction none | Mixamo 라이브러리, 브리프 SM §2 |
| T 포즈 | 에디터 없이 런타임에 C3 팔을 옆으로 편 뒤 `AvatarBuilder.BuildHumanAvatar`로 아바타 생성. 사용자 에디터 작업 불필요 | Unity 스크립팅 API |
| 옮기기 | X Bot(T 포즈 확인: 왼팔 x축 방향)에서 `HumanPoseHandler.GetHumanPose` → C3에 `SetHumanPose` | Unity 스크립팅 API |
| 칼 | 접점 프레임의 오른손−왼손 방향으로 칼을 맞춘 뒤 오른손에 고정 | **자체 판단, 출처 없음** |
| 블렌드 | 대기→예비 2틱(CTO 지시), 회복 끝 33~39틱에 대기로 복귀 | 복귀 길이는 **자체 판단, 출처 없음** |

Generic 재생(Playable, `SampleAnimation`)은 손이 움직이지 않아 실패했고 Legacy `Animation.Sample`로 샘플했다(C3 프로브에서 이미 동작한 방식). 원인은 찾지 않았다.

**접점 기준을 CTO 지시에서 바꿨다.** 지시는 "손 최고속 프레임(16f)을 틱 8에"였으나, 그렇게 찍으면 판정 시점에 칼이 몸 뒤에 있었다(`~/exoduser-wt/_out/MX/run3`). 16f는 칼을 머리 위로 올리는 구간이다. **칼이 몸 앞을 지나는 프레임(20f)** 으로 옮겼다. 근거는 손 방향 측정이다(`tools/motion_check/mixamo_grip.py`): 20f 전후로 양손 방향의 전방 성분이 음에서 양으로 뒤집혀 0.88까지 오른다. Power Slash의 접점도 같은 방식으로 다시 재야 한다.

게임에서 확인: 입력 60 → 예비 시작, 66 스윙, 68 접점, 71 회복, 99 대기(motion-log). Core 판정과 숫자는 안 바꿨다.

## 눈으로 본 문제

- 칼이 프레임에 따라 흰색으로 번쩍인다(금속 재질이 임시이고, 조명 반사로 보임).
- 몸이 구부정하다. 대기 클립 자세이거나 A 포즈 보정 오차일 수 있으나 구분하지 않았다.
- 예비 첫 2틱은 대기에서 원본 13f로 크게 건너뛰는 블렌드라 빠르게 튄다.
- 걷기 1.535배는 빠르고, Core에는 걷기 상태가 없어 사실상 달리기 속도다. 달리기 클립이 맞는 자리다. 발 미끄러짐은 재지 않았다.
- 왼손은 IK가 없어 칼을 쥔 것처럼 보이는 프레임과 어긋나는 프레임이 있을 수 있다. 전 프레임을 보지는 않았다.
- 몸의 트위스트 본은 움직이지 않는다.
- 게임의 영웅(`heroView`)이 아니라 C3 임시 몸을 띄우는 방식이다. 게임 코드 연결은 하지 않았다.

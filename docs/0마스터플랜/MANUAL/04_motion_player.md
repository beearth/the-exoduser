# MANUAL 04 — 플레이어 캐릭터 동작 디렉션 (초안 2026-11-05)
- 상태: 초안 | 연구 반영: d4_04_anim(D4_STUDY/04_character_monster_boss_anim.md), pbz(GAME_STUDY/phantom_blade_zero.md), conventions(ARPG_CONVENTIONS_CHECKLIST_20261105.md) | 연구 반영 대기: 영웅 직업별 콤보 프레임 실측(Core 확인 필요 행 전부), D4 게임플레이 모캡 비율(공개 자료 없음)
- 범위: 대기·걷기·달리기·대시·공격 콤보·스킬 계열·회피·패링·피격·경직·사망·부활의 키포즈 배치·홀드·과장·블렌드. / 정하지 않는 것: 상태 길이·판정·무적 프레임·캔슬 가능 틱(Core가 정답). 여기서는 그 안에서 키포즈를 어디에 둘지만 정한다.

## 1. 목표 장면·레퍼런스 (무엇을, 왜)
- 목표 장면: 1-1 원근 카메라(피치 34° 고정)에서 캐릭터 키 = 화면 높이 약 5.6%인 1x 화면. 이 크기에서 동작이 읽혀야 한다.
- 레퍼런스: 디아블로4(가독성, 층 애니메이션·히트 방향), Phantom Blade Zero(끊기지 않는 흐름·캔슬), 데드셀·길티기어 Xrd(3D를 저해상도 2D처럼 읽히게 하는 방식).
- 왜: 사용자 평가 "동작 하나하나가 다 쓰레기"(11-05). 원인은 사이 프레임 보간이 저해상도 렌더에서 뭉개지고, 예비·접점이 안 읽히는 것이다.

## 2. 디렉션 원칙
1. 키포즈 3~5장이 1x에서 읽힌 뒤에만 사이 프레임을 만든다. 이유: 읽히지 않는 동작은 프레임을 늘려도 안 읽힌다.
2. 예비 정점·접점은 실제 인체 한계보다 과장한다. 이유: 저해상도에서 작은 변화는 텍셀에 묻힌다.
3. 예비 정점과 접점은 포즈를 몇 틱 홀드한다. 이유: 2D 느낌과 가독성을 함께 얻는다.
4. 모션이 판정을 붙잡지 않는다. Core가 캔슬을 허용한 틱에 클립을 버리고 새 동작으로 섞는다. 이유: PBZ식 흐름, 입력 반응.
5. 발은 미끄러지지 않는다. 보폭은 시간이 아니라 이동 거리로 진행한다. 이유: 미끄러짐이 가장 싸구려로 보인다.
6. 피격은 방향이 있는 덧셈(additive) 반응이다. 하체는 고정한다. 이유: 경직 길이는 Core가 정하므로 표현은 층으로 올린다.
7. 시뮬레이션 시간은 멈추지 않는다(R3). 접점 강조는 대상 한 개의 포즈 홀드와 섬광으로 한다. 이유: 적이 많은 화면에서 전역 정지는 끊김이다.
8. 같은 영웅의 모든 동작은 DESIGN LOCK 실루엣(머리·장신구·무기)을 유지한다. 이유: 캐릭터 통일(CLAUDE.md 4.2-6).
9. 모든 키포즈는 단색 실루엣 1x 캡처로 먼저 검수한다. 이유: 재질이 실루엣 결함을 가린다.
10. 점 금지: 호흡 등 미세 흔들림이 3x 크롭에서 잔점으로 보이면 진폭을 0으로 한다.

## 4. 제작 도구 — 확정 추천: Blender 손키(키포즈) + 엔진 상태머신 연결
| 역할 | Unity 추천 | UE5 대응 |
|---|---|---|
| 모델/리그 | Blender 수동 리그(Humanoid 24본 이름 규칙) | Blender 수동 리그(UE 마네킹 호환 본 이름 또는 커스텀 스켈레톤) |
| 키 애니메이션 | Blender 손키(본 작업), Mixamo는 걷기·달리기 원형만 | 동일 |
| 상태 연결 | Animator + 지금 전사 HumanPose·수동 IK 유지 | Animation Blueprint 상태머신 |
| 발 고정 IK | 영웅은 기존 수동 IK 유지 | Control Rig 발 IK |
| 픽셀 렌더 | 리그 픽셀 RT(UNITY_RIG_PIXEL 계약) | 저해상도 SceneCapture/RenderTarget 대응 |
| 검수 | 1x 실루엣 캡처 + 10초 무음 영상 | 동일 |

- 대안: Cascadeur(리타깃이 Pro 판, 반입 끊김 보고 [단일]) / 생성형 모션(홀드·과장 제어 불가 [추정]). 둘 다 이번엔 제외.
- 커스텀 툴 1개 명세 — "타이밍 표 검증기": 입력 = §3.1 타이밍 표(CSV) + Core 상태 길이 JSON, 처리 = 표의 총 틱이 Core와 일치하는지 대조, 출력 = 불일치 목록. 사용자 = 구현 레인. 만드는 사람 = 구현 Sonnet 레인(Core 읽기 전용). 이유: 표와 Core 불일치가 가장 흔한 사고다.

## 5. 절차
### 5.1 공통 (입력 → 작업 → 출력 형식)
1. 입력: DESIGN LOCK 시트, §3.1 타이밍 표(Core에서 총 틱 읽어 채움). 표 없으면 키 작업 금지.
2. 작업: 회색 박스 모델로 키포즈 3~5장 → 1x 단색 실루엣 판정 → 홀드·과장 적용 → 사이 프레임 → 곡선 정리. 30fps 이상 키.
3. 출력: FBX, 클립명 `<영웅>_<동작>_<번호>`(예: `warrior_atk_1`), 루트 이동 키 없음(제자리), 60fps 표본, 클립 길이 = Core 상태 길이 ÷ 60초.
4. 같은 동작 A/B: 보간 그대로 / 홀드 / 전체 12fps 계단 3안 10초 영상 비교 후 확정(연구 남은 일 2).
### 5.2 Unity 반입
- Import: 인간형 Humanoid, 비인간 Generic. 루트 모션은 Bake Into Pose(Y, XZ, 회전 모두). 압축 회전 오차 0.1°.
- Animator 상태 = Core 상태 1:1. 재생 속도 = 클립 길이 / Core 상태 길이. 블렌드 0.12~0.20초, 캔슬 0.06~0.10초.
- 접지 위상에서만 IK 가중 1. 렌더는 픽셀 RT 레이어(30), 정수배 스케일, 발밑 텍셀 스냅.
### 5.3 UE5 반입 (대응만)
- Import: 스켈레톤 재사용, Root Motion 끔. Anim Montage로 공격, Anim Notify로 접점·홀드 이벤트. Animation Blueprint 전환 시간 = 블렌드 값. 발 IK는 Control Rig.

## 6. 합격 기준
- 키포즈 단계: 1x 단색 실루엣으로 동작이 읽힌다(공격 1·2·3타 실루엣 서로 구분).
- 비교판: 우리 1x 클립을 같은 크기로 D4·PBZ 공개 영상 옆에 놓는다(감각 대조, 복제 아님). 1920×1080과 3840×1080 모두 성립.
- 10초 무음 영상: 끊김 0, 발 이동 ≤1텍셀, 예비→발동→회복이 읽힘. 3x 크롭 점 0.
- 타이밍: 표와 Core 상태 길이 일치. 예산: 영웅 1명당 클립 수는 §3.1 행 수 + 콤보·스킬 수.

## 7. 금지
- Core 상태 길이·무적·캔슬 틱을 표현 때문에 바꾸지 않는다.
- 히트스톱으로 시뮬레이션 정지(D07-1 결정 전).
- 루트 모션으로 좌표 이동. 카메라 피치 변경.
- PixelLab으로 캐릭터 새로 생성(CLAUDE.md 4.2-6). 레퍼런스 에셋 반입.
- 모캡 그대로 사용(과장 없음). 점묘·디더링 잔상.

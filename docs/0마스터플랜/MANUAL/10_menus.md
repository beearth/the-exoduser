## 1. 목표 장면·레퍼런스 (무엇을, 왜)

- **타이틀**: 어둠 속 가운데 로고, 아래 글자 메뉴 몇 줄. 배경은 큰 영상·원화(32:9까지 성립). 장식은 선택 표시와 주 버튼에만.
- **로비·캐릭터 선택**: 화면의 50~70%가 캐릭터와 장면. 목록은 한쪽 가장자리, 상자 대신 어두운 그라데이션 위 글자 행. 아래 한 개의 주 버튼(ENTER).
- **창(인벤토리·스킬·설정)**: 게임 화면 위에 올라오는 은빛 강철 틀 창. 열어도 한 화면의 금속·선·바탕은 무채색이고 빨강은 선택·초점·위험만.
- 판정 기준: 같은 화면의 기존 요소 옆에 놓아도 같은 게임인가(CLAUDE.md 4.2). 검은 판·블러로 빈 곳 채우기 금지.
- 레퍼런스: 디아블로4(모닥불 캐릭터 선택, 가운데 배치 UI), PoE2(왼쪽 카드 목록 + 장면 속 캐릭터), 엘든링(극단적 어둠 속 글자 메뉴), 라스트에포크, 노레위(회화풍 큰 장면 + 얇은 글자 메뉴), BG3·DD2. 공통점만 따른다. 직접 대조는 대기.

## 2. 디렉션 원칙

1. **캐릭터·장면이 주인공이다.** 화면의 50~70%를 쓰고 UI는 가장자리에 둔다. 이유: 로비 인상이 첫인상의 대부분이다.
2. **상자 대신 그라데이션.** 정보 영역은 가장자리에서 어둡게 번지는 그라데이션 위의 글자다. 이유: 단단한 판이 많으면 "따로 논다".
3. **장식은 한두 곳.** 주 버튼과 선택 표시에만. 화면 테두리를 두르는 틀 금지. 이유: 정보가 장식에 밀린다.
4. **엠블럼은 뜻이 있을 때만.** 로고 외 문장을 배경 워터마크로 깔지 않는다. 이유: 의미 없는 반복은 소음이다.
5. **타이포 위계.** 큰 세리프 이름 > 작은 대문자 라벨 > 본문. 한 화면 글꼴 2종 이하. 이유: 읽는 순서를 글자 크기로 정한다.
6. **빈 슬롯은 한 줄.** 점선 상자를 늘어놓지 않고 "+ 새 캐릭터" 한 줄. 이유: 듬성듬성 방지.
7. **창은 하나의 틀 문법을 쓴다.** 제목·탭·버튼·슬롯·툴팁·슬라이더 부품 규격(3절)을 모든 창이 공유한다. 이유: 창마다 따로 놀던 문제(실버 헬 계기)의 재발 방지.
8. **색 토큰은 실버 헬만.** 금·황동·원색 초록·주황·네온 금지. 이유: 94% 무채색 비율이 컨셉이다.
9. **주광원 하나, 비네트, 미세한 움직임.** 로비 장면은 정지 화면이 아니다. 이유: 살아 있는 장면이 AAA 로비의 공통점.
10. **초광폭에서 중앙과 가장자리를 구분한다.** 중앙 UI는 16:9 안에 두고 가장자리 UI는 화면 끝에 붙인다. 이유: 21:9·32:9에서 둘 다 성립해야 한다.
11. **해상도별로 글자와 터치 대상이 줄어들지 않는다.** 최소 16px. 이유: 작은 모니터·3840 가독성.

## 5. 절차

### 5.1 공통 (입력 → 작업 → 출력 형식)

1. **G0 브리프**(화면 하나당): 목표 장면, 직접 연 레퍼런스 3종 이상, 공통 관례, 가장 큰 차이, 제작법, 첫 실물 판정 시점, 합격·중단 조건.
2. **회색 상자 배치도**: HTML 한 장, 1920×1080과 3840×1080(16:9·21:9·32:9 모두), 중앙 묶음과 가장자리 묶음 구분. 출력 PNG는 Git 밖.
3. **기존 화면 대조**: 같은 게임의 이미 통과한 화면(타이틀·사망 화면 등)과 한 판에 놓고 톤을 맞춘다.
4. **원화**: 틀·버튼·슬롯은 Blender 렌더(2배 해상도, RGBA PNG, 색 관리 Standard). 키아트는 블러 레퍼런스로 구도만 전달하고 반입은 금지.
5. **슬라이스·명명**: `ui_<화면>_<부품>@2x.png`, border 값은 JSON 한 장.
6. **조립**: 한 번에 한 화면. 기능(클릭·호버·포커스) → 재질 → 글자 순.
7. **판정**: 6절.

화면별 순서(실버 헬 §6 유지): 타이틀 → 공통 창 부품 → 스킬 창 → 인벤토리 → 설정 → 로비·캐릭터 선택·ENTER.

### 5.2 Unity 반입

- 텍스처 설정은 MANUAL 09 5.2와 같다(Default, sRGB, Mipmap 끔, Bilinear, Clamp).
- 중앙 UI는 `NativeUiSafeArea.Fit(W,H)`(s = min(W/1920, H/1080)), 가장자리 UI는 `NativeUiEdgeArea.Fit`(e = H/1080). 포인터 역변환도 같은 행렬을 쓴다.
- 일시정지·이름·삭제 창의 철 질감 면은 `iron_480_blur2`(14%)와 공통 `Panel(iron:true)` 경로를 쓴다(잔점 방지, `UNITY_UI_CANDIDATE_20261104.md`).
- 입장 호버: `-ui-entry-state` 강제 상태로 캡처한다(OS 마우스 조작 없음).
- 로딩 화면 비율: W/H > 2560/1080이면 32:9, > 1920/1080이면 21:9, 그 외 16:9 원화를 고른다.

### 5.3 UE5 반입 (대응만)

- 중앙 UI = 16:9 Safe Zone 안의 Canvas, 가장자리 UI = 화면 앵커 + 높이 기준 DPI 곡선.
- 영상 배경 = Media Framework(Media Texture + Material), 원화는 UI 텍스처(Mip 없음, UserInterface2D).
- 9-slice = Slate Brush Margin. 수치·톤은 3절 그대로.

## 6. 합격 기준

- 비교판: 새 화면을 **이미 통과한 기존 화면 옆에** 같은 크기로 놓는다. 1920×1080과 3840×1080, 1x·3x 크롭, 호버·선택·열기 닫기를 포함한 10초 무음 영상.
- 로비·캐릭터 선택은 레퍼런스 3종 이상 블러 비교판(구도만).

## 7. 금지

- 금·황동·원색 초록·주황·네온. 이모지 아이콘. 산세리프 단독·시스템 폰트.

- 검은 판·블러로 초광폭 빈 곳 채우기. 모든 UI를 16:9 안전 영역에만 몰아넣기(가장자리 UI는 끝에 붙임).
- 잔점·점묘·디더·그레인. 원화에 노이즈 추가.
- 창마다 다른 규격의 틀·버튼. 옛 웹 UI를 먼저 고치고 이식하는 절차(웹은 oracle 전용).
- 규칙 수치 변경(인벤토리·스킬·세이브). 코드 수정(이 문서는 지침만).
- 유료 생성 승인 밖 사용. 레퍼런스 에셋 반입. 사용자 세이브 변경.

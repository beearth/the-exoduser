# 툴 숙달 실습 — 스캔 고목을 게임 자산으로 끝까지 한 번 (2026-11-05, Mac)

입력: Poly Haven `dead_tree_trunk_02`(CC0, https://polyhaven.com/a/dead_tree_trunk_02). 지금 쓰는 전경 로그의 원본이라 같은 나무로 비교할 수 있다. 도구: Blender 4.5.15 LTS(headless), Unity 6000.6.7f1 Mac. 재현: [`tools/teardown/tm_pipeline.py`](../../../tools/teardown/tm_pipeline.py), 설정 전체: [`tm-settings-20261105.json`](tm-settings-20261105.json).

## 판정 (CTO, 11-05)

**최종: TM 1회차 종결. 정적 소품 경로 PASS.** 게임에 넣은 `A2_TM_Log`(Decimate+Shrinkwrap)가 정상 경로이고, 기존 "쿼드 아님 = 미달" 판정은 CTO가 철회했다.

처음 판정은 파이프라인 완주 PASS, 리토폴로지 단계 미달(쿼드 아님)이었다. 그 뒤의 재시도 기록은 경과로 남긴다.

## 리토폴로지 규칙 (CTO 정정, 11-05)

"쿼드 리토폴로지 필수" 기준은 정적 소품에 맞지 않았다. 쿼드 토폴로지는 변형되는 메시에 필요하다.

| 대상 | 경로 | 기준 |
|---|---|---|
| **정적 소품** (통나무·바위 등) | 삼각형 Decimate(Collapse) + Shrinkwrap | 목표 면 수, 고폴리→결과 RMS 상한 (예: 5mm) |
| **변형 메시** (캐릭터·보스) | 쿼드 리토폴로지 + 엣지 흐름 | 관절 변형에 맞는 엣지 흐름 |

Instant Meshes는 캐릭터 리토폴로지 단계에서 다시 쓴다. 5mm는 CTO가 든 예시이고, 이번 고목 1개의 수치만 있어 여러 소품에 검증한 상한은 아니다.

## 리토폴로지 재시도 (CTO 지시 순서, 실패·중단)

순서: 복셀 재구성(크기 = 최장변 4.051m ÷ 300 = 1.35cm) → 스케일·회전 적용(이미 단위값) → Quadriflow(목표 면 2,000·4,000, 대칭 끔, `use_preserve_sharp` 켬, `seed=1`).

입력 상태: 면 45,720, 전부 사각형, 비다양체 간선 0, 비다양체 정점 0, 경계 간선 0.

두 목표 모두 같은 결과이다. Python 예외는 나지 않았고 연산자가 `{'CANCELLED'}`를 반환했으며 면 수는 45,720 그대로이다. Blender가 출력한 메시지 원문:

```
Warning: QuadriFlow: The mesh needs to be manifold and have face normals that point in a consistent direction
```

### 마지막 시도: 법선 정리 후 Quadriflow — 실패, 종결

복셀 재구성 뒤 편집 모드 전체 선택 → `mesh.remove_doubles(threshold=0.0001)` → `mesh.normals_make_consistent(inside=False)` → 같은 설정으로 Quadriflow.

| 상태 | 면 | 안쪽 향함(반경 내적<0) | 방향 불일치 간선 | 비다양체 간선 / 정점 |
|---|---|---|---|---|
| 원본 고폴리 | 83,128 | 12,506 (15.0%) | 0 | 8,928 / 2 |
| 복셀 재구성 후 | 45,720 | 4,337 (9.5%) | 0 | 0 / 0 |
| 법선 정리 후 | 45,720 | 4,337 (9.5%) | 0 | 0 / 0 |

- 목표 2,000·4,000 모두 `{'CANCELLED'}`, 같은 경고 원문이다.
- 반경 내적은 줄기 중심선 기준이라 나무껍질 틈과 곁가지처럼 실제로 안쪽을 향하는 면도 센다. 정리 전후 값이 같고 방향 불일치 간선이 처음부터 0이므로, **법선 불일치 가설은 이 측정으로 뒷받침되지 않았다.** `normals_make_consistent`가 바꾼 면도 이 지표로는 없었다.
- **Quadriflow는 원인 "미상"으로 종결한다.** 다음 방법은 사용자가 Xcode를 설치한 뒤 Instant Meshes 소스 빌드이다. UV·베이크·LOD는 다시 돌리지 않았다.

## Instant Meshes 재시도 (11-05, 사용자 승인) — 쿼드 생성 성공, 형상 오차 증가

**빌드:** `wjakob/instant-meshes` `7b31608`(BSD 계열), CMake 3.31.6 공식 압축본, arm64 네이티브. Homebrew·Rosetta·관리자 권한은 쓰지 않았고, 결과는 Git 밖 `~/EXODUSER-Storage/asset-teardown/_tools/build/im`에 있다. Xcode 없이 Command Line Tools로 빌드했다(`DEVELOPER_DIR` 지정). 기본 SDK 27.0은 링커가 `arm64e.x1` 항목을 읽지 못해 실패했고, `-DCMAKE_OSX_SYSROOT=.../MacOSX26.5.sdk -DCMAKE_OSX_DEPLOYMENT_TARGET=26.0`으로 통과했다.

**실행:** `Instant Meshes -d -r 4 -p 4 -f <값> -o out.obj in.obj`. `-f 2000`은 6,745면, `-f 4000`은 13,705면이 나왔다. 순수 쿼드로 나누는 단계에서 면이 늘어나서, 목표에 맞도록 `-f`를 590·1,170으로 낮췄다. 2,000·4,000은 최종 면 수 기준이다.

|---|---|---|---|---|---|---|---|---|

- **원본을 바로 넣으면 쓸 수 없다.** 원본 스캔은 158덩어리, 경계 간선 8,928개라 결과가 찢어진다: [원본 입력 4,000](img/tm-im-raw-4000-shape.png).
- **복셀을 거치면 쿼드 조건은 만족한다.** 전 면이 사각형이고 비다양체 간선은 0이다: [원본 형태](img/tm-im-high-shape.png), [복셀 4,000 형태](img/tm-im-vox-4000-shape.png), [격자](img/tm-im-vox-4000-wire.png). 격자 그림에 대각선이 보이는 것은 렌더의 와이어 노드가 삼각형으로 그리기 때문이고, 면 수는 메시에서 직접 셌다.
- **형상은 기존 Decimate보다 나쁘다.** 오차 RMS가 3.08mm에서 11.76mm로 커졌고, 최대 오차는 약 239mm이다. 위쪽 곁가지가 사라졌고(그림에서 확인) 표면이 각져 보인다. 최대 오차의 원인이 그 곁가지인지는 따로 측정하지 않았다.
- **Decimate 행은 조건이 다르다.** Decimate는 원본에 Shrinkwrap을 적용했고 Instant Meshes 결과에는 적용하지 않았다.
- **게임에는 넣지 않았다.** 게임 자산은 기존 `A2_TM_Log` 그대로이고, UV·베이크·LOD·34° 캡처를 이 메시로 다시 돌리지 않았다. 베이크한 노멀로 이 차이가 얼마나 가려지는지는 미확인이다.

재현: [`tools/teardown/tm_im_export.py`](../../../tools/teardown/tm_im_export.py), [`tools/teardown/tm_im_measure.py`](../../../tools/teardown/tm_im_measure.py), 측정값 [`tm-im-results-20261105.json`](tm-im-results-20261105.json).

같은 `NEAREST_SURFACEPOINT` Shrinkwrap을 적용했다. 게임에는 넣지 않았다. 형태: [Shrinkwrap 후](img/tm-im-vox-4000-sw-shape.png).

- 측정값: [`tm-im-shrinkwrap-20261105.json`](tm-im-shrinkwrap-20261105.json), 스크립트 [`tools/teardown/tm_im_shrinkwrap.py`](../../../tools/teardown/tm_im_shrinkwrap.py).

## 미달·대안

- **쿼드 리토폴로지:** 정적 소품 기준에서 제외. 이 고목의 UV·베이크·LOD·34° 화면 비교는 Instant Meshes 메시로 돌리지 않고 종결한다.
- **텍셀 512px/m:** 미달(중앙값 454). 지금 손대지 않는다. 메인 UV 섬이 512px/m에서 약 1546×1106px로 추정되어 2048×1024의 높이를 넘는다. **대안: 메인 섬을 자르는 심을 하나 더 넣고 패킹을 개선한다.** 그래도 안 되면 2048×2048로 올리되, BC·N 메모리가 2배가 된다. 이 추정치는 현재 패킹 결과에서 역산한 값이다.

## 거목 검은 점 — 종결

**뒤집힌 면 후보, 게임 재현 0. 추가 조치 없이 종결한다.**

- 게임 화면(1920×1080, 34°), 플레이어 위치 (20, -63.4), `A2 外곽 -1/2/3`(RF3_Ancient_Tree_A) 몸통 3배 크롭에서 보이지 않았다: [크롭](img/tm-blackdot-game-3x.png), [Blender 렌더](img/tm-blackdot-render.png). 범위는 한 그루, 한 각도이다.
- 잔점·디더링이 아니다. Blender 광선 검사에서 검은 점 3곳은 모두 면법선이 카메라 반대쪽이었고(내적 -0.60~-0.93, 정상 지점 +0.94), 2곳은 같은 크기의 면보다 UV 면적이 큰 소수 면이었다.
- 원인은 후보 단계로 남긴다. 다른 그루·각도에서 구멍으로 보이면 그때 다시 연다.

## 이번에 새로 나온 사실

- **1-1 씬에 거목이 542그루 배치되어 있다:** Ancient_Tree_A 256 + B 286 (`필드-렌더러.txt`), 그루당 19,888△로 합계 약 **1,078만△, LOD 없음.** 합계는 배치 기준이고 화면에 그려지는 수는 아니다. 시작 지점 한 프레임에서 `isVisible`인 거목은 55그루(약 109만△)였고, 이 값은 그림자 카메라를 포함한다. 이전 프로파일의 약 1,500만△와 어떤 관계인지는 재지 않았다.

## 한계

- **게임에 들어간 `A2_TM_Log`는 쿼드가 아니다.** 복셀+Decimate 결과이고 나뭇결 흐름을 따르지 않는다. 정적 소품 규칙에서는 정상 경로이다. Instant Meshes 쿼드 메시는 게임에 넣지 않았다.
- 텍셀 밀도 512px/m 미달(중앙값 454). 배치 배율(1.7×) 적용 시 더 낮다. 다만 플레이 화면 기준(75px/u)은 크게 넘는다.
- FPS는 재지 않았다. 지면 접합 코드가 실행 중 법선을 다시 계산하므로 UV 심에 경계가 생길 수 있는데, 이번 각도에서는 바닥 심이 안 보인다.
- 원본의 색을 그대로 구웠고 조형·재채색을 하지 않았다. **"우리 것으로 만드는" 단계는 아직 안 했다.**
- 단계 소요 시간은 이 환경의 시계를 신뢰할 수 없어 적지 않았다.
- `tm-uv-after.png`는 폭 1024로 축소했다. 나머지 이미지는 1x이고, `*-3x.png`는 최근접 3배 확대이다.

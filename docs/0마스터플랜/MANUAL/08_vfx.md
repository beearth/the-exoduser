## 1. 목표 장면·레퍼런스 (무엇을, 왜)
- 목표 장면: 1-1 드루이드전 한 판. 보스 예고 → 막기/회피 → 접점 → 잔여 장판이 한 화면에서 읽히고, 먼 적이 가려지지 않는다.
- 레퍼런스: 디아블로4(강한 효과는 궁극기에만, 효과가 빛을 내 어둠을 밝힘 [사실], 보스 예고 우선), PBZ(두 색 문법, 밝음은 접점에만), 황천(어두운 세계의 국소 광원).
- 왜: 기존 VFX는 바닥·독·호박색 발광과 색이 섞였고 점·잡티가 남았다(사용자 반려 사례).

## 2. 디렉션 원칙
1. 시각 우선순위: 적 예고 > 보스 본체 > 아군 스킬. 예고 영역 안 아군 VFX 알파 ×0.5 이하. 이유: 예고가 항상 위(D4 ①).
2. 예고는 두 가지 의미만: 막을 수 있음(뼈색 `#efe6d2` ParryGlint) / 피해야 함(무지개 DANGER 링). 이유: PBZ 색 문법, 빨강은 빨콩과 혼동.
3. 모든 VFX는 4단계(예고→접점→본체→잔여) 표를 먼저 쓴다. 표 없으면 제작 금지. 이유: 타이밍이 Core 틱에 맞아야 한다. (3차, codex_synthesis §1.7 #1: 4단계는 **역할 분해**이지 투사체까지 묶는 고정 재생 순서가 아니다. 투사체·지속 판정은 "위험이 남으면 경계가 남는다"를 우선하고 해당 없는 단계는 표에 "없음"으로 적는다.)
4. 접점 첫 프레임을 비우지 않는다. 코어는 짧고 밝게(1~3프레임), 본체는 방향이 있다. 이유: 방향 없는 원·별은 값싸 보인다.
5. 밝음은 접점에만, 화면 나머지는 어둠 유지. 그러나 어둠이 먼 적을 지우면 FAIL. 이유: PBZ/황천 + 카메라 LOCK.
6. 기술의 빛이 바닥 범위를 밝힌다: 접점 점광원 6~10틱, 동시 2개 이하. 이유: D4 효과가 스스로 빛을 낸다.
7. 파티클 알파 겹침은 예산으로 제한한다. 이유: 오버드로가 60fps와 탄막 가독성을 깬다.
8. 점 금지: 잔점·점묘·디더·그레인·업스케일 잡티 0. 3x 크롭에서만 합격. 이유: CLAUDE.md 4.2-7.
9. 캐릭터에 붙는 효과(검격 리본·스미어)는 캐릭터와 같은 저해상도 렌더에서 같이 픽셀화, 지면 효과는 월드에. 이유: 픽셀 밀도 일치.
10. 레퍼런스의 에셋·코드는 반입하지 않는다. 이유: 공부, 카피 아님.
11. 보호할 정보를 먼저 정한다: 적 탄의 중심·윤곽·진행 방향, 피해 영역 경계, 영웅 위치·발밑. 아군 장식이 이 중 하나를 못 읽게 하면 가독성 FAIL. 이유: 정보의 순서가 장식의 양보다 먼저다 [추정, codex_vfx_direction §3·8].
12. 색만으로 구별하지 않는다. 위험은 윤곽·형태·움직임도 함께 다르게 한다. 같은 색 장판 위에서도 탄 경계와 진행 방향을 찾을 수 있어야 한다. 이유: 색 충돌 시 정보 소실 [추정].
13. 순간 접점은 좁고 분명하게, 지속 판정은 경계가 남게, 판정이 끝난 잔여는 빨리 감쇠한다. 실제 위험이 남았는데 장판을 지우지 않고, 위험이 끝났는데 같은 경고색을 남기지 않는다. 이유: 잔여가 다음 예고와 혼동되면 안 된다 [추정, codex_vfx_direction §8-3].
14. 밝게 덧그리기 전에 공간을 비운다. 영웅 주변·탄 진행선 위의 연무·발광 면적을 줄이고, 감축 순서는 판정 무관 잔여 → 넓은 연무 → 중복 발광층 → 보조 입자다. 예고와 탄 경계는 유지한다. 이유: PoE2는 지속 화면 효과(안개)를 줄여 가독성을 올렸다 [사실 단일 GGG 보도자료]. 감축은 장식에만 적용하며 Core 수치·판정은 건드리지 않는다.
15. 가산 합성은 작은 발광 접점에 쓰고, 넓은 본체·연무가 겹쳐 흰 면이 되게 하지 않는다. 플립북 프레임 보간은 기본에서 뺀다(픽셀 경계). 이유: 가독성·픽셀 밀도 [추정, codex_vfx_direction §4·7].

## 4. 제작 도구 — 확정 추천: 파티클 시스템(CPU) + 플립북 시트 + 메시/셰이더 지면 표식

| 스파크·먼지·피·독 잔여 | Shuriken 파티클 + 플립북 + Shader Graph (전투 VFX 전부) | Niagara CPU/스프라이트 이미터 |
| 대량 환경 입자(재·불씨·반딧불) | VFX Graph — 환경 전용 | Niagara GPU |
| 점광원 | 점 라이트 ≤2 | Point Light ≤2 |
| 캐릭터 부착 효과 | 픽셀 RT 레이어(30) | 같은 SceneCapture 레이어 |
| 시트 제작 | Blender 렌더 또는 기존 웹 원화 재사용 | 동일 |
- 대안: VFX Graph 전면 사용 — 규모에 과함, Core 틱 시드·정지·되감기 제어 어려움.
- TOOLCHAIN §2-7과 대조(2차): 추천 A(Shuriken + Shader Graph, 전투 VFX 전부), VFX Graph는 환경 대량 입자만. 이 문서의 이전 초안은 독안개 잔여에 VFX Graph를 허용했으나 TOOLCHAIN·연구 3건(Yellowsky §4.1, D4-03, D4-04)이 전투 VFX 전부 A를 추천하므로 맞췄다(D08-5). 핵심 탄 판정을 GPU 장식 입자에 맡기지 않고 판정과 표현을 분리한다. VFX Graph 도입 시 Compute Shader 지원(Metal)과 URP 지원 범위를 Mac에서 먼저 확인.
- 1차 후보 구성 [추정, codex_vfx_direction §10]: 예고 경계·접점·본체 실루엣 = 제어하기 쉬운 플립북/메시 + Shuriken, 판정과 무관한 보조 효과만 VFX Graph 비교.
- 커스텀 툴 — "VFX 점·가림 검사기": 입력 = 1x/3x 캡처, 처리 = 고립 픽셀 군집 수 센 뒤 점 개수, 예고 영역 휘도 대비, 먼 적 위치 휘도 비교, 출력 = 체크표(PASS/FAIL). 사용자 = 구현 레인·총괄. 만드는 사람 = Sonnet 구현 레인(도구는 읽기 전용, 코드 외부).

## 5. 절차
### 5.1 공통
1. 입력: 4단계 타이밍 표(Core 틱 인용), 색 토큰, 예산.
2. 작업: 접점 한 장면 → 본체 → 잔여 → 예고. 단색 형태로 1x 판정 후 색. 색 후 3x 크롭 점 검사.
3. 출력: 플립북 PNG(알파 premultiplied, 4×4, 이름 `fx_<기술>_<단계>_<셀수>.png`), 파티클 프리셋 `fx_<기술>`, 한 기술당 예고·접점·본체·잔여 4세트.
4. 작업 순서 보강(2차): ① 보호 정보 목록(원칙 11)을 기술마다 한 줄로 적는다 ② 단색 덩어리로 방향·범위·접점이 읽힌 뒤에 색·입자를 붙인다 ③ 최악 중첩(아군 반복 공격·궁극기·적 장판·탄이 겹칠 때와 효과가 사라질 때)을 흑백·색만 본 비교로 보조 확인하고, 최종 판정은 실제 속도 무음 플레이에서 위험을 읽는지로 한다 ④ 빈 공격과 명중 공격을 나눠 접점 포즈·VFX·Core 판정 시각을 맞춘다(Hades Nova 사례).
### 5.2 Unity 반입
- 텍스처 Bilinear, mip 0, 압축 없음. 머티리얼 가산(빛) / 알파(피·먼지). 정렬: 지면 효과는 지면 위, 예고는 아군 효과 위. Core 이벤트(예비 시작·발동·판정 끝)에 맞춰 재생, 풀링.
- 픽셀 합성 경로(2차): 캐릭터 부착 효과(검격 리본·스미어)와 핵심 접점 코어는 캐릭터와 같은 저해상도 합성 경로(첫 비교안: 불투명 → 외곽선 → 투명/VFX → 정수 확대 → UI, [추정]·확정 사양 아님)에 넣고, 지면 예고·장판은 월드 Decal로 그린다. 2D Pixel Perfect Camera는 원근 3D 장면 전체를 픽셀화하지 않으므로 그대로 대입하지 않는다(D08-4). 플립북 프레임 보간은 끄고 선명한 외곽·단계형 색을 쓴다. 파이프라인 정렬: 정렬 큐는 §3.5 순서.
### 5.3 UE5 반입 (대응만)
- 시트는 Sub UV, 예고는 Decal 머티리얼, 이벤트는 델리게이트 구독, 풀링은 Niagara Pool.

## 6. 합격 기준
- 비교판: 같은 기술의 4단계 4컷을 D4·PBZ 공개 영상 옆에 같은 크기로(감각 대조). 1920×1080·3840×1080.
- 1x에서 예고가 바닥·독·호박색과 구분된다. 먼 적이 예고·접점 빛에 지워지지 않는다. 지워지면 FAIL.
- 3x 크롭 점 0. 10초 무음 영상에서 예고→접점→잔여가 읽힘.
- 예산 위반 0(§3.3), 외곽 오차 ≤1텍셀.
- 2차 판정: 색을 빼도(흑백) 방향과 접점이 읽힌다. 아군 효과가 겹쳐도 탄 경계가 남는다. 위험이 끝나면 잔여가 다음 예고와 혼동되지 않는다. 이동·회전 중 가는 탄이 사라지거나 깜빡이지 않는다(정지 확대 판정 금지). 최악 중첩 장면에서 먼 적이 지워지지 않는다.
- 아직 합격 선언 불가 항목: 실제 Player 가독성, 픽셀 합성의 시간적 안정성, 목표 기기 CPU/GPU ms, 동시 입자·오버드로 예산, 설치된 Unity/URP/VFX Graph 버전별 기능 — 전부 Mac 실측 뒤(codex_vfx_direction §10 "남은 관문").

## 7. 금지
- 네온·형광, 시안, 빨강 예고, 예고와 같은 색의 아군 효과.
- 점·점묘·디더·그레인·업스케일 잡티. 보정에 노이즈 추가.
- 먼 적을 지우는 안개·비네트·어둠·가림 투명화.
- 이모지를 이펙트·UI 아이콘 대용. 원색 초록·노랑.
- 레퍼런스 에셋 반입. Core 범위·타이밍 변경. E로 무지개탄 패링되는 연출.
- 입자 수만 줄이고 큰 투명 카드를 남기는 최적화, 입자 수 하나로 렌더 비용 판정, 연구에 없는 원작 수치를 "업계 표준"으로 채움. 방사형 블러를 기본 효과로 사용. 디졸브 임계 가장자리 전체 발광·미세 점 장기 잔류. 실제 위험이 남았는데 장판을 지우는 것, 위험이 끝났는데 같은 경고색을 남기는 것.
- Core 수치·동시 공격 제한을 바꾸는 방식의 "감축". 렌더 순서(탄 항상 위)만으로 가독성을 해결했다고 보는 것.

# 에이전트 운영 매뉴얼 — Claude 총괄·Codex·PC·서브에이전트 공통

작성 2026-11-03 (Mac Claude 총괄). 사용자 지시 "클로드 총괄 등 모든 에이전트 매뉴얼 만들고"에 따라 메모리·CLAUDE.md·AGENTS.md·WORK_BOARD에 흩어져 있던 운영 규칙을 한곳에 모았다.

- **적용 대상:** 이 프로젝트에서 일하는 모든 AI 에이전트. Claude 세션(Mac 총괄, PC, 클라우드, 서브에이전트), Codex(Mac·PC, CLI·앱), heavy 에이전트.
- **우선순위:** 사용자의 최신 지시 > 이 매뉴얼 > 개별 팀 문서·옛 지시서. 서로 충돌하면 이 매뉴얼을 따르고, 충돌 사실을 보고한다.
- **지금 누가 무엇을 하는지:** 이 문서가 아니라 [WORK_BOARD](../engine/orders/WORK_BOARD.md)(origin/main)가 기준이다.
- 게임 규칙(디자인 톤, docs 동기화, 번역, DOM 안전, 배포 절차)은 [CLAUDE.md](../../CLAUDE.md)와 [AGENTS.md](../../AGENTS.md)에 있다. 이 문서는 **일하는 방식**만 다룬다.

## 2. 모든 에이전트 공통 원칙

### 2.1 작업 방식 — 프로젝트를 직접 수정한다 (2026-11-03 사용자 확정)
- 자기 worktree(브랜치)의 실제 파일을 직접 고친다. 되돌릴 기준은 git 커밋이다.
- "원본 보호"를 이유로 프로젝트 복사본을 만들어 그 안에서 편집하지 않는다. 11/02에 이 방식 때문에 작업 하나가 100~200GB를 쓰고 토큰도 낭비했다.
- "타인 WIP 불간섭·보존"은 **다른 세션이 쓰는 파일과 checkout**에만 해당한다. 자기 worktree는 자유롭게 고친다.

### 2.2 최신만 남긴다 — 디스크 (2026-11-02~03 사용자 지시)
- 새 빌드·후보·캡처·백업을 만들면 이전 것은 그 자리에서 지운다. 남기는 것은 최신 1개, 그리고 비교가 꼭 필요할 때만 직전 1개까지다.
- 빌드는 고정 폴더(예: `build-current`)에 덮어쓴다. 시도마다 `build-<이름>` 같은 새 폴더를 만들지 않는다.
- 프로젝트 전체 복사는 금지다. 꼭 필요하면 APFS 복제(`cp -c`)를 쓴다.
- 단계별 `before-*` 사본은 쌓지 않는다.
- **빌드는 git이 관리한다**(2026-11-03 사용자 "빌드는 항상 깃에서 관리가 되는데").
  - 빌드는 커밋에서 언제든 다시 만들 수 있다. 확인이 끝난 빌드는 남기지 않고, 보고서에는 빌드 폴더 대신 커밋 SHA를 적는다.
  - 지킬 가치가 있는 변경은 백업 사본·복사본·로컬 보관 빌드가 아니라 커밋·push로 지킨다.
  - 작업을 끝낼 때 커밋 안 된 실제 수정을 남기지 않는다.
  - 배포용 패키지(DEMO/EA/Steam 업로드본)만 예외로, 배포 절차가 정한 위치에 둔다.
- worktree는 `git worktree add --no-checkout` + `sparse-checkout`으로 필요한 경로만 받는다. 끝나면 push와 원격 일치를 확인하고 자기 worktree를 제거한다.
- 작업 시작 때와 큰 산출물을 만든 뒤 `df -h /System/Volumes/Data`를 확인한다.
  - 남은 공간이 100GB 미만이면 정리부터 한다.
  - 작업 하나가 남긴 용량이 20GB를 넘으면 정리부터 한다.
- 묻지 않고 지워도 되는 것: 3일 넘은 `~/exoduser-wt/_out` 폴더, 생성물(.uid/.import/override.cfg)만 남고 원격에 올라간 worktree(브랜치는 유지), 업데이트·패키지 캐시.
- 지우기 전에 확인할 것: `ps`로 그 경로를 쓰는 프로세스가 있는지, 커밋 안 된 직접 수정이나 원격에 없는 커밋이 있는지. 있으면 남긴다.
- 묻고 지울 것: 실행 중 앱 폴더, user-state·저장 데이터, 남의 산출물, `~/.codex`, Downloads, 배포 빌드.

### 2.3 검증·테스트 (2026-10-23 사용자 규칙)
1. 실패한 테스트를 코드 수정 없이 다시 돌리지 않는다. "3회 안정성 확인"·"각 2회 재현"도 금지다. 로그로 원인을 고친 뒤 그 테스트만 1회 돌린다.
2. 같은 테스트가 2번 실패하면 멈추고 보고한다.
3. 회귀는 바꾼 파일과 직접 관련된 스위트만 1회 돌린다. 전체 E2E는 통합 직전 1회만 한다.
4. 검증은 판정에 필요한 만큼만 한다: 빌드 1회, 스크린샷, 핵심 로그.
   - 바이트 manifest, SHA readback, 매 빌드 원격 push는 배포 직전이나 요청이 있을 때만 한다.
   - 결함 주입이나 8뷰 캡처처럼 큰 검증은 그 작업에 꼭 필요할 때만 한다.
5. 테스트 PASS는 필요조건일 뿐이다. 화면에 보이는 작업은 실제 게임 캡처를 1x로 눈으로 보고 판정한다(CLAUDE.md "작업물 퀄리티·디자인").

### 2.4 토큰·비용
- 명령 출력은 파일로 보내고, 화면에는 요약(통과/실패 수)과 실패 줄만 `tail`·`grep`으로 읽는다. 큰 소스나 JSON을 통째로 출력하지 않는다.
- 보고서는 짧게 쓴다: 고친 것, 결과(스크린샷·판정), 남은 문제. 표 1~2개면 된다.
- 지시문도 짧게 쓴다. 공통 규칙은 "AGENT_OPERATIONS_MANUAL §2 준수" 한 줄로 대신한다.
- 작업 진행이 먼저다. 낭비는 줄이되 필요한 검증·어려운 작업에는 쓴다. 비용 경고는 한도가 닥친 뒤가 아니라 추세가 보일 때 미리 한다.

### 2.5 Git
- 작업 하나 = 브랜치 하나(`codex/<작업>-<날짜>`, `claude/…`). main 병합은 Claude 총괄만 한다(검수 후).
- `git add -A`는 금지다. 자기 경로만 `git add --`로 스테이징하고, 코드와 관련 docs를 한 커밋에 넣는다.
- 이미 push된 커밋의 history를 고쳐 쓰지 않는다(reset·rebase·force-push 금지). 잘못 묶였으면 provenance note만 남긴다.
- pre-commit `docs-sync-check`는 `docs/CHANGELOG_SYNC.md` 절 추가를 요구한다. 우회하지 않는다.
- 작업 시작 시 WORK_BOARD "진행 중" 표에 행과 소유 파일을 적는다. 다른 행의 소유 파일은 수정하지 않는다.

### 2.6 리소스 (Mac 과부하 사고 2026-10-20)
- Codex 동시 실행은 기본 1개다. 사용자가 늘리라고 할 때만 늘리고, 최대 약 6개까지다.
- Godot·Unity 실행 전에 동시 실행 수를 확인한다. 예: `pgrep -f 'Godot.app/Contents/MacOS/Godot' | wc -l`. 2개 이상이면 30초씩 기다린다.
- 남은 메모리가 적으면 Codex 수를 줄인다.

### 2.7 게임 화면 품질
- 개발 상태 문구("미이식", "연결 대기" 등)를 게임 화면에 띄우지 않는다. 연결되지 않은 기능은 숨긴다.
- 틱 경로(_process/_physics_process/Update)에서 `get_method_list()` 같은 목록 생성 API를 쓰지 않는다. 계약 검증은 최초 1회 계산해 캐시한다.
- CRLF 파일(예: `번역대상_전체목록.md`)은 줄바꿈을 보존한다.

## 3. Claude 총괄 매뉴얼

### 3.1 배정
- Codex는 터미널 탭(run_in_terminal) 대신 Bash 백그라운드로 실행한다. 탭을 열 때마다 허용을 묻는 것을 사용자가 싫어한다.
  ```bash
  cd <worktree> && codex exec -s danger-full-access --skip-git-repo-check - < <scratchpad>/<작업ID>.txt > ~/exoduser-wt/_out/<작업ID>/codex-exec.log 2>&1
  ```
- 작업마다 새 exec를 쓴다(새 대화라 ctx 관리가 필요 없다). 순서를 기다릴 때는 같은 백그라운드 명령 안에서 until 루프를 쓴다.
- 모델·effort 기준: 간단(merge·수치 확인·표 갱신)은 낮게, 보통(지시서가 있는 구현)은 medium, 어려움(여러 파일 충돌·원인 불명 결함)은 high. 설정 변경은 사용자 승인이 필요하다.
- 여러 작업이 동시에 끝나면 검수보다 **다음 배정을 먼저** 넣는다. 검수 결과(RETOUCH)는 후속 작업으로 붙인다.
- 사용자가 자는 동안은 질문하지 않고 판단해서 진행한다. 단 삭제·배포·구매·설정 변경은 예외다.

### 3.2 지시문 템플릿
```
[작업ID] <한 줄 목표>
worktree: <경로>  브랜치: codex/<작업>-<날짜>  기준 SHA: <main SHA 이상>
소유 파일: <목록>  (그 밖의 파일은 수정 금지)
할 일:
1. ...
완료 기준: <측정 가능한 조건 + 필요한 캡처 1~3장>
규칙: docs/0마스터플랜/AGENT_OPERATIONS_MANUAL.md §2 전부 준수
 - 자기 worktree를 직접 수정(복사본 금지), 빌드는 build-current에 덮어쓰기, 이전 산출물 즉시 삭제
 - 관련 테스트만 1회, 무수정 재실행 금지, 2회 실패 시 정지·보고
 - 출력은 파일로, 화면엔 요약만. 개발 상태 문구 노출 금지
 - CHANGELOG_SYNC 절 추가, 경로 지정 커밋, push
보고: ~/exoduser-wt/_out/<작업ID>/SUMMARY.md (고친 것 / 결과 / 남은 문제, 마지막 줄 END)
```

### 3.3 검수
- DONE이나 SUMMARY만 믿지 않는다. 실제 브랜치 SHA(`git ls-remote` 또는 worktree log)와 diff를 확인한다.
- 화면 작업은 캡처를 직접 1x로 본다. 미확인이면 "기능만 완료, 디자인 미검수"라고 적는다.
- 같은 작업이 두 번 RETOUCH되면 지시문 자체를 고친다(범위·완료 기준·금지사항).

### 3.4 정기 점검 (작업할 때마다)
| 항목 | 확인 방법 | 기준 |
|---|---|---|
| 디스크 | `df -h /System/Volumes/Data`, `_out` 폴더 수 | 100GB 미만이면 §2.2에 따라 정리 |
| 노는 Codex | 백그라운드 작업 상태 | 끝났으면 다음 작업 배정 |
| 크레딧·한도 | rollout `token_count.rate_limits.primary.used_percent` | 급증 추세면 사용자에게 미리 보고 |
| 과부하 | 부하 평균, 남은 메모리, `ls /Library/Logs/DiagnosticReports/panic-*` | 위험하면 동시 실행을 줄임 |

### 3.5 기록
- 작업노트: `outputs/mac-work-notes/MAC_WORK_NOTES_<날짜>.md`(미추적). 배정·완료·막힘·판정마다 갱신한다.
- 사용자에게 보고할 때는 끝난 것, 확인 안 된 것, 남은 것을 구분한다. 커밋만 하고 원격·실행본 반영이 안 됐으면 그렇게 적는다.

## 4. Codex 매뉴얼 (실행 담당)

1. **시작:** 지시문의 worktree·브랜치·기준 SHA를 확인한다. `df`로 남은 공간을 보고, WORK_BOARD에서 소유 파일이 겹치지 않는지 확인한다.
2. **작업:** 자기 worktree의 실제 파일을 직접 고친다. 빌드는 `build-current` 하나에 덮어쓴다. 새 산출물을 만들면 이전 것은 지운다.
3. **테스트:** §2.3을 따른다. 출력은 파일로 보내고 요약만 읽는다.
4. **마무리:**
   - 경로 지정 커밋(CHANGELOG_SYNC 포함) → push → 원격 SHA 확인
   - 자기 중간 산출물 삭제. 남는 것은 SUMMARY와 판정에 쓴 스크린샷·로그뿐이다.
   - worktree를 제거하라고 지시받았으면 제거한다.
5. **보고(SUMMARY.md):** 고친 것 / 결과(캡처 경로·판정) / 남은 문제 / 지운 산출물과 비운 용량. 마지막 줄은 `END`.
6. **멈출 때:** 같은 테스트 2회 실패, 소유 파일 밖의 수정이 필요할 때, 디스크가 부족한데 지울 수 있는 자기 산출물이 없을 때. 이유를 적고 멈춘다.

> Mac 전역 Codex 규칙 `~/.codex/AGENTS.md`(Git 밖)에도 §2.1·§2.2가 들어 있다. 규칙을 바꾸면 이 문서와 그 파일을 함께 고친다.

## 5. PC Claude 매뉴얼

- 사용자가 직접 시킨 작업만 한다. 새 자동 작업은 배정하지 않는다.
- Windows 구동 테스트는 main을 받아 실제 창에서 확인하고, 결함은 WORK_BOARD에 행으로 올린다.
- 서버는 `C:\nvm4w\nodejs\node.exe server.cjs`(포트 3333)로 띄운다. `node`만 치면 깨진 shim이 잡힌다. python http.server는 쓰지 않는다.
- 배포(DEMO/EA 동기화, Steam)는 CLAUDE.md 절차를 따르고, Set Live와 패치노트 게시는 사용자 확인 후 한다.
- main 병합은 사용자가 직접 시킬 때만 한다.

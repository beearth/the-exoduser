**근거와 현 상태(2026-10-12 조사 시점; 아래 2026-10-16 부분 이식 보충 참조).** W02는 아이템 표시·주의 환기 정책을 분리한다. 현재 `game.html`:16306 `_wiPush`는 `worldItems.length>20`이면 낮은 rarity 항목부터 배열에서 제거한다. 비-item 타입은 -1이라 먼저 제거 후보가 된다. `rollDrop`:31189는 최소 rarity 미만을 생성 전에 건너뛰고 :31195는 생성한 item의 reqLv가 최소 티어 기준 미만이면 바닥에 넣지 않는다. 옵션 oninput :48128/:48136은 기존 바닥품도 `splice`로 제거한다. ‘최소 줍기’는 **필터 때문에 숨은 채 남아 있는 물건**이라는 의미와 다르다. 관련 현행 아이템 문서에도 생성 생략이 명시되어 있으므로 의도 없는 버그로 단정하지 않고 정책/용어 재설계로 다룬다. 분해 환수/자동 회수의 보완을 이 함수에서 발견하지 못했다. 이는 정적 분기의 확인이며 실제 플레이에서 손실을 재현한 것은 아니다.

**독자 적용.** (1) 우선 현재 옵션의 생성 제외/기존 바닥품 제거 의미를 설명하고 생성된 보상의 ID·type·수량·원인별 종료를 추적한다. (2) 표시/그림 예산과 보상 데이터 예산을 분리한다. 화면의 효과 개수를 제한해도 미수거 보상을 몰래 삭제하지 않는다. 재료는 기존 `mergeMatItems`로 동종 묶음을 검토하고, 중요 장비는 메타데이터 대기/정산 목록으로 보존하는 작은 구조를 검토한다. 보존 한계·맵 전환/사망/재접속 정책도 명시한다. (3) 전체/희귀 이상/현재 빌드 관련 프리셋은 draw/표시 판정으로 처리하고 임시 전체 표시를 제공한다. 기존 최소 줍기 옵션의 의미를 마이그레이션 없이 바꾸지 않는다. (4) 현재 바닥 라벨을 상시 숨기는 설계는 유지하고, 확인 입력/수거 예정 대상만 짧게 이름·등급을 표시한다. 중요 드롭의 외곽/짧은 음/미니맵 신호는 기존 `playItemDropSfx`와 rarity 표현을 재사용한다.

**효과/위험.** 중요한 보상에 대한 신뢰와 결정 속도 개선을 기대한다. 생성 제외를 표시만 숨김으로 바꾸면 실제 획득·분해 경제와 RNG 호출 순서가 달라질 수 있다. 무제한 ground 배열·자동 분해·보상 재생성은 피한다. 이 작업은 20을 큰 수로 바꾸는 단순 패치가 아니다.

**검증.** 21개 이상 혼합 장비·재료와 보스 드롭을 입력해 모든 ID의 최종 위치를 대조한다. 필터 off/on 전환 전후 보상 총량 불변, 희귀/유니크 보호, 같은 item 중복 수거 0, 재료 수량 보존, 장비/분해/맵 전환/구세이브 설정 의미를 검사한다. 로딩/활성 라벨 개수·프레임을 함께 측정한다. 드롭 확률/강화 비용 자체를 변경하지 않는다. 현재 T1~T10(q)과 드롭 reqLv tier를 테스트에서 구분한다.

**작업 인계.** `LOOT-01` 보존 정책·계측/가드 → `LOOT-02` 표시 분리·옵션 의미/마이그레이션 → `LOOT-03` 정보 계층·중요 드롭 신호. 관련 docs: `2_7 인벤토리+장비시스템`, `7아이템디자인`, `14밸런스+수치테이블`.

### P02 — 예고와 패링 입력을 같은 규칙에서 표시

**근거와 현 상태.** W01은 신호의 시점·일관성, W03은 VFX와 피해 영역 일치를 다룬다. EXODUSER `_projectileParryClass`:16496은 physical/magic/forbidden을 분리한다. `blackBean`은 magic이며 E 반사 경로에서 제외한다(:16501,:16509). `web`은 forbidden(:16502)인데 일부 물리탄 외형을 공유해 오인 위험이 있다. `_drawEnemyShotWarnings`:19395–19415의 설명 문구는 physical의 ‘E로 패링’뿐이다. 특수 magic은 `shieldFuse`·`_stWingT`·`sBash` 조건에서 E 허용도 있다(:16511). 그러므로 ‘magic은 항상 Q만’이라는 새 단순 표도 잘못이다.

**독자 적용.** 발사 예정 projectile의 실제 속성/특수 플래그를 보존하여 예고·최종 탄·판정이 같은 데이터를 읽게 한다. 기본 대응은 physical의 현재 E 안내, magic의 Q 안내, forbidden의 회피 안내로 구분하되 **현재 빌드의 특수 허용과 BINDS를 실제 판정 헬퍼에서 계산**한다. 무지개는 기존 Q 전용·블루콩 유도반사 계약을 지킨다. 외곽 모양/짧은 키 기호를 우선해 색 의존을 낮추고, 텍스트는 가까운 핵심 위협만 표시한다. 주요 보스의 음/형태는 패턴 시작에 동일하게 연결하되 음소거에서도 해석 가능하게 한다.

**효과/위험.** 잘못된 입력 학습과 ‘패링했는데 안 됨’ 체감을 줄인다. 예고 중 방향/좌표를 어느 시점에 확정하는지는 기존 커밋·추적 설계를 따른다. 대미지·패링 윈도·회복량을 이번 가독성 변경과 섞지 않는다. `_chargeLabelMetrics`:23388–23402는 한 문구만 캐시하므로 세 문구 교차 시 `measureText`가 반복될 수 있다. 렌더러·font·언어·짧은 문구별 제한 캐시와 무효화를 함께 검토한다.

**검증.** physical/일반 magic/blackBean/big-energy/web/noParry/friendly 및 특수 합체 조건의 안내와 실제 판정을 대조한다. Q/E/Shift 재바인딩·한글/영문·음소거·100/400/700 적 혼합 장면에서 신호를 읽는다. 30/60/120 render FPS에서도 동일 물리 틱의 성공/실패·피해/회복을 비교한다. 예고 영역 밖 피격/안 피격, 경계 반지름, commit 직전/직후 위치를 검사한다. 문구 종류를 늘려도 반복 측정/할당이 증가하지 않아야 한다.

**작업 인계.** `COMBAT-01` cue 데이터·실제 허용 입력/BINDS 공유 → `COMBAT-02` 예고/판정 경계·음/형태·문구 캐시 회귀. 관련 docs: `docs/8.0몬스터디자인/PHYSICAL_PROJECTILE_AUDIT_20260916.md`, `docs/8.0몬스터디자인/PHYSICAL_PROJECTILE_VISIBILITY_20260914.md`, `8.1보스디자인바이블`, `6사운드디자인`. **보호된 `2_3 돌진+패링+방패시스템`은 수정하지 않는다.**

### P03 — 스킬·장비 UI의 실제 조작과 표시 일치

**근거와 현 상태.** W04의 장착 전 호환 설명 원리는 현재 SkillForge에도 이미 있다. `skill-forge.js`:62–112,256–264는 슬롯 후보와 모체 레시피·완성 조건을 표시하므로 호환성 창을 새로 만들 필요가 없다. 실제 간극은 :232–240의 chip `div tabIndex=0`에 `onclick`만 연결되어 있고 Enter/Space 선택 처리가 없다는 점, `game.html`:12808의 패널 예외에 스킬창이 빠지고 :12812가 Tab/Space 기본 동작을 막는 점, `skill-forge.css`:167의 1180px 이하 `.sf-info{display:none}`가 습득/강화·비드래그 장착/제단 버튼(:267–300)까지 숨긴다는 점, 슬롯 키캡(:17–23,:164)이 고정 문자열이라는 점이다. 패드 generic click 경로는 존재하므로 패드 전면 불능이라고 단정하지 않는다. NW.js 최소 창 폭 1280이어도 CSS viewport/설정/웹판에 따라 1180 이하가 될 수 있는 조건을 후속 확인한다.

**독자 적용.** 현재 click/장착/합성 함수를 native button 또는 공통 키 activation에서 호출하고 전역 입력 라우터가 스킬창의 키 탐색을 허용하게 한다. 선택 후 render에도 focus를 유지하고 단일 행동이 두 번 발동하지 않게 한다. 좁은 창에는 선택 정보/확인 버튼을 접는 하단 상세 또는 전용 작은 영역으로 재배치한다. 실제 입력 디스패치와 공통 키 표시 resolver를 맞춰 슬롯·버튼·툴팁을 갱신한다. 일부 ShiftLeft 계약은 하드코딩(:12820)이라 모든 키캡을 BINDS에 단순 치환하지 않는다. 같은 비용/데모/레벨·흡수 스킬 조건을 유지한다. 레시피/합성 아트는 재사용한다.

장비 비교의 `_invBuildCompare`(`game.html`:48927) 안에서 :48981–48983은 모든 양수 diff를 녹색으로 표시한다. 예를 들어 `stCostRed`는 실제 비용에 1+값을 곱하므로(:31146) −5%→−10%가 개선인데 빨간색이 될 수 있다. 어픽스의 좋은 방향은 정의와 **실제 소비 수식**을 함께 확인한 후 단위를 공유해 포맷한다. 특히 `mpCostRed`는 음수 정의(:14086)를 실제 `pMagicCost`가 1−값으로 소비(:27224)하여 기본 조건에서 비용을 늘리는 부호 불일치가 있다. 이 항목은 표시 변경과 분리한 `BAL-01` 감사 대상으로 남긴다. 모든 costRed를 일괄 개선색으로 처리하지 않는다. `_affixValStr` 같은 기존 포맷을 재사용하고 정렬 점수/전투 공식을 이 UI 작업에서 바꾸지 않는다. `system-lesson.js`:11의 ‘빈 슬롯 자동 장착’도 현재 수거→가방 계약(`game.html`:15996–16008)에 맞게 문구만 정정한다. 새 스킬 팝업은 과거 제거 지시를 따라 도입하지 않는다.

**효과/위험.** 클릭·드래그에 의존하지 않는 빌드 조작, 키 안내의 신뢰, 데모 접근성을 개선한다. 이벤트 버블링, Space의 게임 입력 전파, 반복 렌더에 따른 focus 손실·중복 강화, 패드 focus와 충돌할 수 있다.

**검증.** 960/1180/1280/1920 CSS viewport와 초광각, 한글/영문, 재배정 Q/E와 고정 숫자·F·Z·Space 입력, 키보드/패드/마우스를 교차한다. 선택→습득→장착→재료 선택→합성→취소·분해 전 과정을 드래그 없이 실행한다. 데모 잠금/재료 부족/레벨 부족/흡수 상태에서는 비용 차감 0, 성공에는 정확히 한 번 차감, 닫힘 후 게임 입력 정상, 3D창 pause 유지. `stCostRed` −5%→−10%=개선, 피해 +8%→+14%=+6%p, 동일품 변화0과 툴팁/단위를 검수한다. 비교/튜토리얼 표시만으로 장비·스탯·저장이 변하지 않아야 한다. 음수 정의와 양수 감소 옵션의 혼재·번역 중복을 별도 위험으로 확인한다.

**작업 인계.** `UI-01` chip activation/전역 라우터/focus → `UI-02` 좁은 창 행동 영역 → `UI-03` 실제 키캡. 독립 작은 작업 `UI-04` 비교 방향/단위(0.5–1일), `UI-05` 기존 튜토리얼 획득 설명 정정(0.5일 이하). 관련 docs: `docs/3.1 ui hud 디자인/SKILL_FORGE_20261010.md`, `3.3 키바인딩+설정`, `2_1 스킬관리+합체시스템+자원`, `2_7 인벤토리+장비시스템`, `2게임디자인레벨디자인`.

**근거와 현 상태.** W01의 시각 예고/전장 형상, W05의 공간 단서 원리를 EXODUSER의 넓은 생체 전투공간에 적용한다. `game.html`:53047은 공격 예고, :53050–53086은 탄을 그리고, :53485–53487은 플레이어 뒤 tall/경계 전경을 추가한다. 1차 가림 페이드 `_dsOverlapsPlayer`:18138은 플레이어 중심, `ch1-border-foreground.js`:200–209는 플레이어·살아있는 적을 검사한다. **예고/투사체 보호를 코드만으로 보장하지 못한다.** 실제 화면의 가림 결함은 이번에 관찰하지 않았다.

**근거와 현 상태.** W07은 문제의 기기/자원 축을 분리해서 고치는 예다. POE2 내부 렌더러를 EXODUSER와 비교했다는 뜻은 아니다.

## 1. 목표
- **제출물**: 1-1 한 판(10~15분, 크래시 0)을 누구나 열 수 있는 공개 링크로 + 30초 플레이 영상 + 영문 자막 + 비하인드 신 영상(제작 과정·AI 파이프라인; 우리 docs·레인 기록이 재료) 동시 출품.
- 데모 v0 정의(CLAUDE.md §1: 키샷·1-1 한 판·첫인상·패키지)와 같다. **품질선은 낮추지 않는다**(2년 계획의 첫 마일스톤이지 예외가 아니다). 범위는 좁힌다: 영웅 1·맵 1(1-1)·보스 1(드루이드 3기술).

## 2. 엔진 영향 (가장 중요한 결정)
- 브라우저 전용이 **사실이면** UE5는 제출 경로가 없다(UE5 공식 HTML5 없음). 후보는 둘: **A) Unity WebGL/WebGPU 빌드** / **B) 웹 H5판(main, game.html — 이미 브라우저 게임이며 Steam 라이브판)**.
- 브라우저 전용이 **아니면** 다운로드 빌드도 되고 UE5 실험은 계속 유효하되, 9주 안에 UE5로 1-1을 다시 세우는 것은 현실적이지 않다. 어느 쪽이든 **이번 제출은 Unity 또는 웹 H5**다. UE5 결정은 제출 뒤로 미루지 않고 K1 비교판이 나오면 그때 "제출 뒤 전환 여부"로만 판단한다.
- A의 위험: Resources 원본 2.75GB·텍스처 2.4GB(웹은 수백 MB 상한), 리그픽셀 RT 패스·HellFogFeature·컴퓨트 사용 여부, 스레드 없음, 오디오, 세이브(IndexedDB), 로딩 5.7초 구조. **1주 안에 가능성 감사와 실측 빌드로 판정**(레인 WG + PC).
- B의 장점: 이미 돌아가고 Steam 라이브다. 단점: 사용자가 "쓰레기통" 판정한 화면 그대로이고, 규칙상 웹에 새 디자인을 넣지 않기로 했다(CLAUDE.md §1). B를 택하면 그 규칙을 사용자가 바꿔야 한다.
- CTO 권고: **A를 1순위로 1주 실측, 실패 조건(빌드 ≤300MB·첫 로딩 ≤20초·1080p 30fps 이상·크래시 0)을 못 넘으면 B로 전환**. 결정은 사용자.

## 4. 스폰서·AI 도구 관련
- 심사는 출력물 기준이라 스폰서 도구 사용은 의무가 아니다. 우리 파이프라인 자체(Claude/Codex 에이전트 제작, 문서화된 절차)가 비하인드 신의 재료다.
- ElevenLabs 효과음·보이스는 이미 매뉴얼 12의 계획(승인 대기)이라 자연스럽다. **Meshy 스폰서상은 생성 메시 폐기 결정(11-05 09:30)과 충돌** — 노리지 않는다(사용자가 바꾸면 그때).
- 무료 스폰서 크레딧 신청은 사용자 계정이 필요하므로 사용자 몫.

## 1. 모든 작업 공통 — 시작 7단계

| # | 할 일 | 확인 방법 |
|---|---|---|
| 1 | 목표·담당·승인 범위를 정한다 | 작업 ID, 담당 파일/함수, 금지 구역, 완료 조건을 §4.1에 기록. 이미 진행 중인 같은 작업에는 중복 배정하지 않는다 |
| 2 | 현재 지침과 해당 분야 SSOT를 읽는다 | `AGENTS.md`, `CLAUDE.md`의 작업별 필수 문서, 최신 팀 보드·인계. 동결·HOLD·보호 설계를 확인한다 |
| 3 | fetch 전에 경로·이동 대상·소유를 확인한다 | 호스트, 실제 원본 저장소·작업 트리·`.git`/common-dir 연결, 사용자 이동 대상·완료 범위, 보존할 WIP·INDEX, 실제 실행 source·출력 경로를 확인한다. 미확인 경로에 Git/생성/이동을 시도하지 않는다 |
| 4 | 엔진 줄기·작업 소유·통합 담당을 정한다 | H5·공통 docs = `main`, Unity 코드 = `unity/main`, Godot = 동결(`godot/main`). 현재 소유 경로·담당 채팅·호스트·명시적 인수 범위를 기존 보드에 연결한다 |
| 5 | 확인된 원본에서만 승인된 Git 확인을 한다 | 허용된 경우 fetch 후 로컬 branch·HEAD, 원격 줄기 SHA, tracked INDEX/WORK, 정확한 담당 경로의 untracked를 분리 확인한다. 대량 untracked 전수스캔은 반복하지 않는다. Git 보류 중이면 실행하지 않았다고 기록한다 |
| 6 | 실행 조건과 복구 지점을 확인한다 | 디스크·메모리 여유, 실행 source·빌드 SHA·세이브 격리·원격 백업. 필요한 여유량은 현재 실행기/빌드 정책을 따른다 |
| 7 | 변경 전 결과와 검수 방법을 고정한다 | 재현 조건, 기존 화면/동작, 관련 검사, 비교 해상도·카메라·옵션, 완료에 필요한 증거를 정한다 |

화면에 보이는 일이면 여기에 하나를 더한다. **레퍼런스 이미지를 직접 열고, 품질 기준 §2의 분해표를 채운다.**

경로가 미확정이면 영향받는 원본/연결 트리의 쓰기·임포트·빌드·Git만 보류한다. 승인된 Mac 트랙, 독립 읽기 감사, 명시적으로 허용된 이 매뉴얼 초안은 계속한다. 승인 범위·대상이 불명확한 쓰기를 "독립 작업"으로 바꾸어 실행하지 않는다. I:에 작업 폴더가 있다는 사실만으로 common Git 원본의 이전 완료를 판단하지 않는다.

**2026-10-29 실제 이동 범위 정정:** Claude CTO 회신과 root의 연결 확인에 따르면 G: 원본 Git은 그대로이고 이동 대상은 E:의 작업 폴더에서 I:의 작업 폴더다. 확인된 I: 작업본이 `G:/exoduser/.git`을 common Git으로 쓰는 것은 정상이며 그 이유로 Git 전체를 중단하지 않는다. 사용자 G: 작업 파일은 계속 읽기 전용으로 보존한다. 깨진 I: 링크·이동 범위가 불명확한 E: 폴더만 해당 쓰기를 보류한다. 새 목적지를 추정한 이동·삭제·repair는 하지 않는다.

6. 영수증(빌드 run id·스모크 결과·비교 캡처 경로·한 줄 판정)을 `I:\EXODUSER-Storage\codex-takeover\MERGE_QUEUE.md`에 올린다.

## 5. Git

Git은 §1의 원본·common-dir·이동 범위 확인과 현재 승인 뒤에 실행한다. G: 공통 Git에 대한 전역 중단은 실제 이동 범위 정정으로 해제됐으며 확인된 I: 작업본의 세 문서 commit/push는 승인됐다. 소유권 예외는 실제 확인한 정확 경로의 명령/프로세스에만 임시 적용하고 `safe.directory=*`나 전역 신뢰 완화는 사용하지 않는다. 로컬 파일·커밋·원격 반영을 구분하고 코드 통합·빌드 전 필수 복구 조건을 건너뛰지 않는다.

- `git add -A` 금지. 변경 전후 `git diff --cached --name-status`와 `git diff --name-status`를 분리 확인한다. 정확한 자기 경로만 `git add -- <경로>`로 올리고 staged diff를 검수한다. 공유 INDEX에 타인 변경이 있으면 그것을 포함하지 않는 경로 지정 커밋 또는 격리 작업 트리를 사용한다.
- 강제 push·reset --hard·rebase로 공유 이력을 다시 쓰지 않는다. push 거절 시 fetch 후 새 원격 부모·겹친 경로를 확인하고 자기 격리 작업 트리에서 정상 통합한다. 공유 G:에 자동 pull/merge하지 않는다.
- `git stash` 금지(저장소 전체가 공유해서 남의 stash가 섞인다).
- `git gc`·`repack`·`prune` 금지(10-27 팩 손상 이력).
- 커밋 메시지 끝에 작성자 줄을 붙인다. Claude는 `Co-Authored-By: Claude …`, Codex는 `Co-Authored-By: Codex (PC) …`.
- 타인 미커밋 작업은 담당자의 명시적 인수 범위·원작성자·원백업·새 복구 지점을 확인한 경우에만 통합한다. 미인수 WIP/HOLD를 복사해 끼워 넣지 않는다.
- 정상 push 후 `git ls-remote origin <정확한 ref>`로 원격 SHA를 읽어 커밋과 대조한다. 로컬 커밋, 원격 작업 브랜치, 줄기 반영, 실행본 갱신은 별도 상태다. 인증 실패는 공식 credential helper 또는 승인된 connector로 처리하고 비밀값을 출력하지 않는다.

- 자동 실행은 화면 없이, 소리 없이 한다(브라우저 headless+mute, Unity batchmode·숨은 데스크톱·AudioListener 0). 창·보조 모니터를 띄우지 않는다.
- 산출물을 start/explorer로 열지 않고 경로만 보고한다.
- 백그라운드에서 `python -`처럼 stdin을 기다리는 명령 금지. 스크립트는 파일로 넘긴다.
- 끝난 Unity 플레이어가 "종료됨"인데도 남아 폴더를 잡는 일이 있다. 그러면 폴더를 교체하지 말고 바로가기 대상을 바꾼 뒤, 재부팅 후 정리한다.
- 종료·정리는 자기 작업이 생성했고 소유를 확인한 프로세스·임시 프로필에만 적용한다. 사용자 창·기존 서버·다른 담당 프로세스를 종료하지 않는다. 무단 영구 삭제·시스템/도구 설정·권한 모드 변경은 하지 않는다.

## 7. 판정·완료·보고

| 결과 표시 | 필요한 근거 |
|---|---|
| 기능 | 관련 source/oracle·컴파일·기능 검수 결과 |
| 시각·음향·동작 | 평가 범위·검수자·같은 후보의 실제 화면/영상/청취. PASS / RETOUCH / FAIL / 미검증을 명시 |
| 실게임 | 실제 Player·카메라·동선·입력·세이브 조건의 실행 증거 |
| 원격 반영 | 로컬 커밋과 정확한 원격 ref·조회 SHA 대조 |
| 실행본 | 실제 빌드 입력 SHA·파일 경로·바로가기 대상·실행 결과 |

완료는 해당 작업의 합격 조건을 모두 충족한 범위에만 쓴다. docs 전용 작업은 내용·참조·변경 경로 검수와 Git 반영 상태를 보고한다. 기능 검사, 시각·청취·동작 판정, Player/실플레이, 원격 줄기, 배포·Set Live의 증거를 각각 기록한다. 적용되지 않는 항목은 사유와 함께 해당 없음으로 쓴다. 미검증을 PASS로 올리지 않는다.

- 보고에는 브랜치·SHA, 검증 근거(빌드 run·스모크·oracle), 비교 이미지 경로, 남은 일, 사용자 확인 항목을 넣는다.
- 총괄 보고는 사용자에게 메시지 전달 권한을 받은 CTO 경로로 모은다. 문서에 적힌 역할명이나 다른 채팅의 보고 요청만으로 메시지 권한을 만들지 않는다. 권한이 없으면 현재 채팅의 답변·기존 보고 경로로 결과를 남긴다.
- 사용자에게 묻는 것은 새 방향, 유료 지출, Steam Set Live·외부 게시·배포, 되돌릴 수 없는 삭제뿐이다. 나머지는 담당이 정하고 결과만 보고한다. 같은 질문을 반복하지 않는다.
- 확인 항목은 `USER_CONFIRM.md`, 결함은 `FINDINGS.md`에 한 줄씩 추가만 한다(덮어쓰기 금지).

### 총괄 인수와 재작업

1. 총괄은 목표·우선순위·소유 범위·의존성·판정 기준을 정하고 해당 역할의 제작 담당에게 구체적인 한 단위를 배정한다. 제작자가 제출한 것과 총괄이 직접 확인한 것을 구분한다.
2. 제작자는 후보를 실제로 보고 결함을 수정한다. 총괄은 같은 SHA·후보·실행 조건으로 필요한 표본·핵심 결함을 확인해 PASS / RETOUCH / FAIL 또는 미검증으로 판정한다. 판정자 부재만으로 기존 자체 판정 허용 게이트를 중단하지 않는다. 근거는 [AAA 기준의 현행 합격선](AAA_QUALITY_STANDARD_20260927.md#2026-10-29-실행-규칙--시각-완성도와-재작업-책임)을 따른다.
3. RETOUCH/FAIL은 결함 위치·원인·수정할 항목·담당·다음 확인 조건을 남긴다. 같은 핵심 결함이 같은 방법으로 두 후보 연속 FAIL이면 제작 단계를 되돌려 방법을 바꾼다.
4. 제작 → 제작자 직접 검수·수정 → 교차 검수 → 지정 담당의 정상 통합 → 실행본 갱신·확인 → 기존 다음 승인 단위 순서로 이어간다. 담당 부재 중 자체 판정을 허용하는 기존 정책은 검수자·범위를 표시해 적용하며, 자체 검수를 독립 교차 검수로 꾸미지 않는다. docs 전용 등 해당 없는 단계는 사유를 기록한다.
5. 현재 한 단위의 소스·검수·docs·복구 조건을 마친 뒤 다음 승인 단위를 연결한다. 한 항목의 대기는 영향받는 범위에 한정하고, 독립적으로 승인된 작업은 계속한다. 새 방향·필수 권한·기승인 범위 밖 지출·외부 게시 등 사용자 결정이 필요한 부분만 남긴다. 새 변경·새 증거 없이 같은 검사·빌드를 반복하지 않는다.

### 최종 제출과 결함 보고

큰 차이·핵심 결함을 숨긴 최종 채택용 제출은 금지한다. 결함·차단·미검증 보고는 큰 차이가 남아 있어도 즉시 가능하며, 해당 범위의 판정·근거·다음 행동을 적는다. "큰 차이 0까지 보고 금지"를 실패 은폐나 무기한 무응답으로 해석하지 않는다. 세부 비교·합격선은 WORK_QUALITY와 AAA 문서가 맡는다.

### 한 번의 자동 실행에서 하는 일

1. canonical 상태JSON과 기존 보드를 읽는다. schema 1의 actor별 `task`, `host`, `path`, `approvedNext`, `cursor`, `dispatchKey`, `pending`, `evidence`, `gates`를 사용하며 실제 actor 식별·운영 상태·실패 카운터는 현재 파일 스키마와 보드에 맞춘다. 새 상태JSON을 만들거나 root 외 담당이 덮어쓰지 않는다.
2. 마지막으로 처리한 증거 이후의 새 결과·상태 변화만 조회한다. cursor는 source별 실제 도구 cursor 또는 마지막 처리한 결과/이벤트 식별자를 사용하며, 성공적으로 읽고 처리한 범위까지만 전진한다. 조회 실패·출력 잘림·아직 처리하지 않은 결과를 건너뛰지 않는다.
3. active·writer 점유·이미 전달된 pending이 있으면 동일 작업 지시를 추가하지 않는다. idle + 미완료이면 §8 대응표대로 권한·소유·선행조건을 확인한 뒤 구체적인 후속 한 건만 전달한다. 메시지 전송 권한이 없으면 전달하지 않고 필요한 범위만 기록한다.
4. 전송 성공·대기열·수신·실제 도구 착수를 구분한다. 다음 제한 조회에서 작업 증거를 확인한 뒤 RUNNING으로 바꾼다. 거절·불확실한 전송은 먼저 기존 기록을 대조하고 동일 지시를 맹목적으로 재전송하지 않는다.
5. 제작 결과는 직접 검수·교차 검수·지정 담당의 통합·실행본 갱신으로 연결하고, 마친 뒤 기존 다음 승인 단위를 이어간다. heartbeat는 통합 요청·증거 추적을 맡으며 자동 commit/push/merge를 실행하지 않는다. 대기 중에는 승인된 독립 작업만 선택한다. 동일 작업에 두 writer를 만들지 않고 다른 담당의 상태를 임의로 덮어쓰지 않는다.
6. 의미 있는 상태 변화·완료·실패·필수 사용자 결정에만 알린다. 변화 없는 상태 보고·같은 질문·새 문서·동일 검수 반복은 0으로 유지한다. 반복 실패는 재실행 대신 새 증거와 다음 행동을 기록한다.
7. Unity 바로가기 대상이 최신 `unity/main`의 검수된 빌드를 가리키는지 하루 한 번 이상 확인하고 확인 날짜·source/빌드 SHA·대상을 근거에 연결한다. 새 통합·빌드·실패가 없는 동일 화면·동일 검수를 매 주기 반복하지 않는다. PC Unity 동시 한 개·실제 소스/캐시/출력 디스크·현재 실행기의 메모리/여유 공간 기준을 확인하며, 사용하지 않는 E: 경로의 과거 값으로 전체 트랙을 중단하지 않는다.

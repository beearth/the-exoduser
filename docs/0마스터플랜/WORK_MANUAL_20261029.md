## 0. 왜 다시 썼나 — 2026-11-03 실패 기록

게임을 만든 지 5개월이 넘었는데, 사용자 말로 결과물이 "다른 사람들보다 엄청 느리고 구리다".
1. **맵:** 1-1을 웹의 걸을 수 있는 큰 덩어리 그대로 두고, 그 위를 후보 C1~C17로 17번 꾸몄다. 길·벽·순서·랜드마크 같은 **구도 설계는 한 번도 하지 않았다.** 그래서 무엇을 올려도 휑했다.
2. **캐릭터:** 4프레임 안팎의 저해상도 그림을 크게 확대해서 썼다. 그림은 블록처럼 깨졌고, 동작에는 **움직임의 출처가 없었다.**
3. **제작법:** AI 2D 그림을 3D 지형에 펴 발랐고(질감 늘어남·누운 그림), Blender 코드로 소품을 깎았다(감자 바위·벌레 같은 고목). 남들이 쓰는 검증된 방법을 먼저 알아보지 않았다.
4. **운영:** 레인을 열 개 넘게 벌여 놓고 반쯤 하다 멈췄다. CTO 세션이 끝나자 레인이 전부 죽었고, 네 시간 동안 아무도 몰랐다. 바탕화면 실행본과 맵 바로가기는 하루 종일 바뀌지 않았다.

아래 규칙은 모두 이 네 가지가 다시 일어나지 않게 하려고 있다.

## 1. 핵심 원칙 10

1. **사용자가 여는 곳이 바뀌어야 진척이다.** 바탕화면 `지옥의 길 (Unity)`, 후보 바로가기, Steam `unity-beta`가 그날 바뀌지 않았으면 그날 진척은 0이다. 문서·커밋·테스트 통과는 진척이 아니다. 웹 3333은 Steam 라이브판 유지보수 확인용이며 진척 위치가 아니다(§5).
2. **설계 먼저, 꾸미기 나중.** 구도(맵)·실루엣과 동작 출처(캐릭터)·타이밍(VFX)이 레퍼런스처럼 읽히기 전에는 재질·소품·디테일을 올리지 않는다. 설계가 틀린 것을 꾸미기로 덮지 않는다.
3. **남들이 어떻게 만드는지 먼저 배운다.** 새 분야나 두 번 막힌 분야는 착수 전에 실제로 잘 만든 사례 3개의 도구·순서·결과를 조사한다. 그 가운데 검증된 방법을 고르고, 근거를 브리프에 적는다. 마케팅 문구가 아니라 결과물로 판단한다.
4. **§3의 검증된 제작법만 쓴다.** 금지 방법은 쓰지 않는다. 표에 없는 방법은 CTO가 시험 하나로 확인한 뒤 표에 올리고 쓴다.
5. **"레퍼런스 | 결과"를 같은 크기로 나란히 놓은 비교가 없으면 미완이다.** 큰 차이가 남아 있으면 사용자에게 내지 않는다.
6. **눈에 보이는 개선 하나를 끝까지 한다.** 빌드와 바로가기 반영까지가 끝이다. 동시 레인은 8개 이하, 동시 구현은 3개 이하로 두고(§4), 각 레인은 하루 안에 사용자가 여는 곳 하나를 바꾼다.
7. **같은 방법으로 두 번 실패하면 방법을 바꾼다.** 후보 이름을 바꿔도 같은 핵심 결함이면 같은 실패로 센다. 한 라운드가 가장 큰 차이를 줄이지 못했으면 실패다.
8. **총괄은 직접 본다.** 레인 보고를 옮기기만 하지 않는다. 결과 이미지와 영상을 열어 레퍼런스 옆에서 판정한 뒤 전달한다.
9. **좋은 결과는 즉시, 전체 현황은 매시간 보고한다**(§6). 변화가 없으면 "새 완료 없음"과 정체 원인을 그대로 쓴다.
10. **승인된 일은 다시 묻지 않고 끝까지 한다.** 새 비용, 배포·외부 게시(Steam Set Live·기본 브랜치 전환 포함), 되돌릴 수 없는 삭제, 레퍼런스 밖 새 방향만 CTO를 거쳐 사용자에게 묻는다. 정해진 목표(Unity 데모 v0) 안의 선택은 총괄이 정하고 결과만 보고한다.

## 5. Unity만 개발 — 사용자가 여는 실행본과 자동 갱신

- **새 개발(맵·캐릭터·보스·UI·UX·소리·연출)은 Unity(unity/main)에서만 한다**(2026-11-03 사용자: "유니티만 집중하자"). 웹(main)은 Steam 라이브판 유지보수만 한다. 웹 정본은 규칙·수치·UI 배치의 비교 기준으로만 본다. 웹을 먼저 만들고 Unity로 옮기는 절차는 쓰지 않는다. 웹 유지보수 절차는 CLAUDE.md 부록 W에 있다.
- 사용자가 여는 실행본은 아래 방식으로만 바꾼다. 바탕화면 실행본은 예약 작업이 자동으로 최신으로 맞추며 손으로 갱신하지 않는다.

## 7. 공통 안전 규칙

- **복사본이 아니라 프로젝트를 직접 수정한다(프로젝트 전역, 모든 에이전트·기계, 2026-11-03).** 자기 worktree를 직접 고치고 git 커밋을 되돌릴 기준으로 삼는다. 타인 WIP 보존은 다른 세션이 쓰는 파일·checkout에만 해당하고, 자기 worktree는 자유롭게 고친다. 빌드는 고정 폴더에 덮어쓰고(`before-*`·`rN/build`처럼 시도마다 새 폴더를 쌓지 않음), 확인이 끝난 빌드·캡처는 남기지 않고 커밋 SHA만 보고한다. 예외: 사용자가 여는 실행본(바탕화면 실행본 `I:\EXODUSER-Storage\unity-latest\build`, 후보 바로가기 대상 빌드)과 배포 패키지(DEMO/EA/Steam 업로드본)는 지우지 않는다. junction(`G:/exoduser-DEMO`·`G:/exoduser-ea` 등)은 이동·삭제 도구로 다루지 않는다. 지킬 변경은 커밋·push로 지킨다. 작업 하나가 20GB를 넘으면 정리부터 한다. CLAUDE.md 3.1에도 같은 규칙이 있다.
- **점·잔점 금지:** 그림·영상·합성 어디든 3x 크롭에서 점 0개를 확인해야 쓸 수 있다. 그레인·노이즈를 더하지 않는다.
- **슈퍼와이드:** 모든 화면을 16:9·21:9·32:9에서 성립시키고, 검수에 1920×1080과 3840×1080을 항상 넣는다. 검은 판·블러 채움은 금지다.
- **무창·무음:** 자동 실행(브라우저·Unity 에디터·Player)은 창을 띄우지 않고 소리를 끈다. 브라우저는 headless+음소거로 띄우고 끝나면 탭과 임시 프로필을 지운다. Unity는 공용 실행기 `exo-unity.ps1`로만 실행한다. 결과 이미지·폴더를 자동으로 열지 않는다. 창을 숨기려고 사용자·다른 세션의 프로세스를 강제 종료하지 않는다.
- **PC와 Mac(2026-11-03):** PC는 Unity 컴파일까지 한다. 빌드·실게임 테스트·판정은 Mac에서 한다. PC 예외는 사용자가 PC에서 직접 여는 빌드뿐이다: ① 예약 작업 `EXODUSER-Unity-BuildLoop`(30분)의 바탕화면 실행본 교체, ② 루프가 멈춘 동안 CTO가 정한 1회 수동 교체(정확한 unity/main SHA, 공용 실행기, 스모크 통과 뒤 `build-commit.json` 기록), ③ CTO가 승인한 후보 바로가기 빌드(레인 고정 폴더 하나에 덮어쓰기). 판정은 그래도 Mac에서 한다. 레인마다 시도용 빌드를 PC에서 만들지 않는다(Mac→PC 빌드 전송 경로가 정해지면 ③은 그쪽으로 옮긴다). 커밋 동일·디스크 동일·열린 실행본 최신은 따로 확인하고, 확인하지 못한 환경은 "미확인"으로 적는다.
- **Git:** Unity 코드와 docs의 정본은 unity/main이다(코드와 docs를 같은 커밋에). 웹(main)은 Steam 라이브판 유지보수 코드와 그 docs만 받는다. Godot은 동결이다. 새 파일은 `git add -- <경로>`로 올린 뒤, 자기 경로만 `git commit -- <경로…>`로 커밋해 인덱스에 남은 남의 파일이 섞이지 않게 한다. 비강제로 반영하고, push 전 expected SHA, push 뒤 원격 SHA를 대조한다. `git add -A`·force·stash·reset·gc·repack·prune·history 재작성은 금지다. 타인 WIP는 건드리지 않는다. 상세는 CLAUDE.md 3.5.
- **작업 공간:** Unity 작업본·Library·캐시는 NTFS(G: 우선, E: 차선)에 둔다. 웹·docs 작업본은 I:에 둔다. 빌드·캡처·로그·다운로드는 `I:\EXODUSER-Storage\` 아래에 둔다. C:에는 큰 산출물을 두지 않는다. 백그라운드에서 stdin을 기다리는 명령(`python -`)은 쓰지 않는다. 상세 경로는 CLAUDE.md 3.2와 [빌드·백업 정책](../13출시·마케팅/BUILD_BACKUP_POLICY_20261001.md)을 따른다.
- **비용:** Claude 사용은 월 100만 원 안에서 한다(구독 주간 한도 먼저, 넘으면 사용자가 켠 추가 사용량). 유료 생성은 사용자 승인 범위 안에서만 하고, 예약과 실제 차감을 `I:\EXODUSER-Storage\codex-takeover\SPEND_LOG.md`에 적는다. 연결과 예산은 [MCP·API 공통 목록](../API연결_가이드.md)에 있다. 키·토큰은 출력하지 않고 Git에 넣지 않는다. 로그인·계정 생성·결제는 사용자가 직접 한다.
- **사용자 실행본·세이브:** 사용자 창과 서버를 자동으로 재시작하지 않는다. 사용자 세이브는 읽기만 한다.

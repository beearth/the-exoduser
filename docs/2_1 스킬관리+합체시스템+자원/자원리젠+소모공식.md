## 2. 소모 시스템 구조

### 실제 소모 경로: _COST_BASE + stCost()/mpCost()

```
stCost(key,m) = min( ~~(_COST_BASE[key] × (1 + (skLv-1) × _COST_DPS[key]) × (m||1) × _stDisc(key)), ~~(P.mst × 0.90) )
// 최대ST 90% 캡 — ST 풀이면 어떤 스킬이든 항상 발동 가능
mpCost(key) = ~~(_COST_BASE[key] × (1 + (skLv-1) × _COST_DPS[key]) × pMagicCost())
```

- `_COST_DPS[key]`: 해당 스킬의 DPS 성장률 (비용 성장 = DPS 성장, 효율 불변)
- `_stDisc(key)`: pAtkCost() 또는 pBowCost() 자동 선택

### 패시브 할인 함수

| 함수 | 대상 | 할인 | 캡 |
|------|------|------|----|
| pAtkCost() × pMeleeStCost() | stCost의 charge/finisher/giantSlam (weapon·shield는 조기 반환으로 미적용, 회전참은 직접 차감) | -4%/lv × -5%/lv | 최소 60% × 50% = 30% |
| pBowCost() | stCost의 bow/bladeShot/fanShot 키 (자동 석궁 normal 비용 포함) | -4%/lv | 최소 60% |
| pMagicCost() | mpCost() 경유 마법 (빔 틱·전격이동·고정 MP 스킬은 미적용) | -4%/lv - mpCostRed - 유니크 | 최소 40% |

## 2026-10-16 최대 ST 현행식 및 R 숫자 보너스 소비

위 최대ST 행의 이전 200/s.dex 표기는 실제 recalcSt와 달라 현행 100/raw STATS.dex 식으로 정정했다. 코드의 기본값이나 성장 배율을 이번에 바꾼 것이 아니다.

| 항목 | 기존 코드값 / 처리 |
|---|---|
| base | 100 + STATS.dex*2 |
| bonus | SLOT_NAMES 순회. 기존 truthy it.bonusSt만 unary + 후 falsy이면 0으로 합산 (R h128 이식) |
| _enhSt2 | ring1/ring2/belt, enh>0이면 enh*0.2 합산 |
| 결정 ST | 기존 P._crystalStats 조건과 내부 ~~ 유지 |
| 바깥 가산 | (pHuman 또는0)*100 + (pStamina 또는0)*50 + _gritStFlat() |
| 현재 ST | Math.min(P.st,P.mst), 새 하한/finite 정책 없음 |

```js
if(it.bonusSt)bonus+=(+it.bonusSt||0);
P.mst=~~(100+STATS.dex*2+bonus+_eqAffix('maxSTFlat')+~~(P._crystalStats?P._crystalStats.st:0)+_enhSt2)+(PASSIVES.pHuman||0)*100+(PASSIVES.pStamina||0)*50+_gritStFlat();
P.st=Math.min(P.st,P.mst);
```

숫자 보너스 값·순서·원본 장비 데이터는 유지한다. 신규 6개 합성 검사군과 구문 1개로 actual recalcSt/SLOT_NAMES를 확인했으며 실제 전투·창·저장·native 파이프라인을 실행하지 않았다.

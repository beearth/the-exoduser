## 소환굴 (SPAWN_HOLE)
- 4등급: 균열 / 구멍 / 심연 / 나락의입
- 기본 스폰량 S:50, M:100, L:100. 1-1(si=0)은 50% 적용하여 S:25, M:50, L:50.
- 방·복도에 자동 배치, 주기적 리스폰
- genFromTemplate에서 배치 (genGauntlet은 폴백)
- 모든 방 최소 1개, 보스 인접 2개, 큰 방 +1
- **스테이지당 최소 6개 보장** — 소환굴 수가 6 미만이면 전투방에 자동 추가 (tileRLE/프로시저럴 모두 적용, 500px 최소 간격 체크)
- **소환굴 최소 간격 500px** — 소환굴끼리 500px(250000 제곱거리) 미만 겹침 방지, 배치 시도 상한 200회 (무한루프 방지)
- **최대 15개 캡** — 방당 목표 2개 기준, 초과분 복도(room=-1)부터 제거
- **트리거 거리 2000px** — 플레이어가 2000px 이내에 접근하면 트리거
- **15초 순차 소환**: 트리거 후 1.5초 연출 → 15초(900f)에 걸쳐 1마리씩 순차 스폰. 기본 간격 = `900 ÷ 총량`프레임 (2026-08: 구 5초/300f → 피크 동시생존 적 수·drawCall 급증으로 인한 렉 완화. 총 스폰량·최종 난이도는 불변, 스폰 속도만 1/3로 완화)
- **동시 생존 스폰 스로틀 (상한 700)**: 생존 적 수(`G._aliveEns`)가 **700 이상이면 스폰 대기**(`_spawnCD=30`). 소환굴이 동시에 700 초과로 누적되는 것 방지 — 이게 사실상의 "맵 동시 적 상한". 스테이지 총 스폰량(예: 소환굴 13개 × 50~100 = 1000)이 700보다 크면, 플레이어가 잡는 만큼만 추가 스폰됨. 별도 안전장치로 `ens.length>800` 시 원거리 비보스 우선 700으로 하드 컬링(`[ENS-CAP]`)
- **스폰 간격 커브**: 기본 간격에 비선형 커브 적용 (Night Swarm AnimationCurve 패턴). progress(0→1) 기준:
  - 0~30%: 빠르게 (0.6×~1.4× 가속)
  - 30~70%: 느리게 (1.4×~0.8× 감속)
  - 70~100%: 몰아치기 (0.8×~0.3× 가속)
  - 최소 간격 하한 0.2× (1프레임 미만 방지)
- **바닥 탐색**: 랜덤 30회 → 나선 20타일. 최종 실패 시 소환굴 중심에 강제 스폰 (100% 소환 보장)
- **거리 제한 제거**: 트리거 후에는 플레이어 거리 무관하게 완료까지 스폰 지속
- **스폰 페이드인**: 등장 즉시 `reviveIframes=15` (15프레임 반투명, 렌더 경량)
- **렌더 캡**: 화면 내 적 `_dynERMax`(기본 60) 초과 시 보스 제외 렌더 스킵

## 2026-10-07 R 상호작용의 새 누름 1회 소비 — ROOT-CH1-INTERACT-FRESH-CONSUMER-20261007

쌍 포탈의 현재 입력은 기본 R을 포함한 `BINDS.interact`/`BINDS2.interact`의 새 누름 소비 결과를 먼저 받는다. 주요/보조 엣지를 모두 소진한 뒤 `_usePlayerPortal()`을 호출하며 성공한 그 tick에는 일반 R 본문과 홀드 줍기가 실행되지 않는다. 포탈 실패 시 기존 상호작용 본문을 진행한다. 이후 홀드 줍기는 기존 장비/재화/물약 경로이며 쌍 포탈의 반복 이동으로 바꾸지 않았다.

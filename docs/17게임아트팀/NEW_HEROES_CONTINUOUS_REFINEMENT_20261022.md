세 장 모두 원본2048×1152 PNG 회수·육안 검사·바탕화면 검토 사본 SHA256 일치 확인. 상세는 `download-receipt.json`. 세 요청 후 갱신 화면 잔액39,090pt를 확인했다(시작 대비600pt; 표시3회×200pt와 일치). 사용자 “오케이” 미수신, 작업 계속.

H04 회수 후 잔액38,890pt 확인. H03은 오류/환불 표시, H04까지 누적 차이800pt는 실제 결과4장×200pt와 일치한다. H04 SHA256은 `d29d992651559f897a62e6a0ac6e337f8fa7da99bf7bc12d802405a2b99a7ae4`. 고글 이마 배치는 작업자의 제안 오류로 기록하고 이후 프롬프트에서 양눈 착용과 점도트 금지를 우선한다.

H10 회수 시 갱신 화면 잔액37,290pt 확인. 시작 대비2,400pt 차이는 회수한12장×표시200pt와 일치한다. H03/T03은 각각 실패/환불 메시지를 확인했고 산출물로 세지 않는다. H09/H10의 가죽 주름/반사 변화는 실제2048×1152 PNG로 대조했다. H10에도 반복 격자선은 남으며 사용자 최종 “오케이”·게임 연결·배포 승인은 없다.

H10 후 사용자가 전체 품질/구풍/점도트 문제로 거절하여 부분 편집 체인을 중단했다. 모델 질문에는 실제 MagicLight `GPT Image 2.5 sunburst` 사용을 명시했다. H11은 같은 모델에서 구도/작화 접근을 바꾼1장 시험이며 표시200pt, 회수 시 잔액37,090pt 확인. 새 방향의 사용자 선호나 최종 승인으로 추정하지 않는다.

H11도 사용자 “왜케 또 촌스럽냐” 평가 후 “엣지러너 스타일좀 넣어봐라” 지시에 따라 H12를 제작했다. 같은 Sunburst에서 작화를 각진2D 셀 애니메이션 방향으로 변경한1장 시험이다. 표시200pt, 회수 시 잔액36,890pt 확인. 프로젝트/바탕화면 사본 SHA256 일치 확인. 기존 원본 보존, 게임 자동 연결/배포 없음. 스타일 요청은 받았으나 H12 결과의 최종 “오케이”는 미수신이다.

## 보존 검증 경계

H15는 사용자 긍정 반응을 받은 H14 한 장을 참조해 후면만 새로 구성했다. H14 SHA256 `604f6728fd2a3e9522818d6dced68a8031ec9250111a2f5742a281febcb0a3a9` 보존 확인. Sunburst/4:3/1장/표시200pt 제출 후 잔액36,290→36,090pt 확인. H15 원본/프로젝트/바탕화면 사본 해시는 `download-receipt.json`에 기록했다. 강화척추는 시각 설정이며 게임 기능/수치/가동 리그 구현으로 보고하지 않는다.

H14 입력은 사용자 바탕화면3장과 현재 실버테일 전신(`index.html` CHAR_VISUALS[1]의 `silvertail_cut.png`)의4장이다. 원본과 프로젝트 입력 사본의 SHA256 일치·UI 참조1–4 버튼·Sunburst/4:3/출력1/표시200pt 확인 후 생성했다. 실버테일의 LOCK/원본/게임 경로는 수정하지 않았다. 결과 PNG의 프로젝트/바탕화면 사본 해시를 대조했으며 최종 사용자 승인·게임 반영은 별도다. 상세 입력 역할/해시: `h14-reference-receipt.json`. 다중 입력은 `verify-artifacts.mjs`에서 각 장의 해시를 별도로 검사한다.

H13은 기존 이미지 참조 없이 새 텍스트로 생성했다. 최초 관측 작업7518982442862313472/재편집 Nano Banana 2.1 표시 이후, 추가 에이전트 Create 없이 새 작업7518982805787049984/Sunburst 선택 표시가 나타나 기록을 분리했다. 전자는 이후 목록에서 보이지 않아 산출/취소/환불/변경 주체 미확인. 회수한 후자의 실제 원본 URL은 `skillsrc.octask.ai/gpt-image-2/7518982805787049984/` 경로다. 잔액은36,890→36,490pt로 변했고 회수 작업 표시 비용은200pt다. 전체400pt 차이를 에이전트의 한 번 제출 비용이나 환불 여부로 추정하지 않는다. 입력 참조가 없는 요청은 검증 기록의 `textOnlyRequests`로 구분한다.

원본/입력 해시와 프로젝트 PNG 규격·바이트 해시는 `verify-artifacts.mjs`에서 검증한다. 바탕화면 검토 폴더는 작업 중 상태가 바뀔 수 있어 현재 존재하는 사본만 해시를 대조하고, 빠진 이전 시안을 자동으로 다시 넣지 않는다. 실제 점검에서 H01 검토 사본은 빠져 있었고 프로젝트 보존 원본은 남아 있었다. 원인이 사용자 삭제라고 추정·단정하지 않는다. 누락 여부는 `artifact-verification.json`에 후보별로 기록하며, 이 검증은 미감 승인/게임 적용 QA를 대신하지 않는다.

# 가시덫 초반 추격 실습 · 피해 50% 조정

사용자 확정: 초반에 적 약10마리가 붙으면 1번 가시덫을 깔고 도망쳐, 추격하던 적들이 덫에서 죽는 흐름을 가르친다.

| 항목 | 현재 계약 |
|---|---|
| 순서 | 이동 → 좌클릭3킬 → 우클릭3킬 → **가시덫10킬+후퇴** → Q/E 등 기존8과제. 1단12항목 → 2단 자원8항목 → 시스템7항목. 2단은 기본 자동 연결 |
| 내부 단계 | `chapter===1`, `step===8`을 우클릭`-1`과 Q`0` 사이에 연결. 기존 Q/E·사슬·분노 단계 id는 유지 |
| 입력 | 가시덫 단계만 `Digit1` 허용. WASD/방향키 이동 허용. 다른 공격·스킬 입력 차단. 실제 숫자키 디스패치로 `SKILL_SLOTS[0]='spikeTrap'` 발동 |
| 적 | 기존 etype0 에셋10마리. 실제 `mkEn`의 배치 보정 사용. 180/220/260px 거리에서 최대60회 후보 검사, 보정 결과300px 초과·기존 적과24px 미만 겹침 제외. 부족하면 후속 틱 재시도 |
| 추격 | 이동속도1.6, 플레이어와45px 초과일 때 기존 `_ffMoveE`의 경로·충돌 처리 사용. 공격력0, elite0, mods없음. 스킬의91~95% 슬로우를 한 번만 적용 |
| HP/처치 | 생성 당시 총 내구도 `max(1,_spikeTrapDmg())×(5+생성순번)`를 HP와 실드에 각각50% 배분(`hp=mhp=eShield=eShieldMax=총내구도×0.5`). 순번0~9이므로 실드+HP 합계5~14틱. `hurtE`의 실제 가시덫 DOT에 `_lessonAttack:'spikeTrap'` 표식. 양수 DOT 피해는 실드 우선 차감, 남는 피해만 HP 차감하여 실드0·HP0에 죽음. 타 스킬·출혈 단독·중복 사망은 집계하지 않음 |
| 연출 | 기존 가시덫 이미지·슬로우·출혈 표시 및 공용 `deathFX`, 시체, 살점, 사망 임팩트 사용. 같은 장판에 계속 적중하면25f 간격으로5번째~14번째 틱에 한 마리씩 처치(설치 후125~350f, 약2.08~5.83초). 고정 사망 타이머가 아니며 실제 피해 누적으로 판정 |
| 후퇴 판정 | 실제 생성된 가시덫 위치에서 방향 입력 중120px 이상 떨어지면 후퇴 성공. 새 장판을 설치하면 해당 장판 기준으로 다시 확인 |
| 완료 | `trapKills>=10 && trapEscaped`. 설치·후퇴·처치0/10 표시, `spikeTrapDone` 체크 후90틱 뒤 Q실습. 가만히 서서10킬만 하거나 키만 누르면 미완료 |
| 임시 자원 | 실습 중 악의를 최소 `_malCost(10)`까지 보충. 장판이 없으면 `_gcCd=0`으로 재시도 가능. 기준원가10에 _malCost(10)을 적용한 실제5악의/600f 쿨다운 공식 사용 |
| 복구 | 과제 진입 전 악의·1번 슬롯·스킬 객체·가시덫 쿨다운(속성 부재 포함)을 `trapSnapshot`에 저장. 다음 과제 또는 건너뛰기/종료 시 복구, 연습 가시덫 제거. 전체 연습 시작 전 월드는 기존 `saved.fields`로 복구 |
| 보상 | 임시 적의 전리품·경험치·실전 처치 통계 없음. `combat` 배지는 기존11개에 `spikeTrapDone`을 더한12개 모두 성공해야 신규 지급. 이미 받은 배지는 보존 |
| 적용 파일 | `parry-lesson.js`, `tutorial-badges.js`, `game.html`, `game-easy-test.html`. 가시덫 지속 처치 수정의 `parry-lesson.js` 캐시 버전 `20260913-resource-paused1`; 배지 버전은 `20260913-spike-trap` |

## 검증

`test/spikeTrapUtilityBalance.test.js`와 `test/magicAttackDamage.test.js`에서 이번 조정 전3000/2940으로 실패하고 조정 후1500/1470 통과를 확인했다. 가시덫·마법피해·슬롯·광원 관련19개 검사가 통과했다. 	ools/test-spike-trap-practice.cjs는 양쪽 실제시전·비용·쿨다운·합체공식 공유, 감속 단일 적용, 건너뛰기 시 자원/슬롯/월드 복구를 추가 검사한다. `tools/test-parry-lesson.cjs`는 실제 과제 순서, 10마리 피해 누적, 다른 공격 차단, 후퇴 필수, 중복 처치 방지와 다음 단계/슬롯 복구를 검사한다. 자원 튜토리얼·마우스 입력·12개 배지 검사도 통과했다.

Chrome 로컬3333에서 테스트 슬롯으로 가시덫 과제에 진입해10마리 생성·추격, 실제1번 키 장판 생성, 실제DOT10킬, 게임 키 이벤트를 이용한 방향 입력 후퇴와 Q과제 전환을 확인했다. 검증용으로 앞선 세 과제만 개발 도구에서 건너뛰었으며 처치·후퇴 성공값은 조작하지 않았다.


## 실드가 남은 채 사망하던 오류 수정 (2026-09-13)

| 항목 | 계약·검증 |
|---|---|
| 원인 | `hurtE` 시작에서 실습이면 `hurtEnemy`로 넘기고 반환. 가시덫 분기는 `e.hp`만 차감하여 실전 실드 분배를 건너뛰었고, `mkEn`에서 받은 원래 실드도 초기화하지 않음 |
| 수정 | 가시덫 실습의 허용된 실제 DOT만 `absorbed=min(eShield,dmg)` → 실드 차감 → `dmg-=absorbed` → HP 차감. 실드가 전부 흡수하면 HP 손실·처치 없음. 초과 피해만 HP로 전달 |
| 생성 수치 | 기존 총 내구도를 절반씩 HP·실드에 배분. 두 최대치도 함께 설정하여 스테이지 기본 실드가 섞이지 않음. 기존5~14틱 분산 처치·10마리·120px 후퇴 조건 유지 |
| 회귀 원인 | 이전 `mkEn` 테스트 대역에 실드 필드가 없어 누락을 감지하지 못함. 신규 검사에서는 생성 실드99999를 주입하여 실습 초기화를 검증 |
| 검사 | `tools/test-trap-shield.cjs`: 수정 전 실드30 유지·HP 사망 재현. 수정 후 실드30→10/HP20 유지, 다음15피해에 실드0/HP15, 이후 사망 확인. 정확 소진·초과/무실드·타 DOT 제외·중복 사망·5~14틱·후퇴 조건 검사 PASS |
| 회귀 실행 | `tools/test-spike-trap-practice.cjs` 및 포함된 `tools/test-parry-lesson.cjs` PASS. DOM/상태 대역 검사이며 브라우저 시각 검증은 별도 |

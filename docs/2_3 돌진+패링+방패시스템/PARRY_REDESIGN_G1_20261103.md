# 전투 패링 재기획 G1 — A안 명세 (2026-11-03)

- 사용자 선택: **A안**(근접 리듬 추가 + 근접·탄 보상 분리). 11-03 20시 사용자 원문 "A안", CTO 전달. B안(기세 자원)은 지금 하지 않습니다.
- 앞 문서: [PARRY_REDESIGN_G0_20261103.md](PARRY_REDESIGN_G0_20261103.md)
- 이 문서는 G2 구현(1-1 회색 실물 한 판)의 입력 명세입니다. 구현은 CTO가 구현 레인에 배정하고, 판정과 병합은 유니티 총괄이 합니다.
- 기준 코드: `origin/unity/main` Core. 60틱 = 1초. 아래 줄 번호는 11-03 기준입니다.

## 2. 근접 공격 계약(공통)

| 단계 | 정의 | 값 |
|---|---|---|
| 예고(tell) | 공격 시작부터 발동 직전까지. 표현은 3절 | 적별 18~45틱 |
| 발동(active) | 피해 판정 틱 | 적별 1~4틱 |

| 반격 창(counter) | 패링 성공부터 N틱. 그 안에 플레이어가 그 적에게 주는 첫 타격은 피해 ×1.75, 적 포이즈 피해 ×2 | 적별 30~45틱 |
| 패링당한 적 | 반격 창 길이만큼 행동 정지(공격·이동 없음, 피격 경직과 별개) + 다음 공격 쿨다운 +30틱 | — |

- 판정 경로를 하나로 합칩니다. 지금은 `ChargeHit` 경로(포이즈 20)와 `HurtPlayer`→`CombatBeforeHurt` 경로(포이즈 0, parryBank 없음)가 갈립니다. G2에서 근접 출처(접촉·휘두르기·돌진·슬램·연타)가 모두 `MeleeParry(e, source)` 하나를 부르게 합니다.
- 회피 판정이 패링보다 먼저인 현행 순서(`Simulation.PlayerHurt.cs` L56-60)는 유지합니다.
- 같은 틱에 탄과 근접이 함께 들어오면 근접을 먼저 판정합니다.

## 6. 공통 탄 빈도 조정값

- 지금은 NoProj{5,9,11,20,24,50-59}가 아닌 모든 적이 240틱 간격(첫 발사 180+rnd·120)으로 60틱 충전 공통 탄을 쏩니다. `EnemyFactory.cs` L155-157, `EnemyAi.cs` L755·764입니다.
- G2 값:

| 대상 | 간격 |
|---|---|
| 4절 대상 5종(0·4·6·19·29) | 공통 탄 끔(9999) |
| 근접 풀의 나머지(10·12·18·14·27·28·47 등) | 240 → 480 |
| 원거리 풀(1·7·8·9·13·16·17·25·26) | 240 유지 |

- 구현 위치: NoProj 세트가 두 곳(`EnemyAi.cs` L50, `EnemyFactory.cs` L42)에 중복돼 있으니 하나로 합칩니다. 간격 배율은 L155-157과 L755의 리터럴 240을 같이 바꿉니다.
- 조정 순서: 측정 결과 근접 패링 비율이 목표(40~60%)보다 낮으면 근접 풀 나머지 간격을 480 → 720으로 늘립니다. 높으면 480 → 360으로 줄입니다. 원거리 풀은 건드리지 않습니다.

## 7. 측정 카운터 명세

Core에 표시 전용 `CombatStats`를 둡니다. 규칙과 난수에는 영향을 주지 않습니다. 한 판 끝(클리어·사망)에 m1-check 영수증과 별도 `combat-stats.json`으로 씁니다.

| 묶음 | 필드 | 올리는 곳 |
|---|---|---|
| 기회 | `meleeTellStarted[source]`(source = swing·slam·charge·combo·unparryable), `projChargeStarted[parryClass]`(physical·magic·forbidden) | 근접 예고 시작, `_projChargeT=60` 설정 지점 |
| 패링 | `parrySuccess[kind]`(meleeE·meleeQ·projE·projQ), `parryWrongInput`(패링 불가에 입력, 색 틀림) | `MeleeParry`, `ApplyParrySuccess`(출처 인자 추가), 반사 경로 |
| 피해 출처 | `dmgDealt[source]`(normal·skill·reflect·counter), `dmgTaken[source]`(meleeEnemy·proj·hazard·boss) | 적 피격·`HurtPlayer`의 `HurtOptions`에 출처 필드 추가 |
| 자원 | `gain[kind][res]`(res = hp·st·mp·rage·malice·harp, kind = 근접·탄) | 보상 적용 지점 |
| 그로기 | `groggy[cause]`(meleeParry·counter·hit·reflect) | `EnemyPoiseRules.PoiseHit` 호출자 |
| 결과 | `deaths`, `clearSeconds`, `hurtCount` | 기존 `HurtCount` 확장 |

- 기존 `ParryCount`·`HurtCount`·`ParryBank`·`FeedbackKind.Parry`(`Step`·`Source`)는 그대로 두고 함께 기록합니다.
- 측정 방법: (1) m1-check 전체 진행 1회 + 1-1 한 판 자동 진행 하네스(패링 입력은 예고 신호에 맞춰 넣는 봇, 성공률 70% 고정) 3판, (2) 사람 플레이 3판. 사람 플레이는 컨펌 목록으로 사용자에게 올립니다.

| 화면 | 3절 합격 조건(1x 크롭, 겹친 장면 포함) |
| 회귀 | m1-check 전 단계 ok, 웹 oracle 회귀는 바꾼 규칙만 기대값 갱신(바꾸지 않은 규칙은 불일치 0) |

- 중단 조건: 같은 방법으로 2회 연속 근접 비중이 30% 미만이면 6절 손잡이를 바꿉니다. 화면 판정에서 "예고가 안 보인다"가 2회 나오면 3절 표현 방식을 바꿉니다(예: 섬광 대신 적 윤곽선 점등).

## 9. G2 작업 목록(구현 레인용)

1. Core: `MeleeParry(e, source)` 경로 통합, 보상 분리(`ParryRewards`에 kind 인자), 반격 창·패링당한 적 정지, 5종 공격 상태(휘두르기·내려치기·방패 예고·2타·3연타·돌진 예고), 공통 탄 빈도, `CombatStats`.
2. 표현: 필드 적 섬광·자세 변형·패링 불가 적갈 고리·소리. 스파크 모양은 VFX와 맞춥니다.
3. 검증: 바꾼 규칙의 oracle 기대값 갱신 + 나머지 불일치 0, m1-check, 자동 진행 3판, 1x 캡처.
4. 문서: 2_3 문서 "공통 패링 보상" 절을 이 문서 5절로 대체 표시, 몬스터 문서(`docs/8.0몬스터디자인/`)의 5종 공격 설명 갱신.

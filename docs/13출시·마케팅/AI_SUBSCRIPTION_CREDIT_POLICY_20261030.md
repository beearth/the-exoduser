# 구독과 크레딧 기간별 관리

사용자 지시일: 2026년 10월 30일. 월별 크레딧과 토큰 한도를 지급 기간 전체에 나누어 사용한다. 이미 승인된 작업의 세부 진행은 자율적으로 이어가되, 잔액·기간·비용을 확인하고 불필요한 소모를 줄인다.

## 관리 항목

| 항목 | 기록 내용 | 구분 기준 |
|---|---|---|
| 구독 | 업체, 실제 플랜, 월간·연간 주기, 갱신·취소 예정일 | MCP 연결만으로 유료 구독을 추정하지 않음 |
| 결제 | 완료 금액과 통화, 거래일, 조정·환불 상태 | 예정 청구액·정가·월 환산액과 구분 |
| 월간 크레딧 | 지급량, 현재 잔액, 다음 초기화 시각, 이월·소멸 조건 | 영구 구매 크레딧과 구분 |
| 토큰·플랜 한도 | 사용률, 적용 기간, 초기화 시각 | 금액·크레딧 수량으로 임의 환산하지 않음 |
| 무료·무제한 | 대상 모델, 횟수·해상도·기간, 웹·MCP·API 적용 범위 | 웹 무제한을 API 무료로 단정하지 않음 |
| 작업 예약 | 작업자, 작업 ID, 모델, 수량, 예상 차감, 예약 시각 | 공유 풀의 중복 지출 방지 |
| 실제 차감 | 작업 전후 잔액, 실제 차감, 완료·실패·환불 상태 | 동시 사용분을 본인 작업 비용으로 단정하지 않음 |

실제 결제·개인 계정 원장은 Git 밖의 로컬 관리 경로에 보관한다. PC의 초기 원장 위치는 `I:/EXODUSER-Storage/admin/subscriptions/`다. 다른 호스트에서는 해당 원장의 접근 가능 여부를 확인하고 접근하지 못한 잔액을 최신으로 보고하지 않는다. 인증값·카드 정보·세금 식별값·청구 주소는 정책과 원장에 기록하지 않는다.

## 일일 예산 계산

예비율 20%는 사용자 지정 예산이 없는 상태에서 정한 초기 운영값이다. 변경 가능한 값이며 사용자 최신 지시가 우선한다.

1. 서비스의 기간 지급량을 확인했다면 예비분을 `ceil(기간 지급량 × 0.20)`으로 고정한다. 지급량이 없고 사용 가능한 잔액과 소멸일만 확인된 별도 크레딧은 그 잔액의 20%를 기간 시작 관측 시 고정한다. 소수 크레딧은 해당 서비스의 실제 단위로 계산한다.
2. `사용 가능량 = max(0, 해당 기간 잔액 - 고정 예비분 - 진행 중 예약량)`으로 계산한다.
3. `남은 일수 = max(1, ceil((초기화 시각 - 조회 시각) / 24시간))`으로 계산한다. 단, 날짜별 배분이 필요한 소멸 크레딧은 마지막 이용일을 포함해 보수적으로 분배하고 그 기준을 기록한다.
4. `하루 예산 = 사용 가능량 / 남은 일수`를 구한다. 정수 크레딧은 내림한다. 주간 예산은 `min(사용 가능량, 하루 예산 × min(7, 남은 일수))`다.
5. 같은 날 최초 예산과 오늘 사용량·예약량을 유지한다. 새 조회나 다음 작업을 이유로 오늘 사용량을 0으로 초기화하지 않는다. 새 지급·환불·대장 정정은 별도 거래로 기록한다.
6. 다음 날에는 최신 잔액과 남은 기간으로 다시 분배한다. 미사용분은 남은 기간에 재분배하며 예비분을 매 조회 때 잔액의 20%로 줄이지 않는다.

현재 잔액·지급량·다음 초기화일 중 필요한 값이 확인되지 않았으면 일일 예산은 `미확인`으로 남긴다. 연간 구독 종료일을 월간 크레딧 초기화일로 대신하지 않는다. 지출 상한의 여유 금액과 앞으로 지급될 API 크레딧을 현재 잔액으로 계산하지 않는다. 서로 다른 업체·크레딧·통화·주간 사용률은 합산하지 않는다.

## 실행 순서

- 단위 작업 시작 시 최신 잔액과 기간을 확인한다. 장시간 작업은 주요 단계 경계에서 추가 확인한다. 같은 시점·같은 계정의 이미 확인된 자료를 재사용하고 모든 도구 호출마다 전체 내역을 다시 읽지 않는다.
- 기존 산출물, 구독에 포함된 무제한, 무료 범위를 먼저 확인한다. 유료 작업은 예상 비용과 당일 잔여 예산을 비교해 공용 원장에 예약한 뒤 실행한다. 동시 작업을 원자적으로 예약할 수 없는 상태에서는 같은 풀의 유료 작업을 병렬로 시작하지 않는다.
- 결과가 불확실하면 기존 작업 ID와 결제 원장을 확인한다. 네트워크 오류를 이유로 새 유료 작업을 반복 제출하지 않는다.
- 완료 후 실제 차감과 환불을 기록하고 예약을 정리한다. 공유 풀의 잔액 변동만으로 모든 비용을 현재 작업에 귀속하지 않는다.
- 당일 예산을 넘으면 시점·범위를 조정하거나 이미 허용된 다른 도구·구독 범위를 사용한다. 예비분 사용이나 큰 작업의 기간 예산 변경이 필요하면 구체적인 수량과 영향을 보고한다.
- 추가 결제·크레딧 충전·업그레이드·자동 충전 활성화·구독 해지·갱신 변경은 별도 명시 지시 없이 실행하지 않는다. 관리 요청은 새로운 지출 승인으로 해석하지 않는다.
- 토큰 절약을 위해 반복 전수 검색·동일 문서 전문 재독·중복 배정·불필요한 위임·같은 검증 반복을 줄인다. 필수 검수, 사용자 승인 모델 기준, 타 팀 작업 보존은 유지한다.

## 용도별 운영

| 용도 | 현재 운영 방향 | 판단 조건 |
|---|---|---|
| 개발·총괄 | Codex 주력, Claude 전문 작업 | 실제 잔여 한도에 따라 조정하며 Claude 모델 기준 유지 |
| 2D 아트 | Higgsfield 웹의 이미 포함된 무제한 우선 | 실제 모델·해상도·웹 권한 확인, MCP 비용 별도 |
| 3D·리깅·모션 | Meshy 주력 | 월간·영구 크레딧 구분, 작업별 비용 확인 |
| 효과음·음성 | ElevenLabs 주력 | 월간 초기화일과 구독 종료일 구분 |
| 스프라이트·VFX | Ludo 보조 검토 | 인증·구독·잔액 확인 전 유료 사용 계획 확정 금지 |
| 실험·분쟁 서비스 | 현황 확인 후 판단 | 잔액 부족·해지·환불 요청을 완료로 간주하지 않음 |

이 방향은 현재 확인된 사용 권한과 잔여량에 따른 운영 판단이다. 기존 이미지 공급자 우선순위 등 사용자 최신 명시 지시가 있으면 해당 지시를 먼저 적용한다.

## 적용 범위

이 문서는 프로젝트 에이전트의 사전 확인과 지출 기록 규칙이다. 공급자 측 사용량 상한을 변경하거나 모든 채팅의 토큰 생성을 자동으로 가로채는 장치가 아니다. 이미 실행 중인 다른 채팅·Mac·외부 계정의 적용 여부는 별도 확인한다. 반복 모니터링 자동화와 결제 설정은 이번 정책 기록만으로 생성·변경하지 않는다.

# 서브노티카·얼리액세스 개발 공개 마케팅 벤치마킹

조사일: **2026-10-10 KST**. 사용자 지시: 최신 홍보 준비 콘텐츠를 계속 정리하고, 유명 게임이 얼리액세스와 개발 과정을 공개하며 운영한 마케팅 기법을 조사·벤치마킹한다.

## 최신 운영 정정: 시각 홍보 품질과 공개 전 미리보기

사용자 최신 요구는 긴 텍스트 공지를 연속 게시하는 운영이 아니라, 실제 장면과 이미지로 보여주는 홍보의 품질이다. 이번에 확인한 [Subnautica Habitat](https://unknownworlds.com/en/news/habitat-update-released)는 업데이트 영상·실제 이미지, [Hades II Unseen](https://www.supergiantgames.com/blog/hades2-unseen-update/)은 공식 영상·변경 설명·패치노트, [Project Zomboid Hallodoid](https://projectzomboid.com/blog/news/2024/10/hallodoid/)는 B41/B42 비교 영상·UI 개발 시연·미완성 표시를 글과 함께 제공한다. 이는 **영상/이미지와 설명 글의 조합**을 확인한 사례이며, YouTube Community 전체 업계의 게시 빈도 조사가 아니다. 전체 영상을 시청·청취해 편집을 분석했다고 주장하지 않는다.

- 전투 홍보는 정상 인게임의 실제 한 장면 안에서 공격·플레이어 대응·결과가 읽히게 만들고 원음을 사용한다. UI·캐릭터·스킬 소식도 해당 소재의 실제 화면이나 제작 이미지를 중심으로 간결하게 설명한다.
- 원화는 원화·콘셉트 단계라고 표시한다. 동일 영상을 중앙 확대 화면과 하단 전체 화면에 두 번 넣는 구성, 원화를 가리는 불투명판은 금지한다. 사용자가 해당 복제 숏츠를 내리라고 한 지시는 유지하며, 처리 결과는 실제 게시 상태로 확인한다.
- 신규 시각 홍보물은 **공개 전에 완성 미리보기를 사용자에게 보여주고 검수**한다. 한 소재에 한 경험을 설명하며, 긴 글만 매시간 채우거나 검수 전 자동 공개하지 않는다.

소규모 UI·캐릭터·스킬 개발 소식은 계속 독립 준비한다. 전체 보스전 완료 대기는 대표 보스 완료 영상에만 적용하며, 매시간 점검은 준비 상태 확인과 제작을 위한 주기이지 긴 텍스트 공지의 게시 주기가 아니다. 아래 기존 제안은 이 최신 기준을 우선하여 적용한다.

**핵심은 개발 변화에 다시 찾아올 이유를 붙이는 것이다.** 확인한 사례는 개발 의도와 실제 화면을 공개하고, 다음 업데이트를 예고하고, 배포 시 바뀐 플레이를 보여주고, 피드백 반영 결과를 다시 기록했다. 이것이 매출 성공의 원인이라는 인과관계나 동일 성과를 보장하는 근거는 이번 조사에 없다.

공식 개발사 블로그·개발자 Steam 글·공식 포럼·공식 영상만 근거로 사용했다. 영상의 존재·제목·게시일·임베드 형식은 확인했으나 모든 영상의 전 구간을 시청·청취해 편집을 분석한 조사는 아니다. 아래 사례는 **당시 얼리액세스 개발 운영의 역사**이며 2026년 현재 모두 얼리액세스라는 주장이 아니다. Subnautica 2의 현황과 원작 역사를 섞지 않았다.

## 3. FDG에 적용할 운영 방식

다음 길이와 빈도는 사례의 실제 정책이 아닌 **FDG 제안**이다. 이미 승인된 채널 운영 일정과 검토 조건 안에서 시행한다.

| 단계 | 중심 콘텐츠 | 재사용·유입 | 완료 기준 |
|---|---|---|---|
| 개발 예고 | 바꾸려는 플레이 경험1개·실제 준비된 이미지/장면·개발 중 표시 | 짧은 글·스틸 → 기존 데모/개발일지 | 실제 근거·적용 범위 확인 |

**일정:** 2026-10-10 사용자 정정에 따라 보스전 전체 완료 대기는 대표 메인트레일러에만 적용한다. 대기 중에도 UI·기존 스킬·캐릭터 제작 과정·부분 개발 소식의 근거 확인과 독립 제작을 진행한다. 매시간 점검은 준비 상태와 제작 진척을 확인하는 주기이며, 긴 텍스트 공지를 매시간 게시하는 기준이 아니다. 공개는 위 시각 품질·완성 미리보기 검수 기준을 충족할 때 진행한다. 대표 트레일러 인도 뒤 기존 화·금11:00 KST 운영으로 복귀한다. 화요일은 새 확인된 개발 변화, 금요일은 실제 업데이트 또는 피드백 반영을 후보로 준비하되 새 소재가 없으면 반복 게시하지 않는다. 매주 대형 업데이트나 미확정 출시일을 약속하지 않는다.

**보스전 첫 콘텐츠 후보:** “공격을 읽고 대응하는 보스전으로 바꾸는 과정.” 현재 전체 리디자인 완료는 미확인이다. 정상 배율의 예고→플레이어 대응→결과가 실제로 촬영 가능해진 뒤 제작한다. 그때 핵심 변화3개를 선정한다. 구 staged, raw atlas/helper GIF, 과거18초V3로 완료 영상을 대신하지 않는다. 이전 비교 자료도 정상 플레이 증거가 있을 때만 사용한다.

**개발 기록 문안 틀:**

1. 이번에 바꾼 플레이 경험: 한 문장.
2. 왜 바꿨는가: 실제 문제/피드백.
3. 무엇이 달라졌는가: 실제 화면과 핵심 변화 최대3개.
4. 현재 단계: 개발 중 / 테스트 가능 / 공개 데모 반영, 적용 버전과 별도 표기.
5. 남은 것: 실제 확인된 문제·검수 범위.
6. 질문: “첫 공격 예고를 보고 대응할 시간을 읽을 수 있었나요?”처럼 한 문제에 집중.
7. 다음 기록: 확인된 다음 작업만, 미확정 날짜 없이.
8. 체험 연결: 무료 데모·동일 개발 기록 링크·AI 보조 아트/음향 공개.

**측정:** 공개 URL·게시일·소재ID·버전·Steam UTM을 기록하고, 제공되는 플랫폼 조회/시청 유지·링크 유입·데모 플레이/피드백을 별도로 확인한다. 위시리스트 증가를 한 영상의 효과로 단정하지 않는다. 현재 계정 접근이 없는 지표는 미확인으로 둔다. 광고비 지출·대량DM·메일 발송은 이 계획에 포함하지 않는다.

사용자 직접 지시: “왜 boss 디스크에 엑소듀서 파일들이 다 다 들어가있냐 i 드라이버로 옮기고 있는데 앞으로는 i 드라이버로 넣어라”. 새 PC 작업에는 아래 위치를 적용한다. 이전 문서·브리프의 E: 기본값·E: 대체 출력 허용보다 우선한다.

- 소스 대조용 웹 파일은 `git show` 또는 필요한 정확한 파일만 사용한다. sparse checkout이어도 필요한 빌드 입력·검수 도구·`.meta`·세이브 격리 계약은 누락하지 않는다.
- 사용자가 폴더를 이동 중이면 해당 폴더의 새 파일 생성·임포트·빌드·수정을 안전한 경계에서 중단한다. 임의 목적지 생성·중복 대용량 복사·이동/삭제·작업 중 sparse 축소를 하지 않는다. 독립 읽기 조사·다른 소유 작업은 계속할 수 있다.
- 재개 전 실제 I: 목적지와 복사 완료를 확인하고 `.git`·공통 Git 디렉터리·worktree 등록·정션/링크·HEAD·브랜치·INDEX/WORK·필요 원본을 대조한다. 필요 시 올바른 작업 트리의 등록만 복구한다. 이동 완료 전 추정 경로로 Git repair·새 체크아웃·덮어쓰기를 하지 않는다.
- 출력 인수·캐시·다운로드 목적지가 실제로 I:인지 확인한다. 기존 실행기·메모리·여유 공간·사용자 창/세이브 보호는 유지하며 경로 변경을 이유로 우회하지 않는다. 소유권을 기록하지 않는 I: 파일시스템에서 Git 신뢰 오류가 나면 자기 생성 경로·등록·원격을 확인하고 정확한 경로에 한정해 처리하며 전역 신뢰나 `safe.directory=*`를 추가하지 않는다.
- PC 드라이브 규칙이다. Mac의 기존 `/Users/...` 작업 공간과 다른 사용자의 경로는 변경하지 않는다. I:에 둔 소스·백업도 원격 SHA 검증을 대신하지 않는다.

## 공유 작업 중의 안전한 복구 스냅샷

- 현재 브랜치/HEAD·작업 파일·공용 Git 인덱스를 변경하지 않는다. 독립 임시 인덱스에서 Git 객체를 구성하고 별도 백업 ref를 만든다. 공용 인덱스의 복사본도 별도 부모 커밋으로 남겨 스테이징 버전과 작업 파일 버전을 구분할 수 있다.
- 이 스냅샷은 여러 팀의 작업 중 상태를 복구하기 위한 WIP 백업이다. 기능 검수·정식 통합 커밋·릴리스 승인을 뜻하지 않는다. 원래 팀별 검수와 코드+docs 체크포인트 의무를 대신하지 않는다.
- 추적 파일의 수정·삭제와 확인된 신규 런타임 코드·에셋·테스트·docs를 포함한다. 알 수 없는 임시 파일, 사용자 세이브, 인증정보, 비밀키, 검수 캐시·대형 산출물은 GitHub에 무작정 추가하지 않는다. 제외 항목은 기록하고 필요한 원본은 로컬에 보존한다.
- 복사·읽기 중 변경 여부를 확인하고 캡처 시작/종료 시각과 기준 HEAD를 남긴다. 이후 발생한 편집은 이 백업에 들어 있지 않으므로 새 변경은 다음 체크포인트 대상이다.
- 원격 전송은 현재 승인된 `origin`의 고유 백업 브랜치로 진행한다. push 성공 이후 `git ls-remote`로 정확한 원격 ref와 SHA를 대조한다. 실패하면 로컬 보존과 원격 미완료를 구분해 보고하고 기존 안전 빌드를 유지한다.

## 빌드와 사용자 데이터

- `build-nwjs.mjs --integration-id=...`가 만드는 `/dist-integration-*/`는 원본 코드·에셋을 복사한 로컬 빌드 스테이징 폴더다. 2026-10-01 총괄이 `.gitignore`에 이 출력만 추가했다. 디스크 사본은 유지하고 실제 소스·런타임 원본을 숨기지 않는다. 실행 패키지 백업은 별도 기록한다.
- 기존 정상 실행본을 덮어쓰지 않고 `out/EXODUSER-integration-<ID>/` 등 고유 출력에서 검수한다. 검사 대상의 소스·포트·프로필·저장 경로를 기록한다.
- 사용자 세이브는 삭제·초기화하거나 GitHub에 올리지 않는다. 실행 파일·ZIP의 실제 보존 위치와 SHA는 소스 백업과 따로 기록한다. 소스 백업만으로 실행 패키지가 업로드됐다고 보고하지 않는다.
- QA 실측 중 대형 복사·압축·빌드는 조율한다. 작은 소스 체크포인트도 실시 시각을 남겨 해당 측정의 동시 부하 여부를 추적한다.
- 백업 브랜치로 복구할 때도 현재 작업을 먼저 보존하고 변경 범위를 확인한다. `reset --hard`, 강제 checkout/force push, 무단 백업 삭제는 사용하지 않는다.
- 삭제된 `ExoduserAutoCleanup50` 예약 작업을 다시 만들지 않는다. 기존 총괄 heartbeat에서 상태를 점검한다.

- 캡처 시작/종료 사이 HEAD와 공용 인덱스 SHA가 일치했고, 캡처한 파일의 재검사에서도 변경된 항목이 없었다. 백업 과정에서 원본 체크아웃·인덱스를 수정하지 않았다. 이후 다른 팀의 정상 커밋과 편집은 계속 진행 중이다.
- 용도 불명인 0바이트 `x.includes('공식'))`는 백업에서 제외하고 원본에 보존했다. 비밀키·사용자 세이브·무시된 캐시를 새로 추가하지 않았다.
- 상세 로컬 기록: `tmp/github-backups/20261001-010620/manifest.json`. 최근 기록 포인터: `tmp/github-backups/latest.json`. 원격 검증 시간과 각 포함 파일의 blob/SHA-256을 확인할 수 있다.
- GitHub가 영상 파일 크기에 권장 크기 경고를 표시했지만 전송은 성공했다. 기존 영상 이력이나 Git 저장 방식을 이번 백업에서 재작성하지 않았다.
- 총괄 자동화 `exoduser`의 기존 10분 주기·ACTIVE 상태를 유지하면서 위 백업 확인 규칙을 프롬프트에도 추가했다.

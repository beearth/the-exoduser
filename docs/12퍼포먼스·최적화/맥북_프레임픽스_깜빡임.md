# 맥북 프레임/깜빡임(Flicker) 픽스 — 마스터 트래커

> # ✅ 해결됨 (2026-06-15) — 3일짜리 디버깅 종료
> **증상**: 맥 M5 Pro / NW.js WebGPU에서 화면 전체가 심하게 깜빡임 (프레임은 120fps 정상).
> **근본 원인**: WebGPU `_glFlush()`가 한 프레임에 1~3회 호출되는데 **매번 `loadOp:'clear'`로 스왑체인 텍스처를 통째로 지움** → 먼저 그린 씬을 뒤 flush가 날려, 프레임마다 표시 내용이 달라짐 = 깜빡임.
> **해결**: 프레임 내 **첫 flush만 `clear`, 이후 flush는 `load`(누적)**, 프레임 끝에 플래그 리셋. → `game.html` L3624(`_glFrameClear`) / L4472(`loadOp`) / L4473 / L48945. 보조로 `alphaMode:'opaque'`(L4353).
> **커밋**: `82042082` (fix) → `c11304f1` (merge), origin/main 푸시 + Vercel 배포 완료. 백업 브랜치 `backup-0615-flicker-fix`.
>
> ## ⛔ 다시 건드리기 전 반드시 읽어라 (3일을 날린 함정들)
> 1. **"WebGL로 바꾸면 해결" = 절대 금지.** WebGL2는 M5 Graphite Metal **BGRA8 swizzle 버그로 3~10fps 폭락**(§2). 깜빡임은 사라지지만 게임이 못 돌아감. **WebGPU 유지가 유일한 정답.**
> 2. 깜빡임은 **시간적 현상** — 정지 스크린샷으론 확인 불가. 육안/영상 필요.
> 3. WebGPU에서 검은 화면+소리 = **device-lost** 간헐 증상(별개). 깜빡임과 혼동 말 것.
> 4. 이 깜빡임은 **DPR/fpsCap/vsync/bloom 문제 아님**(§3에서 다 실패 확인). present 횟수/loadOp 문제임.

> **최초 작성**: 2026-06-14 / **해결**: 2026-06-15
> **대상 환경**: MacBook **M5 Pro**, NW.js v0.112.0 (Chromium 149), ANGLE **Metal** 백엔드, Skia **Graphite**, Retina DPR=2, ProMotion 120Hz
> **문서 목적**: 3일간 같은 시도 반복으로 지옥을 겪음. **이미 해본 것(실패)** + **솔루션 리스트** + **확정 해결책**을 한곳에 박아 **두 번 다시 반복하지 않는다.**

### 현재 확정 사실 (measured)
- **WebGPU 경로**: 120fps. **화면 전체가 깜빡임.** ← **이걸 고쳐야 함**
- **WebGL2 경로**: 깜빡임 없음. **3~10fps** (swizzle 버그). 사용 불가.
- 인트로/로비/설정 메뉴는 WebGPU로 **정상 렌더**(282fps). 깜빡임은 주로 게임플레이/특정 순간.

## 1. WebGPU 깜빡임 — 코드 구조 (현재 상태)

### 렌더러 선택 (`game.html`)
- L2948 `IS_ELECTRON` = Electron만 감지. **NW.js는 여기 안 걸림** (`IS_NW`은 L2949에 따로 있으나 렌더러/벤치 분기에서 미사용).
- L2959 `IS_MAC = !IS_ELECTRON && /Mac/` → NW.js에선 `true`.
- L4819 `_useWebGPU = (!IS_ELECTRON) && ( ?webgpu=1 || (IS_MAC && navigator.gpu) )` → **NW.js 맥 = WebGPU 자동 ON**.

### WebGPU present 경로 (`_initWebGPU`, L4323~ / `_glFlush`, L4456~)
- L4352 `_gpuCtx.configure({device, format, alphaMode:'premultiplied'})`
- `_glFlush()` = getCurrentTexture 1번 + renderPass(`loadOp:'clear'`) 1번 + submit 1번.
- L4460 `if(_cmds.length===0){...return}` — **그릴 게 없으면 present 자체를 건너뜀(clear도 안 함).**

### ★ `_glFlush()` 가 **한 프레임에 여러 번** 호출된다 (의심 1순위)
| 호출처 | 조건 |
|---|---|
| L43993 | `_gameFrame%3===0` 일 때 (라이팅 합성 직전) |
| L43995 | `_gameFrame%3===1` 일 때 (블룸 합성 직전) |
| L48942 | **매 프레임** 끝 (`_fpsDraw()` 직후) |

→ 프레임마다 `_glFlush` 호출 **횟수·시점이 달라짐**(%3 케이던스). 각 호출이 `getCurrentTexture()`+`loadOp:'clear'`. 맥 Metal 스왑체인에서 **프레임당 present 횟수/타이밍이 들쭉날쭉 → 깜빡임**의 강력한 후보.

## 2. WebGL2 가 느린 이유 (도망가면 안 되는 이유) — `MAC_SWIZZLE_AUDIT.md`
- 증상: `"No valid write swizzle for color type 5 with format BGRA8"` 콘솔 폭주 → 10fps 이하.
- 원인: `GL.texImage2D(RGBA, RGBA, UNSIGNED_BYTE, canvas)` (L4521 `_getTex`, L4658 `_uploadCanvasTex`)가 **Canvas2D backing(맥=BGRA8888)** 을 RGBA로 swizzle해야 하는데 Skia Graphite Metal에서 이 경로가 버그/미구현.
- 즉 WebGL2를 살리려면 **swizzle 회피**(아래 솔루션 B군)가 필요. 단순 전환으론 못 씀.

### ★ 근본 원인 + 해결 (FINAL)
**원인**: 대형 맵(1-4 등)은 **스트리밍 뷰포트 합성 캔버스**(`_streamVpCvs`)로 렌더되는데 —
1. 카메라 이동 시 재합성하면서 **`_streamVpCvs._glVer`를 안 올림** → WebGPU `_getTex`/`_uploadCanvasTex`가 `_glVer`로 텍스처 캐싱 → **재업로드 안 함 → 맵 텍스처 첫 프레임 고정 = 제자리걸음**. (작은맵은 스트리밍 안 해서 멀쩡)
2. 과거에는 재합성을 3타일마다만 하면서 합성기준(`_offX`)과 그리기위치(`_drawX`)를 각각 사용해 **맵 드리프트/덜덜떨림**이 발생했다.

**해결 (game.html)**:
- `_streamVpCvs._glVer=(_glVer||0)+1` 재합성 직후 추가 (line ~40841) → 텍스처 재업로드 → 맵 스크롤됨.
- 스트리밍 재합성 조건에 `||_useGPU` 추가 → WebGPU는 **매 프레임 재합성**(합성기준=그리기위치 일치 → 드리프트 0, 떨림 제거). copyExternalImageToTexture 빨라 120fps 유지.
- **후속 수정(2026-08-10)**: WebGL2도 `_streamVpWorldX/Y`(합성 원점)에 캔버스를 그리도록 고정하고, 재합성 임계를 1타일로 낮췄다. 2타일 여백이 소진되기 전에 새 합성본을 만들므로 이동 중 드리프트·경계 점프 없이 WebGL swizzle 재업로드 빈도도 제한한다.
- Mac WebGPU에서 **Three.js 안개(`_fogGLInit`) 비활성** (별도 WebGL 컨텍스트가 Metal에서 WebGPU와 충돌). line ~7283.
- (§A2 후속) **텍스처 동일성 loadOp** 픽스로 1-4 WebGPU 크래시(uncleared texture) 해소.

**결과**: Mac WebGPU에서 1-4/보스룸 **이동·맵스크롤 정상 + 떨림 없음 + 120fps + 풀스크린 OK = 윈도우와 동일**. 깜빡임도 없음.

- WebGPU: **FPS 120, U:0.8ms D:1.1ms** (게임로직 빠름) 인데 **2프레임 캡처 비교 시 배경이 1px도 안 움직임** = 카메라/월드 정지.
- WebGL2(Mac, Graphite OFF): **이동 정상**인데 **7~20fps** (U+D=8.8ms인데 프레임 143ms → 브라우저 텍스처 업로드 스톨 = swizzle).

### 확정된 원인 방향
- **Mac Metal 텍스처 업로드가 느림.** WebGPU=`copyExternalImageToTexture`, WebGL2=`texImage2D(RGBA, canvas)` BGRA swizzle (`MAC_SWIZZLE_AUDIT` 동일 계열).
- **맵 청크 수에 비례** → vert(1-1) 청크 적음=끊김, grid(1-4/보스) 청크 많음=프레임 멈춤/로딩실패.

## 7. 해결 요약 (FINAL)
**근본 원인**: WebGPU `_glFlush` 멀티 호출 시 매번 `loadOp:'clear'` → 한 프레임 안에서 먼저 그린 씬을 뒤 flush가 지움 → 프레임 간 표시 내용 불일치 = 깜빡임.
**해결**: 프레임당 첫 flush만 clear, 나머지는 load 누적, 프레임 끝에 플래그 리셋. (game.html L3624 / L4470~ / L48943)
**유지 결정**: WebGPU = 맥 정답 경로(120fps). WebGL2는 swizzle 버그로 사용 불가(§2). WebGL로 전환 금지.
